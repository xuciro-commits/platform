# 设计：归一资源目录页

## 分类判定规则（可操作）

打开任意清单页，依次回答：

1. 清单里的记录**由谁产生**？成员声明（资源目录页/通用记录页）或系统产生（运行监控页/聚合索引页）。
2. 成员能否**创建**？动作目录里有 `create` 类动作 → 资源目录页，New 必须在页头；没有 → 不是资源目录页，禁止伪造 New，必须归因。
3. 数据来自**实体目录还是定制端点**？实体目录 → `Records`（自动获得完整能力）；定制端点 → DataTable + 行内动作（从动作目录渲染）+ 归因。

## 与现行规范的关系

- 「记录列表按选择渐进显示详情」「列表自带完整数据能力」已规定通用记录页的行为；本 change 把同等纪律扩展到**非实体目录**的清单页（监控页、索引页），补齐分类学与归因义务。
- 「顶级入口按构建运营系统三区组织」不受影响；本 change 不动导航结构。

## 不做的事

- 不把监控表迁到实体目录（`platform.connector` 等不在 `/v1/entities`，迁移动需后端建模，超出本 change；已在任务中注明后续路径）。
- 不统一监控页高度到一个常量（各页信息密度不同），只修明显失配（180px 的连接器表）。
- 不动 build 包 16 个已归一的资源目录页。
