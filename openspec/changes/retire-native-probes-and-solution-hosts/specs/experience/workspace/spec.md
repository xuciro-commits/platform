# Spec Delta

## ADDED Requirements

### Requirement: 已准备的业务应用支持通用离线工作

工作区 SHALL 允许用户显式准备已获权应用的确切发布内容、动作描述及有限任务数据，在断网和客户端重启后重新打开该范围、编辑本地草稿并排队请求。缓存 MUST 标明来源与时间；未准备的页面、记录、动作和新身份登录明确不可用。离线排队不是业务接受，客户端不执行最终授权、容量预留或其他服务端业务裁决。

#### Scenario: 断网后重新打开已准备应用

- **GIVEN** 用户已在线准备一个已发布业务应用及其必要表单
- **WHEN** 网络断开，客户端关闭后重新打开该应用
- **THEN** 可读取已准备范围和继续编辑本地草稿，提交显示为待发送
- **AND** 不把缓存显示为实时状态，不将本地草稿显示为已获业务确认

#### Scenario: 离线访问未准备任务

- **WHEN** 用户离线打开未缓存页面或请求未准备的数据和动作描述
- **THEN** 工作区明确说明该任务需要联网，保留原输入
- **AND** 不伪造空列表、最新定义或成功答复

### Requirement: 离线草稿与队列按身份持久保存

本地草稿、已准备内容和发件箱 SHALL 按宿主、租户、实际主体及适用发布身份隔离；切换身份后只能恢复该身份自己的内容。持久化失败或已有内容无法解码时 MUST 明确报告并保留可恢复内容，不以空队列或内存写入冒充保存成功。离线请求状态继续使用既有 K5 实现，不另建应用专用队列。

#### Scenario: 同一客户端切换主体和租户

- **GIVEN** 原主体有未完成草稿或待确认请求
- **WHEN** 用户切换主体或租户后再次进入工作区
- **THEN** 新会话不会读取、显示或发送原会话的业务内容
- **AND** 切回原身份时仍能恢复其原草稿和队列

#### Scenario: 本地持久化失败

- **WHEN** 客户端无法保存草稿、请求或状态变化，或不能读取既有保存内容
- **THEN** 用户看到实际失败及仍可操作的原输入
- **AND** 不提示已安全保存，不静默清空原内容，不在未保存请求身份时发送业务请求

### Requirement: 离线续传保留原意图和权威答复

续传 SHALL 使用原租户、主体、目标、幂等键、输入、预期修订和固定版本，按 K5 与原宿主答复接续。发送过程中断或崩溃后无法确认的请求 MUST 按原意图核对，不生成新键或改用最新动作；服务端仍决定当前授权与版本兼容。冲突、拒绝和未知状态须在原任务中可见，人工修改形成关联原请求的新意图。

#### Scenario: 已提交请求在客户端得到答复前重启

- **GIVEN** 客户端已保存并发送一项请求，但尚未保存确定答复
- **WHEN** 客户端重启并恢复联网
- **THEN** 恢复原待确认请求并沿原键取得确定答复，不重复产生业务结果
- **AND** 同样行为适用于 PMS 及另一种业务应用，不依赖房间或预订专用代码

#### Scenario: 排队期间撤权或模型升级

- **GIVEN** 离线请求排队后，其主体被撤权或目标动作发生不兼容升级
- **WHEN** 客户端联网发送原请求
- **THEN** 展示原宿主的授权或兼容拒绝并保留原请求
- **AND** 不自动提升权限、改写参数或换版本后重新执行

#### Scenario: 用户纠正已拒绝的请求

- **WHEN** 用户在原任务中修改导致冲突或拒绝的输入并确认重新提交
- **THEN** 客户端建立关联原请求的新意图，保留原请求及答复
- **AND** 对结果仍未知的原意图先完成核对，不能通过修改输入绕过未知状态
