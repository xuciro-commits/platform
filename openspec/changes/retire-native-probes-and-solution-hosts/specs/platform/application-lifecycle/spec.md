# Spec Delta

## MODIFIED Requirements

### Requirement: 试用与验证不修改正式状态

系统 SHALL 通过原候选、私有执行上下文和受控样本执行预览与验证，保留接受、拒绝和变化比较。验证 MUST 使用实际业务规则及其读取边界，不应另写一个宽松模拟执行器；试用不得把业务写入、通知或效果泄漏到正式环境。需要组织范围的试运行 SHALL 明确提供有界合成组织，由原 Enterprise owner 在隔离环境维护，不能复制正式组织、任职或自动授予角色；便携计划不绑定本地成员身份，空任职主体表示本次选定成员。

#### Scenario: 验证方案尝试执行外部效果

- **GIVEN** 候选验证运行在非正式私有上下文
- **WHEN** 被验证动作准备生成外部投递
- **THEN** 结果保留可检查的意图或明确的不支持诊断
- **AND** 不实际向客户设备或外部业务系统发送该效果

#### Scenario: 相同角色在不同合成单位试运行

- **GIVEN** 两个当前成员持有同一业务角色，合成任职只允许其中一人读取目标单位
- **WHEN** 在同一候选及固定组织样本中运行受范围限制的任务并恢复
- **THEN** 原授权规则接受获权成员并拒绝另一成员，恢复保留相同结果
- **AND** 正式组织与任职没有变化，试运行不能解析只存在于正式环境的企业元素

### Requirement: 原生参考能力只有完成替代后才退出

原生应用的退出 SHALL 先区分负责人明确撤回的功能与仍需交付的能力。保留能力的替代 MUST 覆盖约定的数据、动作、规则、权限、界面、版本、历史和在途责任；受控构建产物完成原任务、比较接受拒绝语义并获负责人体验确认后，才删除被替代普通路径。明确撤回的功能无需重建；获准重建的测试环境按 `runtime/deployment` 隔离旧状态，此例外不改变其他数据的历史责任。MUST NOT 用 API、绿测或模拟包宣称完整替代。

#### Scenario: 原生界面尚未获得等价确认

- **GIVEN** 通用页面已能运行，相关业务能力仍在保留范围，但负责人尚未确认原任务等价
- **WHEN** 整理原生参考应用
- **THEN** 保留仍承担该任务的入口和所需历史读取
- **AND** 不因代码重复或行数目标提前删除

#### Scenario: 负责人明确撤回参考应用功能

- **GIVEN** 本次范围明确撤回 HCM、CSM，且其旧业务数据可重建
- **WHEN** 退出对应参考应用
- **THEN** 删除其产品入口和专用普通执行路径，不生成同名替代应用或保留隐藏运行入口
- **AND** 原审批、任务、通知和 AI 平台能力继续由原 owner 提供

#### Scenario: 保留任务只能调用原生规则

- **GIVEN** 通用页面仍依赖待退出原生应用的对象、动作或回调
- **WHEN** 检查该应用是否完成完整替代
- **THEN** 该替代尚未完成，相关能力在原归属方补齐
- **AND** 不把页面替换映射或行业代码改名视为业务实现已退役

## ADDED Requirements

### Requirement: 声明式行业包形成可编辑的完整构建输入

声明式行业包 SHALL 提供具备确切版本与完整依赖的模型、规则、流程、页面、AI 定义及受控样本，供构建者生成原 owner 草稿、修改并经原候选发布。该交付范围内的行业行为 MUST 由可编辑声明表达；需要行业算法代码的例外须先由负责人另行决定。包安装不自动发布业务、授予权限或携带环境凭据；包和发布沿用既有生命周期。

#### Scenario: 在纯平台租户中构建应用

- **GIVEN** 目标租户只有平台能力，没有任何待退出原生参考应用
- **WHEN** 构建者从行业包生成草稿、配置环境绑定并发布应用
- **THEN** 应用可通过工作区完成其保留任务
- **AND** 其定义、动作和运行不依赖原生应用注册、专用种子或开发者直调

#### Scenario: 修改模板形成不同业务配置

- **GIVEN** 构建者已从同一行业包生成受控草稿
- **WHEN** 为另一酒店或工厂修改业务数据、规则、流程与页面并发布
- **THEN** 差异由新发布内容表达，不要求修改或重新编译宿主
- **AND** 适用的授权、版本与接受结果约定保持一致

#### Scenario: 模板包含与对象同名的编排页面

- **GIVEN** 包内页面使用对象名称，但包含作者声明的布局、动作与查询
- **WHEN** 生成原 owner 草稿并发布
- **THEN** 保留该页面声明，不将它替换成对象的自动生成页
- **AND** 只有没有独立页面草稿且内容与自动生成页完全相同的页面才省略页面草稿

#### Scenario: 较大草稿包在后续批次追加失败

- **GIVEN** 包草稿处于原联合草稿上限内，但超过单个 Composite 的 64 项上限
- **WHEN** 后续批次追加失败，客户端以原请求键重试或宿主从前批接受结果恢复
- **THEN** 每批仍不超过原上限，并绑定相同的完整草稿计划
- **AND** 已接受的前批保持未发布且不被重复创建或覆盖，只接续未接受的剩余批次
- **AND** 使用原键替换草稿计划被拒绝

### Requirement: 完整替代验收覆盖保留的协同任务

完整替代 SHALL 将保留业务任务与其接受、拒绝、记录变化、权限及异常处理对应起来；发现差异时明确判断原实现缺陷、已确认裁剪或构建缺口。应用间任务 MUST 通过既有版本化协议、请求答复与补偿完成，其语义引用 `platform/integrations`；单页成功或单方状态变化不能证明整条任务已完成。

#### Scenario: 团体订房出现部分预留失败

- **WHEN** CRM 通过 PMS 预留一组房间，后续预留被容量规则拒绝
- **THEN** 原预留、拒绝和释放补偿均可追溯，商机不被误标为全部预留成功
- **AND** 构建产物自身完成处理，不回到原生 CRM 或 PMS 执行

#### Scenario: 生产协同收到重复或超量结果

- **WHEN** MES 按稳定批次身份提交生产结果，ERP 收到重复批次或超过剩余数量的结果
- **THEN** 重复请求沿原答复处理，超量被拒绝，累计数量、库存和核算事实保持一致
- **AND** 答复丢失沿原批次身份核对，不以新请求重做已发生业务
