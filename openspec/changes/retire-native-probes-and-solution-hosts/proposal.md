# Proposal

## Why

变更前，酒店与制造靠 `solutions/*` 编译装配六个 Go 参考应用和对应专用客户端，不能证明构建者可以仅用平台交付这些业务。本次明确退出 HCM、CSM，用声明式构建产物完整重建 CRM、PMS、MES、ERP，并把仍有价值的离线、观测和 AI 任务交回通用能力。

## What Changes

- **BREAKING**：删除 HCM、CSM 的产品入口、服务端、客户端和专用场景，不重建请假、人事审批、客服工单或客服 Agent；平台通用审批、任务、AI 和通知继续保留。
- **BREAKING**：CRM、PMS、MES、ERP 的对象、动作、规则、流程和界面改由行业包模板及发布后的应用资产承担。替代验收通过后，同批删除对应原生普通路径，不把行业 Go/React 搬到另一个目录继续运行。
- 保留 CRM↔PMS 团体订房，以及 MES↔ERP 生产协同。前者覆盖预留、确认、释放和失败补偿；后者覆盖工单执行、分批结果、数量核对、库存与账务事实。
- 保留并重建离线草稿与发件箱、设备采样与停机分析、销售和制造的有用 AI 任务；使用既有 K5、Observation/Flow、AI/Agent 等 owner，补齐跨应用可用的正常产品入口。
- **BREAKING**：用同一通用宿主程序及镜像替换酒店、制造专用启动程序。行业差异来自受控包、应用发布内容和环境配置；安装包、生成草稿、发布、授权继续是不同决定。
- **BREAKING**：本次已获准重建旧探针的测试数据和结构；不迁移其历史、在途实例、旧对象名、旧接口或桌面草稿。使用新的测试数据范围隔离旧请求，保留部署配置、密钥和非本次授权数据，不能通过放宽恢复检查启动旧日志。
- 本次行业逻辑全部采用可编辑声明和可视化表达。若完整业务任务证明必须引入行业算法代码，先单独讨论该例外，不能自动改用受控代码或原生回调完成退役。

四个重建应用的保留范围：

| 应用 | 保留的业务结果 |
|---|---|
| CRM | 客户与商机、归属权限、赢单/丢单、团体房预留与成交协同、可复核的销售建议 |
| PMS | 房型与按日/按小时容量、预订/保留/修改/确认/取消/释放、到期处理、渠道接入与重复识别、必要通知 |
| ERP | 科目与期间、凭证及明细、平衡过账与冲销、采购/收货/库存、生产数量与标准成本核算 |
| MES | 主数据与工艺版本、工单与拆批、资源能力匹配、现场执行、质量双签/返工/报废、完工追溯、设备停机与原因、生产协同及辅助建议 |

## Capabilities

### New Capabilities

无。沿现有职责扩展，不为退役任务新建永久模块。

### Modified Capabilities

- `platform/application-lifecycle`：区分明确撤回的探针功能与必须完成替代的能力；规定声明式行业包、应用构建与完整替代的验收边界。
- `runtime/deployment`：通用宿主与配置装配取代编译时行业组合；规定本次测试环境重建及原部署资源保留边界。
- `platform/business-models`：补齐有界时段迭代和整体容量约束；复用唯一平台账簿，以记账声明表达关闭期间策略并保留原冻结意图。
- `experience/workspace`：将已有 K5 队列补齐为通用离线工作体验，覆盖已准备应用的离线重开、持久草稿、身份隔离、未知结果和冲突处理。
- `platform/integrations`：声明式状态区间分析与事件纠正保留停机原因、来源和身份，不依赖 MES 私有事实容器或算法。
- `platform/ai-knowledge`：在原评估器声明结构化比对字段、绑定候选查询，并通过原提议采纳路径写入受保护生成字段；完整输出验证、当前权限、计量与保存结果恢复保持原归属。

## Impact

- 删除范围包括 `apps/{crm,pms,mes,erp,hcm,csm}` 的被替代/撤回部分、`web/packages/{crm,pms,mes,erp,hcm,csm}`、`solutions/{hospitality,manufacturing}` 及其专用启动、注册、构建与部署引用。旧测试中的有效规则转为平台 owner 场景和可移交验收资产，不能只删断言。
- 新通用启动入口复用 `capabilities/server/deploy*.go`、平台应用和原恢复工厂；受控包复用 `packages.go`、`package_drafts.go`、候选发布与安装机制。`industry.mes-workspace` 依赖原生 MES 的版本随完整替代退出。
- 业务建模复用对象、关系、集合、事务、编号、Core 账簿、版本、Flow/Work；记账声明补齐期间策略，不保留 ERP 的第二套账簿。AI 重建沿 `platform/ai-knowledge` 的原授权、评估和执行归属补齐声明能力，不增加专用 Agent 执行路径。
- 离线扩展位于现有 `web/packages/kernel`、`@platform/app` 与工作区；观测分析位于原 Observation/Flow、规则和身份能力归属处。设备技术驱动仍可用平台代码实现，行业规则不进入驱动或宿主。
- 同步调整 Makefile、模块依赖、Catalog/生成物、模板、验证与本地更新入口。统一宿主指统一程序和镜像；酒店 8495、制造 8490 可继续作为两个配置实例，不要求合并物理进程。
- 保留 `industry.heating` 与现有构建资产作为回归对象。平台现存历史兼容、K1–K9、身份和持久接受规则不因本次测试数据重建而放宽。
- 本提案不改变 WorkQueue 的项目优先级；实施与必要验收进度以本 change 的 tasks 为准，不把提案场景当作已通过的运行证据。
