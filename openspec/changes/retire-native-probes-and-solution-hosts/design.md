# Design

## Context

动机和确认范围见 [proposal.md](proposal.md)。源码核对基线为 `30bb68ee00836c2ada9845bb60bdfb23de916903`。下文说明目标边界；实施与验证进度以 [tasks.md](tasks.md) 为准，设计场景本身不是运行证据。

| 已观察的实现 | 对方案的约束 |
|---|---|
| `solutions/*` 的租户工厂和 `cmd/*-server` 直接导入原生业务应用，制造还用 Go 播种产品、科目和组织 | 退役同时替换装配、初始化、恢复工厂及构建入口，不能只删菜单 |
| `capabilities/server/tenants.go` 已由配置列出租户，但其业务组合仍取决于 `Deployment.Rebuild` | 复用配置与部署，不另建租户管理器 |
| `packages.go`、`package_drafts.go` 已支持封存包、生成 Build 草稿和原候选发布；`industry.mes-workspace` 仍引用原生 MES | 行业包机制可复用，现有 MES 页面包不是完整替代 |
| Build 对象以 `build.<name>` 安装到原 owner，Application 主要组织页面及资源 | 应用入口、包身份与运行权威分开；不从四个应用图标推导四个独立权威 |
| `platform/transaction.go` 已有集合迭代、余额、账簿意图；规则有日期比较和日/月运算 | 先用规范化子对象与既有机制，补齐具体时间片和批量业务表达缺口 |
| `web/packages/kernel/src/client.ts` 已持久化 K5 队列，但存储键在主体解析前固定，保存错误被忽略，恢复发送中请求和离线重开缺少完整接线 | 离线工作不是新造队列；要修复现有客户端生命周期并补有限离线内容 |
| MES 在 `equipment.go` 私有保存样本、派生区间及原因；通用 Observation 目前以数值摘要和有界外部来源为主 | 不能把 MES 算法直接复制到宿主，需要原观测/流程的通用状态区间表达 |
| ERP 自有账簿与 `apps/core/books.go` 重复；两者的关闭期间行为不同 | 保留唯一 Core 记账实现，用声明表达必要期间策略 |

## Goals / Non-Goals

**Goals:**

- 交付可从纯平台租户构建、发布、运行和修改的应用；原生探针不再是隐含依赖。
- 用业务结果确定数据模型和通用缺口，允许改变旧结构与身份；保留边界内的规则、权限和可操作结果。
- 每项能力沿原 owner 扩展，验证与产品入口使用同一声明、求值器及接受路径。

**Non-Goals:**

- 本次不迁移旧原生测试历史、在途流程或桌面草稿，不维持其接口、字段及深链兼容。
- 不更换内核、授权体系、发布机制或基础设施，不新增时序数据库、业务执行器或插件市场。
- 离线以现有工作区客户端交付；不保留 PMS 专用 Tauri 应用，也不把新原生安装包作为本次前置要求。
- 本提案不重排 WorkQueue，不把独立 FDE 交付、客户上线、真实模型品质或生产容量计为本次已验证事实。

## Decisions

### 1. 一个通用程序，多个配置实例

在 `capabilities/server/cmd/platform-server` 提供通用启动入口，集中装配当前公共平台应用、Console 和技术依赖；正常启动与 `Deployment.Rebuild` 调用同一工厂。行业方案不进入该工厂，不用行业开关加载不同 Go 业务代码。

酒店 8495、制造 8490 沿用原运维入口，运行同一程序和镜像。实例仍可各自承载一个或多个租户；统一程序不要求合并数据库、进程或端口。现有 `TenantSpec`、模板、身份提供方和本地模式继续复用。

没有选择把两个 Solution 目录改为两套“通用”包装：它会继续维持两份装配和恢复责任。也不把方案实现为另一个运行时插件层。

### 2. 行业模板、应用发布和权威保持不同身份

以酒店和制造的可编辑行业模板组织四个应用根及其共享资产，使用现有 `PackageDescriptor`、`PackageBlueprint` 和 `ReleaseAsset`。包名在实施时沿现有命名确定；行业包带声明、样本、验收计划与配置说明，不带业务 Go/React。客户应用由构建者修改模板后经原候选闭包发布，发布内容和环境绑定分别保存。

导入保留作者编排的同名页面，只有没有独立页面草稿且内容与对象自动生成页完全相同才省略页面草稿。包草稿继续受原联合草稿上限约束，超过单个 Composite 的 64 项时按原接受路径分批创建；每批绑定完整草稿计划的摘要。追加失败可留下已经接受、尚未发布的前批草稿，客户端保留原请求键，重试和恢复核对相同计划后接续剩余批次，不覆盖前批，也不宣称整包原子发布。旧 Composite 格式保持原摘要与恢复语义，新批次使用带计划摘要的格式 3。

复用 `industry.production-provider`、`industry.production-consumer` 的声明式分批协同内容，补齐其业务模型及界面后纳入制造模板；不在同一安装中保留两套相同协议或业务状态。依赖原生 MES 的 `industry.mes-workspace` 版本随完整替代退出。`industry.heating` 保留并作为回归对象。

新对象继续使用 Build 的真实资产 owner；科目、期间、总账归 Core，组织与身份继续归原平台能力。采购的账务参照读取使用 Core reference-reader，仅开放科目和期间，不授予主数据维护、凭证读取或账务写入；无完整凭证范围时试算拒绝，不将过滤后的空查询显示为零余额。Application 的资源引用不转移所有权，普通使用者不因应用安装获得 Builder。各业务对象显式声明角色、行范围和字段读取规则。

行业包的 `blueprint.setup` 保存可审阅的初始化请求及所需角色，载荷保留确切 JSON 字节。包页面展示计划；操作者发布业务定义后，以 `make initialize` 显式执行，客户端逐项调用 Enterprise、Core、Build 各自的原提交入口，并携带原动作目录的 schema 内容版本。计划不安装为跨应用 Flow，不增加服务端初始化执行器，也不在安装、激活或重启时执行。角色授予、组织任职和环境凭据仍由操作者单独配置。

初始化没有跨 owner 原子性。计划内容、操作者与运行键确定每项原请求键；中途失败后，用相同内容、身份与运行键接续已接受前缀，原 owner 决定重复、冲突与当前权限。更改计划或运行键是新的显式意图，不能用来绕过未知答复；定义已变化时先核对原请求，不自动改写已提交请求。样本使用明确标识，不覆盖已有冲突记录。

MES 工作中心的产线是原企业组织引用。工单由首工序派生所属产线，批次由当前工序派生产线；主管按 `site/below` 处理所属单位及下级工单，操作员按 `site/unit` 执行当前产线批次。工单的操作员读取保留跨工序协作所需范围，质量角色保留跨线复核资格，生产服务角色保留声明的协议职责。异常、签署及协同结果带原业务产线引用；完工工单、终结批次和历史结果用原 `EnterpriseUse` 区分当前使用与历史使用，不删除原引用。

候选试运行可以显式携带有界 `organization` 合成样本，由 Enterprise 自己创建隔离模型，仍由原目录与授权引擎判断范围；不复制正式组织或任职，不授予正式角色。便携验收计划的任职 `party` 留空，绑定本次选定成员；本地多主体试运行可以明确列出受控试验成员。组织样本随固定输入保留在计划、候选与恢复环境中，构建器可在原试运行编辑器审阅和编辑。

CRM/PMS 和 MES/ERP 的协同使用版本化协议及独立请求、答复和补偿，即便某个配置中对象共用 Build owner，也不靠跨应用直接改记录模拟另一方确认。另用独立租户场景验证真正的跨权威协同，不把同一 Build owner 下的四个应用宣称为四个独立权威。原协议的 Go 契约与一致性向量可以保留；无消费者的原生参考提供方和模拟启动程序退出。

### 3. 按业务职责重新建模，不复制旧结构

| 应用 | 声明与数据组织 | 必须观察的业务结果 |
|---|---|---|
| CRM | 客户、商机、团体预留及逐房请求分为对象；归属与阶段由规则声明，团体任务用 Flow/Confirmation 组织 | 获权销售操作自己的商机；部分预留失败会释放已取得的房间；赢单确认、丢单和到期释放均有答复 |
| PMS | 房型、容量、预订与占用记录分开；时间片容量及超售上限由声明维护；渠道为受控 Source/Connection | 按日和按小时均不能超限；修改先计算整体变化；拒绝不遗留占用；重复渠道输入只形成原结果；到期处理和通知走原 Work/Effect |
| ERP | 单据草稿和明细为子对象，商品/组件、采购/收货、库存流水与余额分开；正式科目、期间和总账使用 Core | 多行平衡、过账编号、冲销和闭期策略成立；收货及生产结果只计入一次，原接受业务与记账状态分别可见 |
| MES | 工艺版本、工序、设备能力、工单、批次、执行、异常和签名为明确对象；发布工艺通过业务版本绑定 | 能力不符拒绝开工；旧批次固定旧工艺；双人不同含义签名才能处置；返工目标合法；批次数量、完工与追溯一致 |

PMS 时间片先复用原完整集合、余额约束及事务迭代。当前规则只有日期比较、日/月运算，事务 `forEach` 消费已声明集合，尚不能据此宣称已支持按日/小时展开整个预订区间；本次在原规则/事务归属处补齐有界时间片输入、小时运算和原子占用变化，进入原类型与预算检查。用酒店占用和会计期间日期枚举检查通用性，不写房型专用算子，不预建无限日历，也不让操作者提交内部时间片数组。

工单拆批、凭证明细、组件消耗与签名首先采用现有子对象、完整集合、具名步骤及版本绑定；不为复刻旧嵌套数组增加无类型 JSON 执行系统。所有新增声明均提供原构建器入口，JSON 源码与可视化编辑同一草稿；只在测试中能拼出的配置不算完成。

### 4. Core 是唯一总账，期间策略由声明固定

原 ERP 的凭证草稿成为可编辑业务对象，正式凭证、编号、平衡、期间、冲销与试算仍由 Core 负责。原 ERP 的第二套记账函数退出；库存、应收应付等分账继续由自己的对象和余额声明承担。

为现有记账声明补充“关闭期间拒绝 / 转下一开放期间”两种明确策略，在 Core 同一检查器解释；旧发布缺省保持当前行为，重建 ERP 显式选择拒绝。策略随原发布和冻结 Effect 保存，重试不能切换，历史不重算。金额和币种沿现有类型化运算及适配边界，验收包含小数金额与反向冲销，不按旧结构的数字字面值猜单位。

Core 与 Build 是不同权威：单据和库存接受后，经已封存意图异步交付总账。界面明确区分待记账、已记账与记账拒绝；不能把原 ERP 同权威原子过账的中间状态照搬到这条路径。此差异采用现行 `platform/business-models` 的共有账簿边界，验证分别核对原业务结果和原账簿收据，不宣称跨权威原子性。

### 5. 通用离线客户端继续使用一份 K5 状态机

在现有 `EdgeClient`、`Authorities`、工作区 Host 和 Outbox 上完成离线能力；持久化适配与内容准备属于客户端，K5 决定状态仍唯一。客户端在实际宿主、租户和主体确认后绑定存储范围，切换会话停止旧范围发送；避免目前先以空主体建立键、随后原地修改 connection 的问题。

已准备范围包含打开应用所需的工作区资源、确切发布页面/动作和用户选定的有限任务数据，供断网重开与编辑；未保存表单草稿与已排队请求区分，后者保留不可变请求身份。缓存只提供本地任务上下文，不保留永续授权或构建新业务数据库。缺少缓存的任务明确需联网。

持久化失败不能吞掉并报成功；发送前保存原请求，重启时将不确定的在发请求交回 K5 的未知处理。续传核对原键、版本、目标与修订，原权威判断当前权限；冲突纠正建立关联新意图。至少在 PMS 预订和制造业务中使用相同客户端机制后，删除 PMS 专用桌面代码和队列。

### 6. 停机分析扩展原观测和流程能力

采样、技术协议和原始保留仍归现有外部来源/网关。通用声明提供状态条件、事件时间与有限窗口，复用原 Observation 读取、Flow 接续和业务动作，不把 MES 的全量 FactLog 搬进宿主，不用仅有均值等数值摘要猜测停机区间。

在原观测来源与流程步骤中提供有界、类型化的状态区间结果，保留覆盖、质量、配置修订与处理前驱。行业模板声明“停机”或“温度越界”的条件、原因字段与通知对象；平台只提供通用区间和纠正机制。

状态条件使用原规则求值器，声明值类型、最大采样间隔、迟到策略和结果上限。来源提供有序事件时间、实际接收时间、质量、来源修订及完整覆盖证据；一次读取最多 5000 个点，结果区间与未知区段合计最多 256 项，超限拒绝而不截断。每个读数只在声明间隔内有效，缺样和不合格质量留下未知区段；窗口切边和未知边界保持开放，不能当作已观测到的正常结束。`reject` 不接受窗口结束后的到达，`correct` 允许截止时间后声明时长内的到达；超过该范围的时段仍是未知。读取只返回紧凑结果，原始采样不进入业务记录或接受结果。

原事务的 `intervals` 步骤只消费宿主私有接受上下文，构建者映射结果对象的标量字段，并指定原有完整、有序集合及同对象前驱关系。普通输入不能提供观测依据；原规则可检查 `observation.ready/source/object/subject`，原不可变约束保护来源和边界，人工原因仍是对象自己的动作与字段。K1 检查身份与拆并，实际记录和前驱边由原账本及关系 owner 保存；Flow 读取这些类型化对象，不另建观测执行器或队列。无变化不改写事件；拆并产生新身份与待复核标记，退出身份不复用。新接受结果格式 10 固定紧凑区间依据和原集合读取见证，继续读取旧格式 8、9；恢复只应用保存映像。相互引用的对象与关系按完整模型闭包安装和复核，不允许执行依赖循环。

制造模板把观测设备、来源标识、主管单位和提醒策略作为普通业务配置；停机事件按原组织范围读取，原因动作与主管复核沿原事务执行。提醒复用 Work 的组织收件人、稳定任务键和到期作业；退出事件关闭原任务，人工原因与操作者仍留在原事件历史。停机页面用原表格、记录视图和有版本的前驱查询呈现当前事件及原决定，不增加私有停机页或通知回调。

事件沿原 K1 身份/关系机制连续，一对一变化保留身份；拆分与合并记录前驱，人工原因只在归属明确时接续，否则要求复核。区间、原因及通知意图经原接受结果保存，重启不重做已接受的分析。用制造停机与供暖越界两种语义验证该能力；真实设备接入和真实外部存储容量分别报告。

### 7. 有用 AI 任务交回平台声明

销售查询与操作辅助、商机建议、制造计划/异常建议、上游订单匹配纠错及交期查询，用既有 Agent、Function、知识来源、工具范围、守卫、预算和 Flow 人工复核表达。原 `advice.go`、原生 Agent 工具过滤与 Go 流程回调退出。

外部智能体询问由原 Writeback 选择 A2A 传输，复用原 JSON-RPC 消息封装、稳定效果身份及接收答复，不增加 Agent 私有网络通道。Connection 仍以部署密钥名取得完整 Authorization 请求头；原 Endpoint 的 A2A bearer-token 约定保持不变。映射可沿普通对象及有界数组路径读取答复，截断与读取不完整进入未知状态。请求接受后切换草稿或当前发布不改变原传输内容，恢复不再次询问。

函数评估缺省继续精确比对完整 JSON。需要保留自由文本说明的任务显式声明 compareFields，质量比对只衡量选中的结构化输出；原函数仍验证全部字段、类型与输出预算。判据随计划、候选及报告固定，修改判据后旧报告不能满足新门禁。未选中的说明文字和模拟提供方不计为真实品质证据。

候选 Agent 的查询工具由原工具编译器绑定同一候选的查询定义，试运行不要求先独立发布查询，也不安装到当前宿主。查询仍经唯一记录查询器按当前主体权限读取；发布查询条件会刷新原 Agent 定义身份，旧运行沿原定义变更路径停止并交接。

提议结果可声明为只读生成字段。只有原提议验证后，采纳事务才由原计算与来源路径赋值，不把这些字段开放给普通 create/edit，也不允许无关事务写入。

保留来源、固定版本、提议采纳时的修订检查、当前权限与模型评估。业务动作仍调用同一服务端规则；不能依赖提示词代替授权或让模型构造隐藏内部索引。HCM/CSM 的 AI 任务随对应功能撤回，不借通用化重新引入它们；也不为了“四个应用各有一个助手”新增未经确认的任务。

## Risks / Trade-offs

- [现有声明不能完成某个复杂任务] → 对 PMS 时间片、ERP 期间和批量记账、MES 拆批/版本/双签及状态区间分别建立具体构建用例；在原 owner 补通用表达和入口。若确需行业代码，保留该项未完成状态并先讨论例外。
- [界面替代掩盖原生后端依赖] → 交付验证在未编译任何参考应用的通用宿主上运行，检查候选依赖闭包；删除同批完成，不保留正常业务双轨。
- [数据可重建被误用为清空全环境] → 只创建明确列出的新测试租户和样本；原卷不删，构建者资产单独移交，身份与密钥不重建。
- [共用 Build owner 被误报为独立应用权威] → 记录真实 owner，跨权威路线用独立租户验证，UI 不承诺不存在的隔离层。
- [Core 账簿异步交付改变原 ERP 中间状态] → 显示原单据与记账分别完成的状态、拒绝与纠正入口，验收不依赖旧字段一一对应。
- [离线数据过期或请求重复] → 标明缓存时间、限定准备范围，保存原请求、在当前身份下续传；服务端继续拒绝撤权及不兼容版本。
- [模板会运行但构建者不能修改] → 两套不同业务配置和一次模型/规则升级通过产品入口完成，再确认替代体验。

WMS 构建定义和有效草稿沿原资产入口移交，其测试数据与结构获准重建，原日志和数据卷归档保留。范围外的供暖、其他既有有效草稿、部署身份与密钥使用原资产和环境入口保留，按 1.4、8.4、9 验收。作者或自动检查不代替负责人对四应用及两条协同链的实际确认。

1. 实施开始时在 WorkQueue 中承接这一块已授权工作，替换仅限 MES 工单界面的旧条目；保留供暖交付事实和其他未授权工作，不建立第二份项目队列。
2. 从当前四应用及其场景提取保留的接受、拒绝和业务结果，冻结可读基线作为对照；HCM/CSM 标为明确撤回。原测试中只证明平台审批、身份、接受或恢复的必要场景改在原平台 owner 验证，不依赖撤回应用。
3. 建立通用宿主和新的测试租户，按依赖完成平台缺口、模板和四应用；旧实例仅在替代确认前提供对照，不能变成永久兼容层。
4. 使用原包、草稿、候选、环境绑定、授权与样本入口建成酒店和制造两条业务链；补齐离线、观测和 AI，负责人确认保留任务可完成。

6. 删除六个原生应用及其 Web 包、PMS 桌面、专用业务 CLI/模拟启动、Solution 目录和失效依赖。更新 Makefile、验证、Catalog、模板与部署脚本为通用宿主两个配置实例；仍使用的协议契约、平台能力和通用测试工具保留。
