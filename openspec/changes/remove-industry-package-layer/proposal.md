# Proposal

## Why

现有行业包没有独立类型、授权或运行语义，酒店和制造包已经是应用声明集合。把可复用业务资产另列为平台开发者维护的行业层，会使应用业务重新进入平台职责。

## What Changes

- 统一平台包、能力包、应用包三个职责维度：平台提供通用机制，能力提供可组合技术扩展，应用承载业务声明、样本与验收；复用范围和行业不决定包的类型或作者身份。
- 删除当前规范、产品说明、部署入口和源码注释中的行业包层级；使用既有包、草稿及发布机制，不新增分类执行分支。
- **BREAKING**：当前分发目录中的五个 `industry.*` 包改为 `application.*` 标识，移除旧目录条目，不提供别名。既有安装记录、封存包、发布资产及初始化请求仍保留原身份和字节，不自动重新安装或初始化。
- 应用包是受控资产的便携表示，不成为另一份业务源代码。完整 FDE 包导出功能不在本次范围，不将概念清理冒充其交付证明。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `platform/application-lifecycle`：统一包的职责边界和应用声明交付；保留历史包身份，不建立行业专属机制。
- `runtime/deployment`：方案由平台、能力和应用配置组合，部署与恢复不依赖独立行业层。

## Impact

影响 Intent、Architecture、WorkQueue、两份现行规范、五个部署包描述符、Makefile 帮助、部署指南及三处源码注释。复用 PackageDescriptor、PackageBlueprint 和原封存恢复路径，应用内部定义、租户配置、密钥及数据卷不变；归档规范保留历史表述。
