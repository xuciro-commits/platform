# 提案：重盘信息架构与语义化呈现

## 为什么 now

负责人走查指出：门户四列工具墙（业务应用 / 知识与数据 / 构建与智能 / 运行与管理）边界重叠、层级混乱、观感差；上一轮 M2 只重排了投影顺序，未消除四类并置本身。同时呈现层欠账严重：字段语义化底座（类型系统、引用选择器、语义组件）早已建成，但表格默认渲染裸 ID 文本与无色标签；甘特、日历、树图、统计卡等大量 Widget 建成未用；155 条后端路由仅 83 条被前端引用，`composites` 零接入，Dashboard 系统整条无声明入口。

## 变化内容

1. **IA 收敛（块1）**：打掉门户工具墙；侧栏承载全部导航（工作快捷区 + 运营/构建/系统三区应用树 + 保存的视图）；应用切换在侧栏与 ⌘K 完成并沿用原切换语义；首页成为唯一工作台（最近 / 收藏 / 三区应用目录）。
2. **语义字段呈现（块2）**：`entityFrom` 默认映射升级为 type-aware——引用列渲染解析标题的 chip、单选/多选渲染分类色标签、成员引用带人物标识、日期呈现本地化与相对时间、数字右对齐等宽；表头带字段类型图标；分类色作为令牌进双主题。
3. **数据视图升级（块3）**：宽表默认启用虚拟列；choice 字段就地 facets；保存的视图进入侧栏导航。
4. **Widget 复兴（块4）**：高价值 Widget 进默认页面模板（统计总览、时间排布）；治理包声明首个平台 Dashboard（AI 与用量），激活闲置的 Dashboard 系统。
5. **平台能力端出（块5）**：`authz/explain` 接入拒绝详情；`export/import` 进列表工具栏；audit 界面化；`composites` 补前端接入。

## 影响

- `experience/workspace`：导航与呈现需求重写（本 change 携差量）。
- `experience/ui-system`：新增语义单元格与分类色令牌需求。
- 不迁移数据、不改后端契约；全部使用既有端点。归档门禁沿用：负责人截图走查通过后合入现行规范。
