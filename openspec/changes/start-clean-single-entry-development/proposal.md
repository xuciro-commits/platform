# Proposal

## Why

当前同一个平台仍保留双业务入口、旧行业账号和多套历史存储，认证又需要额外浏览器端口，妨碍从空白环境开发测试。负责人已明确授权退出本项目全部旧本地状态、身份与密钥，建立新的单入口环境。

## What Changes

- 平台只提供一个可配置产品入口，默认 localhost:8495；移除8490、SOLUTION/compat及行业宿主命名。
- 登录服务沿原OIDC在同一入口的/auth路径访问；部署只选择一个固定身份服务上游，不新增业务执行器。Docker只发布平台端口；本机热更新需要的基础服务连接仅绑定回环。
- 从原角色机制建立管理员、构建者和无默认业务权限的普通测试账号；去掉旧行业用户及客户端。
- 初次引导生成随机密码、基础服务凭据与主密钥，保存在忽略的本地配置和0600账号说明，仓库不保存实际凭据。普通启动不覆盖既有状态。
- 清除本项目的旧容器、卷、数据库、对象字节、旧本地数据/恢复副本和密钥；其他项目资源、平台源码与可安装包保留。使用新租户身份隔离旧离线请求。
- 更新认证缓存边界、启动/更新检查和文档；验证新账号同源登录、权限隔离及空白业务状态。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `runtime/deployment`: 单入口部署、同源登录、可重复的私有本地引导以及明确授权的完整重建边界。
- `runtime/access-control`: 浏览器登录缓存绑定当前OIDC配置，新账号只获得明确的技术角色。

## Impact

涉及deploy/local、deploy/dev、Makefile、部署HTTP接线、Web认证缓存及相应检查和说明。此次本地删除包括上一轮保留的账号、AI配置和密钥，不沿用旧数据库或恢复副本；不改变内核和普通部署的历史保留规则。
