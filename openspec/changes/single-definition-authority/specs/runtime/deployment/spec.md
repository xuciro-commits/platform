## ADDED Requirements

### Requirement: 拉取请求上运行快速检查门

仓库 SHALL 在 `pull_request` 与手动触发上运行快速检查门（`make check`：宿主构建与 vet、格式、边界、逃逸、架构判据、web 类型检查），并在 `v*` 标签上继续运行完整验收（`make verify`）。PR 门 MUST 在分钟级返回结果，不依赖容器、浏览器或真实数据库。

#### Scenario: 提交一个拉取请求

- **WHEN** 开发者对一个拉取请求推送提交
- **THEN** 快速检查门运行并给出通过或失败
- **AND** 失败信息指出具体是哪一步、哪一个判据

#### Scenario: 固定一个版本

- **WHEN** 负责人推送 `v*` 标签
- **THEN** 完整验收照旧运行，包含契约、形式化证明、组合与 web 构建
- **AND** PR 门不替代完整验收

### Requirement: 架构判据只在下降时通过

架构检查 SHALL 读取受版本控制的基线，对每一项比较当前值与基线：上升 MUST 失败，下降 MUST 要求同一次改动下调基线，标记为零容忍的项 MUST 恒为零。基线 MUST NOT 包含零容忍项。

#### Scenario: 规模回升

- **GIVEN** 基线与当前值相同
- **WHEN** 一次改动使根包文件数或种类扇出上升
- **THEN** 检查失败并输出项名、旧值、新值与原因

#### Scenario: 规模下降但未下调基线

- **WHEN** 一次改动使某一项低于基线
- **THEN** 检查失败并提示在同一次改动里更新基线
- **AND** 不接受「以后一起改」的基线漂移
