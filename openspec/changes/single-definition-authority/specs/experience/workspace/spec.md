## ADDED Requirements

### Requirement: 每个视图声明它的参数

工作区 SHALL 为每个视图维护一份参数声明（视图名、允许的参数名、是否必需）。视图注册、深链解析与退役别名 MUST 依据该声明；注册一个未在声明中的视图、或解析产生未声明的参数 MUST 使类型检查或架构检查失败。

#### Scenario: 注册新视图

- **WHEN** 一个应用包注册新视图
- **THEN** 该视图在参数声明中出现一次
- **AND** 它的参数名由声明约束，深链不能携带未声明参数

#### Scenario: 退役视图的别名

- **GIVEN** 一个视图已退役
- **WHEN** 旧链接携带该视图名到达
- **THEN** 别名表把它解析到声明中的现役视图及其参数子集
- **AND** 别名表不得解析到未声明的视图或参数

### Requirement: 客户端按协议判定错误，不按文本

浏览器客户端 MUST 从响应得到结构化的状态与错误代码，并据此判定（未认证、无权、不可用、冲突、未知），MUST NOT 通过匹配错误消息文本来推断语义。人类可读消息 SHALL 保留用于展示，但不作为判定依据。

#### Scenario: 身份不是本宿主成员

- **GIVEN** 宿主以未认证状态拒绝请求
- **WHEN** 工作区读取成员信息得到该拒绝
- **THEN** 工作区按状态与代码判定为「不是本宿主成员」并给出对应入口
- **AND** 判定不依赖错误消息的措辞

#### Scenario: 读取不存在的记录

- **WHEN** 一次读取返回不存在或无权
- **THEN** 调用方按状态区分，并对两者给出各自的结果
- **AND** 源码中不存在以正则匹配状态文本的判定

### Requirement: 客户端错误判定保持零文本匹配

架构检查 SHALL 以零容忍方式禁止 web 源码出现匹配 HTTP 状态文本的正则或等价字符串判定。`String(error)` 的剩余使用计入基线并只降不升。

#### Scenario: 引入文本判定

- **WHEN** 一次改动在 web 源码里加入按错误文本判定的代码
- **THEN** 架构检查失败并指出文件与行
- **AND** 正确做法是读取结构化的状态或错误代码
