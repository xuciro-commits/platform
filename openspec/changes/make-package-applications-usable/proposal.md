# Proposal

## Why

现有包安装、草稿构建、连接检查、发布、评估、授权和初始化分别可调用，但用户从包入口无法完成连续任务；失败后也没有与创建对称的应用退出入口。当前工作区的酒店销售包实际证明了这一断点，不能继续用局部检查通过代表应用可用。

## What Changes

- 包详情在导入前说明包含的应用、外部连接、AI、权限和初始化要求，区分可导入与可使用。
- 创建草稿后进入可恢复的应用准备入口，集中提供配置、完整候选发布、业务权限、初始化与打开应用的实际操作；不再把用户直接丢进资产编辑器。
- 未发布应用能直接删除草稿；删除不要求连接、模型或发布校验成功，并可复用原归档处理独占草稿。来源包卸载与应用退出分别说明。
- 支持重新打开已有草稿和归档后的再次创建，避免反复导入撞上旧身份。
- 以真实包从空白工作区完成一件业务操作，以及放弃、再次创建、退出为交付依据；真实外部系统和模型要求必须提前可见，不能伪造就绪。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `platform/application-lifecycle`：包应用准备、草稿退出、再次创建与原生命周期边界。
- `experience/workspace`：连续的包应用准备与退出操作。

## Impact

涉及原 PackageBlueprint/PackageDraftResult、Build 草稿、应用目录、包详情及原候选、权限、初始化接线。沿用接受结果、Composite、封存内容和原资产依赖投影；不引入另一套安装器、授权或运行账本，不修改内核语义或清空正式存储。
