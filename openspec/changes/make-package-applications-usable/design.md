# Design

## Context

调查开始时 workspace 的 `application.hospitality@0.1.0` 包含 64 项草稿、预订与销售两个应用；销售的 47 项候选依赖未配置的上游连接和 AI。包页只显示结构预检，生成后跳到第一个应用设计台，初始化只能看 JSON 或运行终端命令。未发布应用后端可归档，但列表与设计台没有入口；实际清理又发现智能体、页面归档误用发布校验。归档后同名目标 ID 仍被历史占用，再次生成也会失败。

历史证据按共同根因归纳：
- `f9f8e901` 修复包同版本重装，处理安装状态和封存内容，没有处理生成后的独立应用。
- `cf39dba6` 完善模块和协议资源排空，不等于声明应用的准备与退出。
- `8745e92e` 增加资产批量退役；`2b3d691f` 冻结批次与发布交接，并把模板入口转向包库；应用根及生成后的下一步仍缺失。
- `44714e72` 与本会话前一轮分别修复应用依赖收集和智能体查询，但没有打通包、环境、评估、权限和初始化的完整任务。
- `6b8c57c7` 合并后受控应用包源码被撤下，本机生成目录仍残留旧包，造成实际包库与干净构建不一致。本次从最后受控版本恢复酒店、制造、供暖原字节，并核对与保留的同版本制品一致。

反复修改的共同原因是以单机制和入口接线作为完成单位，缺少从空工作区安装、使用、放弃、再次创建的实际路径。原历史检查不能证明当前完整路径可用。本次删除的错误路径包括：导入后仅跳设计台、用发布检查阻止丢弃草稿、归档占用 ID 导致不能再次创建、只有终端可执行的初始化。

## Goals / Non-Goals

目标是让无外部依赖的包能通过产品入口完成启用和一件业务操作；有真实外部系统或模型要求的包，在导入前明确要求，生成后有集中配置入口和可返回的下一步。安装、发布、授权和初始化仍是明确操作，不能伪造外部可用性。

不改内核，不自动授予角色或填入秘密，不关闭其他应用共用的能力，不清空历史数据库，不把教学设备或模型替身当真实服务。

## Decisions

1. **准备信息来自原封存描述与当前 owner。** 使用原 Blueprint、ArtifactOfApplication、环境检查和记录身份，返回全部应用、连接、AI/评估与业务角色需求，以及已创建草稿。准备查询不执行发布检查、不访问外部系统、不生成新状态账本。结构合法与当前环境可使用分别呈现。
2. **一份可恢复的准备任务。** 包详情提供“准备应用”，生成后列出所有应用，连接、模型、发布评估、授权和初始化各有实际原入口。当前准备页可重开，不只依赖创建结果的瞬时回调。无外部依赖时直接进入原候选发布，激活后提供正式应用入口；配置缺失时保留原任务与明确原因。
3. **草稿身份与逻辑名称分开。** 正在编辑的同名草稿进入原记录；已归档历史不覆盖。再次生成时只为发生记录 ID 冲突的资产分配按原请求固定的新 ID，所有内部记录引用通过原 owner 的 releaseDraftIDs 绑定。重试得到同一身份，不能把归档字节改成新内容。
4. **退出不依赖成功发布。** Build 自身声明的草稿归档仍走原授权、已发布保留检查和接受结果，但不执行草稿的编译校验。应用有独立删除草稿入口，明确保留可复用资产及历史；资产批量归档继续使用原 Composite。已发布应用提供明确的入口撤回与恢复，保留其定义、业务数据和独立运行任务，不把入口撤回宣传为业务资源全部销毁；包卸载单独显示这些影响。
5. **初始化在产品中执行。** 逐项审阅原 setup，使用当前人员和原提交/发件箱执行。每次明确初始化固定原包内容、执行键及步骤；中断后继续同一组请求。缺少权限先定位原授权入口，不自动扩大权限，也不重新创建已经接受的业务记录。
6. **修复原包业务声明。** 生产提供方和消费方将可选良品、报废数量直接用于算术，用户只填必填项仍被拒绝。新版本 0.1.2 沿原表达式声明未发生的数量按零计算，保留旧包及旧记录存储格式。恢复受控包源码后，从干净目录构建全部应用包。
7. **准备任务跟随原读取。** 目录重新读取时保留包列表实例，避免令牌续期丢失选择和版本。准备查询加入原实时通道，随连接、角色、模型和应用改变刷新；不建立第二套监听。

## Risks / Trade-offs

外部系统地址、凭据和真实模型无法由包凭空提供。产品应在使用前完整呈现这些要求，并保留不带这些依赖的包的直接使用路径；不能通过跳过校验或清空数据解决。已发布业务共享资产继续由原 owner 管理，撤回应用入口不撤销对这些资产的独立授权或擅自停止其他应用任务。

## Migration Plan

先沿原决定清退当前 workspace 导入的两个业务包和未发布草稿，再实现准备与退出能力。从原包库重新安装一个无外部依赖的包，走完使用、删除/撤回与恢复；再打开需要外部连接的包，逐项核对引导。原封存包、历史、密钥、数据库和 system 租户保留；不重写旧包版本。

## Validation

- 原安装的酒店、供暖包和 64 项未发布草稿已沿原决定退出，历史、密钥及 system 租户保留。
- 真实 8495 包库完成生产提供方安装、全部 24 项候选、激活、显式角色授权及正式业务创建；随后审阅升级至 0.1.2，以只填必填项创建订单。入口撤回关闭旧深链，恢复沿原发布内容。
- 真实酒店包重建后列出两个应用、两条连接、三项 AI 条件、业务角色和六步初始化；未配置的销售应用从界面删除并再次创建成功。未提供真实外部服务与模型，不声称酒店业务可运行。
- `package-applications` 浏览器路线覆盖包审阅、删除再建、发布激活、显式授权、初始化第二步接受但答复丢失、刷新后继续第三步；前两条记录修订仍为 1，第二步请求键唯一；撤回与恢复保留业务数据。
- Go owner 回归覆盖封存来源、请求重试、分批接续、归档再建与重放；Go 构建、Web 类型、生成一致性和边界检查通过。规范场景本身不作为测试证据。
- `package-lifecycle`、`agent-query-release` 浏览器路线通过；390px 准备页已实际检查并修复横向溢出。全新包目录构建产出五个应用包，三个恢复包的原字节与保留版本一致。
- 走查后重新卸载酒店及生产提供方包、归档酒店未发布资产并撤回生产应用入口；两笔走查订单及原发布历史保留，不留半配置应用入口。
