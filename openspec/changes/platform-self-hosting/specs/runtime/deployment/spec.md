## ADDED Requirements

### Requirement: 自举构建与激活由独立进程执行

系统构建与激活 MUST 由宿主之外的 updater 进程执行，宿主只记录已批准的决定与结果，不持有构建职责。构建 MUST 在独立物化工作树中以固定命令执行，MUST NOT 运行仓库提供的脚本。updater MUST 使用 publisher 身份与宿主既有的提交接口读写 system 作用域，不另建一条绕过接受结果的写入路径；它的凭据只从部署环境读取。

#### Scenario: 宿主请求激活一个代码类发布

- **WHEN** system 作用域接受一次代码类发布并请求激活
- **THEN** updater 物化工作树、构建、启动新版本体检并切换
- **AND** 宿主只记录决定和结果，不持有构建职责

#### Scenario: updater 不可用

- **WHEN** updater 未启动或构建环境缺少工具链
- **THEN** 激活请求保持 requested，运行版本与数据不变
- **AND** 状态与日志说明是缺少 updater 还是构建环境不可用

### Requirement: 系统升级保留数据、版本与回滚能力

系统升级 SHALL 保留原数据目录、身份密钥、租户配置与至少上一版本的可执行产物；切换前 MUST 排空在途写入并落盘检查点。健康检查失败 MUST 自动回到上一发布，MUST NOT 通过清空数据、重建租户或改写历史处理失败。未观察的恢复能力 MUST 明确标注。

#### Scenario: 新版本切换后租户进入隔离

- **WHEN** 切换后健康检查显示隔离租户或页面资源与发布摘要不一致
- **THEN** updater 回滚到上一发布并保留失败证据
- **AND** 数据目录、密钥和租户日志未被重建或覆盖

#### Scenario: 构建机缺少新增依赖

- **WHEN** 发布包含尚未缓存的依赖且构建环境无法解析
- **THEN** 构建失败并保留当前版本
- **AND** 报告缺少的依赖与工具链，不产生部分更新

### Requirement: 共享前端资源随发布版本一致

工作区资源 MUST 与宿主二进制来自同一系统发布；切换后 MUST 能从健康端点读到实际发布版本。客户端 MUST 能识别发布变化并提示刷新；离线快照 MUST NOT 跨发布复用。

#### Scenario: 二进制已更新而资源仍旧

- **WHEN** 健康端点报告的发布版本与实际资源摘要不一致
- **THEN** 该次激活不得标记完成
- **AND** 按发布清单重新切换或回滚，不通过清空客户端缓存宣称完成
