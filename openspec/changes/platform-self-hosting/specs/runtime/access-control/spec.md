## ADDED Requirements

### Requirement: 系统作用域角色与提案主体分离

系统作用域 SHALL 区分编辑、提案与批准：具备构建者角色的成员可以编辑元对象与源码、发起提示词；具备发布者角色的成员可以批准、请求构建与激活。AI MUST 以受管智能体主体提案，MUST NOT 持有批准或激活资格。宿主治理主体与租户角色仍按原规则独立授予。

#### Scenario: 智能体提案等待批准

- **WHEN** 智能体完成一次提示词运行并产生系统变更
- **THEN** 变更处于待批准，提案主体记录为该智能体
- **AND** 只有具备发布者角色的人可以批准

#### Scenario: 发布者尝试编辑内核路径

- **WHEN** 具备发布者角色的成员提交包含内核路径的变更
- **THEN** 宿主拒绝，角色不能覆盖路径闸门
- **AND** 拒绝作为该次提交的证据保留

### Requirement: 系统定义投影不扩大读取资格

system 作用域的定义对其他租户 SHALL 只读可见，并继续执行当前成员的角色、读取范围、标记与保留版本规则。投影 MUST NOT 因来源为 system 而绕过过滤，MUST NOT 允许其他租户的成员通过编辑入口取得写入资格。

#### Scenario: 业务成员读取系统页面

- **WHEN** 业务租户成员读取一个来源为 system 的页面定义
- **THEN** 仍按当前权限过滤其引用的数据与动作
- **AND** 不因该页面由系统发布而获得额外记录读取权

#### Scenario: 业务租户没有系统角色

- **WHEN** 成员在业务租户中打开 Studio
- **THEN** 不出现 Platform 应用入口，也不能提交系统变更
- **AND** 已投影的系统页面仍按普通业务页面可读
