## ADDED Requirements

### Requirement: 系统作用域复用租户提交与接受

系统自身的定义、源码文件、变更、发布与激活 SHALL 保存为 system 作用域的受控记录，并通过与其他租户相同的提交、私有决定、接受结果与持久应用路径写入。该作用域 MUST NOT 拥有第二套提交入口、直接修改路径或独立日志。激活决定 MUST 作为接受结果保存其证据；恢复只应用已保存映像。

#### Scenario: 系统变更与其他租户并发提交

- **WHEN** system 作用域接受一个系统变更，同时业务租户提交业务动作
- **THEN** 两者各自在自己的租户日志内完成决定与应用，不共享事务或锁
- **AND** 系统发布不改变业务租户的幂等键、版本或在途工作

#### Scenario: 恢复时遇到已接受的系统激活

- **WHEN** 宿主从检查点与日志恢复并遇到一条已接受的系统激活
- **THEN** 只恢复该决定、证据与已保存的版本引用
- **AND** 不重新构建、不重启进程、不重新授权

### Requirement: 系统作用域不可被普通租户写入

宿主 MUST 拒绝在非 system 作用域提交系统文件、系统变更或系统发布。该拒绝 MUST 在私有决定阶段发生，不产生接受结果、不占用幂等键、不影响其他租户。

#### Scenario: 业务租户伪造系统发布

- **WHEN** 业务租户的成员或智能体提交 `system.*` 动作
- **THEN** 宿主在决定阶段拒绝，租户日志只保留该拒绝的常规证据
- **AND** system 作用域的当前发布与文件保持原样
