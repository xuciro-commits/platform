## MODIFIED Requirements

### Requirement: 页面契约唯一来源与版本兼容

系统 SHALL 使运行渲染、作者注册、普通属性、端口、作用域、常见查询窗口和实体字段角色检查消费同一 Widget 清单；专用 Inspector 与专项校验保留实际绑定及跨资产语义。未知组件、未知配置版本或不兼容 profile MUST 保留原配置并明确拒绝或要求兼容处理，不静默删除后保存；现有全局 Profile 的语义和组件版本不得因重整改变。

#### Scenario: 打开包含未知组件配置的旧页面

- **GIVEN** 保存页面包含当前渲染器不支持的组件版本
- **WHEN** 构建者检查页面兼容性或尝试升级
- **THEN** 系统定位不支持的配置并保留原值，不能把组件丢弃后当成成功转换。

#### Scenario: 组件带有另一个组件的配置

- **WHEN** 页面组件携带清单未声明且实际已配置的属性或端口
- **THEN** 统一检查拒绝字段归属错误，不依赖另一个组件的校验函数被偶然调用
- **AND** 零值结构、空集合及非空配置指针按原读取语义处理，不误拒原合法页面。

#### Scenario: 绑定逃逸或查询窗口不合法

- **WHEN** 端口读取其他 Loop 或 Overlay 的局部变量，或其计划排序、窗口及来源不满足原约束
- **THEN** 页面仍被拒绝，实体字段角色检查继续使用原获权模型
- **AND** 声明化不放宽查询图预算、窗口乘法展开、动作签名或跨资产身份检查。

#### Scenario: 普通属性扩展不改变历史 Profile

- **GIVEN** 旧页面使用一个受支持的历史全局 Profile
- **WHEN** 当前组件增加向后兼容属性或实现改为共有校验
- **THEN** 新旧页面保持各自原版本的查询激活、预算和能力门槛
- **AND** 不把旧 Profile 当成最新档，不为普通增量再增加全局版本，也不直接提高组件版本排除旧配置。

## ADDED Requirements

### Requirement: 构建任务共享五个工作域

系统 SHALL 用 Model、Logic、Interface、Integration、Release 的同一职责分类驱动全局构建菜单、应用资产树、创建入口和当前定位。每个资产只有一个主要工作域，仍使用原资产类型、身份和发布闭包；对象行为可以定位原对象，但不能复制一套对象资产或另建执行入口。

#### Scenario: 在应用中完成跨域构建

- **GIVEN** 构建者正在编辑一个业务应用
- **WHEN** 依次打开对象、动作、来源映射、页面与发布候选
- **THEN** 编辑器保留原应用及草稿会话，所选资产在同一分类中定位
- **AND** 原对象、计算或流程不因全局与应用内导航采用不同分类而重复归属。

### Requirement: 作者视图统一而治理权限仍归原主责

系统 SHALL 在同一 Build 作者上下文提供集成和 Agent 定义编辑；Data Connection 的运维接口与 Agent 的运行、记忆、评估仍使用原授权。Integrator 只得到获权的 Integration 入口与运行模型，Publisher 保留原发布范围；可见工作区不授予读取 Builder 草稿或治理数据的资格。

#### Scenario: Integrator 打开集成编辑入口

- **GIVEN** 成员只有 Integrator 而没有 Builder 角色
- **WHEN** 打开统一工作区的来源或映射
- **THEN** 使用获权的运行模型与集成资源，不请求对象、页面或应用草稿
- **AND** 原管理员或 Agent 运行资格不能由 Build 可见性替代。

### Requirement: 对象编辑采用分层但保留全部行为

系统 SHALL 将对象编辑组织为结构、行为、规则与访问、数据与预览四个主区，原概览、字段、关系、集合、状态、动作、协议、约束、业务版本、角色、行范围、血缘和预览均有明确入口。区域切换 MUST 共用原草稿、选择、错误定位和撤销历史，不因重建编辑器丢失输入。

#### Scenario: 切换规则和行为时草稿尚未保存

- **GIVEN** 对象字段或动作已有未保存或非法输入
- **WHEN** 作者切换主区并返回原字段或动作
- **THEN** 原输入及问题仍可修正，保存继续受原检查约束
- **AND** 区域重组不删除高级字段、不缩减动作或权限能力。

### Requirement: 作者旧链接继续定位原资源

系统 SHALL 保留已有作者视图 ID、记录参数与应用关系；旧工作域和对象区段链接在入口解析到对应新分组。已保存标签和原生应用扩展继续使用原解析规则，不因作者归属调整而跳到错误应用、清空草稿或生成同名新记录。

#### Scenario: 同一对象从字段跳到旧生命周期链接

- **GIVEN** 对象已在原草稿会话打开
- **WHEN** 旧生命周期、权限或版本链接再次定位同一对象
- **THEN** 选择对应新主区内的原内容，保留记录 ID 和现有未保存输入
- **AND** 原发布扩展的 entry、extends 和 replacements 仍按原规则解析。

### Requirement: 原生定义承接页面复用与交付

构建者 SHALL 通过平台原生 Page/Process 源码和受控包复用、移交应用，不再提供旧 Next.js Workshop SourceModule 私有 JSON 的迁入入口或适配器。此能力退出 MUST 保留已经转换为原生定义的草稿、页面、流程、历史及其原编辑发布路径，不清理客户数据。

#### Scenario: 原生页面继续编辑和发布

- **GIVEN** 页面已经使用平台原生字段、查询、变量和文档结构保存
- **WHEN** 原型适配器退出后再次打开该页面
- **THEN** 仍可按原权限编辑、验证和发布，控件及动作继续由原声明解释
- **AND** 页面行为验证不再依赖外包格式或捕获文件，入口也不保留隐蔽的旧导入路径。
