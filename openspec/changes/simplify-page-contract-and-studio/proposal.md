# Proposal

## Why

页面清单已经统一了作者字段，但宿主仍逐组件重复检查字段归属、变量模式、作用域与实体字段类型。构建者也仍在不同作者应用及两套分类之间切换，同一对象编辑器平铺十二个区段；这增加修改成本，也打断完整应用的构建上下文。

## What Changes

- 在现有 Widget 清单补足可声明的端口、作用域、端口组合、计划窗口和字段角色，由共有校验消费；删除对应重复规则，保留文档树、查询预算与专属业务语义。
- 保留现有 Page JSON、组件配置版本及全部历史 Profile 的解释；普通增量不再要求维护新的全局版本档位，不把旧 Profile 别名为最新语义。
- 统一作者视图到 Build 的五域：Model、Logic、Interface、Integration、Release；一份分类驱动全局入口、项目树、创建与定位，保留原 Data Connection / Agents 运维权限。
- 对象编辑器使用四个主区：结构、行为、规则与访问、数据与预览；保留所有原内容、草稿会话、旧定位参数及引用身份。
- 用原数值语义的 Go 实现替换固定遥测 Wasm 统计实例，删除只为它存在的制品和运行装配；通用租户 Wasm、连续窗口、Frame 与 GC 保留原职责。
- 删除已退出支持范围的 Workshop 私有 JSON 迁入器及所有调用入口；把原来的页面路线改为平台原生定义，并保留其验证过的页面行为。

## Capabilities

### New Capabilities

无。均归现有模块，不新建逐功能规范目录。

### Modified Capabilities

- `experience/workspace`：单一页面契约的完整校验、统一构建域、对象分层编辑与旧链接定位。
- `platform/automation`：明确保留固定遥测数值语义、连续窗口状态和原批次接受边界。

## Impact

涉及公共页面声明与校验、生成的浏览器清单、Build 作者入口和原编辑器、工作区已有路由归属、固定统计核与对应既有验证。基线为 `d5d5c8173f6b97d7500763b89df0af943ca871b3`。不改变 AssetKind、权限、业务规则、发布闭包、Page 存储格式、原历史字节或 SQL 兼容承诺，不新增数据库、调度器、画布或产品文档框架。
