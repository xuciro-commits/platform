# Design

## Context

见 [proposal.md](proposal.md)。本方案面向没有模型、供应商、Token 或向量知识的租户管理员与业务构建者，沿用现有工作区和共享控件，不改视觉体系。本轮是设计，下面的目标能力尚未实施。

### 已核对的实现

| 用户任务 | 当前前端 | 当前后端 | 缺口与后果 |
| --- | --- | --- | --- |
| 接入供应商 | `govern/src/ai.tsx` 已有提供方编辑、凭据入口和连接检查 | 原 AI provider 动作；凭据单独加密、按消费者和 origin 授权 | 检查后仍需自己找到模型、启用和用途设置；连接成功不代表生成成功 |
| 发现模型 | 提供方下展开模型列表，可按名称搜索 | `aicall.go: ProviderModels` 查询 `/models`，缓存十分钟 | `CatalogModel` 仅保留 ID、名称、Context、Free；只识别 `context_length`，丢掉其他格式的上下文、输出限制和能力 |
| 启用模型 | 每行 `everyone / ai users` 两个按钮 | `AIModel` 只有 provider、model、access、dailyTokens | 未区分生成和向量用途；没有可治理的能力资料、运行默认值和引用影响 |
| 配置默认模型 | `operations.tsx: AppSettingsView` 把模型画成普通文本输入，按 `ai/knowledge/agent` 技术名分组 | `ai/app-model`、`agent/model`、`knowledge/embedding-model` 三个原设置 | 用户必须记住并输入 `provider/model`；没有用途筛选、继承来源和设置后下一步 |
| 函数与评估选模型 | 函数编辑器仍为 `provider/model` 文本；部分评估页已经使用已启用模型下拉 | 函数声明可覆盖模型和输出预算，评估固定模型及配置摘要 | 同一任务有两种选择方式；新增参数若不进入摘要，会出现评估与实际运行不同 |
| 推理与上下文 | 没有思考设置；通用设置暴露数字 0 等内部约定 | `ChatRequest` 支持 maxTokens、temperature、缓存和流式；两类适配器均未发送统一思考参数 | 不能只添加滑块；缺参数校验、协议映射与跨轮状态处理 |
| 参数生效范围 | 没有“实际使用什么配置”的说明 | 全局 `mostTokens()` 调用时限幅；函数固定部分输入，Agent `turns()` 每轮读取 `agent/model` | 多轮运行可能随全局默认模型改变；需要明确新运行与在途责任 |
| 知识检索 | 向量模型是文本框 | 可不配置向量而使用关键词；配置后沿原 embedding 与索引路径 | 不能把聊天模型当向量模型；换模型须考虑维度、旧索引和重建状态 |

实现定位：`capabilities/server/platform/{ai,model_call,function}.go`、`apps/ai/ai.go`、`aicall.go`、`anthropic.go`、`agent_engine.go`、`agent_candidate.go`、`function.go`、`knowledge.go`；Web 的 `govern/src/{ai,credentials,operations,processes}.tsx`、`build/src/functions/{function,evaluation}.tsx` 及 `govern/src/package-preparation.tsx`。持久格式归原 `internal/aistate`；沿原接受结果写入。

### 已核对的供应商接口

2026-10-26 查阅官方资料，具体模型和数值不写死在设计中：

- [DeepSeek 模型目录](https://api-docs.deepseek.com/api/list-models/) 已声明 `context_window`、`max_output_tokens`、`effort.supported_levels/default_level` 和按协议区分的能力；当前平台解析没有消费这些字段。[思考模式](https://api-docs.deepseek.com/guides/thinking_mode/) 同时区分思考开关、强度和模式下无效的温度参数，工具续接还有协议状态要求。
- [Claude Models API](https://platform.claude.com/docs/en/api/models/list) 提供能力及输入、输出上限；[思考接口](https://platform.claude.com/docs/en/build-with-claude/thinking) 的 effort、adaptive 和旧预算方式须按实际模型处理。
- [OpenRouter 模型目录](https://openrouter.ai/docs/api/api-reference/models/list-all-models-and-their-properties) 包含支持参数、上下文、最大生成量与价格；支持一个参数名不等于已提供该参数全部合法取值。
- [Gemini 模型资料](https://ai.google.dev/api/models) 包含输入、输出 Token 限制和支持方法；[思考设置](https://ai.google.dev/gemini-api/docs/thinking/) 随模型与接口不同，不能因为兼容 OpenAI 请求就套用相同等级。

结论：能自动读取的信息自动读取，但“模型列出来了”“供应商声称支持”“平台当前协议已实现”“此用途已经验证”是不同事实。未知不等于不支持，也不能伪装成可配置且已生效。

## Goals / Non-Goals

**Goals:** 第一次使用者不输入内部模型路径，也不必先懂 Token；从接入服务走完启用模型、给用途选择默认项、保存并验证。已配置用户能看懂当前有效模型、参数来源和失效原因。构建者、运维及实际运行消费同一配置规则。

**Non-Goals:** 不新建模型代理、路由服务、配置档案资产、执行队列或凭据存储；本期不做多个模型同时回答、自动选择“最优模型”、自动故障切换、用户自定义模型排名或跨供应商虚构的统一思考档位。不扩展图像生成等无当前消费入口的任务。不通过界面配置更改模型物理上下文能力，不向用户展示模型私有思维原文。

## Decisions

### 1. 接入可多，启用可多，每种默认用途只选一个

- 一个租户可以接入多个提供方，每个提供方可启用多个模型。
- “业务应用默认生成模型”“智能体默认模型”“知识检索模型”各引用一个已启用模型。生成试用可临时单选另一个获准模型；多模型对比只在明确的评估任务中运行。
- 模型选择以可搜索单选为主，选项按提供方分组，显示“模型名 · 提供方”；“先选提供方，再选模型”作为长目录的筛选，不要求每个用户多点一次。
- 函数、智能体和评估共用同一模型选择控件。继承是明确选项：“跟随用途默认”；下面显示实际引用和来源。切换到指定模型后才显示局部覆盖。
- 模型列表的批量启用可多选，但每次明确显示访问范围，不能把选中模型自动变为所有用途默认。

不采用默认模型多选：一次调用仍需要明确目标；若无路由或对比语义，多选只会隐含不可解释的成本和行为。

### 2. 一个 AI 配置入口，三个任务页

在现有 AI 入口内提供如下任务导航；应用设置中的三个模型项只显示当前值和“前往 AI 配置”，不保留另一套编辑框。来源和深链可回到原任务，不新建平行状态。

| 页面 | 用户要做什么 | 主内容和操作 |
| --- | --- | --- |
| 接入服务 | “让平台连接我的 DeepSeek 等服务” | 提供方、凭据就绪状态、地址、检查时间；新增采用“选择服务 → 输入 Key → 检查连接并读取模型”。凭据在原托管入口保存，并按提供方和目标自动填入用途，保存仍显式确认 |
| 可用模型 | “允许哪些模型在这里使用” | 从已接入服务发现的模型、生成/向量用途、工具/结构化输出/思考能力、可用状态；一项模型详情集中放能力资料、平台运行默认、组织限制、被哪些用途引用 |
| 默认用途 | “不同任务默认用哪个” | 业务应用、智能体、知识检索三行；当前实际模型、来源、可用状态和更改。高级运行参数在当前用途详情中设置，保存为一次明确操作，显示更改影响 |

“用量与限额”仍复用原用量入口，出现在 AI 导航中；每天额度、每分钟频率属于组织治理，不与思考强度混成模型属性。原 `ai`、`agent`、`knowledge` ID 不作为主标题。

首次没有提供方：只显示“先接入一个模型服务”及入口。接入后明确“发现 N 个模型，尚未启用”，勾选模型、选访问范围，再选择适用默认用途；完成时显示原设置的逐项回执。AI 与 Platform 是不同权威：任一步失败保留已完成项，不伪造跨 owner 原子成功，也不换新键重做已接受决定。

### 3. 模型能力与运行参数分开摆放

模型详情的“模型能力”是只读资料，显示来源和更新时间；“使用设置”才是可编辑配置。

| 信息 | 放置位置 | 编辑规则 |
| --- | --- | --- |
| 最大输入、最大生成量、共享上下文窗口 | 模型详情“模型能力”；选中模型后在高级区简要提示 | 优先供应商元数据；未报告显示“未提供”。管理员可明确录入部署资料，注明人工来源和未验证状态，不能覆盖已有更严格上限 |
| 支持思考及合法等级、工具调用、结构化输出、向量维度 | 模型详情“模型能力” | 区分供应商支持、平台适配支持及验证状态；不从名称猜测能力 |
| 模型运行默认 | 模型详情“默认运行设置” | 可设置思考、输入预算、生成预算、可用的采样参数；可恢复跟随供应商，不另建配置档案实体 |
| 用途的思考、上下文使用量和生成预算 | 默认用途详情；函数/智能体覆盖处 | 默认继承模型设置，仅对该用途覆盖；能看到继承后的有效值 |
| 日额度、调用频率、组织生成硬上限、模型每日额度 | 原 AI 用量与限额、模型治理区域 | 明确“0 表示不限制”或“由服务决定”的人类文案，不让用户直接解释零值；额度仍可限制调用 |
| 温度及供应商专用参数 | 模型/用途详情的高级区 | 只显示当前协议已实现的参数；未支持或当前思考模式下无效的参数不可保存，不出现无效滑块 |

新手默认只选模型；思考、上下文和长度都先采用有来源的默认行为。高级区展开后：

- “思考方式”：跟随模型默认；模型支持时可选关闭或开启。强度显示该模型实际等级，可给已知等级加中文解释，但保留准确取值。未知等级不能任意映射为“快/均衡/深”。
- “最多带入多少内容”：自动或自定义输入 Token 预算，说明包括问题、系统说明、工具声明、历史和检索材料。模型能容纳的最大内容与本用途使用预算分别显示。
- “一次最多生成多少”：自动或自定义生成 Token 预算，明确某些接口含思考 Token，不能等价称为“最终答案字数”。自动值不承诺低成本；默认思考可能产生费用，展示计量规则。
- “Token”只在高级区出现，解释为“模型计算文字量的单位，不等同于汉字数”；不作固定字数换算。日额度与每次生成量的区别就地说明。

输入预算、生成预算及模型共享窗口须联合检查；思考预算是否占用生成预算、最小值、关闭兼容性由当前协议规则决定。用户输入超限时指出哪项需修改，不能保存后在调用时无声丢弃。超长输入沿现有会话整理路径保留工具调用完整性和来源；没有已实现的整理策略时明确要求缩短，不能宣称后台自动压缩已完成。

### 4. 能力资料由原 AI owner 持有，适配器只做协议翻译

- 在原 `ProviderModels` 扩充标准化模型资料，包含用途、模态、输入/输出/总窗口、思考模式/等级/预算、工具及输出能力、价格资料、来源时间与证据标识；分页供应商沿实际分页读取，不把首批当完整目录。
- 每项能力允许“支持、不支持、未知”，并区分供应商声明与平台适配结果。列表不得把未知值渲染为零或免费。标准化与参数校验只有一份，UI 消费其投影。
- 发现读取保持只读、临时且受原凭据与权限控制；启用或管理员确认刷新时，经原 AI 接受结果保存所选择的能力资料及其来源修订，不将远端读取直接写入正式状态。
- 原 `AIModel` 扩展能力资料和默认运行配置、组织限制及配置修订；继续用 provider/model 身份。目录缓存按租户及实际提供方配置/凭据修订隔离，修订变化不沿用旧连接“成功”。
- 不把模型目录名称相同当成参数支持相同。DeepSeek、Anthropic、OpenAI 兼容网关及 Gemini 的元数据/请求差异由原适配路径归一处理；未实现的模式显示“平台暂未支持”。
- “结构化输出”分别标注供应商原生 JSON/Schema 约束和平台现有的严格结果校验。函数已经通过原输出验证器拒绝非法结果，不因供应商未提供原生 Schema 字段就判定整个函数不可用；未知能力允许明确的试验配置，但正式用途仍须满足原评估和接口要求。
- 新参数进入 `ChatRequest`、原函数请求、Agent/评估和原 effect 接受映像。适配器处理对应的字段、温度限制、输出 Token 语义、流式与工具续接所需协议状态；协议状态作为受保护的原会话内容保存，不作为用户可读推理原文。

不引入另一个模型目录权威或任意 JSON 透传。仅供应商返回一个 `supported_parameters` 名称，还不足以决定等级枚举和参数组合，须有对应接口资料或经过管理员确认的能力证据。

### 5. 配置解析只有一份，运行与评估使用同一结果

有效模型先按资源明确选择、所属用途默认解析，再从模型默认运行参数继承；资源/用途的显式参数覆盖模型默认值。组织、模型与供应商上限是约束，不是另一层可覆盖默认。

保存用途绑定、试用、发布评估和正式派发复用同一解析与校验，返回有效引用、参数、能力修订、来源和诊断。界面没有独立的有效配置算法。

- 函数、智能体及评估的新接受请求固定实际 provider/model、有效运行参数、协议、能力资料修订和配置摘要。Agent 需消除每轮重新读取全局默认模型的路径。
- 配置后续改变只影响新接受的运行；在途任务保留原目标和参数，权限、凭据当前使用资格及额度继续复核。当前约束使原配置不可执行时明确暂停/拒绝，不能静默换模型、降思考等级或产生新输入。
- 评估摘要涵盖影响行为的有效配置，不仅是当前 model/provider 两个旧结构；改变思考模式、预算、协议或输入整理策略后，旧评估不能作为新配置已通过的证据。
- 凭据值不进入摘要或模型工件；凭据轮换、权限撤销仍按原治理生效。纯密钥轮换不等于新模型质量，但仍须重新确认连接可用，保留实际配置变更证据。

前后端新增读取返回“适用性和有效值”，不用把所有调用设置强塞到通用 Setting 的 choices。三个既有默认值的编辑继续由原设置 owner 接受；原 AI owner 负责模型能力、启用、模型默认和限额，消费者只固定绑定。新增读取和动作扩展的具体路径须在实施时由原 API 目录生成并检查，不额外开独立配置服务。

### 6. 不可用时保留选择，并说清下一步

| 状态 | 用户看到什么 | 可做什么 |
| --- | --- | --- |
| 未接入服务 | 尚未接入模型服务 | 去接入；不显示可保存的空模型文本框 |
| 已发现未启用 | 已发现模型，尚未启用 | 管理员启用；其他用户请求授权 |
| 正在加载 / 加载失败 | 明确读取状态、失败原因 | 重试，保留原选择；不把网络失败显示成没有模型 |
| 模型未授权或不匹配用途 | 保留原引用并标明原因 | 选择其他可用模型或跳转管理员配置 |
| 模型支持但平台协议未接通 | 平台暂未支持此能力 | 选择已支持模型；不显示无效思考设置 |
| 当前模型被停用、删除或供应商不再提供 | 保留原名称和绑定，标记不可用 | 查看受影响用途并更换；不自动选择列表第一项 |
| 凭据未授权、已停用或无法解密 | 准确原因与提供方处理入口 | 原凭据治理入口；不统一报缺少 Key |
| 未配置知识向量模型 | 正在使用关键词检索 | 可继续关键词检索或配置向量模型，不把整个 AI 页报成不可用 |

保存默认值后显示“默认值已保存”，不显示“AI 已可使用”。“试用一次”是独立明确操作，说明可能产生费用，只用当前用户填写的试验文本，不自动带业务数据；结果按“生成成功、工具校验、结构化输出校验、向量返回”分别记录。对于管理员自身可用而实际 Agent 主体不可用的模型，明确展示用途限制；不因管理员能选而自动授权运行主体。

### 7. 知识模型单独处理变更

知识检索选择器只列 embedding 用途，默认保留关键词模式。模型和维度改变后，原 Knowledge owner 创建显式重建任务及进度；旧索引保留原模型身份，不能在重建期间与新空间混用。展示当前检索模式和切换状态；未选择模型的词法检索继续可用。模型参数中不出现对向量接口无意义的“思考等级”。

### 8. 构建与包准备复用配置入口

包准备列出“需要文本生成/工具/结构化输出/向量”的用途要求，跳到默认用途或相应资源的同一选择器。缺少连接或模型时，配置完成能返回原包任务。应用包保留用途与能力要求，提供方凭据和本地实际绑定仍是目标环境配置；不把源环境 Key、目录临时缓存或已保存历史字节塞进包。

### 9. 界面组织与文案

采用现有共享 PageHeader、Select/搜索选择器、列表、详情、状态及原回退机制。默认用途为任务行，不用技术模块名嵌套卡片；选中用途进入同一详情区，模型能力资料与当前运行设置不混在一个输入表里。桌面可用列表与详情，窄屏先任务列表再详情，保留返回和未保存确认。

保存前展示本次影响，例如“影响新启动的智能体任务；已运行任务保留原配置”。技术详情按需展开，常用路径不要求理解 wire、origin、provider/model 或 API JSON。

“跟随业务应用默认”用于智能体时仍须通过工具能力与主体授权检查；若该模型不适合，明确要求单独选择，不提供会运行失败的便利选项。初始无明确绑定不替用户自动启用付费模型，已保存合法设置不被新手引导覆盖。

## Risks / Trade-offs

- 元数据缺失或变化 → 保留未知、来源和刷新时间；不把未知当成功，人工补充与供应商事实区分。
- 服务实际路由与目录声明不同 → 保存请求和实际返回的模型身份；对网关能力取当前路由可保证的范围，不能将最强上游当所有请求能力。
- 思考等级跨厂商不等价 → 不提供统一的虚假质量分数或速度保证；按确切模型显示选项。
- 新配置使旧评估看似仍通过 → 共用配置摘要；新参数不另设脱离评估的临时运行开关。
- 组织权限与管理员预览不同 → 默认配置可保存为待就绪，但正式用途能否执行由当前运行主体校验，不自动扩大权限。
- 可选模型很多 → 按用途筛选、提供方分组和搜索；不让用户先维护另一份“路由配置”才能选一个模型。
- 只做下拉看似完成 → 验收以从空配置到实际一次调用、失效恢复及原任务返回为单位；能力和参数后端未接通前不暴露为可用控制。

## Migration Plan

1. 保留 `provider/model` 模型身份及三个原设置键。将现有合法值无损投影为明确绑定，旧空值保持原“未配置/关键词”语义；新手流程可明确选择继承，但不悄悄改变旧行为。
2. 持久模型配置及运行接受格式在原 owner 升级，新字段缺省按旧规则读取。已封存请求、评估与历史不重写；旧 Agent 继续旧格式解释，新运行才固定完整配置。
3. 发布统一适用模型读取和原动作校验后，替换所有现有模型文本输入；通用设置的旧入口改为当前值及正式配置链接，不保留双重可写 UI。
4. 分组完成目录能力和调用适配、用途继承及知识切换，再验收完整界面。平台组合、真实数据库恢复、合成协议检查和真实供应商检查分别报告。
5. 回滚保留新记录及历史；不允许不认识新参数的旧程序把配置忽略后继续发调用，沿原维护与兼容检查拒绝不支持格式。

### 实施归属与格式

原 AIModel 扩展 capabilities/defaults/revision，修订直接取 ChangeRecord.Revision；原 ai.model.enable 负责采用能力资料与保存参数。原设置保存三个用途引用及两个参数覆盖；agent/model 的 @generation 是明确的模型引用继承，不改变旧空值。模型选项只由原 AIModel.Resolve 合并和检查，宿主负责读取原设置。

新 AgentRunRecord.modelBinding、modelAsk.binding 与原评估配置摘要固定接受时的模型和参数，旧格式可选字段为空时保持原读取。协议续接字节在原 Agent 记录的 read:"-" 字段中保存，普通记录投影不返回。模型目录只读，GET /v1/ai/model-selection 与 GET /v1/ai/knowledge-index 接入原 live queries 及 owner 变更依赖。

Knowledge 沿原 Embed 与 Store 准备索引，embedding-next-model 保存待准备目标。原设置动作在启用时同批保存活动空间元数据并清除准备目标；模型修订改变后先保留关键词检索，明确重建并启用后恢复语义检索。私有控制决定复用原 Store 核对准备情况，结果经原接受映像保存，不在恢复中再次检查向量存储。向量空间包含原模型配置身份，不增加索引调度和配置权威。

OpenAI 官方 Chat Completions 的生成预算沿 [max_completion_tokens](https://developers.openai.com/api/reference/resources/chat/subresources/completions/methods/create) 发送，包含可见与推理输出；其他 OpenAI 兼容来源维持其原 max_tokens 协议，不按模型名称猜测协议。DeepSeek 与 Anthropic 思考参数只开放目录已声明、原适配器已实现的模式；原函数严格结果校验独立保留。
