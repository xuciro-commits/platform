## ADDED Requirements

### Requirement: 运行服务与工具显式分类

`cmd/` SHALL 按「运行服务、运维工具、代码生成工具」分类维护，每个二进制标注是否属于部署拓扑及归哪个运行服务。部署文档、compose 与演练 MUST 只把运行服务计入拓扑；工具二进制（代码生成、边界检查、UAF 元模型生成、规则浏览、停机文件校验）不作为部署服务运行、不出现在默认 compose 服务清单。分类清单随 Architecture 代码地图维护。

#### Scenario: 新增一个辅助二进制

- **WHEN** 开发者新增一个辅助命令
- **THEN** 它在分类清单中标注归属与部署相关性
- **AND** 不因存在即成为部署服务，也不绕过边界检查。

### Requirement: 默认拓扑收敛为三个运行服务程序

交付与轻量形态 SHALL 以三个运行服务程序为默认拓扑：platform-server（宿主）、gateway（设备网关及其托管的驱动子进程）、compute（受控编译与隔离执行服务，含 builder 与 worker 两个协作进程）。本地栈与演练用的入站接收能力 SHALL 作为 platform-server 的可选进程内能力，由装配显式声明启用；未声明时不监听对应端点，端口与签名校验语义保持不变。宿主进程与 compute 之间、gateway 与驱动子进程之间的既有隔离与故障边界 MUST 保持，不因拓扑收敛把租户代码执行或设备会话并入宿主进程。

#### Scenario: 轻量形态启动默认拓扑

- **WHEN** 负责人以轻量形态启动宿主并声明接收能力
- **THEN** 三个运行服务程序及可选接收端点按声明启动，对外端口语义与原部署一致
- **AND** compose 服务清单不再包含可收编的独立接收服务。

#### Scenario: 显式外置隔离执行

- **GIVEN** 部署需要把受控执行保持为独立最小特权进程
- **WHEN** 装配按显式声明选择外置 compute 服务
- **THEN** 宿主按原 socket 与依赖检查协作，能力未配置时明确不可用
- **AND** 不为减少进程数把租户编译或 Wasm 执行并入宿主进程。

#### Scenario: 驱动保持子进程隔离

- **GIVEN** gateway 正在为多个会话托管共享驱动进程
- **WHEN** 一个驱动子进程崩溃或退出
- **THEN** 故障边界与引用回收沿用网关既有规则，宿主进程不受影响
- **AND** 拓扑收敛不改变驱动会话的共享与回收语义。
