# Design

## Context

见 proposal.md。当前 Home 和 ApplicationsPortal 重复呈现同一应用数组；ApplicationTile 使用 Button 的默认布局承载多行图文。RecordWorkspace 未选择时仍保留 55% 空详情列。PackageList 为每包绘制全部操作和元数据，底部又画一份 tiers 模块图，而能力矩阵已承担该职责。Build 已有 studio-model 的五域与 assetRoute，但项目概览把资源入口留给侧栏，把统计放在固定右栏。多个 StructuredEditor 调用显式设为 source，覆盖组件本来的 visual 默认值。

## Goals / Non-Goals

**Goals:** 保留现有视觉语言与唯一 owner，通过删除重复区域、按选择展开及直接任务入口改善使用；以截图前后对照和原浏览器路线验证。

**Non-Goals:** 不重新实现壳层、设计系统、应用目录、业务工作流、权限或发布；不写行业专用菜单、不批量覆盖已安装应用定义，不增加第二套导航状态、兼容开关或操作执行器。

## Decisions

1. **收敛首页与门户。** 首页显示业务应用、已有最近/收藏及紧凑工作状态，使用既有 projections 将任务入口链接到同一门户。门户按原分类过滤且不重复画收藏与分类两份相同应用。ApplicationTile 改为明确的横向图文按钮布局，收藏保持可触达。
2. **列表实例保持稳定。** RecordWorkspace 依据 selected 切换网格列，仅挂载已选详情；原 RecordList 始终保留以保存筛选/分页。所有尺寸均提供返回列表，窄屏隐藏列表而非卸载。未选中时不画空详情占位。
3. **一个目录、一份包详情。** PackageList 保留原决定函数、幂等创建键、拒绝与未知结果处理，用原 packageID 选择当前项。目录显示名称和安装状态，详情显示一个包现有操作；技术元数据与完整内容折叠。删除 tiers 和页面内置模块重复投影，给出能力矩阵原入口。版本仍由用户明确选择，不自动安装最新版；未选版不显示预检成功。导航选择不产生业务写入。
4. **设计台让资源成为首屏。** 删除固定统计侧栏，用当前域资源列表复用 assetRoute 进入原编辑器；应用概览侧栏只保留五域，编辑具体资源时再显示原资源树，避免重复目录。切换域进入目标概览，不强带原资源；原编辑器会话继续保留。保留选中资源的依赖与移除保护、草稿变更和发布闭包。原五域与资源树保持唯一来源。移除具有可视化内容的编辑器显式 source 默认；没有可视化内容时 StructuredEditor 原行为不变。
5. **公共呈现改在原归属方。** 不新增业务组件或 CSS 体系。新增文案在现有 i18n；不翻译数据。应用分组与任务页面由现有 application.groups/Page 声明维护，本次不在平台对 MES/ERP 特判。

## Risks / Trade-offs

- 长期用户需适应包目录选择 → 原路由与权限保留，目录显示安装状态和筛选，详情全部旧操作保留。
- 改可视化默认可能暴露旧画布或表单布局问题 → 原定义保持不变，集中走查页面、对象、流程及集成编辑器；源码显式可达，非法输入沿原会话保护。
- 截图含补充深链或空测试数据 → 不把补充路由错误当正常任务故障；浏览器验证选择原菜单与构建路线。
- 减少首屏统计可能降低诊断可见性 → 运行、发布与能力矩阵原入口保留，技术详情可展开。

## Migration Plan

只替换现有 Web 组件，数据与历史无迁移。先完成规范与任务，再集中替换、运行 check-web 和受影响测试、选原通用浏览器路线验证，再同步 Architecture 与现行规范。负责人未授权新提交前不自行提交；若提交 main，按仓库规则更新两宿主。代码回退只回退本次 Web 差量，不触碰卷、密钥、应用配置或既有历史。
