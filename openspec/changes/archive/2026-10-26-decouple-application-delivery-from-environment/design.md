# Design

## Context

原包预检已保留结构边界，但 AssetLifecycle 的环境解析、Build 安装校验、候选评审和前端按钮重复将运行就绪当作发布资格。来源/流水线安装还设置 Requested，发布者身份被当作运行主体。动机见 proposal。

## Goals / Non-Goals

**Goals:** 消除交付依赖实时外部环境的结构；目标环境只需平台能力即可交付完整合法应用。

**Non-Goals:** 不删除集成功能、不自动授权、不伪造评测、不放宽实际外部请求和在途恢复的原安全语义；不设计新执行器。

## Decisions

- 删除交付协调器的环境目标解析、绑定列表和 credential 查询。保留唯一 EnvironmentRequirements 作为安装后条件投影及声明配置种类检查；本地记录目标由原 owner 的唯一逻辑身份查找和原 create 决定生成。不能只绕过一层 ready 而保留重复门禁。
- Build 的检查只校验合法声明、类型、协议与闭包；实际 Request/Source/Observation/AI 路径检查就绪和权限。Source/Pipeline 新发布不设置 Requested，显式运行固定主体与令牌范围，准备后的执行单独保存原范围，恢复不借目录身份扩大权限；已有显式运行责任按原保存状态保留。定时观测保留声明，但缺环境不执行外部 I/O。
- 评测报告继续固定候选与配置。删除把所有函数/Agent 的报告变为整体激活门禁的代码和前端重复判定；保留应用提议与函数结构关联校验。评测模型空值跟随函数或目标环境默认，只有执行时解析，不用虚构 configure/model。
- 包内容修改提升版本；独立示例的对象和连接身份互不占用。共享本地对象与平台 Core/Enterprise 能力仍是有效结构依赖，不能误删。
- 当前环境清理只按负责人选择的重置范围执行；停止宿主后退出整个获准重置的业务作用域，不修改保留日志或伪造旧结果。重建分配新的业务租户身份，隔离旧浏览器自动恢复的未确认请求和离线内容。负责人已确认保留账号、AI服务与平台密钥；清空包、草稿、已发布应用和业务数据。AI托管凭据在旧AAD下解密后通过原封装接口重封装，以新配置请求恢复；不复制旧密文版本冒充新凭据。

## Risks / Trade-offs

- 移走发布门禁可能暴露迟到的外部失败 → 实际执行准备必须拒绝未配置连接；发布、定时扫描不发送外部请求。
- 安装成功易被误认作所有功能可用 → 界面分别呈现交付状态和安装后配置/评测状态。
- 旧安装不可同版换字节 → 新包版本独立封存，旧历史不重写。
- 本地重置不可逆 → 等待范围答复，按真实存储边界清理并验证空白状态；不将代码部署等同于完成重置。

## Migration Plan

完成 owner、宿主、前端与包内容修改及对应机制路线；同步规范后提交并更新两个本地入口。按负责人答复重置当前业务配置，核对平台账户/保留配置及空白业务状态，最后检查真实版本、健康和页面资源。
