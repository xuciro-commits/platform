# Design

## Context

动机及已确认范围见 [proposal.md](proposal.md)。负责人明确选择：规则、授权、存储等平台基础实现也允许替换，仍须满足原契约；本次又明确要求在线获取、本地导入、已有包选择及新用户帮助，原有应用和基础包都须遵守可插拔与无残留资源边界。本文件描述目标设计，不代表这些接口或切换能力已经实现。

当前实现有可以继续使用的归属边界，也有实际绑定：

| 当前位置 | 已有能力 | 本次要解开的绑定或缺口 |
|---|---|---|
| `capabilities/server/composition/tenant.go`、`host.go` | 通用租户工厂、具名消费角色、原声明和恢复资格 | 工厂固定构造；部分具名角色由遍历赋值选择，不能作为明确的实现选择 |
| `platform/rules.go`、`internal/rules/` | 单一表达式实现、类型、预算和一致性向量 | `ExprProgram` 是具体类型别名；编译、比较、聚合及多个消费者直接使用全局函数 |
| `authorization_decision.go`、`platform/authz/` | 当前事实解析、固定授权层次和封存证据 | 正式入口、原生入口、目录与宿主管理存在直接调用具体 `authz.Decide` 的位置 |
| `journal/`、`journal_bridge.go`、`deploy.go` | 接受日志、正式状态、固定读取视图、检查点和多种运行形态 | 创建及部分接线识别具体 PostgreSQL 类型；已有接口支持范围不同，不能仅统一名称就互换 |
| `packages.go`、`package_drafts.go` | 版本封存、依赖预检、排空、退役、保留制品与原 owner 草稿 | 包依赖主要是包 ID；安装状态不能证明外部驱动就绪或资源已经释放 |
| `gateway/`、`driver/rpc.go` | `driver/v1`、摘要验证、会话、技术尝试收据 | 会话、采样与共享进程缺少完整的统一退出协调；`Close` 发出终止后未提供等待完成的契约 |
| `web/packages/platform/src/apps.tsx`、工作区贡献加载 | 原包管理、能力矩阵、权限过滤与贡献组合 | 主要显示治理状态；不能完整解释实现选择、排空阻碍与清理失败 |

参考 [dsh 架构](https://github.com/deepseek-ai/deepseek-harness/blob/master/docs/architecture.md)、[服务依赖](https://github.com/deepseek-ai/deepseek-harness/blob/master/docs/user/develop/framework/service.md)及[插件生命周期](https://github.com/deepseek-ai/deepseek-harness/blob/master/docs/user/develop/framework/index.md)中的接口、显式依赖、作用域和资源清理思想。借用这些组织方法，不移植其运行时或依赖覆盖规则。

## Goals / Non-Goals

依据 [Cordis 论文 arXiv:2608.25512](https://arxiv.org/abs/2608.25512) 第 3.1、3.3–3.4、4.3、5.1–5.2、6.1、6.3 及 6.6 节，并对照官方 `fiber.ts` 的 effect、committed、epoch、unload 和依赖等待实现，本次自审修订如下：

- 可撤回效果需要在发生处返回清理责任；清理不能用整个共享状态快照覆盖，否则会撤销其他组件之后的合法变化。所有注册都携带所属实例身份，清理仅移除该身份的贡献。
- 时间可组合性是资源与注册可撤回；空间可组合性是依赖响应与消费者先退出。原设计只列包状态及清理顺序，必须补齐可观察的活动实例、作用域、依赖和退出结果。
- 观察等价不承诺物理世界回到原状。论文第 6.1 节明确区分资源获取与向外发送；本平台继续通过先接受意图、后投递及原补偿处理持久事实和外部效果，卸载不抹掉它们。
- 逆操作正确性和共享操作独立性仍是提供方的责任，接口检查不是任意下载代码安全的证明。第 6.3 节要求不可信代码有独立沙箱；第 6.6 节说明只按键名绑定不足以保证版本兼容。
- 原提案排除远程获取、缺少新手帮助、只细化驱动退出，均未满足本次完整产品目标；现将来源获取、原有包和基础包生命周期、最小维护入口及帮助纳入同一设计。正文不声称已经获得论文的形式化证明。

**Goals:**

- 提供方的身份、包版本、接口版本、语义版本、状态格式和实例代际各有清楚含义。
- 规则、授权和存储的真实消费者可通过同一装配选择使用另一受信实现，不靠编辑宿主调用点或替换全局变量。
- 一份依赖解析结果驱动就绪与退出；基础实现切换和普通能力装卸遵守各自作用域与在途责任。
- 实际运行与清理结果可从现有治理入口观察，失败不伪装为完成。

**Non-Goals:**

- 不改变 K1–K9、表达式算子、授权政策语言或业务权威；不借本次工作设计另一个数据库或另一种规则语言。
- 不增加包层级，不执行下载包的安装脚本，不使用 Go 动态库加载。在线获取平台格式的声明、受控制品及描述；受信原生实现仍须由部署准入，租户算法继续走原隔离路径。来源选择器不是第三方插件交易市场。
- 不保证所有基础模块无停顿热替换；不在业务决定中调用远程授权或规则服务，不引入另一个 I/O 调度器。
- 不为证明接口存在而复制第二套生产规则或授权算法；可替换机制、候选契约一致性和另一个生产实现的实际验证分别报告。

## Decisions

### 1. 包职责与实现装配分开，沿原归属方接入

平台包、能力包、应用包继续回答内容的职责。具名能力契约及提供方描述回答实现如何组合；不把“插件”设成第四种包，不把所有资产降成 `map[string]any`。

在 `platform/` 维护公共能力元数据和各自类型化接口；原 `internal/host` 继续只暴露消费者所需角色。能力装配是现有 `composition/` 的一部分，返回解析后的不可变描述、类型化实例和资源清理责任，不新建业务注册数据库、事件总线或提交入口。

原平台 owner 仍拥有状态与恢复格式，替换技术实现不等于转移业务权威。若某个 owner 本身更换实现，仍须满足其原声明与映像格式；不能因某项依赖下线就删除该 owner 的已接受记录。

### 2. 显式选择、类型化绑定、唯一解析

提供方描述包括契约 ID、接口版本、语义版本、实现 ID/版本、支持的运行形态、状态格式、必需依赖、资源作用域和替换方式。版本初期使用明确的受支持集合，不另造通用包管理器或 SemVer 求解器。

原包 ID 依赖和新增能力依赖共同进入原包预检的纯解析投影；装配、治理 API 和前端消费同一结果。应用资产的依赖闭包仍归原发布机制，不与技术能力图合成第二份资产目录。某个契约只能绑定显式选中的一个兼容提供方，禁止后注册覆盖和可选缺失时的隐式默认回退。

依赖解析先完成缺失、歧义、循环及作用域检查，再按提供方先于消费者的顺序构造；失败逆序清理已构造资源。就绪前不启动业务接入或后台执行。作用域区分部署、租户及短期调用/预览；租户实例不能释放共享存储或其他租户持有的驱动。

替代方案：通用字符串 `ctx.get()` 加可变服务定位器更接近 dsh，但会隐藏依赖、扩大宿主访问面并允许运行时漂移；本次采用类型化构造参数与已存在的窄角色。

### 3. 规则和授权实现成为真正可替换的依赖

| 能力 | 接口与迁移位置 | 必须保留的原责任 |
|---|---|---|
| 规则 | 版本化规则引擎提供检查、编译、比较和聚合；编译程序通过求值接口使用，解除 `ExprProgram` 的具体类型别名。迁移 `platform/`、`internal/construction/`、Build、事务、约束、观测和迁移读取的实际调用方 | 表达式与类型、精确数值、预算、不完整与不可读、错误定位均不变；输入主体和时间显式提供，纯编译层不获得 Tenant 或网络 |
| 授权 | `platform/authz/` 提供类型化引擎接口；事实解析仍归宿主与原 owner。迁移普通、原生、能力目录、服务端动作检查及宿主管理的判定入口 | 当前事实、固定合成顺序、拒绝与封存证据不变；登录认证和企业任职仍由原归属方处理 |

每个实际消费范围显式接收引擎，不设置进程全局可变 `SetEngine`。无请求的纯构建检查也由构造时选定的能力上下文传入，不能在遗留静态函数中继续选择另一实现。仅构造字面量等不选择执行引擎的纯值工具可以保留。

浏览器已有 `cmd/rule-browser` 使用同一原规则源码。所有宣称兼容的实现都运行同一规则及授权契约用例，浏览器预览仍只支持其明确声明的语义版本，不能因新引擎选择新增私有算子。计划缓存包含语义、声明与类型摘要、提供方及代际，绝不跨不兼容实现传递具体编译程序。

这些是受信本地实现的替换接口；协议化外部授权、外部规则服务及新算法不属于本次内容。契约符合性在候选构建与验证中检查，启动核验身份与版本；不能声称有限用例证明任意第三方代码安全或等价。

### 4. 存储按已有能力拆分接线，保留原事务

复用 `journal.Journals`、`RuntimeState`、`StateReadViews`、检查点与恢复角色，收窄消费者实际需要的方法；正式接受仍由原 `accepted_store.go` 和原变化计划接线，不能在“提供方适配器”里另写业务转换。

原 PostgreSQL、文件、内存实现登记为受信提供方并声明各自支持范围。日志接受与完整正式状态事务是不同要求：轻量文件模式不能冒充支持正式 SQL 当前状态的交付存储。PostgreSQL 专有投影留在明确的可选适配器，通用接受、恢复和装配不再通过具体类型或连接池指针选择业务路径；不为无消费者的其他数据库预造抽象。

存储切换使用原受控备份、快照及恢复格式。在受支持能力交集中交接；不支持的组合在预检阶段拒绝。实施须提供可运行的显式交接检查入口，复用 `make rehearse` 和原部署工具，不能只写一个接口即声称可替换。

### 5. 一份组合固定代际，基础切换在静止边界完成

每个租户实例持有不可变的已解析能力组合；私有决定、协调读取、嵌套决定和锁外工作捕获关联其代际。已封存结果不需要重新执行该代际的规则或授权，恢复继续应用保存映像；旧输入恢复维持原兼容二进制责任。

| 实现或资源 | 切换方式 | 激活条件 |
|---|---|---|
| 租户作用域规则、授权等基础实现 | 原宿主治理暂停该租户接入，构造并验证隔离替代实例，经原恢复入口切换代际 | 原决定、读取及不能移交的后台工作退出；旧外部结果按原身份及世代处理；新实例恢复检查成功 |
| 部署共享的基础实现、正式存储 | 部署维护，停止所有依赖作用域，经受控重启启动目标组合 | 写者停止、源位置固定、目标交接验证成功；不能由租户自行切换共享资源 |
| 协议驱动、短期预览及声明为可排空切换的技术能力 | 原包和连接边界下的受控排空与资源交接 | 新连接使用兼容提供方；旧配置只保留必要在途核对；最后引用释放后回收进程 |

获权租户基础选择由原 Console 的接受结果保存；部署共享选择留在原部署配置，秘密只使用平台凭据引用。启动、创建租户、试验及恢复都由同一装配描述构造，恢复不得暗中回到硬编码默认工厂。维护权限由切换前的有效治理规则判定，候选不能批准自身激活。

恢复资格沿 `snapshotCompatibility` 与 owner 格式扩展：实现身份用于诊断和缓存隔离，契约、语义及状态格式决定恢复资格。仅换了满足同一格式的实现不应无故使封存结果失效；不能声明格式兼容的实现仍保留原构建限制。不为装配统一重写历史或给全部旧接受封套强加新字段。

### 6. 生命周期管理可释放资源，业务事实保持原归属

沿原运行协调保存所需的轻量代际、接入开关和在途资源引用；资源清理以所属作用域为单位登记，构造失败和正常退出共用同一清理路径。新调用先检查接入状态再取得引用，排空后不能偷偷重新启动进程。依赖方退出后才关闭提供方，完成包括等待 goroutine、设备连接和子进程结束。

治理期望状态沿原包/Console 接受机制持久保存；正在运行、连接故障、清理错误等为原运行实例的诊断投影，不建立另一套业务状态机。重启从保存的期望状态重建最小资源，不能把“正在清理”恢复成新采样或新写入；清理重试不重新提交原决定。

`gateway.Server` 维护会话与共享进程的使用关系，驱动已有 `stop`、`close` 方法继续承担真实设备连接释放；`driver.Client` 扩展可等待、有界、重复安全的关闭。预览检查结束及超时走同一释放路径。保留技术收据和未知命令所需旧映射，排空不强行当作撤回命令，也不清除已确认的外部事实。

### 7. 三种来源与原有包使用同一受控入口

包管理的“加号”提供“已有包”“从网址获取”“本地导入”三个来源。平台格式支持现有纯声明描述和携带内容寻址制品的版本化平台归档；读取后展示名称、确切版本、来源、职责、内容摘要、依赖、执行权限及预计影响。获取与审阅只产生受控候选，不安装、不发布、不授权、不创建组织或业务记录；安装仍提交原 owner 的受控决定。确认绑定审阅过的内容摘要，不在确认时重新下载最新版。

在线获取使用有界、受控的 HTTP 读取，不执行 npm、Git hooks 或其他安装脚本；本地导入处理内容，不接受宿主任意路径。所有制品验证摘要、类型、预算和所需执行边界。纯声明与隔离代码可由获权构建者使用；原生驱动和基础实现须满足部署信任准入，不能通过上传一个描述获得宿主执行权。密钥使用引用，不在包中输入或导出真实秘密。

原部署包目录、已获取候选和内置能力描述向原包目录投影，不成为另一安装权威。移除来源候选只清除未安装/无引用内容；卸载撤销运行贡献但保留正式资产和历史。已发布应用、在途流程、未知派发、其他包依赖及最后一个必需基础提供方都进入影响预检，用户先看到哪些功能将停止以及保留什么，不能先删除后再发现依赖。

### 8. 内置模块与最小维护入口

原有平台模块、业务内核、规则、授权及存储都登记提供契约、需求和作用域，依赖它们的业务入口不再仅凭二进制内存在就可用。维护启动器只承担装配、受信维护身份、包获取/审阅、诊断和恢复入口，不处理业务决定。卸下必需基础提供方先完成静止，依赖业务保持不可用；恢复兼容提供方后沿原恢复检查重新接入。共享存储停用采用部署维护模式，不在仍有正式写者时关闭连接池。

业务内核的具体实现与契约条款分开：K1–K9 仍为不可由包改写的语义约束，所选兼容实现可替换。原有 MES 等应用声明仍保留在原 owner，应用入口退出不删除原定义、数据、历史或验收资产。编译进二进制的受信模块也通过装配选择与运行注销退出，不能只给新包增加此机制。

### 9. 原治理入口同时显示期望状态与实际状态

扩展现有 `/v1/packages`、能力矩阵及 Host Console 的原投影，显示实现身份、契约、依赖、作用域、实际代际、就绪、在途阻碍、清理错误及重启要求。内置实现可以展示和按其作用域切换，不伪装成刚安装的应用包。

界面沿原权限展示维护入口；无支持的切换方式时展示明确的维护步骤，不提供会失败的通用“热替换”按钮。贡献退出复用工作区原加载、视图、订阅和未保存输入机制，不加入任意远程前端模块加载。API DTO 与 Catalog 由原工具生成，产品文案中英双语。

### 10. 面向初次使用者的帮助

沿现有工作区提供“包使用指南”帮助入口，包页面、加号来源选择、安装预览、卸载预检及基础维护页面都能直接进入相应主题。指南说明先选择哪一种来源、如何核对内容、安装后如何构建/发布、权限与凭据如何配置，以及停用、卸载、移除候选各自保留什么。错误状态给出可执行的重试、替换依赖或恢复入口，不能只展示内部错误码。全文双语、适配窄屏，提供空状态、加载、失败与失联说明。

## Risks / Trade-offs

- [接口只包住入口，内部仍调用固定实现] → 列明并迁移真实编译、求值、比较、聚合与授权路径；用会故障的测试提供方发现隐藏回退，不能只检查构造参数。
- [统一装配变成第二个注册权威] → 解析结果是既有声明的不可变投影；正式包状态、资产、业务和恢复仍归原 owner。
- [热替换混合授权或状态] → 租户基础实现采用静止与隔离实例切换，共享基础资源采用维护重启，迟到结果仍复核原世代及当前资格。
- [停止信号误报为资源释放] → 明确等待退出、错误与超时；共享引用未清空及未知命令未处理时保持阻碍。
- [恢复兼容检查过宽或过严] → 分别检查接口、语义和状态格式，保留旧二进制限制；真实固定位置及末态比较优先于实现名。
- [接口替换被误报为另一算法已经验证] → 注入路由与故障用例只证明接线；真实提供方切换、契约向量、存储恢复与生产质量分别说明。

## Migration Plan

1. 将现有实现声明为默认受信提供方；以显式组合代替隐式默认，先保持当前行为。每迁移一个责任块，同批删除被替代的普通接线路径，不保留两套选择器。
2. 完成规则、授权和存储的消费接口迁移，检查启动、新租户、试验、恢复及后台路径都使用所选组合。旧接受日志与包描述保持原字节；新增元数据的缺省只用于解释已知历史格式，不给新配置猜测提供方。
3. 打通原治理切换、静止检查、资源释放及诊断；再集中验证契约、故障、共享资源和恢复。测试提供方用于证明接线与失败边界，不宣称新增了生产授权算法。
4. 在隔离环境停止源写者、固定租户位置，交接并比较目标日志、答复、历史、当前状态、键、收据与外部字节。先验证原 PostgreSQL 提供方的独立实例交接与同形态恢复，再验证文件/内存在各自支持形态内的提供方接线；不支持的跨形态组合明确拒绝。
5. 目标接受第一项新正式结果前，失败可保留或恢复原部署组合；之后回退须停写、交接并验证新增后缀。禁止同时启动源和目标写者，不做永久双写或自动改用陈旧源端。
6. 同步 Architecture、当前规范与原部署指南。按现有授权完成代码提交和本地更新时，核对两宿主实际版本、租户健康及页面资源，保留原数据卷、密钥和租户配置；纯规划不触发部署重建。
