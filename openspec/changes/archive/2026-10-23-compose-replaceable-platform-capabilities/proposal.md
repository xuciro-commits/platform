# Proposal

## Why

平台已有包安装、版本保留和类型化驱动，但规则编译、授权合成、存储接线及宿主组合仍绑定具体实现，安装状态也没有完整表达运行资源是否退出。借鉴 dsh 的接口、依赖装配和资源生命周期，使平台基础实现与技术能力都可替换，同时保持既有业务契约、单一权威和历史责任。

## What Changes

- 将规则编译与执行、授权合成、正式存储等基础实现纳入具名、版本化、类型化的能力接口；消费者只依赖契约，同一作用域内每项能力只有一个激活提供方。
- 使用同一装配描述选择实现、检查依赖和建立实例；普通启动、新租户创建、隔离试验和恢复使用相同的解析与校验。显式区分部署共享资源与租户实例，禁止注册顺序决定提供方。
- 基础实现可以替换。规则与授权在租户静止边界切换；正式存储及共享基础实现经部署维护和受控重启切换。切换先检查契约、原位置、状态格式和在途责任，不承诺所有实现均可任意热替换。
- 沿原包安装、升级、排空和退役决定管理可安装能力。资源生命周期负责停止接入、等待或隔离在途调用、注销贡献、关闭会话、取消任务和回收进程；不撤销已接受的业务结果或实际外部效果。
- 在既有包管理、能力矩阵和宿主运维入口展示已选择实现、接口与语义版本、依赖、运行状态、排空阻碍和重启要求。安装成功、运行就绪和卸载完成分别呈现。
- **BREAKING**：替换只能由部署及原平台治理选择受信实现，业务应用不能覆盖基础引擎。实现迁移到类型化接口后，同批移除活动路径中的具体类型依赖、静默覆盖及重复装配；旧接受字节与旧格式读取责任保留。
- 增加面向初次使用者的“加号”入口，支持从网上获取平台包、本地导入平台包或选择现有包。三种来源使用同一预览、依赖检查、安装及清理路径，下载与安装不运行包内业务或任意脚本。
- 原有应用包和内置规则、授权、存储及业务内核实现也纳入同一能力描述与生命周期；缺少必需基础提供方时停止受影响业务，保留最小维护与恢复入口，不能造成宿主崩溃、其他作用域污染或历史丢失。
- 提供双语就地帮助与完整操作指南，说明包来源、信任、权限、依赖、停用/卸载/移除的区别及失败恢复入口；从包管理、能力矩阵与相关维护操作可直接进入。
- 保持平台包、能力包、应用包三个职责维度；不增加行业包或第四种插件包类型。本次不导入 Cordis，不修改 K1–K9 的语义。

## Capabilities

### New Capabilities

无。沿现有模块扩展，不新建插件子系统规范。

### Modified Capabilities

- `runtime/deployment`：明确基础与扩展能力的统一装配、依赖选择、实例作用域和部署切换条件。
- `runtime/host`：明确能力代际、私有决定绑定、运行资源排空和清理完成条件。
- `runtime/storage`：允许满足相同正式存储契约的实现替换，固定源位置并验证交接与恢复资格。
- `runtime/access-control`：授权实现可替换，保留唯一合成顺序、当前事实与失败拒绝。
- `platform/business-models`：规则实现可替换，编译与求值通过原版本化表达式契约，保持预览与正式执行一致。
- `platform/application-lifecycle`：统一三种来源、内容审阅及原有/新增包生命周期，明确安装无业务副作用与移除边界。
- `platform/integrations`：完善协议驱动会话、采样和共享进程的替换与释放，保留未知命令核对。
- `experience/workspace`：提供三种来源的“加号”流程、双语帮助入口及真实运行与清理反馈。

## Impact

- Go 归属：`capabilities/server/platform/` 的公共能力契约、`internal/host/` 的消费角色、`composition/tenant.go`、`host.go`、`authorization_decision.go`、`platform/authz/`、`internal/rules/`、`platform/rules.go`、`journal/`、`journal_bridge.go`、`deploy*.go`、`packages.go`、`protocol_connections.go`、`gateway/` 和 `driver/`。
- Web 归属：现有 `web/packages/platform/src/apps.tsx` 的包与能力矩阵、宿主运维入口，以及工作区原有贡献加载与清理。API 类型变化由原生成器生成，产品文案双语。
- 状态与兼容：能力实现身份与原业务定义版本分别管理；存储格式及恢复资格仍由原 owner 声明；历史接受结果不增加恢复时重新求值、重新授权或外部调用。
- 验证：原契约与规则向量、授权拒绝与来源保护、接受结果与固定视图、真实 PostgreSQL 交接/恢复、驱动资源生命周期，以及一条既有治理入口的浏览器路线。接口测试不能替代真实提供方切换与恢复证据。
- 实施完成后同步 `docs/Architecture.md`、相应现行规范与部署指南；代码交付沿原本地更新流程保留两宿主的数据、密钥与配置。
