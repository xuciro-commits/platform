# Design

## Context

Console 已拥有受控治理状态和私有接受映像；Tenant.secret 是 AI、连接器和投递共用的部署秘密入口。AI 只有 provider.add/remove，页面也没有编辑。见 proposal.md。

## Goals / Non-Goals

交付可操作的托管 API key、Bearer、密码和部署引用，提供方编辑及连接检查。沿用 Console、Ledger、SQL 接受结果和原工作队列；不建新执行器、数据库、OAuth、外部 Vault 适配或加密主密钥轮换。

## Decisions

- 凭据归 Console，新增受控状态和动作，公开元数据不含密文；持久私有状态含认证密文。空状态省略，保留旧检查点摘要与恢复责任。
- POST 在线封装读取瞬时明文，以独立部署 AES-256-GCM 主密钥加密；关联数据固定租户、凭据 ID、类型、来源、绑定及预期版本。响应仅返回普通保存动作所需密文，浏览器清空明文后经原 decide 保存，重试不重新封装。
- 保存动作校验当前权限、预期版本及密文认证；只应用已接受映像的恢复不解密。新密文版本、元数据修改和停用留原历史，禁用或解密失败不回退部署秘密。
- 使用按 consumer（ai/provider、connection/id、endpoint/id）和实际目标 origin 校验；集成已有 HTTP Authorization、数据库密码与签名语义保留。旧部署名没有管理记录时继续沿原路径；创建部署引用记录后也受显式使用绑定约束。
- 管理权限属于 platform.admin，AI 管理员可选凭据元数据但不能取得原值；有平台权限时可从提供方表单就地创建凭据。编辑提供方保留模型，不强迫删除重建；检查沿原模型目录请求强制刷新。
- 本地部署生成一次独立主密钥写入已忽略 .env，通过原启动入口注入，不提交、不打印，不因重启更换。托管功能未配置主密钥时明确不可用，原部署引用仍可使用。

## Risks / Trade-offs

- 密文表单重试重复封装 → 保留同一封装及原请求键，输入修改后才创建新提交。
- 名称引用绕过消费者或目标 → 所有出站使用点复用同一解析器，真实请求地址参与检查，不仅检查配置中的地址。
- 保存映像扩大恢复格式 → 沿现有可选状态字段，集中验证失败追加、重启、旧无凭据状态和真实 PostgreSQL。

## Migration Plan

原提供方和部署密钥名继续使用，不自动复制原密钥。管理员可录入新平台凭据并显式改绑。更新两台本地宿主并保留原租户、日志、数据卷及密钥；完整备份包含数据库和独立主密钥。
