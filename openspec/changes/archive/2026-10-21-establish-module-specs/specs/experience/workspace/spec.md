# 工作区与构建体验 Specification

## Purpose

本模块负责宿主统一 Web 工作区、原生与构建应用的导航和界面身份、共享 UI 与 Catalog、受控草稿的编辑会话，以及表单、Inspector、流程节点与布局的职责边界。它不定义业务权限、不执行另一套业务规则，也不把组件数量或界面展示当成完整应用交付。

业务模型和规则见[业务模型](../../platform/business-models/spec.md)，候选与发布见[应用生命周期](../../platform/application-lifecycle/spec.md)，专业空间交互见[专业可视化](../professional-visualization/spec.md)。

代码来源：`web/apps/workspace/src/App.tsx`、`web/apps/workspace/src/host/applications.ts`、`web/apps/workspace/src/host/usePlatformHost.ts`、`web/packages/ui/src/shell/Workspace.tsx`、`web/packages/ui/src/components/StructuredEditor.tsx`、`web/packages/ui/src/fields/`、`web/packages/ui/src/graph/`、`web/packages/app/src/widgets/registry.ts`、`web/packages/build/src/session/`、`web/packages/build/src/automate/process-draft.ts`、`web/packages/build/src/workshop/page-editor/`、`scripts/catalog.mjs`、`capabilities/server/platform/pageui/widgets.json`。视觉品质、触控手感和实际任务耗时仍需用户操作确认，本规范不新增未观察的体验或性能承诺。

## ADDED Requirements

### Requirement: 一个宿主一个工作区入口

系统 SHALL 在同一工作区提供身份、应用门户、导航、记录与运行入口；原生应用和租户发布应用共用宿主会话与当前授权发现。工作台内新建应用不得要求独立容器、固定端口或另一套登录和数据权限。

#### Scenario: 打开租户构建的应用

- **GIVEN** 成员可发现一个已发布的业务应用
- **WHEN** 成员从应用门户打开它
- **THEN** 页面继续使用所属宿主和当前成员身份，业务动作走原宿主入口。

### Requirement: 原生与构建应用保留真实身份

系统 SHALL 以代码应用声明和已发布应用定义组成应用目录，原生应用不伪装成 Build 草稿；已发布扩展归属于其原应用。声明的界面替换须一致处理菜单、深链和恢复的标签页，同时保留原路由参数与业务记录身份。

#### Scenario: 从旧链接打开已替换的业务界面

- **GIVEN** 已发布扩展为原生应用某视图声明了有效页面替换
- **WHEN** 成员使用原菜单、历史链接或恢复标签页打开该视图
- **THEN** 工作区解析到已发布替换页，并保留原记录上下文，不另造业务数据副本。

### Requirement: 角色发现与编辑模型分开

系统 SHALL 使用当前发现结果决定应用与操作可见性；Builder 可读的保存草稿与 Integrator 可读的运行模型须分开。角色变化后不得继续向非 Builder 暴露查询缓存中的草稿，也不能通过读取草稿取得实际执行权限。

#### Scenario: 原编辑器中的构建者被降为集成人员

- **GIVEN** 同一浏览器已经读取保存的对象草稿
- **WHEN** 原成员的 Builder 授权被撤销，仅保留 Integrator 范围
- **THEN** 数据映射改用当前运行模型，隐藏草稿编辑入口，不再消费或请求 Builder 草稿数据。

### Requirement: 共享 UI 与统一资产目录

系统 SHALL 由原归属方随代码维护资产信息，生成统一 Catalog 索引并复用共享 UI、样式和应用 API。目录须指明用途、归属与真实引用，不能以展示清单另建运行时注册表、权限或执行路径；业务专用页面不得改名后搬入共享 UI。

#### Scenario: 构建者或开发者选择已有组件

- **GIVEN** 组件已经由所属包导出并登记资产信息
- **WHEN** 用户或开发工具查询 Catalog
- **THEN** 得到其原导入位置与真实示例，而不是第二份组件实现或业务许可判断。

### Requirement: 页面契约唯一来源与版本兼容

系统 SHALL 使运行渲染、作者注册、普通属性和共有检查消费同一 Widget 清单与配置版本；专用 Inspector 只承担实际绑定或专业交互。未知组件、未知配置版本或不兼容 profile MUST 保留原配置并明确拒绝或要求兼容处理，不静默删除后保存。

#### Scenario: 打开包含未知组件配置的旧页面

- **GIVEN** 保存页面包含当前渲染器不支持的组件版本
- **WHEN** 构建者检查页面兼容性或尝试升级
- **THEN** 系统定位不支持的配置并保留原值，不能把组件丢弃后当成成功转换。

### Requirement: 可视化与源码共用草稿会话

系统 SHALL 使可视化、JSON/YAML 源码、撤销和重做作用于同一草稿；未应用或非法文本属于原输入会话并阻止保存。切换选中项、编辑模式或隐藏面板不得静默提交、丢弃或绕过这些输入；保存冲突保留用户草稿，不用服务器新值强行覆盖。

#### Scenario: 输入尚未完成时切换编辑对象

- **GIVEN** 用户在字段、表达式或源码中输入了尚不合法的文本
- **WHEN** 用户切换 Inspector 选中项、隐藏面板或请求保存
- **THEN** 输入继续保留，保存被阻止；用户可以返回修正或通过原放弃操作清除。

#### Scenario: 可视化应用合法源码

- **GIVEN** 源码能按当前声明正确解析且通过输入检查
- **WHEN** 用户显式应用源码并切换可视化
- **THEN** 修改进入同一草稿与撤销记录，应用源码本身不代表持久保存或发布。

### Requirement: 编辑器往返保留原任务

系统 SHALL 在查看字段定义、模型来源或原编辑器时保留工作区、应用上下文和来源草稿；返回使用已有视图调用与未保存确认。映射须显示目标字段类型、必填、引用与已有约束；不可用字段保留原绑定并提示，不能自动删除。

#### Scenario: 从未保存的来源映射编辑目标字段

- **GIVEN** 来源映射已有未保存输入，Builder 有权编辑其对象草稿
- **WHEN** 用户跳转到目标字段编辑器，再取消放弃并最终返回
- **THEN** 目标编辑器遵守原未保存确认，来源映射输入和应用上下文继续存在。

### Requirement: 表单和 Inspector 共用字段语义

系统 SHALL 复用字段类型、解析、输入草稿、声明校验和业务错误定位，不由普通表单、源码导入与 Inspector 各自复制一套值转换。条件字段、复杂绑定和联动修改仍由相应归属方保留；输入检查通过不能冒充业务规则已执行。

#### Scenario: 输入通过但业务动作拒绝

- **GIVEN** 字段结构合法，但当前业务条件或权限不满足
- **WHEN** 用户提交原动作
- **THEN** 宿主按业务规则拒绝，界面保留输入并展示原拒绝，不把前端检查结果当成提交许可。

### Requirement: 流程编辑保留控制和数据引用

系统 SHALL 由原流程模型提供节点种类、类型化端口、控制与数据通道和问题位置；重命名、移动、删除和接线使用模型编辑命令，保留嵌套绑定语义。简单 Automation 仅编辑能无损表示的形态，不支持的合法图须转到原 Flow 编辑器。

#### Scenario: 修改含嵌套条件的流程

- **GIVEN** 分支条件引用上游步骤的结果字段
- **WHEN** 构建者重命名上游步骤或连接条件操作数
- **THEN** 原嵌套引用随模型命令更新，错误定位能选中对应步骤，不生成顶层伪字段。

#### Scenario: 在简单视图打开高级流程

- **GIVEN** 合法流程包含卡片不能无损表达的分支或高级配置
- **WHEN** 用户进入简单 Automation 入口
- **THEN** 视图识别不可无损编辑并提供原 Flow 编辑入口
- **AND** 不因切换或保存重建流程、清空高级字段。

### Requirement: 手持扫码与打印复用原业务页面

系统 SHALL 在同一页面树和记录查询上提供手持、扫码和标签呈现；扫码使用原查询文本，标签使用获权记录详情，条码只引用原 ID 或声明的文本字段。设备呈现不能建立移动端业务副本、赋予新动作权限或承诺未实现的打印机协议。

#### Scenario: 扫码定位记录并打印标签

- **WHEN** 用户在扫码输入中提交扫描文本并打开匹配记录的标签呈现
- **THEN** 原查询与读取权限继续生效，标签只打印该记录获权的原详情
- **AND** 不因手持布局或打印操作产生业务写入。

### Requirement: 布局与绘图不接管业务执行

系统 SHALL 区分流程图与关系图的结构和布局职责，复用现有节点、端口与布局实现；读者本机排布与作者保存布局分开。拖动、缩放、展开或自动排布不能修改业务定义或执行状态；可编辑流程布局只有进入原草稿保存才成为作者配置。

#### Scenario: 业务人员调整只读运行图

- **GIVEN** 用户正在查看一个已存在的运行或关系图
- **WHEN** 用户拖动节点或使用自动排布
- **THEN** 变化只影响适用的阅读布局，不产生业务决定、重新执行步骤或覆盖作者定义。
