# Spec Delta

## ADDED Requirements

### Requirement: 声明式外部智能体调用复用原回写与 A2A 通道

构建者 SHALL 在原 Writeback 中选择 HTTP 或 A2A 传输，使用原 Connection 的地址与凭据名。A2A 请求 MUST 复用原消息协议、稳定效果身份及接受结果，冻结传输选择、映射和版本；草稿或后续发布改变不得改写在途请求。完整外部答复通过原映射和受权对象决定保存；不完整、截断或失败答复不能变为成功业务结果。

#### Scenario: 供应方已处理询问但答复丢失

- **WHEN** 原询问按既有 A2A 重试策略接续
- **THEN** 沿用同一消息身份与冻结内容，由原接收方识别重复
- **AND** 保存答复后宿主恢复不再次询问，也不重写已经接受的业务结果

#### Scenario: 更新配置时询问仍在途

- **WHEN** 构建者修改传输方式、映射或当前连接配置
- **THEN** 原在途请求继续使用原接受内容和部署密钥名
- **AND** A2A 不能成为设备协议命令的旁路

### Requirement: 状态区间分析使用通用声明与原观测来源

构建者 SHALL 用原观测、规则和流程声明采样来源、状态条件、事件时间、窗口、迟到策略及结果动作，将状态持续区间转为可追溯的业务结果。原始采样存储与完整性仍遵守原观测约定；MUST 保存结果依据的来源、配置和处理版本，不将质量未知、缺失或截断解释为正常状态。行业状态名与通知规则不得成为宿主或驱动的专用分支。

#### Scenario: 在两个行业声明不同状态区间

- **GIVEN** 制造声明设备停机区间，供暖声明温度越界持续区间
- **WHEN** 两者从已声明来源取得满足覆盖与质量要求的采样
- **THEN** 同一通用机制按各自声明形成区间和后续业务动作
- **AND** 不调用 MES 私有事实容器或新增供暖专用执行器

#### Scenario: 状态采样存在未知区段

- **WHEN** 当前采样不足以证明请求区间的状态或完整性
- **THEN** 结果保留未就绪或不合格信息，按声明拒绝完整业务结论
- **AND** 不生成虚假的停机结束、正常运行或完整时长

### Requirement: 区间纠正保留事件身份与人工决定

区间纠正 SHALL 使用原身份、关系和接受结果机制记录前后事件与来源；确定的一对一边界变化保持事件连续，拆分、合并保留前驱关联且不复用已经退出的身份。人工原因和确认 MUST 保留实际目标与决定者；无法唯一归属的决定进入待复核状态，不自动复制给所有后继。重复采样或无变化重读不重复产生事件和通知。

#### Scenario: 已记录原因的停机事件被迟到采样拆分

- **GIVEN** 人员已经为一项停机事件记录原因
- **WHEN** 合法迟到采样将该事件纠正为两个区间
- **THEN** 原原因、原事件和两个后继均可追溯，原因归属标为需要复核
- **AND** 不静默把原原因当成两个新事件都已确认的原因

#### Scenario: 多个事件合并或新事件重现

- **WHEN** 合法纠正合并多个区间，或后续事件恰有相同起始时间
- **THEN** 合并结果保留全部相关前驱与人工决定，新事件不复活已经退出的事件身份
- **AND** 需要人工消解的归属继续显式存在

#### Scenario: 结果重试和宿主恢复

- **GIVEN** 区间及原因变化已经持久接受
- **WHEN** 原输入重试、相同来源重读或宿主重启
- **THEN** 重试沿原身份接续，恢复只应用已保存结果，不重做已经接受的分析或通知
- **AND** 原始采样和处理状态继续由原来源及流程 owner 管理
