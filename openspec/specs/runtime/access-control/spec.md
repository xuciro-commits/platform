# 身份与访问控制 Specification

## Purpose

规定宿主如何从可信身份解析当前租户成员，并对动作、记录、字段、来源、历史与派生内容作同一授权决定。本模块不替代身份提供方、企业组织模型或业务人员主数据，不引入租户可编程授权语言、任意关系遍历或跨租户联合权限；接受与恢复顺序引用[宿主规范](../host/spec.md)及[存储规范](../storage/spec.md)。

来源：从 Git 历史中的租户隔离、授权合成、人员分工和受保护读取决定提炼，已对照 `capabilities/server/server.go`、`capabilities/server/idp/`、`capabilities/server/console_identity.go`、`capabilities/server/console_member.go`、`capabilities/server/authorization_decision.go`、`capabilities/server/platform/authz/`、`capabilities/server/records_access.go`、`capabilities/server/internal/records/access.go` 与 `capabilities/server/internal/construction/marking.go`。规范只约束已声明的来源与有界访问行为，不将现有检查视为任意业务算法自动正确声明来源的证明。

## Requirements

### Requirement: 可信身份与当前租户成员分别确认

宿主 SHALL 先验证当前部署接受的凭证，再由目标租户目录解析有效成员；有效外部身份本身不授予业务权限。请求主体与租户 MUST 与实际调用者一致，不能借另一租户的成员 ID、请求内容或应用名越过隔离。

#### Scenario: 身份有效但不是目标租户成员

- **GIVEN** 凭证能被身份提供方验证，但目标租户未接纳该主体
- **WHEN** 主体请求读取或修改目标租户业务
- **THEN** 请求被拒绝；只有原受控加入规则能够创建无角色成员，凭证中声称的业务角色不能直接成为租户授权

### Requirement: 身份、企业人员和业务人员职责分开

登录成员及其授予 SHALL 归身份目录，组织、岗位与任职归企业模型，业务人员字段归原主数据归属方。它们 MUST 通过显式引用关联，不因姓名、邮箱、岗位或组织父子关系自动同步为统一人员表、创建租户或产生角色。

#### Scenario: 人员任职或业务资料发生变化

- **GIVEN** 一个业务人员记录关联了企业人员与登录成员
- **WHEN** 业务姓名、企业任职或组织层级改变
- **THEN** 各归属方保留自己的历史和决定，成员授权只有通过原授予规则改变，不从新的组织位置推导管理员或应用角色

### Requirement: 宿主治理与租户权限独立

宿主管理权限 MUST 由宿主明确配置的主体范围授予，不能由租户管理员角色推导。租户管理员、构建者、集成者、普通成员、服务账号和智能体 SHALL 各按原声明取得权限；看到应用入口、模型或配置不等于取得其数据和动作权限。

#### Scenario: 租户管理员操作宿主控制台

- **GIVEN** 成员拥有某租户管理员权限，但不在宿主管理主体范围
- **WHEN** 成员请求创建、停用其他租户或打开宿主管理接口
- **THEN** 宿主拒绝该操作，其租户角色不能扩展到其他租户或宿主级维护范围

### Requirement: 授权通过唯一且固定的合成顺序

授权 MUST 按租户、主体、显式 deny、动词、行、字段、来源、标记、最终 allow 的顺序合成。显式 deny 优先；allow 只能提供动词授予，不能越过后续限制。动作、读取、导出、协议、后台输入和能力目录 SHALL 使用同一引擎，由原归属方提供事实。

#### Scenario: 有动作角色但被策略或字段限制

- **GIVEN** 成员的有效角色允许某动作
- **WHEN** 匹配的 deny 拒绝该动作，或目标行、字段、来源超出其范围
- **THEN** 最终决定仍拒绝，角色、自动执行身份或匹配的 allow 不覆盖这些限制；解释结果保留实际拒绝层

### Requirement: 授予按有效期和归属方范围生效

系统 SHALL 合并成员当前有效的多角色和授予，再按对象原 scope 计算可见行；单位与结构授予仅在对应 unit/below 规则内起作用，不改变 all/own 语义。有效岗位不自动授予角色；租户策略 MUST 保持原精确匹配与起止日能力，不解释任意表达式或无限关系遍历。

#### Scenario: 单位关系到期或授予失效

- **GIVEN** 成员依靠有时效、单位和指定结构的授予读取下级记录
- **WHEN** 授予过期、单位关闭，或该结构中的关系失效
- **THEN** 当前读取不再沿失效关系展开，其他仍有效授予保持原并集；换用另一个结构或岗位不能恢复失去的范围

#### Scenario: 构建者显式增加业务角色

- **GIVEN** 成员已有有效构建角色，正在准备一个应用
- **WHEN** 成员经原授权动作取得该应用已经声明的业务角色
- **THEN** 原构建资格及其入口保留，仍有效的原主角色不因新增授予而被替换
- **AND** 原主角色被撤销或到期后仅从剩余有效授予选择主角色；实际授权继续合并当前有效授予。

### Requirement: 登录限制保留实际凭证边界

登录域自动加入 SHALL 只接纳满足原规则的已验证主体并创建无角色成员；启用多因素要求时 MUST 有可信验证后的多因素证明。会话时长从本凭证首次被宿主看到起计，个人令牌走独立范围校验；当前内存会话与撤销状态不得宣称跨重启持久保存。

#### Scenario: 单因素身份请求受保护登录

- **GIVEN** 租户要求多因素登录
- **WHEN** 凭证不能证明多因素，或开发凭证没有这类可信证明
- **THEN** 登录被拒绝，普通用户声明或单个持有因素不能替代证明；角色授予也不绕过该登录条件

### Requirement: 历史与保留版本仍执行当前权限

历史详情、原答复、保留能力版本、查询、导出、AI 结果、错误详情和派生数据 SHALL 按当前有效成员及原归属方规则过滤。保留旧定义、旧来源或接受时的成员快照 MUST NOT 保留已经撤销的读取资格，也不得通过隐藏记录的名称、数量或字段错误泄漏内容。

#### Scenario: 撤销来源字段后读取旧结果

- **GIVEN** 成员以前能够读取某字段，并产生了历史版本或 AI 调用结果
- **WHEN** 该来源字段的读取角色被撤销，而成员仍持有旧成员快照或结果 ID
- **THEN** 当前请求拒绝或遮蔽相关内容，旧历史字节不改写，结果存在本身不恢复来源权限

### Requirement: 派生信息保留可验证来源

复制、计算或嵌入受保护内容的归属方 MUST 声明原来源；读取 SHALL 按当前主体检查所需记录及字段，来源缺失、不可读、循环或超过有界深度时不得扩大权限。一次判定内可复用结果，不得将成员授权缓存为其他主体或跨请求的资格。

#### Scenario: 输出来自不可读来源或来源循环

- **GIVEN** 一个可见输出引用受保护字段，或其来源构成循环
- **WHEN** 当前成员读取该输出、聚合或嵌入内容
- **THEN** 系统按声明的来源拒绝或遮蔽相应内容，不因输出本身可见而公开原值；有界检查不能被解释为任意新业务算法已自动取得完整来源

### Requirement: 数据标记沿来源传播且不能降级

来源、数据集和管道输出 SHALL 传播不低于输入的分类标记。机密或受限数据写入对象字段时 MUST 满足原明确读者要求，受限数据集不得导出 CSV；标记复用原字段和导出授权，不另建第二套权限引擎。

#### Scenario: 将受保护数据映射到开放字段或导出

- **GIVEN** 输入带有机密或受限标记
- **WHEN** 映射试图写入没有明确读者的字段，或请求导出受限数据集
- **THEN** 操作被拒绝，不能靠目标的较低标记、空字段声明或新的导出入口降低来源保护

### Requirement: 自动化等待后复核当前资格

服务账号、工作流和智能体 SHALL 在原声明的身份或明确代办主体下执行。锁外等待后接受结果前 MUST 复核当前主体、动作、来源与相关版本；宿主拥有更宽权限不代表自动执行可以借用它们。已封存结果恢复只应用原依据，不能重新授权或发送外部请求。

#### Scenario: 自动化等待期间撤权

- **GIVEN** 自动化按明确主体读取来源并在锁外等待模型或外部计算
- **WHEN** 主体被停用或所需权限被撤销后收到答复
- **THEN** 答复不能继续执行失去资格的业务动作；恢复已接受的旧结果也不能变成再次调用授权或外部系统的机会

### Requirement: 出站凭据统一由平台治理

平台 SHALL 管理租户级凭据的名称、类型、来源、使用绑定、版本和停用状态。平台管理员维护凭据，AI 和连接的使用者只能沿获权的消费者及绑定目标使用，不取得读取原值的权限。平台托管值 MUST 加密保存，主加密密钥留在部署环境；部署引用继续由原环境提供，不进入应用包。

#### Scenario: 更换并停用托管凭据

- **WHEN** 管理员替换凭据值或停用凭据
- **THEN** 版本通过原接受结果递增，消费者下次请求使用当前版本或明确失败
- **AND** 元数据、审计和 API 不返回密钥原值，停用后不回退同名部署秘密

#### Scenario: 凭据被另一个租户或目标引用

- **WHEN** 未获绑定的消费者或目标地址请求使用托管凭据
- **THEN** 拒绝使用，不因名字相同或宿主能解密而取得权限

### Requirement: 密钥录入与普通提交分离

平台 SHALL 提供受权的在线密钥封装入口，明文只用于生成绑定租户、凭据及配置的认证密文；保存该密文仍经原提交和持久接受路径。明文 MUST NOT 进入普通动作提交、离线队列、业务历史或应用包。重试复用原密文和请求键，同键换内容拒绝；恢复只应用已保存的密文映像，不重新加密或调用外部系统。

#### Scenario: 保存追加失败后重试并恢复

- **WHEN** 密文保存追加失败，随后以原密文和请求键重试并重启
- **THEN** 失败不泄漏正式状态，成功后复用原答复和版本
- **AND** 无解密主密钥仍可恢复保存状态，实际使用明确报告不可用

#### Scenario: 篡改密文或配置

- **WHEN** 调用者改变封装的租户、凭据身份、配置或密文字节后提交
- **THEN** 普通保存拒绝无效封装，不接受明文代替密文

### Requirement: 授权实现可替换但判定契约唯一

平台 SHALL 通过版本化、类型化的授权接口选择一个实现，由原事实归属方提供当前租户、主体、角色、策略、行、字段、来源和标记。替换 MUST 保持本模块规定的合成顺序、拒绝优先级、诊断与证据语义；动作、读取、历史、导出、协议及自动化共用所选实现，不能只替换展示解释或留下另一条正式判定路径。

#### Scenario: 替换后读取已撤权的历史或派生结果

- **GIVEN** 原成员已失去来源字段权限，历史结果仍然保留
- **WHEN** 新授权实现处理该成员的历史读取、导出或 AI 来源请求
- **THEN** 继续按当前事实拒绝或遮蔽，不复用旧允许、旧角色快照或其他实现的缓存
- **AND** 可公开的拒绝层与来源信息满足同一契约

#### Scenario: 可替换实现没有就绪或返回无效判定

- **WHEN** 选定授权实现缺失、不可用或不能返回符合契约的完整判定
- **THEN** 相关请求明确失败且不扩大权限
- **AND** 不回退为仅检查角色、无条件允许或从 UI 可见性推导授权

### Requirement: 基础实现切换由原资格检查且隔离授权缓存

能力切换 SHALL 由切换前仍有效的治理资格检查，租户管理员不能选择部署级授权实现；候选实现不得自行批准其安装、激活或使用范围。切换后的判定缓存及其他权限派生状态 MUST 与原代际隔离；当前成员与事实仍由原归属方维护。封存结果恢复依本模块及存储规范保留原证据，不运行新授权实现重判旧业务。

#### Scenario: 候选实现试图扩大维护者资格

- **GIVEN** 当前主体没有部署级基础实现维护资格
- **WHEN** 主体提交一个声称允许其切换授权实现的应用包或候选配置
- **THEN** 原资格检查拒绝，候选判定不参与批准自己的切换
- **AND** 原成员目录、授予和正式运行组合保持不变

#### Scenario: 替换后查询旧请求的接受结果

- **WHEN** 新实例恢复旧封存结果，或获权主体核对原请求答复
- **THEN** 恢复只应用原映像，实际读取答复仍执行当前权限
- **AND** 原业务是否接受不因新实现重新判定，旧允许缓存不恢复已撤销资格

### Requirement: 浏览器派生读取结果按当前作用域隔离

浏览器 SHALL 将从受保护记录派生的标题等展示结果限定于原宿主、租户、实际主体及当前读取范围。结果复用 MUST 遵守原读取的失效与授权变化；相同类型和记录 ID 不足以证明可复用。失败回退不得永久遮蔽后续合法读取，也不得以旧标题代替已拒绝的当前结果。

#### Scenario: 两个租户使用相同记录身份

- **GIVEN** 第一租户的成员已经查看某引用的标题
- **WHEN** 同一客户端切换到另一租户或主体并展示相同类型和 ID
- **THEN** 只从新作用域获得标题，未完成时显示原 ID
- **AND** 不展示第一身份缓存的名称，也不以缓存跳过新作用域读取。

#### Scenario: 撤权或引用内容更新

- **WHEN** 标题字段读取权被撤销，或原记录标题变更后重新读取
- **THEN** 当前展示遵守原读取的最新允许、遮蔽或失败结果
- **AND** 不继续把早先允许的名称当成当前获权结果。
