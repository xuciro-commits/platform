# experience/ui-system Specification

## Purpose

`experience/ui-system` 是共享 UI Kit 的能力规范：三层设计令牌（原始值 → 语义 → 组件）是唯一视觉权威，双密度与双主题作为一等令牌同时维护，业务应用换肤只开放品牌层（accent 与标识）。本模块规定组件质感的状态完备性（空态、加载、禁用、焦点、错误）与单一图标体系，使构建者与使用者在任何宿主界面中获得一致、可走查的视觉与交互基准。

## Requirements

### Requirement: 设计令牌是唯一视觉权威

共享 UI SHALL 通过三层令牌（原始值 → 语义 → 组件）提供全部颜色、间距、字号、圆角、阴影、动效时长与缓动；组件与应用界面 MUST NOT 硬编码视觉字面量。需要新的视觉表达时先扩展令牌层，不在组件内另写值。令牌的取值与命名在 `@platform/ui` 一处维护，任何包不得建立第二份令牌表。

#### Scenario: 组件需要新的状态色

- **WHEN** 开发者为某组件引入新的状态颜色
- **THEN** 该颜色先登记为语义令牌并在两主题下给出取值，组件只引用令牌
- **AND** 不在组件样式内出现未登记的字面量颜色。

### Requirement: 双密度作为一等令牌

令牌体系 SHALL 提供 compact 与 comfortable 两档密度，由同一语义令牌驱动；工坊与治理界面默认 compact，业务操作台默认 comfortable。共享组件 MUST 在两档密度下同时成立，不得为某一密度另写平行组件或复制样式分支。

#### Scenario: 同一表格在操作台与工坊呈现

- **GIVEN** 一个由 `@platform/ui` 提供的数据表组件
- **WHEN** 它分别运行在业务操作台（comfortable）与构建工坊（compact）
- **THEN** 行高、内边距与字号取自当前密度令牌，组件代码为同一份
- **AND** 切换密度不丢失功能、状态或键盘可达性。

### Requirement: 双主题一等公民

浅色与深色主题 SHALL 同时维护：每个语义令牌在两主题下都有明确取值；工作区默认跟随系统并允许手动切换。新增或修改的组件界面 MUST 在两主题下验收，不允许仅单主题可用的界面进入主干。

#### Scenario: 跟随系统切换主题

- **GIVEN** 成员未手动固定主题
- **WHEN** 操作系统在浅色与深色之间切换
- **THEN** 工作区界面随之切换且全部界面可读
- **AND** 手动固定主题后不再跟随系统，选择被记住。

### Requirement: 业务应用换肤只开放品牌层

已发布业务应用 MAY 通过发布定义声明品牌层：accent 主色与应用标识（logo / 图标）。品牌层只改写允许的品牌令牌；布局结构、组件形态、密度与非品牌令牌 MUST NOT 被应用定义改写。未声明品牌的应用使用平台默认外观。

#### Scenario: 应用声明品牌主色

- **WHEN** 构建者为已发布应用设置 accent 主色并发布
- **THEN** 该应用的操作界面以品牌主色呈现关键强调元素
- **AND** 页面结构、组件形态与其他令牌保持平台默认，无法注入自定义样式或脚本。

### Requirement: 组件质感状态完备

每个共享 UI 组件 SHALL 具备并验收空状态、加载态、禁用态、焦点态与错误态；过渡动效使用统一时长与缓动令牌；键盘焦点始终可见。超过一秒的加载 SHALL 呈现进度或占位反馈，不出现无响应静默；空列表 MUST 呈现说明与下一步动作，不呈现无解释的空白。图标使用单一图标体系，同一语义不在两套图标间重复。

#### Scenario: 列表加载与空态

- **WHEN** 用户打开一个正在加载且随后确认为空的记录列表
- **THEN** 加载期间显示占位反馈，确认后显示空状态说明与创建或导入入口
- **AND** 全程不出现无反馈空白或未定义样式的默认浏览器控件。

#### Scenario: 键盘焦点可见

- **WHEN** 用户仅用键盘在表单与按钮间移动
- **THEN** 焦点位置在两主题、两密度下均清晰可见
- **AND** 焦点环不遮挡文字、不触发布局跳动。
