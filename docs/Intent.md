# 产品意图与方向

面向 FDE 与客户构建者的 AI 业务应用平台。目标设计归 [Platform §10](Platform.md#10-未来方向)，近期顺序在 [WorkQueue](WorkQueue.md)，工作规则在 [AGENTS](../AGENTS.md)。

## 我们在构建什么

让团队构建、运行和持续演进业务应用：**接入数据与系统 → 语义建模 → 动作/流程/AI → 操作界面 → 测试发布 → 运营与变更**。底层契约、持久化和数学保证服务这条路径。成功由交付耗时、任务完成、资产复用和升级成本衡量，代码量、功能数、测试数不能代替这些结果。

平台开发者提供类型化底层能力；FDE 用代码、声明和可视化工具组装行业方案；客户构建者在授权范围内修改受控定义。三者共享语义、权限和发布。AI 使用相同 API 提议与执行变更，没有额外特权；业务人员获得清晰的任务、状态和恢复入口。

CRM、MES、ERP 是目标验证领域，PMS、HCM、CSM 为参考应用；Music 归 MSRU。至少两个行业证明平台复用，各自有连贯的操作任务。应用是验证载体，不定义平台真理；行业深度只增加到当前探针需要的程度。

## 研发取舍

- 已有底层能力优先形成可见、可操作的前端，贯通工作区、构建者工坊与业务操作台；后台只补当前任务的必要依赖。FDE 切换对象、关系、页面、流程、AI 与发布时保留上下文，不把一个画布当作全部前端。
- 每批交付一个可用结果，事先确定停止条件；通过适用检查后转向下一断点。可靠性加固针对当前交付实际触及的保证，不自动扩展至所有入口与极端故障。
- 优先复用规范主人：内核、宿主、应用 API、平台应用、`@platform/app` 或 UI Kit。共性缺口在主人处补齐，不由行业应用重复实现；非阻塞缺口按队列处理。
- 代码与可视化都是有效构建路径。可配置定义引用已注册的类型化能力；复杂算法通过受控编译、隔离执行与统一发布的 Go/TinyGo Wasm 制品参与装配，设计见 [ADR-0044](ADR/0044-capability-fabric.md)。复用现有 Flow/Work、决策与结果恢复，不在宿主直接运行任意租户脚本，不建立私有解释器。
- 组件和自动页面只是机制；完整构建、发布和操作任务才是产品进展。视觉、窄屏、中文、键盘与手感由截图检查和负责人实际操作判断，避免用大量样式断言代替体验。

## 不变量

- **单一语义与权威。** 应用独立自治，跨应用通过显式协议；不直接写另一应用的记录，不保留永久重复执行器。
- **受控演进。** 身份稳定、定义版本明确、依赖和权限可检查，客户扩展及在途工作按支持的升级规则保留。发布定义不授予额外执行权限。
- **持久结果与恢复。** 目标是状态、工作/外部效果意图原子入账，恢复应用保存的结果，不重新裁决或发外部请求。当前覆盖范围归 ADR-0038，不能把受限路径外推为全租户保证。开发日志可重建基线，真实客户数据受保护。
- **受治理 AI。** 模型、函数、智能体、工具、评测与运行共用权限、预算、动作规则和人工审批。模型结果在动作采纳前是证据或草稿；检索、引文、追踪遵循数据读取边界。
- **租户隔离。** 持久化/恢复失败有隔离与恢复入口；逻辑隔离和进程级隔离分别声明。
- **有界证明。** 选定内核不变量用 Lean 建模，并与规范/向量/实现测试对应，公开可信前提；不宣称证明整个系统。

## 技术与参考

Go 为主要后端，TypeScript/React 与共享 UI 为 Web，Rust 用于明确有系统优势的组件，Tauri 为桌面方案；内核契约语言中立，Lean 只在研发工具链。

产品形态与功能切分对标 Palantir Foundry/AIP（Ontology、Workshop、Automate、AIP Logic、Control Panel 等），现行结构归 [ADR-0052](ADR/0052-foundry-aligned-platform-experience.md)；其他产品（Retool、ServiceNow、SAP、Power Platform 等）只作为局部技法参考，采纳边界在 Platform §10.1。不复制任何一家的数据模型或软件栈。
