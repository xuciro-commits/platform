# 产品意图

## 我们构建什么

为 FDE 与客户构建者做一套**业务应用构建平台**：接入数据与系统 → 语义建模 → 动作/流程/AI → 操作界面 → 测试发布 → 运营与变更。底层契约、持久化和数学保证服务这条路径。

**交付给客户的是构建这类业务系统的能力，不是这些系统本身。** 客户不必为每个行业重新开发一套底层业务系统。

成功由交付耗时、任务完成、资产复用和升级成本衡量。代码量、功能数、测试数不能代替这些结果。

## 为谁

| 角色 | 做什么 | 边界 |
|---|---|---|
| 平台开发者 | 提供类型化的底层能力 | 不预先写好客户的应用 |
| FDE | 用代码、声明和可视化工具组装行业方案 | 应用包是交付物 |
| 客户构建者 | 在授权范围内修改受控定义 | 不获得额外执行权限 |
| 业务使用者 | 完成任务、看到状态、在失败时恢复 | 不需要理解平台 |
| AI | 用与应用相同的 API 提议与执行变更 | 没有额外特权 |

**一个 FDE 像一名律师**：各有所精，各需自己的武器库。武器库装的是判断（这类设备怎么编、异常怎么分级、哪些指标真的有用），不是组件；判断必须有载体，否则每次交付都从头再来。

## 武器库的四层

| 层 | 内容 | 谁写 | 客户可见 |
|---|---|---|---|
| 平台包 | 内核、宿主、构建器、事务/规则/约束/集成/AI 的原语 | 平台开发 | 否 |
| 能力包 | 面向一种**技术**的扩展：数字孪生、3D 库位、GIS、时序、设备对接 | 平台开发 | 否 |
| 行业包 | 某个**行业**的特殊性：对象骨架、规则模板、页面装配、样本、验收场景 | 平台开发，可带 FDE | 否 |
| 应用包 | 某个客户的应用 | FDE | 是 |

**交付完成 = 系统上线 + 一件可复用的行业资产 + 本次构建发现的通用缺口清单。**

## 最终要实现什么

平台并不固化组织或应用当下的形态。它提供应用走向**下一形态**所需的能力——新产品、新流程、新结构、新运营模型，乃至不同的主营业务——而无需重写底座。业务领域注定变化；只有发现真正的跨领域通用缺口时，内核才变。

完整生命周期是目标：构建者定义、发布、运行、观测、修改、升级，数据、历史、权限与在途工作保持连续。

## 验证

- **第一次：楼宇供暖管理系统。** 真实客户，多栋楼分布在不同城市。执行者是负责人本人，此前做 MES/ERP，楼宇供暖是他不熟的领域——验证的是**域中立**。
- **MES 是第二探针。** 负责人熟悉的领域；在那里测出来的是经验在起作用，不是平台在起作用。
- **第二次交付**（候选：MES + WMS、立库 RCS / AGV WCS）：可能是别人的领域，验证的是**武器库可移交**。不发生就如实记为未验证。

CRM、MES、ERP、PMS、HCM、CSM 是参考应用，是临时验证载体：不定义平台真理，在等价构建产物存在后退出。

## 明确的取舍

- 已有能力优先形成可见、可操作的前端，贯通工作区、构建者工坊与业务操作台；后台只补当前任务的必要依赖。
- 每批交付一个可用结果，事先定停止条件；可靠性加固针对当前交付实际触及的保证，不自动扩展至所有入口与极端故障。
- 代码与可视化都是有效构建路径；复杂算法走受控编译、隔离执行与统一发布。
- 组件和自动页面只是机制；完整构建、发布和操作任务才是产品进展。
- 视觉、窄屏、中文、键盘与手感由截图和负责人实际操作判断。

## 不做什么

- 不做预置的 ERP/MES 成品，不复制任何一家的数据模型或软件栈。
- 不做零代码宗教：真正需要代码的行业算法是合法构建手段。
- 不做插件市场、行业交易/排产、第二数据库；这些不是当前施工范围。
- 不用测试数量、代码行数或功能清单代替真实使用。

## 技术与产品参考

Go 是主要后端，TypeScript/React 与共享 UI 构成 Web；Rust 用于有明确系统收益的组件，Lean 只在研发验证中使用。内核契约保持语言中立。

产品组织参考 Foundry/AIP 的 Ontology、Workshop、Automate、AI 与治理工作区；其他产品用于具体做法的比较。采纳必须结合本平台任务和实际代码，不复制其数据模型、权限或执行体系。
