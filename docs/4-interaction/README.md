# 4 交互设计

## 目标

整个产品只有一套交互：一个外壳、四种页面、一个视图模型、一个记录形状、一个保存模型。组件全部来自 Astryx（`@astryxdesign/core`），页面从它的官方模板起步；外壳以 ERPNext 的应用轨加应用菜单为基准，列表、记录与录入以 Frappe CRM 为基准。用户学会一个列表和一条记录，就会用全部工具与全部业务应用。本目录三份文件：

- 本文：不变式、外壳、页面原型、记录页分区、编辑与保存、选择、窗口与覆盖层、键盘、密度、动效、登录页。
- [patterns.md](patterns.md)：每个交互模式的规格。
- [workbenches.md](workbenches.md)：每个工具应用的工作台布局。

视觉令牌与组件用法见技能 `platform-design`。

## 4.1 不变式

以下十三条是人机界面的不变式。任何界面不得违反；要改变其中一条，先改本文。

- R1 一个外壳，两级导航。最外侧是应用轨，列出成员可打开的全部应用；其右是当前应用的侧栏，列出该应用的全部入口。没有顶部菜单栏，没有第三级导航栏。侧栏只属于应用：打开记录不改变侧栏（导航位置变了，用户就要重新找路）。
- R2 四种页面。每个页面是列表、记录、画布或仪表盘之一（4.3）；不属于这四种的界面不建，先改本文。
- R3 列表即视图。每个列表都是一个视图：筛选、排序、列、分组与呈现方式（表格、分组、看板）。任何调整立即生效并保存为该成员的默认视图，不需要按保存；视图可命名、置顶到侧栏、公开。
- R4 记录一个形状。资源与对象用同一种记录页：页头、页签、右侧字段栏（4.3 B）。不为某类记录另造详情布局。
- R5 输入即保存。没有编辑模式，没有“保存”按钮：对象字段在失焦或回车时提交；资源定义的输入自动写入工作状态（4.5）。成功不打断，失败显示在出错的字段上并保留输入。
- R6 新建只经快速录入。新建是一个只含必填与关键字段（至多 7 个）的对话框；创建后进入记录页继续就地完善。不做向导，不做整页新建表单。
- R7 一个区域一个主动作。主动作是该区域最可能的下一步；其余操作次级或进入 ⋯ 菜单。
- R8 ⌘K 到达一切。任何应用、视图、记录与当前可执行的动作都能从命令面板到达；每个操作都能只用键盘完成，高频操作的快捷键显示在菜单与工具提示里。
- R9 选择出现批量条。列表多选后浮现批量操作条，只列对全部选中项都可执行的动作；取消选择即消失。
- R10 四种状态齐全。每个读取数据的区域都有空、加载、错误、拒绝四种状态：空状态说明如何产生第一条数据，加载用骨架，拒绝显示服务端原因与下一步；禁用的控件说明原因。
- R11 能撤销的不确认，不能撤销的必须确认。编辑可撤销；删除、归档、发布、安装、发送需确认并写明后果。结果用 Toast，可撤销时带“撤销”。
- R12 状态在地址里。应用、视图、筛选、记录与当前页签都能从 URL 还原；后退回到上一个界面状态，分享链接看到同一个界面。选中项与未提交的输入不进地址。
- R13 只用 Astryx，从官方模板起步。每个页面先落地对应的 Astryx 官方模板，保留它的框架、间距与交互，只替换内容与数据；不从空白写页面（模板已经处理好筛选、分组、拖动、键盘、窄屏与无障碍，重写一遍就要重新犯一遍错）。界面不写裸 HTML 控件，不硬编码颜色、尺寸、间距、圆角或阴影；平台自有的界面组件只有外壳、页面原型及其组成部分。主题只有一个，由负责人选定（两套组件并存时，每个界面都要选一次）。

不显示原始 JSON：常规流程用结构化编辑器，JSON 只在“高级”折叠中出现。

## 4.2 外壳

```
┌──┬──────────────┬────────────────────────────────────────────┐
│应│ 应用侧栏       │ 主视图                                      │
│用│ 可收为图标     │ 页头 / 内容                                  │
│轨│              │                                            │
└──┴──────────────┴────────────────────────────────────────────┘
```

- 构造：Astryx `AppShell`；应用轨与应用侧栏一起放进它的 `sideNav` 槽，应用侧栏是 `SideNav`。宽度、收起与窄屏行为取组件默认，不另定像素。
- 应用轨自上而下：搜索（⌘K）→ 通知 → 分隔 → 应用图标（平台应用在前，已安装的业务应用在后），悬停显示名称 → 底部成员菜单（租户、语言、外观、账户）。成员无权打开的应用不显示。
- 应用侧栏自上而下：应用切换器（显示当前应用名，下拉可切到任一应用）→ 该应用的菜单 → 置顶视图 → 状态脚注（分支、发布、离线）。
- 应用菜单：带标题的分节，每项是一个列表、仪表盘或画布入口，可有一层可展开的子项；一级项至多 12 个，超过就归入子项或另立应用。
- 一个应用是一个功能块：它的菜单合起来是完成一类工作所需的全部入口；一个入口只属于一个应用（同一入口出现在两处，用户就不知道哪个是真的）。
- 工具应用的分支控件在状态脚注上方，显示当前分支与“Changes (N)”。
- 主视图只有一个滚动容器；页头吸顶。
- 宽度小于 768px：应用轨与应用侧栏并入抽屉（`MobileNav`），记录页的字段栏并入页签，表格保留首列与状态列、其余列进入行展开。

## 4.3 页面原型

只用以下四种；新页面必须声明它是哪一种。每种以对应的 Astryx 模板为起点（`astryx template <id>`）。

### A 列表

- 模板：`table-grouped`（框架、筛选与分组）、`table-filter`（条件筛选、保存的视图、批量条）、`kanban-board`（看板）；层级数据用 `table-tree`，左列表右详情的收件箱（通知、待办、审批）用 `table-inbox`。快速录入（R6）用 `form-wizard-dialog` 的对话框。
- 页头：左侧为视图切换器（当前视图名与图标；下拉列出默认视图、成员的命名视图、公开视图与“新建视图”），右侧为唯一主动作“新建…”。
- 视图栏：左侧为快速筛选（该类型声明的至多 4 个字段）；右侧依次为刷新、筛选、排序、列、分组、⋯（导出、导入、另存为视图）。筛选用 `PowerSearch`，条件即 Expr。
- 呈现方式：表格（`Table`，默认）、分组（按一个字段折叠成段）、看板（按一个枚举或状态字段分列，拖动卡片即执行改变该字段的动作）。呈现方式是视图的一部分。
- 首列：类型图标 + 显示名；行单击打开记录；行内不放编辑控件。跨项目的资源列表必有“项目”列与“更新时间”列。
- 多选后出现批量操作条（R9）。空列表用 `EmptyState` 说明这类记录是什么，主按钮“新建…”。

### B 记录

- 模板：`work-item-detail`、`detail-page`。资源与对象共用。
- 页头：面包屑回到来源视图（保留其筛选与滚动位置）、图标、显示名、状态、指派与关注者、保存状态、唯一主动作、⋯。主动作是这条记录最可能的下一步：对象是其类型声明的首要动作，资源是“Review and save”。
- 主区：页签（`TabList`）。顺序固定：定义分区（4.4）→ Usage → Activity。Activity 是一条时间线，合并评论、字段变更、版本、运行与审计。
- 字段栏（右侧，可收起）：分节的摘要字段（`MetadataList`），就地编辑（R5）；节与字段由类型元数据生成。身份信息（RID、API 名）在最后一节，等宽弱化。
- 对象记录的页签与字段栏可被一个绑定到该对象类型的 Workshop 对象视图模块替换；每个打开实例拥有独立的模块状态。
- 动作只显示调用者可执行的；不可执行但可见的动作禁用并说明原因。

### C 画布

- 模板：`ide`、`canvas-editor`。用于 Workshop、Pipeline Builder、逻辑流、Data Lineage、动作规则的图形视图。
- 构造：左面板（结构树、组件库、变量）→ 中画布（浮动 `Toolbar`、缩放、迷你地图）→ 右 Inspector（选中项配置）→ 底部 dock（问题、实时值、预览数据、运行记录）。面板之间用 `Resizable`，可拖拽、可键盘调节，按工作台记忆。
- 画布是记录页的一个全幅页签：页头与记录页相同，进入画布页签时字段栏收起。
- 可用宽度不足时一次显示一个区域，首次打开显示画布；选择具体内容或主动打开才进入面板，面板内提供“返回画布”。
- 编辑 / 预览切换在页头；预览时隐藏左面板与 Inspector。
- 画布内容本身用专用库（图、图表、代码编辑、三维），不属于 R13 的组件范围；其工具条、面板与表单仍属于。

### D 仪表盘

- 模板：`dashboard`、`dashboard-progress`、`dashboard-scorecard`；运行中的故障总览用 `incident-console`。用于 Home、项目首页、Monitoring、Control Panel 首页。
- 构造：全局筛选栏 → 统计块一行（可点击进入对应视图）→ 图表与紧凑行列表，带“查看全部”。
- 仪表盘不放编辑；只放导航与就地下一步。

设置不是页面：应用与工作区设置用对话框（模板 `settings-dialog`），左侧分节，右侧表单，输入即保存。

## 4.5 编辑与保存模型

- 对象字段：字段栏与表格看板中的就地编辑，在失焦或回车时作为该对象类型的编辑动作提交；没有工作状态。被拒绝时原因显示在该字段上，输入保留。
- 工作状态：每位构建者在当前分支上有一个工作状态。编辑先进入工作状态，不直接生效。
- 自动保存：输入停止 900ms 后把编辑与原始输入写入当前成员在该分支的私有工作状态；记录页头显示状态：`Saving…`、`Working state saved`、`Saved as draft`、`Saved to branch`、`Unsaved changes`、`Not saved`、`Fix the problems to save`。
- 被拒绝的保存停止自动保存，显示原因与手动“保存”按钮；修正后恢复自动保存。
- 校验：字段级问题就地显示；资源级问题进入 Problems 列表（画布在 dock，记录页在页头下方的 Banner）；有错误时仍可保存草稿，但不能进入审阅。
- 审阅并保存：分支控件显示“Changes (N)”与主按钮“Review and save”。审阅界面列出全部变更资源与字段级差异，可逐项放弃；main 上保存即生效（先经保存审阅中的自动检查），分支上保存生成或更新提案。
- 没有单个编辑器的“发布”按钮；打包与安装只在 DevOps 与 Marketplace。
- 放弃：⋯ 菜单“放弃更改”恢复到上次保存；确认对话框列出将丢失的字段数。
- 离开保护：切换视图、应用、租户、语言与“Review and save”先立即写入等待自动保存的编辑；仍有未写入的编辑（保存被拒绝或有问题）时才弹出“Unsaved changes”，列出面板，提供“继续编辑”“放弃更改”。正在进行的提交或查询不锁住工作区；离开不取消已受理工作，结果仍由该面板的工作状态与请求回执恢复。
- 并发：两人编辑同一资源时，后保存者看到“Someone else saved this first”，按字段列出对方与自己的值，并说明是谁、何时保存；“Keep mine”以对方的修订重提自己的更改，“Keep theirs”放弃自己的更改并载入对方的版本；选择之前不覆盖任何内容。分支上的并发由从 main 更新处理（6-domain/change §6.20）。

## 4.6 选择

- 列表：行单击打开记录；复选框、Ctrl/⌘ 单击多选，Shift 单击范围选；↑↓ 移动，Enter 打开，空格勾选。
- 画布：单击选中，Inspector 显示选中项配置，标题为名称与类型，底部为该项的危险操作；多选时显示共同属性并批量修改。
- 选中状态不写入 URL；切换页签或视图清除选择。

## 4.7 窗口模式

| 模式 | 用于 | 行为 |
|---|---|---|
| 主视图 | 打开视图、记录 | 替换主视图，经离开保护；后退返回 |
| 悬停预览 | 看一眼被引用的记录而不离开 | `HoverCard` 显示标题、状态与摘要字段；单击进入主视图 |
| 新标签 | 并排对照 | ⌘ 单击或 ⋯ 菜单在新浏览器标签打开规范 URL |
| 选取 | 选一个数据集、对象类型、成员 | 字段内 `Typeahead`；需要浏览时打开选取对话框，返回值交回调用方，调用方状态保持 |

没有侧窗：记录只在主视图打开（同一条记录两种打开方式，就有两套布局要维护）。

## 4.8 覆盖层选择

| 需要 | 用 | 不用 |
|---|---|---|
| 新建记录（R6）、设置、选取 | `Dialog` | 整页表单 |
| 确认不可逆操作 | `AlertDialog`，写明后果，危险按钮写出动词 | 无说明的“确定” |
| 单字段就地修改、筛选、排序、列 | 行内编辑或 `Popover` | Dialog |
| 少于 8 项的操作列表 | `DropdownMenu`、`MoreMenu`、右键 `ContextMenu` | Dialog |
| 操作结果反馈 | `Toast`（可撤销时带“撤销”） | Dialog |
| 持续的警告、错误、就地下一步 | `Banner`（就地） | Toast |
| 帮助说明 | `InfoTip` | 页面内大段文字 |

覆盖层不叠覆盖层（选取对话框除外）；对话框中需要确认时，确认在对话框内以 `Banner` 加按钮完成。`Drawer` 与 `BottomSheet` 只用于窄屏下的侧栏与字段栏。

| 快捷键 | 作用 | 范围 |

| ⌘K | 命令面板与搜索 | 全局 |

| ⌘S | 立即保存到工作状态 | 资源记录 |
| ⌘⇧S | 打开审阅并保存 | 工具应用 |
| ⌘Z / ⇧⌘Z | 撤销 / 重做 | 画布、资源记录 |
| ⌘C / ⌘V / ⌘D | 复制 / 粘贴 / 复制一份 | 画布、表格 |
| Delete | 删除选中 | 画布、表格（经 R11） |

| ⌥⌘\ / ⌘J | 右 Inspector 或字段栏 / 底部 dock | 记录、画布 |

焦点规则：打开覆盖层时焦点进入第一个可编辑字段；关闭后回到触发元素；快速录入创建成功后焦点进入新记录的第一个空字段。

## 4.10 密度与适配

- 尺寸、间距与字号只取主题令牌；密度由应用类别经 Astryx 的尺寸上下文统一设定（工具应用紧凑，业务应用舒适），不由页面自选。
- 业务应用的列表、记录与快速录入在手机宽度下必须可完成任务，点击目标不小于 44px；工具应用的画布不承诺手机可用，但不得报错。

## 4.11 动效

只用于说明空间关系，时长与缓动取主题的动效令牌；不做装饰性动画；遵循“减少动态效果”系统设置。

## 4.12 登录页

未登录时工作区不直接跳转身份服务，先渲染平台登录页：宽屏（≥1024px）左栏为产品说明（标题、四张能力卡、产品示意），右栏为登录卡；窄屏登录卡排在最前，产品示意隐藏，页脚换行。

- “使用 SSO 继续登录”走授权码流程，覆盖 MFA 与通行密钥；已填邮箱作为 `login_hint` 预填身份服务页面。
- 邮箱加密码的登录走身份服务的直接登录流程：凭据由浏览器直接送到身份服务换取令牌，不经过平台后端。启用 MFA 或通行密钥的账号用 SSO，页面就地说明原因。
- “申请访问”说明席位由工作区管理员授予，不提供自助注册。
- 登录页以 Astryx `login-split` 模板为底，是产品中唯一的营销式页面；其余界面按 4.1。触控目标不小于 40px。页面铺满视口：主区垂直居中、页脚贴底，页脚下方不留空白。

## 现存差距

- 交互层整体：新前端在 `frontend/` 从零建立，现有外壳（应用轨、应用侧栏、切换器、地址路由）、列表原型的第一段，以及原样落地、带示例数据的官方筛选表格与看板模板（主页应用的“官方模板样张”）；其余不变式尚无实现。
- 交互层 §4.3 A：列表原型现在只有标题、文本筛选、按字段分组与空、加载、拒绝、出错四态；视图切换器、快速筛选与条件筛选、排序、列、看板、批量条、主动作“新建…”、行打开记录、类型图标首列都还没有，分组与筛选也不进 URL（R3、R6、R9、R12）。
- 交互层 §4.12：新前端的登录页是 `login-card` 模板上的开发身份选择，只在宿主提供开发身份时可用；OIDC、邮箱加密码与 `login-split` 版式尚未接入。
- 交互层 §4.2：窄屏下应用轨没有并入抽屉，会压在顶栏与内容上；⌘K、通知、成员菜单、置顶视图与状态脚注尚未实现。`web/` 的全部界面仍按上一套语言（自有组件库、Radix、Tailwind），只修缺陷，不再演进。顺序见[路线图](../roadmap.md)“五、前端重建”。
- 交互层 patterns.md、workbenches.md：仍按上一套语言书写（全局工具导航轨、资源分区接管侧栏、Inspector 检查、侧窗、Sheet）；与本文冲突处以本文为准，随各工作台重建逐节改写。
- 信息架构与体验层：[3-information](../3-information.md) 的导航轨、应用门户与 [5-experience](../5-experience.md) 任务路径的步骤仍描述上一套外壳与产品名。
- 产品层（R3）：命名视图、公开视图与置顶没有资源归属；现在只有浏览器本地的列宽记忆。归属先在 [2-product](../2-product.md) 确定。
