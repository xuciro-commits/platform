# 长期规划

这份文档回答：现在在哪，往哪走，下一步做什么，什么先不碰。
产品阶段的进度写在这里；当前阶段每一行的细目在 [roadmap](roadmap.md)。

## 规划的规则

- 产品路线一次只做一个阶段。前一个阶段的门槛没过，不开下一个。
- 门槛是一次演示：AI 扮演负责人或客户，按门槛剧本在浏览器里十分钟内走完，留下录屏、日志与结论。走不完就是没过，不看代码行数与检查数。
- 研发阶段不设人工门禁（负责人 11-26 定）：定客户、真实使用、负责人亲自演示，都由 AI 模拟的客户、陌生人与第三方代替。
  仍要人的只有法律意见、真实付费与对外发布。
- 批次的每一行是一个看得见的结果，不是一项技术工作。宿主缺什么，在用到它的那一行里补。
- 一次做一项。做完即提交、推送 main，用几句话向负责人报告并给出能点开的地址；做完的行从表里删掉。
- 每一行先有能跑的验收再动手。界面的行，是主干用例里新增的一步（定点执行）；工程验收遵循[三档验收](README.md#三档验收)，不代替阶段演示。
- 行在这里不拆子行；当前阶段的细目写在 roadmap，做完一项删一项。
- 后面的阶段只写门槛，到了再拆批次。本文不超过 150 行。

## 现在在哪（2026-11）

- 宿主：约 15 万行 Go，内核与十二组服务都在运行，有十三组内核不变量守着。它已经有主干要的多数能力：
  明细行、引用、状态流转、评论、关注、附件、任务都有对应的字段类型或动作。
- 新前端 `frontend/`：约 7600 行。四种页面里的列表与记录页、构建者的类型定义与发布、市场安装、收件箱与命令面板都由类型生成；
  成员菜单能切租户、语言与外观，设置对话框改个人资料与通知；登录页支持工作账号与单点登录。
- 没有客户在用。此前的力气花在三条并行的线上：搬 Go 包、给旧前端换组件、重建新前端，前两条不产生看得见的东西。

所以顺序倒过来：先做用户看得见的主干，结构只在主干被它挡住时才动。

阶段 2 的门槛 11-25 已过：空租户装 CRM，线索到赢单，期间没有改宿主。它剩下的两行只收口，细目留在 roadmap。
阶段 3 让一个 CRM 租户每天在用：数据落在 PostgreSQL 上不丢，客户在自己的项目里加字段与动作，官方升级后扩展还在。

- 客户由 AI 模拟：一家虚构的 B2B 公司，人设、团队、数据与每日剧本在 `idea/sim-customer/`，租户名 `sim`。

- 宿主与前端仍不写 CRM 特化代码；客户要的东西先问是不是平台特性，是就做成所有类型都得到。
- 不在本阶段：自助注册、计费与配额（阶段 4）；邮件收发与外部同步（阶段 5）；开放应用接入的第二波（库存、购销、会计、制造与质量）按客户需求接。

## SaaS 产品矩阵

| 产品面 | 用户来这里做什么 | 随租户变化的内容 |
|---|---|---|
| 行业应用 | 采购、生产、交付等每日工作 | 订购并安装的应用根、业务视图和客户扩展 |
| 工作台能力 | 在原记录上审批、流转、查状态，或从收件箱继续任务 | 包贡献的动作、视图、连接与自动化；能力可以没有独立应用入口 |
| 构建与交付 | 建对象与流程，预览差异，发布、安装、审阅升级 | 项目、产品版本、依赖、客户扩展和发布权限 |
| 租户与宿主管理 | 开通、邀请、订阅、连接授权、用量与配额、支持与审计 | 租户管理员管理本工作区，宿主运营管理租户；服务端决定商业权益和成员授权 |

产品包是唯一交付物，按贡献分四层：组织（平台内）、主数据、能力、应用；包由此推导为应用、主数据、能力、扩展四种（[architecture](architecture.md)“扩展”）。
安装状态、外部连接、商业权益、成员授权分别呈现。付款或安装本身不授予数据读取和动作权限。

## 之后的阶段

到了再拆批次，这里只记门槛之外必须带上的事。

- 平台的重型块到用它的阶段再做，每个仍是 `src/pages/` 里的一个表现：
  - 阶段 3（客户自己扩展、升级）：`ConditionBuilder` 与 `ExpressionEditor` 写 `when`、`default` 与规则，引一个代码编辑器；
    `RelationCanvas` 画类型之间的关系；`RecordComparison` 做结构化对比，先给升级审阅用，再给报价对比。
  - 打印在第一个客户提出时排进阶段 3：`PrintPreview` 与 `Barcode` 是平台特性，单据模板是定义资源；服务端渲染 PDF 是能力，随 B4 做。
  - 阶段 5：`FlowCanvas` 画流程、管道、血缘与智能体的节点图（`@xyflow/react`，`elkjs` 排布）；AI 批量提案的审阅复用 `RecordComparison`。
  - 第一个要排程的包（项目管理、MES 或 APS）出现时，列表加第四种布局 `RecordGantt`。
- 阶段 4：租户自助开通、计量与配额、宿主控制台、运营观测、容量证据、安全评审。
  - 导入 1 万行端到端 ≤ 20 秒，应用吞吐 ≥ 2,000 行/秒。用 80、800 行/秒作前两档验收线，核对导入成本随存量增长的变化。
  - 5000 人在线且有导入时，交互写入 P95/P99 ≤ 30/80 ms，单条读取 P50/P95 ≤ 12/25 ms，列表 P50/P99 ≤ 10/40 ms。
    列表 P99 ≤ P95 的 2.5 倍。全员收到 SSE 更新，推送 P95 ≤ 100 ms，连接存续时堆占用 ≤ 200 MB。
    前两档单条读取 P50/P95 分别为 15/35、12/30 ms，第一档单条 P50 ≤ 列表 P50 的 1.5 倍。列表 P50/P99 分别为 12/150、10/50 ms。
    前两档 SSE 推送 P95 分别为 150、120 ms，连接存续时堆占用分别为 250、200 MB。
  - 同租户按 1、4、16、64 并发各饱和写入 30 秒，记录吞吐、P50/P95/P99、重试和回退比例及错误率。
    先核对单次写入 P50 ≤ 15 ms。16 并发达到 300 次/秒且 P95 ≤ 150 ms，单租户交互写入达到 500 次/秒。车道持有超过 10 ms 告警。
  - 5000 名成员下串行新增成员达到 100 次/秒，其写入字节数与成员规模无关。记录控制台状态距 4 MiB 上限的余量，规范摘要占 CPU ≤ 2%。
    新增成员先过 15、50 次/秒两档，摘要 CPU 占比先过 5%。10 万条日志下重启恢复 ≤ 3 秒，只重放最近快照之后的日志。
  - 预热后同环境跑三轮取中位数。P95 极差超过 25% 时排查后重测。延迟和吞吐轮次关闭 pprof，另测峰值 RSS 和强制 GC 后堆占用，断开后堆占用回到基线的 120% 以内。
  - 防退化验收比较 1,000 行与 100,000 行，成员场景比较 1,000 与 10,000 人。单条读、列表、单次写、导入每行和新增成员的耗时及每次操作分配次数之比 ≤ 1.5。
    核对 1,000 万行以内单次写入成本的趋势。用相关不变量守住详情目标行只读一次、读取时零原始映像摘要、常规读取零租户分叉、每批接受结果只算一次批次摘要。
    用微基准核对摘要、详情、来源声明分叉和行应用。摘要或编解码优化用既有日志语料逐字节对照，格式变更遵循 [architecture](architecture.md) 的版本与纪元规则。
- 阶段 5：重建连接、同步、管道、数据集、血缘、智能体工作室与全局助手，Frappe 应用转换成体系。
  用已有 `/mcp` 选 ChatGPT、Claude 或 DeepSeek Harness 中一个支持的客户端走通授权读取、提议和确认。
  先交付结构化结果与工作台链接，需要原位交互时验证 MCP Apps。Magpie 的模型供应侧接网关，调用平台业务能力时按 MCP 客户端核对。
- 阶段 6：对外发布、上架审核与分成；按客户端实际支持的技能、工具和界面分发，目录只指向不可变产品版本。

## 冻结

冻结的意思是：保持能跑，由它已有的测试守着，坏了要修；不加功能，不重构，不为它写文档。
它的事实是代码与测试；解冻时再把它的规则写进文档。

| 冻结的东西 | 位置 | 何时解冻 |
|---|---|---|
| 没有功能依赖的 Go 包搬迁与改名 | `capabilities/server` | 某个功能被结构挡住时，只动挡路的那一块 |
| 数据接入、管道、数据集、血缘 | `services/data` | 阶段 5 |
| 页面搭建（Workshop）与对象视图 | `services/apps` | 阶段 2 里出现类型生成的界面表达不了的页面时 |
| 智能体、助手、检索与评估的新功能 | `services/ai` | 阶段 5 |
| 运营观测、容量剖面 | `services/resources/monitoring` | 阶段 4 |
| 把内置应用改成系统产品包 | `services/work` 等 | 阶段 2 之后 |

## 条件触发

- 第一个客户租户装载之前冻结格式纪元：此后任何格式变化只经版本化迁移。
- 彻底清除、输出保留、制品回收、自动升级、维护窗口、多安装实例：等真实需求出现再做。默认保留数据、手动升级。
