# 长期规划

这份文档回答：现在在哪，往哪走，下一步做什么，什么先不碰。
项目的进度只写在这里，别的文档不写进度。

## 规划的规则

- 产品路线一次只做一个阶段。前一个阶段的门槛没过，不开下一个；已授权的 U 系列后端收尾与阶段 1 并行。
- 门槛是一次演示：负责人在浏览器里十分钟内能走完。走不完就是没过，不看代码行数与检查数。
- 批次的每一行是一个看得见的结果，不是一项技术工作。宿主缺什么，在用到它的那一行里补。
- 一次做一行。做完即提交、推送，用几句话向负责人报告并给出能点开的地址；做完的行从表里删掉。
- 每一行先有能跑的验收再动手。界面的行，是主干用例（`make trunk`）里新增的一步。
- 行不拆子行。一行太大就换成两行；细节写在提交说明里，不写在这里。
- 后面的阶段只写门槛，到了再拆批次。本文不超过 150 行。

## 现在在哪（2026-11）

- 宿主：约 15 万行 Go，内核与十二组服务都在运行，有十三组内核不变量守着。它已经有主干要的多数能力：
  明细行、引用、状态流转、评论、关注、附件、任务都有对应的字段类型或动作。
- 新前端 `frontend/`：约 2300 行。外壳、登录、由类型生成的列表（条件筛选、排序、分组、看板、勾选批量）、
  记录页就地编辑、新建。业务类型一经发布就出现在“对象”里。
- 旧前端 `web/`：约 7 万行，功能最全，但每个页面都是手写的。
- 没有客户在用。此前的力气花在三条并行的线上：搬 Go 包、给旧前端换组件、重建新前端，前两条不产生看得见的东西。

所以顺序倒过来：先做用户看得见的主干，结构只在主干被它挡住时才动。

## 路线

| 阶段 | 做成什么 | 门槛：负责人能走完的演示 |
|---|---|---|
| 1 类型即应用 | 在新前端里，声明一个类型就得到一个完整的应用；构建者自己的工具也由同一套界面生成 | 建类型 → 发布 → 录入 → 流转 → 换一个角色只看到该看的 |
| 2 第一个行业包 | 旗舰包只用平台工具搭成，装进空租户就能办完一条业务主线 | 空租户安装 → 走完主线 → 期间没有改宿主 |
| 3 第一个客户 | 一个真实租户每天在用 | 用满两周；升级一次，客户自己的扩展还在 |
| 4 SaaS 运营 | 陌生人自己注册、开通、安装、邀请同事 | 全程没有我们介入；备份恢复与容量有演练记录 |
| 5 数据与智能 | 接外部系统的数据；智能体搭应用 | 一张外部表变成对象；让智能体搭出一个能用的类型 |
| 6 生态 | 别人在平台上做包、卖包 | 第三方的包上架并被别的租户安装 |

## 阶段 1 的批次：类型即应用

对照物是 Frappe 的工作台，清单见 [ux](ux.md)“类型开箱清单”。每一行都做在界面运行时里，所有类型同时得到（[frontend](frontend.md)）。
按顺序做；地址是 `http://localhost:8496`。

| 行 | 做完你能看到 | 宿主 |
|---|---|---|
| 1.2 明细行 | 记录页与新建对话框里能增删改明细行（表中表） | 字段类型已有 |
| 1.3 用通用页面定义类型 | 对象类型的字段、状态就在它的记录页上编辑，不再有专门的类型编辑器 | 核对编辑动作的参数；类型记录给出“有未发布的改动” |
| 1.4 引用 | 字段能选另一类对象（输入即搜）；记录页上点过去；被引用方列出引用它的记录 | 字段类型已有；补检索 |
| 1.5 状态与动作 | 状态转换之外的动作也在记录页上（“⋯”菜单）；不能做的动作说明原因，不藏起来 | 动作已有；补“为何不能做” |
| 1.6 活动 | 记录页有评论、关注、指派与时间线 | 动作已有 |
| 1.7 附件 | 记录上能传文件、看文件 | 动作已有 |
| 1.8 列表补全 | 保存的视图、列的取舍；筛选、排序、分组、布局进地址；批量动作先确认；大数据量不卡 | 补分页、筛选、排序 |
| 1.9 应用来自宿主 | 应用轨与菜单取自宿主；装上的产品包自己成为一个应用，菜单是它的类型 | 应用注册换成新名字 |
| 1.10 搜索与通知 | ⌘K 能找到记录、类型与入口；通知与待办在收件箱里 | 检索与通知已有 |
| 1.11 登录与权限 | 正式登录；没权限的入口不出现，被拒绝的操作给出原因；能切换语言 | 授权已有 |

## 之后的阶段

到了再拆批次，这里只记门槛之外必须带上的事。

- 阶段 2：编号规则、默认值、取自引用的值、打印与导出、统计与仪表盘、数据导入。
  旗舰包的资源由我们用智能体经平台动作产出，这本身就是“AI 是一等构建者”的检验。阶段结束时删除 `web/`。
- 阶段 3：验收跑在 PostgreSQL 上；“安装 v1 → 客户扩展 → 升级 v2”的演练；备份恢复只应用已接受映像；装载客户之前冻结格式纪元。
- 阶段 4：租户自助开通、计量与配额、宿主控制台、运营观测、容量证据、安全评审。
- 阶段 5：连接、同步、管道、数据集与血缘的界面在新前端重建；智能体工作室与全局助手；Frappe 应用转换成体系。
- 阶段 6：包作者的文档与工具、上架审核、分成。

## 冻结

冻结的意思是：保持能跑，由它已有的测试守着，坏了要修；不加功能，不重构，不为它写文档。
它的事实是代码与测试；解冻时再把它的规则写进文档。

| 冻结的东西 | 位置 | 何时解冻 |
|---|---|---|
| U 系列以外的 Go 包搬迁与改名 | `capabilities/server` | 某个功能被结构挡住时，只动挡路的那一块 |
| 旧前端 | `web/` | 不解冻。只修让它起不来的缺陷；阶段 2 结束时删除 |
| 数据接入、管道、数据集、血缘 | `services/data` | 阶段 5 |
| 页面搭建（Workshop）与对象视图 | `services/apps` | 阶段 2 里出现类型生成的界面表达不了的页面时 |
| 智能体、助手、检索与评估的新功能 | `services/ai` | 阶段 5；U 系列内已有实现的归位继续 |
| 运营观测、容量剖面 | `services/resources/monitoring` | 阶段 4 |
| 把内置应用改成系统产品包 | `services/work` 等 | 阶段 2 之后 |
| Frappe 应用转换 | `scripts/frappe-read.mjs` | 阶段 2 选包时可用作起点；阶段 5 成体系 |

## 条件触发

- 第一个客户租户装载之前冻结格式纪元：此后任何格式变化只经版本化迁移。
- 彻底清除、输出保留、制品回收、自动升级、维护窗口、多安装实例：等真实需求出现再做。默认保留数据、手动升级。
