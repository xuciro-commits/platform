# 长期规划

这份文档回答：现在在哪，往哪走，下一步做什么，什么先不碰。
产品阶段的进度写在这里；当前阶段每一行的细目在 [roadmap](roadmap.md)。

## 规划的规则

- 产品路线一次只做一个阶段。前一个阶段的门槛没过，不开下一个。
- 门槛是一次演示：负责人在浏览器里十分钟内能走完。走不完就是没过，不看代码行数与检查数。
- 批次的每一行是一个看得见的结果，不是一项技术工作。宿主缺什么，在用到它的那一行里补。
- 一次做一行。做完即提交、推送，用几句话向负责人报告并给出能点开的地址；做完的行从表里删掉。
- 每一行先有能跑的验收再动手。界面的行，是主干用例（`make trunk`）里新增的一步。
- 行在这里不拆子行；当前阶段的细目写在 roadmap，做完一项删一项。
- 后面的阶段只写门槛，到了再拆批次。本文不超过 150 行。

## 现在在哪（2026-11）

- 宿主：约 15 万行 Go，内核与十二组服务都在运行，有十三组内核不变量守着。它已经有主干要的多数能力：
  明细行、引用、状态流转、评论、关注、附件、任务都有对应的字段类型或动作。
- 新前端 `frontend/`：约 2700 行。外壳、登录、由类型生成的列表（条件筛选、排序、分组、看板、勾选批量）、
  记录页就地编辑、状态与流转、新建。对象类型在自己的记录页上发布，发布后它出现在“对象”里。
  记录页按类型描述分节、旁栏与条件显示排字段；明细、引用、活动与文件还没用上。
- 旧前端 `web/`：约 7 万行，功能最全，但每个页面都是手写的。
- 没有客户在用。此前的力气花在三条并行的线上：搬 Go 包、给旧前端换组件、重建新前端，前两条不产生看得见的东西。

所以顺序倒过来：先做用户看得见的主干，结构只在主干被它挡住时才动。

## 路线

| 阶段 | 做成什么 | 门槛：负责人能走完的演示 |
|---|---|---|
| 1 前端重生 | 类型生成应用，已发布的包能接入同一个工作台 | 建类型 → 发布 → 录入并流转；安装示例包 → 使用它的动作 → 换角色核对入口和权限 |
| 2 第一个行业包 | 旗舰包只用平台工具搭成，装进空租户就能办完一条业务主线 | 空租户安装 → 走完主线 → 期间没有改宿主 |
| 3 第一个客户 | 一个真实租户每天在用 | 用满两周；升级一次，客户自己的扩展还在 |
| 4 SaaS 运营 | 陌生人自己注册、开通、安装、邀请同事 | 全程没有我们介入；备份恢复与容量有演练记录 |
| 5 数据与智能 | 接外部系统；让内部助手和外部 AI 客户端调用平台能力 | 外部表变成对象；智能体搭出类型；外部客户端读取并提议同一个业务动作，由成员确认 |
| 6 生态 | 第三方发布业务应用和能力插件 | 第三方的包经审核上架，被另一个租户安装、启用和升级 |

## 阶段 1：前端重生

宿主有的远多于用户看得见的：引用、状态、活动、附件、检索、通知、保存的视图、宿主端的筛选排序分页都已在宿主里；
作者定义的类型已能声明分节与旁栏；选项标题来自租户词汇；业务明细是引用父记录的子对象，与产品包一致。
所以这一阶段是产品的重新设计：界面运行时把宿主的每一种能力，变成四种页面里看得见、用得顺的东西。平台的重生从这里开始。

- 先立三个核心：界面描述、动作运行器、视图状态（[frontend](frontend.md)“运行时的核心”）；记录页、列表与构建者的工具长在它们上面。
- 第一个扩展位用现有动作菜单验证。安装包后，获授权的人能在对应记录上直接用包带来的动作；这和装出一个完整应用同属 1.7。
- 对照物是 Frappe 的工作台，清单见 [ux](ux.md)“类型开箱清单”。每一行都做在界面运行时里，所有类型同时得到。
- 每一行的细目与验收在 [roadmap](roadmap.md)。
- 按顺序做；地址是 `http://localhost:8496`。

| 行 | 做完你能看到 | 核心 |
|---|---|---|
| 1.2 界面描述 | 记录页的字段按分节排，旁栏字段在右栏；选项、金额、日期、人、引用按规范显示；列表、看板、记录页说的是同一份描述 | 界面描述 |
| 1.3 动作 | “⋯”里是其余动作，不能做的写着原因；能撤销的不问而给“撤销”；两人同时改看到按字段的对比；批量与拖卡走同一套 | 动作运行器 |
| 1.4 记录页 | 页签：字段、活动、关联、文件；子对象明细是能编辑的表；引用能搜、能点、能悬停；被引用方列出引用它的记录 | |
| 1.5 列表即视图 | 筛选、排序、分组、布局、列进地址；保存、置顶、公开视图；数据在宿主端筛选分页，一万行不卡 | 视图状态 |
| 1.9 登录、权限、语言 | 正式登录；切租户后地址、搜索、菜单与连接跟随当前上下文；能切换语言与外观 | |
| 1.10 切换 | 新前端走通类型构建、安装和业务路径，已有链接能到同一资源；核对仍需旧入口的任务后切宿主默认入口 | |

## SaaS 产品矩阵

| 产品面 | 用户来这里做什么 | 随租户变化的内容 |
|---|---|---|
| 行业应用 | 采购、生产、交付等每日工作 | 订购并安装的应用根、业务视图和客户扩展 |
| 工作台能力 | 在原记录上审批、流转、查状态，或从收件箱继续任务 | 包贡献的动作、视图、连接与自动化；能力可以没有独立应用入口 |
| 构建与交付 | 建对象与流程，预览差异，发布、安装、审阅升级 | 项目、产品版本、依赖、客户扩展和发布权限 |
| 租户与宿主管理 | 开通、邀请、订阅、连接授权、用量与配额、支持与审计 | 租户管理员管理本工作区，宿主运营管理租户；服务端决定商业权益和成员授权 |

产品包是唯一交付物。应用是包可以声明的工作空间，插件是包可以带来的可启用能力；一个包可声明多个应用根，也可没有。
安装状态、外部连接、商业权益、成员授权分别呈现。付款或安装本身不授予数据读取和动作权限。

## 之后的阶段

到了再拆批次，这里只记门槛之外必须带上的事。

- 阶段 2：编号规则、默认值、取自引用的值、打印与导出、统计与仪表盘、数据导入。
  旗舰包的资源由我们用智能体经平台动作产出。空租户的管理者能审阅依赖、完成配置与授权，业务成员能在工作台做第一笔业务。
  接管清单走完、契约与夹具已脱离旧前端后删除 `web/`。
- 阶段 3：验收跑在 PostgreSQL 上；“安装 v1 → 客户扩展 → 升级 v2”的演练；备份恢复只应用已接受映像；装载客户之前冻结格式纪元。
- 阶段 4：租户自助开通、计量与配额、宿主控制台、运营观测、容量证据、安全评审。
- 阶段 5：重建连接、同步、管道、数据集、血缘、智能体工作室与全局助手，Frappe 应用转换成体系。
  用已有 `/mcp` 选 ChatGPT、Claude 或 DeepSeek Harness 中一个支持的客户端走通授权读取、提议和确认。
  先交付结构化结果与工作台链接，需要原位交互时验证 MCP Apps。Magpie 的模型供应侧接网关，调用平台业务能力时按 MCP 客户端核对。
- 阶段 6：对外发布、上架审核与分成；按客户端实际支持的技能、工具和界面分发，目录只指向不可变产品版本。

## 冻结

冻结的意思是：保持能跑，由它已有的测试守着，坏了要修；不加功能，不重构，不为它写文档。
它的事实是代码与测试；解冻时再把它的规则写进文档。

| 冻结的东西 | 位置 | 何时解冻 |
|---|---|---|
| 没有功能依赖的 Go 包搬迁与改名 | `capabilities/server` | 某个功能被结构挡住时，只动挡路的那一块 |
| 旧前端 | `web/` | 不解冻。只修让它起不来的缺陷；阶段 2 结束时删除 |
| 数据接入、管道、数据集、血缘 | `services/data` | 阶段 5 |
| 页面搭建（Workshop）与对象视图 | `services/apps` | 阶段 2 里出现类型生成的界面表达不了的页面时 |
| 智能体、助手、检索与评估的新功能 | `services/ai` | 阶段 5 |
| 运营观测、容量剖面 | `services/resources/monitoring` | 阶段 4 |
| 把内置应用改成系统产品包 | `services/work` 等 | 阶段 2 之后 |
| Frappe 应用转换 | `scripts/frappe-read.mjs` | 阶段 2 选包时可用作起点；阶段 5 成体系 |

## 条件触发

- 第一个客户租户装载之前冻结格式纪元：此后任何格式变化只经版本化迁移。
- 彻底清除、输出保留、制品回收、自动升级、维护窗口、多安装实例：等真实需求出现再做。默认保留数据、手动升级。
