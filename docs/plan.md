# 长期规划

这份文档回答：现在在哪，往哪走，下一步做什么，什么先不碰。
产品阶段的进度写在这里；当前阶段每一行的细目、分波与验收在 [roadmap](roadmap.md)。

## 规划的规则

- 产品路线一次只做一个阶段。前一个阶段的门槛没过，不开下一个。
- 门槛是一次演示：AI 扮演负责人或客户，按门槛剧本在浏览器里十分钟内走完，留下录屏、日志与结论。走不完就是没过，不看代码行数与检查数。
- 研发阶段不设人工门禁（负责人 11-26 定）：定客户、真实使用、负责人亲自演示，都由 AI 模拟的客户、陌生人与第三方代替。
  仍要人的只有法律意见、真实付费与对外发布（打发版 tag 也算）。
- 批次的每一行是一个看得见的结果，不是一项技术工作。宿主缺什么，在用到它的那一行里补。
- 一次做一项。做完即提交、推送 main，用几句话向负责人报告并给出能点开的地址；做完的行从表里删掉。
- 每一行先有能跑的验收再动手。界面的行，是主干用例里新增的一步（定点执行）；工程验收遵循[三档验收](README.md#三档验收)，不代替阶段演示。
- 行在这里不拆子行；当前阶段的细目写在 roadmap，做完一项删一项。
- 后面的阶段只写门槛，到了再拆批次。本文不超过 150 行。

## 阶段 4：ERP 地基

灵魂有三句，roadmap 每一项都对着它们验收：

1. **事实不改，只冲正。** 过账写下的是事实；余额是事实的投影，由宿主在同一次接受里维护，谁也不能直接写。
2. **每个数字都有出处。** 任何合计、余额、汇总格子都能点开，看到组成它的那些记录。
3. **单据是平台特性。** 粘进 50 行、逐格报错、一次过账、打印，任何类型都一样，不为库存写一行界面。

包各自能用，装在一起自动接上，停用一个另一个照常；平台不含库存、采购、会计的概念，它们只在包里。

门槛剧本（空租户，期间不改宿主）：

1. 安装 item-master、inventory、purchasing；采购单从表格粘进 50 行，错的两格就地标红，改好后一次提交。
2. 收货过账：库存出现 50 条流水，余额按物料与库位更新；两个库管员同时争最后 4 件，只过一笔，另一笔说清原因。
3. 冲正一张收货单：原流水保留并标“已冲正”，余额回到冲正前。
4. 库存期间汇总：期初、收、发、期末与独立计算一致；点开任一格看到对应流水；打印收货单，换页时表头重复。
5. 停用 inventory：采购照常能用，收货回到只记采购事实，界面写明“库存未接入”。
6. 1 万笔流水下，过账与余额读取的延迟、内存留下基线；重启重放后余额逐字节一致。
7. 再装 sales、accounting、manufacturing：一张销售单经 MRP 建议、采购收货、生产完工、发货、开票走到总账；
   库存金额与存货科目对得上，差额逐笔点得开；关账后试算平衡，补记上期的收货被拒。

| 行 | 做完你能看到 | 核心 | 波 |
| --- | --- | --- | --- |
| 4.1 账本 | 流水只能过账与冲正，余额由宿主维护，可按任意日期读，1 万笔不挡；改坏任一处规则，不变量变红 | 余额是投影，不是记录 | 收口 |
| 4.3 包能组合 | 采购独立能用；装上库存，审阅写明要接上的契约，收货开始过账；停用即退回 | 包级契约，调用经接受路径 | 收口、ERP |
| 4.4 包只有一份、能发版 | 平台发了版；包库钉到发行版并发版，市场装得到新版本 | 一个事实一处 | 收口、ERP |
| 4.6 销售到出库 | 销售单预留、发货扣库存、开票；最后 4 件只卖出一次；销售单上看得到全部下游单据 | 承诺不超过可用 | ERP |
| 4.7 总账与关账 | 业务单据自己出凭证；试算平衡；关账后上期补记被拒；库存与总账的差额逐笔点得开 | 总账只是另一本账 | ERP |
| 4.8 MRP 与排程 | 一次运行给出建议采购与建议工单，每条说得出为哪个需求、扣了哪些供给；人确认才成单 | 只提建议 | ERP |

## SaaS 产品矩阵

| 产品面 | 用户来这里做什么 | 随租户变化的内容 |
|---|---|---|
| 行业应用 | 采购、生产、交付等每日工作 | 订购并安装的应用根、业务视图和客户扩展 |
| 工作台能力 | 在原记录上审批、流转、查状态，或从收件箱继续任务 | 包贡献的动作、视图、连接与自动化；能力可以没有独立应用入口 |
| 构建与交付 | 建对象与流程，预览差异，发布、安装、审阅升级 | 项目、产品版本、依赖、客户扩展和发布权限 |
| 租户与宿主管理 | 开通、邀请、订阅、连接授权、用量与配额、支持与审计 | 租户管理员管理本工作区，宿主运营管理租户；服务端决定商业权益和成员授权 |

产品包是唯一交付物，按贡献分四层：组织（平台内）、主数据、能力、应用；包由此推导为应用、主数据、能力、扩展四种（[architecture](architecture.md)“扩展”）。
安装状态、外部连接、商业权益、成员授权分别呈现。付款或安装本身不授予数据读取和动作权限。

## 之后的阶段

到了再拆批次，这里只记门槛之外必须带上的事。

- 阶段 4 之后的 ERP：多币种总账、有限产能排程，先在包里用账本表达，挡住了再补平台。
- 平台的重型块到用它的阶段再做，每个仍是 `src/pages/` 里的一个表现：
  - 服务端渲染 PDF 是能力契约 `document.render/1`（roadmap“之后的项”），归档与对外发送单据时做；阶段 4 的打印在浏览器里完成。
  - 阶段 6：`FlowCanvas` 画流程、管道、血缘与智能体的节点图（`@xyflow/react`，`elkjs` 排布）；AI 批量提案的审阅复用 `RecordComparison`。
  - `RelationCanvas` 画类型之间的关系，等模拟客户的剧本用到。
- 阶段 5：租户自助开通、计量与配额、宿主控制台、运营观测、容量证据、安全评审。
  - 导入 1 万行端到端 ≤ 20 秒，应用吞吐 ≥ 2,000 行/秒。用 80、800 行/秒作前两档验收线，核对导入成本随存量增长的变化。
  - 5000 人在线且有导入时，交互写入 P95/P99 ≤ 30/80 ms，单条读取 P50/P95 ≤ 12/25 ms，列表 P50/P99 ≤ 10/40 ms。
    列表 P99 ≤ P95 的 2.5 倍。全员收到 SSE 更新，推送 P95 ≤ 100 ms，连接存续时堆占用 ≤ 200 MB。
    前两档单条读取 P50/P95 分别为 15/35、12/30 ms，第一档单条 P50 ≤ 列表 P50 的 1.5 倍。列表 P50/P99 分别为 12/150、10/50 ms。
    前两档 SSE 推送 P95 分别为 150、120 ms，连接存续时堆占用分别为 250、200 MB。
  - 同租户按 1、4、16、64 并发各饱和写入 30 秒，记录吞吐、P50/P95/P99、重试和回退比例及错误率。
    先核对单次写入 P50 ≤ 15 ms。16 并发达到 300 次/秒且 P95 ≤ 150 ms，单租户交互写入达到 500 次/秒。车道持有超过 10 ms 告警。
  - 5000 名成员下串行新增成员达到 100 次/秒，其写入字节数与成员规模无关。记录控制台状态距 4 MiB 上限的余量，规范摘要占 CPU ≤ 2%。
    新增成员先过 15、50 次/秒两档，摘要 CPU 占比先过 5%。10 万条日志下重启恢复 ≤ 3 秒，只重放最近快照之后的日志。
  - 预热后同环境跑三轮取中位数。P95 极差超过 25% 时排查后重测。延迟和吞吐轮次关闭 pprof，另测峰值 RSS 和强制 GC 后堆占用，断开后堆占用回到基线的 120% 以内。
  - 防退化验收比较 1,000 行与 100,000 行，成员场景比较 1,000 与 10,000 人。单条读、列表、单次写、导入每行和新增成员的耗时及每次操作分配次数之比 ≤ 1.5。
    核对 1,000 万行以内单次写入成本的趋势。用相关不变量守住详情目标行只读一次、读取时零原始映像摘要、常规读取零租户分叉、每批接受结果只算一次批次摘要。
    用微基准核对摘要、详情、来源声明分叉和行应用。摘要或编解码优化用既有日志语料逐字节对照，格式变更遵循 [architecture](architecture.md) 的版本与纪元规则。
- 阶段 6：重建连接、同步、管道、数据集与血缘，Frappe 应用转换成体系。智能体按 [architecture](architecture.md)“智能体：工具由类型生成”做，三步：
  - 工具面：`/mcp` 扩成由类型生成的工具，选 ChatGPT、Claude 或 DeepSeek Harness 中一个客户端走通读取、调用与 `ask` 的批准；先给结构化结果与工作台链接，要原位交互时验证 MCP Apps。
  - 委派：委派资源、回执一次接受、提问进收件箱、跳数与来由；先接 agent-autoloop 当编排，宿主不自建接单。之后删掉宿主内的智能体运行。
  - 助手：工作台里的一问一答，模型经网关，工具是同一个工具面；Magpie 的模型供应侧接网关。
- 阶段 7：对外发布、上架审核与分成；按客户端实际支持的技能、工具和界面分发，目录只指向不可变产品版本。

## 冻结

冻结的意思是：保持能跑，由它已有的测试守着，坏了要修；不加功能，不重构，不为它写文档。
它的事实是代码与测试；解冻时再把它的规则写进文档。

| 冻结的东西 | 位置 | 何时解冻 |
|---|---|---|
| 没有功能依赖的 Go 包搬迁与改名 | `capabilities/server` | 某个功能被结构挡住时，只动挡路的那一块 |
| 数据接入、管道、数据集、血缘 | `services/data` | 阶段 6 |
| 页面搭建（Workshop）与对象视图 | `services/apps` 的搭建部分 | 出现类型生成的界面表达不了的页面时 |
| 助手、检索与评估的新功能 | `services/ai` | 阶段 6；工具面、先问、来由与委派已提前（6.1–6.4） |
| 运营观测、容量剖面 | `services/resources/monitoring` | 阶段 5 |
| 把内置应用改成系统产品包 | `services/work` 等 | 阶段 5 |

## 条件触发

- 格式纪元已冻结：此后任何格式变化只经版本化迁移（[architecture](architecture.md)“版本与纪元”）。
- 彻底清除、输出保留、制品回收、自动升级、维护窗口、多安装实例：等真实需求出现再做。默认保留数据、手动升级。
