# 路线图

这份文档回答：当前阶段的每一行拆成哪几项，每项改哪里、怎样验收。
行与“做完你能看到”在 [plan](plan.md)；三个核心的规则在 [frontend](frontend.md)“运行时的核心”。

## 规矩

- 一项一次提交。先写能跑的验收，再动手；做完把这一项删掉，一行的项删完就删掉 plan 里的那一行。
- 路上发现的新项加在本行末尾，不另起清单。
- 验收里的“trunk”指在 `frontend/e2e/trunk.spec.ts` 加一步并让 `make trunk` 通过；“夹具”指 `scripts/frontend-seed.json`。
- 每一行做完，负责人按 [design](design.md)“负责人怎样看”的六步看一遍。

顺序：1.9 → 1.10。同一行里按编号做；标了依赖的等依赖做完。

## 1.9 登录、权限、语言

目标：像正式产品一样进出：用身份提供方登录，在自己的几个租户之间切换，选语言与外观；换了租户，一切跟着换。

- **1.9.2 跟随租户** 菜单列出 `/v1/me` 的租户，选中即切换：留在同一入口（新租户里没有就回首页），
  已安装应用、命令面板的最近、通知流都换成新租户的。验收 trunk：夹具的 acceptance 与 publisher 两个租户来回切。
- **1.9.3 正式登录** 宿主给出 issuer 时，登录页走授权码加 PKCE，回调换得令牌即开始会话；令牌失效回登录页，登录后回原地址。
  登录页按 [ux](ux.md)“四种页面”末尾那句排：宽屏左栏是产品说明，右栏是登录卡。没有 issuer 的开发宿主仍列夹具身份。
  验收：trunk 核对开发宿主的登录页；`make local` 下用身份提供方的账号登录，由负责人走一遍。
- **1.9.4 账户** 成员菜单加“账户”：本人的资料（名字、时区、格式、通知）与会话（`/v1/sessions`，可结束其他会话），都在同一张记录页上就地改。
  验收 trunk：改显示名后菜单里跟着变；结束其他会话后列表只剩当前一个。

## 之后的行

1.10 到了再拆。切换时验证已有链接、所用角色与关键任务；回退只切前端入口，保持已接受状态。

## 后端

后端边界由 `make check` 守住：`platform` 不超过 8000 行且只保留应用 SDK，依赖例外、包名与目录名不一致、能力探测均为零。
宿主为上面某一项补字段或接口时，保持租户数据、凭据引用、授权、当前格式纪元内的历史字节与已接受结果；用 `make verify` 验收，
涉及并发、分叉或恢复时跑 K13 竞态检查或 `make verify-sql`（[architecture](architecture.md)）。
