# 路线图

这份文档回答：当前阶段的每一行拆成哪几项，每项改哪里、怎样验收。
行与“做完你能看到”在 [plan](plan.md)；三个核心的规则在 [frontend](frontend.md)“运行时的核心”。

## 规矩

- 一项一次提交。先写能跑的验收，再动手；做完把这一项删掉，一行的项删完就删掉 plan 里的那一行。
- 路上发现的新项加在本行末尾，不另起清单。
- 验收里的“trunk”指在 `frontend/e2e/trunk.spec.ts` 加一步并让 `make trunk` 通过；“夹具”指 `scripts/frontend-seed.json`。
- 每一行做完，负责人按 [design](design.md)“负责人怎样看”的六步看一遍。
- 这里写到的文件、读取与动作都已对过宿主（夹具宿主 18511）；照写的做，对不上先停下问，不自己改设计。

## 接手怎样用模板

模板与组件是设计好的成品，它们的说明就是设计。照下面的顺序用，不跳步。

1. **先找自己的。** `src/pages/` 已有的表现能接住，就只写入口声明，不碰界面代码。
2. **再落官方的。** `pnpm --dir frontend astryx template <id> src/templates/<id>`；先把文件顶部的说明块整段读完。
   说明里的“Extending this template”逐条是约束：哪条保留、哪条因契约不同要改，写在下面各项里；没写到的一律保留。
3. **组件先读后用。** 每个用到的组件跑一次 `astryx component <Name>`，按它给的属性与示例写；文档说“别这样用”的不用。
4. **改造只做三件事：** 示例数据换成契约；补模板缺的表现；改完删掉 `src/templates/<id>`。框架、间距、交互、键盘与无障碍属性不动。
5. **说明不进代码。** 我们不写注释：模板说明里讲的道理，留在这里或 [frontend](frontend.md)，代码里删掉注释。
6. **一个表现服务所有入口。** 新表现做成 `src/pages/` 里的一个声明函数（像 `recordList`、`listPage`），入口只写一句声明。

- 业务对照只读 `study/from-frappe-crm/matrix.md`；`study/**/captures/` 与 `study/**/evidence/` 只为核对某个具体细节时定向看一张。

顺序：2.0.5。

## 2.0 CRM 骨架

目标：只用阶段 1 已有的能力搭出 CRM 主线，把搭不顺的地方全部暴露并修实，再进 2.1。

### 2.0.5 阶段 1 的短板

- 2.0.2 到 2.0.4 记下的每一项在这里修完；修在界面运行时或宿主的通用处，所有类型同时得到。
- 验收：负责人在 8495 用真实账号十分钟走完 CRM 主线无卡点。
- **界面微件第一批**（负责人定，2026-11-20；先于本行其余各项）：每个做成 `src/pages/` 里的一个表现，所有类型同时得到；一个一次提交，trunk 在 CRM 主线里加一步用到它。
  1. `MediaPreview`、`PdfViewer`、`Markdown`：附件里的图片与 PDF 在弹层里预览，长文本（备注）按 Markdown 显示；用 Astryx `Thumbnail`、`Dialog`、`Markdown`。
     PDF 用 pdf.js（负责人定，2026-11-21）；凡是可能读附件的地方（文件页签、附件字段、引用旁的预览）都走同一个预览入口，按类型挂渲染器。
- **列表的余项**：快速筛选的标签被截成“E…”，应不截断。
- **内部字段露出**：有公式的类型多出只读字段 `rulewithheld`，在记录页右栏显示成“Rulewithheld: No”；它是宿主的簿记，不该进字段描述。
  对象类型记录页的“Installed”把已安装的定义整段 JSON 显示出来，应折成摘要或只在“变更”页签里看。
- **改图标后发布**：在对象类型草稿里先加字段再改图标，发布后页头仍显示“有未发布的改动”；单改图标不显示改动。还没查是图标不进发布还是比较漏了它。
- **译文的余项**：包的译文按应用合并在 build 下，同一租户里两个包的同一原文译法不同就都退回原文（如 Released：酒店“已释放”、制造“已下达”），应按项目名分开；
  平台有十来个字段标题是 Go 字段名（`PauseReason`、`CandidateDigest`），英文界面直接露出，应给标题；生产包的复数写成了“Production batchs”。
  文本排序按码点，中文按公司名排出来是“北风、子午、峡湾……阿特拉斯”而不是拼音序；排序应按读者语言的排序规则（中文按拼音）。
  语言与词汇页缺“原文已变”：租户用词按原文记，原文改名后旧译文无处可见，应列出并能删除；整批导入导出也没做。
- **包带参考数据**：线索与商机状态已是字典（domain“类型”），但字典记录只由种子写入，空租户装 CRM 后看板没有列；
  字典记录的标题是业务数据不翻译，中文界面里状态显示 New、Qualification。参考数据应随包安装，标题随包的译文显示。
  夹具 crm 租户的成员没有显示名，负责人显示“未命名成员”；种子应给成员资料写上名字。
- **转换时不认同名组织**：现在由人在对话框里选已有组织，不选就新建；Frappe 按组织名自动关联。已有的匹配资源（`build.match`）应能在事务里查重，并让人确认关联还是新建。
- **事务新建的记录没有编号**：组织、联系人、商机的标识是 `chg-…-organization` 这样的内部值，出现在地址里；随 2.1 的编号一起解决。

## 之后的行

2.0 过了再拆 2.1。它的设计要点：

- 字段声明加 `default`（表达式：字面值、今天、当前成员、租户设置），类型声明加 `naming`（如 `CRM-LEAD-{YYYY}-{#####}`）。`from` 已有（[domain](domain.md)），引用带出用它。
- 两者都由唯一的规则求值在宿主执行：默认值在创建时补齐，编号在接受时发且不重复。
- 界面只读描述：新建对话框预填默认值；跟随字段说明来源；编号字段在新建时显示“保存后生成”。
- 不变量：编号在并发创建与重放下唯一且连续；验收 trunk：在商机上新建两条看编号，改组织看行业跟着变。
- 商机与线索的状态改用平台状态机：进行中阶段之间自由移动，赢单、输单经动作（输单原因是动作的必填项），结束后只经“重新打开”回到进行中。
- 界面微件第二批落在各行，做法同第一批：
  - 2.1 `RecordPeekDrawer`：点引用字段侧滑打开那条记录、在引用里就地新建，不跳页；列表的详情栏改用同一个抽屉（Astryx `Drawer`）。
  - 2.3 `ImportWizard`：上传 CSV 或 Excel → 字段映射 → 宿主试算 → 逐行报错、原位改错重试。Excel 由宿主解析，前端不引表格库。
  - 2.4 `ChartBlock`、`MetricCard`：引入 `echarts`；指标卡、漏斗、柱图、折线、环形图，点任一块带着筛选进列表。
  - 2.6 `CalendarView`：`ListPage` 在表格、看板之后的第三种布局，按日期字段排，拖动改日期；从 Astryx `Calendar` 起步。

## 后端

后端边界由 `make check` 守住：`platform` 不超过 8000 行且只保留应用 SDK，依赖例外、包名与目录名不一致、能力探测均为零。
宿主为上面某一项补字段或接口时，保持租户数据、凭据引用、授权、当前格式纪元内的历史字节与已接受结果；用 `make verify` 验收，
涉及并发、分叉或恢复时跑 K13 竞态检查或 `make verify-sql`（[architecture](architecture.md)）。
