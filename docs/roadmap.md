# 路线图

这份文档回答：当前阶段的每一行拆成哪几项，每项改哪里、怎样验收、谁来做。
行与“做完你能看到”在 [plan](plan.md)；三个核心的规则在 [frontend](frontend.md)“运行时的核心”。

## 规矩

- 一项一次提交。先写能跑的验收，再动手；做完把这一项删掉，一行的项删完就删掉 plan 里的那一行。
- 路上发现的新项加在本行末尾，不另起清单。
- 谁来做：
  - 〔灵魂〕决定产品样子的部分。主会话亲自设计、亲自写，不派出；它定下的接口与规则先写进 frontend，后面的项才能派。
  - 〔主会话〕要判断，或高风险（授权、发布、宿主契约）。高风险的提交前过 `critic`。
  - 〔执行者〕规则已定、有先例、验收能跑。按技能 `work-order` 从这一项展开成工单，交给 `builder`。
  - 〔定式〕照例子填。交给最便宜的执行者。
- 验收里的“trunk”指在 `frontend/e2e/trunk.spec.ts` 加一步并让 `make trunk` 通过；“夹具”指 `scripts/frontend-seed.json`。
- 每一行做完，负责人按 [design](design.md)“负责人怎样看”的六步看一遍。

顺序：0 → 1.2 → 1.3 → 1.4 → 1.5 → 1.6 → 1.7。同一行里按编号做；标了依赖的等依赖做完。

## 0 清场

- **0.2 夹具补齐**〔定式〕
  做：用宿主现在收的属性：商机加只在 stage 为 lost 时出现的 reason（标题 Loss reason，`when`），状态带语气与说明；客户与商机各补到 20 条。
  验收：`make frontend-host` 灌入无错；`/v1/entities` 里商机的 reason 带 when。

## 1.2 界面描述〔灵魂〕

目标：表现不再各自猜布局。类型描述里的每个属性（分节、旁栏、只读、条件显示、选项标题）在所有页面一次生效。

## 1.3 动作〔灵魂〕

目标：用户做的每一次改变都是提交一个动作，交互只有一套：一个运行器。D1 在界面上的样子就是它。

## 1.4 记录页〔灵魂〕

目标：一个形状装下任何记录。比 Frappe 的表单更密、更静，与这条记录有关的一切在一处看到。

## 1.5 列表即视图

目标：列表的每一次调整都是一个视图：能从地址还原、能保存、能分享；一万行也快。

## 1.6 构建者自举〔灵魂〕

目标：构建者的工具也由同一套界面生成。对象类型就是一条记录，在通用记录页上定义，这一点追平 Frappe（DocType 本身也是 DocType）；
发布之前就看见它的样子、知道发布的后果，这一点胜出。

- **1.6.1 宿主核对**〔主会话〕
  做：列出对象类型编辑动作的参数：字段明细行的子字段（名、标题、类型、必填、可搜、选项、引用、分节、旁栏、条件）、显示字段；
  状态与转换在哪个资源上定义。缺的补成编辑动作的参数，不另开接口；结论写进 [domain](domain.md)。
  验收：`make contract`；`make check`。
## 1.7 应用与插件〔灵魂〕

目标：装一个版本，业务成员在同一个工作台中看到新增入口，在原记录上直接用新能力。换角色或停用后，入口与动作随之变化。

- **1.7.1 交付与启用**〔灵魂〕
  做：复用产品版本与安装计划。“交付”分开查看市场、已安装版本与待配置能力；审阅时给出依赖、适用范围及停用影响。首个夹具不要求外部凭据。
  验收：trunk：管理员审阅并安装示例版本，返回安装页能看到版本并继续管理；已知无效的目标或依赖在审阅中给出原因。
- **1.7.2 一个外壳与首个扩展位**〔灵魂〕依赖 1.3.3、1.7.1
  已做：`/v1/applications` 的授权菜单投影成应用轨、侧栏和通用对象页；包退役后入口消失。宿主已有记录动作贡献与通用运行器。
  剩：从交付审阅流程安装示例版本，再从“⋯”执行该包贡献的记录动作并用浏览器验收。
- **1.7.3 角色与停用**〔主会话〕高风险：授权
  做：让两个角色使用同一安装。停用贡献后保留原记录与历史；旧链接按宿主权限读取，直接执行仍由宿主拒绝。
  验收：trunk：授权角色可操作，受限角色看不到该能力；管理员停用后入口消失，已有历史可由获授权者查看；过 critic。

## 之后的行

1.8 到 1.10 到了再拆。切换时验证已有链接、所用角色与关键任务；回退只切前端入口，保持已接受状态。

## 后端

后端边界由 `make check` 守住：`platform` 不超过 8000 行且只保留应用 SDK，依赖例外、包名与目录名不一致、能力探测均为零。
宿主为上面某一项补字段或接口时，保持租户数据、凭据引用、授权、当前格式纪元内的历史字节与已接受结果；用 `make verify` 验收，
涉及并发、分叉或恢复时跑 K13 竞态检查或 `make verify-sql`（[architecture](architecture.md)）。
