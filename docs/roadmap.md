# 路线图

这份文档回答：当前阶段的每一行拆成哪几项，每项改哪里、怎样验收、谁来做。
行与“做完你能看到”在 [plan](plan.md)；三个核心的规则在 [frontend](frontend.md)“运行时的核心”。

## 规矩

- 一项一次提交。先写能跑的验收，再动手；做完把这一项删掉，一行的项删完就删掉 plan 里的那一行。
- 路上发现的新项加在本行末尾，不另起清单。
- 谁来做：
  - 〔灵魂〕决定产品样子的部分。主会话亲自设计、亲自写，不派出；它定下的接口与规则先写进 frontend，后面的项才能派。
  - 〔主会话〕要判断，或高风险（授权、发布、宿主契约）。高风险的提交前过 `critic`。
  - 〔执行者〕规则已定、有先例、验收能跑。按技能 `work-order` 从这一项展开成工单，交给 `builder`。
  - 〔定式〕照例子填。交给最便宜的执行者。
- 验收里的“trunk”指在 `frontend/e2e/trunk.spec.ts` 加一步并让 `make trunk` 通过；“夹具”指 `scripts/frontend-seed.json`。
- 每一行做完，负责人按 [design](design.md)“负责人怎样看”的六步看一遍。

顺序：0 → 1.2 → 1.3 → 1.4 → 1.5 → 1.6 → 1.7。同一行里按编号做；标了依赖的等依赖做完。

## 0 清场

- **0.2 夹具补齐**〔定式〕
  做：用宿主现在收的属性：商机加只在 stage 为 lost 时出现的 reason（标题 Loss reason，`when`），状态带语气与说明；客户与商机各补到 20 条。
  customer 暂不改成引用：值会变成标识，1.4.3 之前界面只能显示标识。
  验收：`make frontend-host` 灌入无错；`/v1/entities` 里商机的 reason 带 when。

## 1.2 界面描述〔灵魂〕

目标：表现不再各自猜布局。类型描述里的每个属性（分节、旁栏、只读、条件显示、选项标题）在所有页面一次生效。

## 1.3 动作〔灵魂〕

目标：用户做的每一次改变都是提交一个动作，交互只有一套：一个运行器。D1 在界面上的样子就是它。

## 1.4 记录页〔灵魂〕

目标：一个形状装下任何记录。比 Frappe 的表单更密、更静，与这条记录有关的一切在一处看到。

- **1.4.2 明细**〔执行者〕交互由主会话在工单里写定；依赖 1.4.1
  定法：业务明细是子对象。子类型用引用指向父记录并写 `inverse`，父类型声明方向为 inverse 的集合（制造包的采购行、BOM 组件就是这样）。
  做：父记录页按它声明的 inverse 集合各画一张明细表：每行是一条子记录，单元格经子类型的编辑动作就地提交；
  “加一行”是子类型的创建动作，父引用预先填好，宿主的守卫决定能不能加；删行是归档。父记录还不存在时不能加明细，新建对话框里没有明细表。
  合计只用宿主给的数：记录读取里集合只给一页，浏览器里不求和；宿主还没给集合的合计时，先不显示合计（宿主项另派）。
  验收：trunk：夹具给商机加子类型“商机明细”（产品、数量、单价、商机）；在 Press line retrofit 上加一行 Press 200t、2、1000 → 刷新后还在。
- **1.4.3 引用**〔执行者〕
  做：输入即搜（经 `/v1/records/<类型>?search=`）选一条；显示被引用记录的显示名，可点；悬停卡给显示名、状态与三个关键字段。
  宿主：读取要给出引用的显示名，先核对 `formats` 与 `related`，没有就补。
  验收：trunk：商机的 Customer 输入 “Hart” 选中 Hartmann → 点过去到客户页。
- **1.4.4 关联**〔执行者〕依赖 1.4.1
  做：页签“关联”按类型分组列出 `linked` 与 `related`，每组显示总数与前五条，“查看全部”到筛选好的列表。
  验收：trunk：客户页的关联里有它的商机；“查看全部”打开只含该客户的商机列表。
- **1.4.5 活动**〔执行者〕依赖 1.4.1
  做：页签“活动”是一条时间线，合并评论、字段变更与状态流转；顶上是评论输入；右栏有关注开关与指派。宿主已有。
  验收：trunk：评论一句 → 出现在时间线；改 Next step → 时间线出现这次变更与新旧值。
- **1.4.6 文件**〔执行者〕依赖 1.4.1
  做：页签“文件”：拖入或选取上传、列表、图片与 PDF 预览、下载；attachment 字段用同一个上传。宿主已有上传。
  验收：trunk：上传一个小文件 → 列表出现 → 能下载。
- **1.4.7 无权的字段**〔执行者〕
  做：`restricted` 里的字段在原位显示“无权查看”，不显示值，也不悄悄消失。
  验收：trunk：换夹具里受限的身份登录，商机的 Amount 显示“无权查看”。
- **1.4.8 键盘**〔执行者〕依赖 1.4.1
  做：Tab 在字段间走，Enter 提交，Esc 关最上层；页签与“⋯”可用键盘操作；`?` 列出本页快捷键。
  验收：trunk：只用键盘新建一条商机并填两个字段。
## 1.5 列表即视图

目标：列表的每一次调整都是一个视图：能从地址还原、能保存、能分享；一万行也快。

- **1.5.1 视图状态**〔灵魂〕
  做：`src/pages/view.ts`，结构见 frontend“运行时的核心”；ListView 的筛选、排序、分组、布局、列全改读写它。
  验收：trunk：筛选 Stage 为 Proposal、按 Amount 降序 → 刷新 → 行与顺序不变；地址在新页打开也一样。
  记录页的“返回”回到带这个视图状态的列表（1.4.1 留下的一半）。
- **1.5.2 宿主端查询与分页**〔执行者〕依赖 1.5.1
  做：列表按视图状态向宿主取页（domain、sort、search、offset、limit），显示“n / 总数”，滚到底取下一页；不再整批读入后在浏览器里筛。
  验收：trunk：一万行夹具的首屏请求一页，筛选在宿主生效；记录验收环境，首屏在两秒内可操作。
- **1.5.3 一万行不卡**〔执行者〕依赖 1.5.2
  做：表格虚拟滚动（先核对 Astryx Table 的能力）；看板每列分页。等待新一页时保留当前内容与操作位置。
  验收：trunk：跨页滚动时渲染行数随视口而定；能点开第二页的记录并返回同一位置；筛选不会混入先前查询的结果。
- **1.5.4 保存的视图**〔执行者〕依赖 1.5.1，交互由主会话在工单里写定
  做：页头标题是视图切换器（默认、我的、公开）；“⋯”里保存、改名、删除、置顶、公开与设为个人默认（不变式 3）。
  宿主：`SavedView` 已有，核对它的动作与可见范围。
  验收：trunk：保存并置顶 “My proposals”，从侧栏还原筛选；另一成员可打开授权的共享链接，其个人默认不变。
- **1.5.5 列的取舍**〔执行者〕依赖 1.5.1
  做：“⋯”里选择与排列列，写进视图状态。
  验收：trunk：隐藏 Next step 列 → 刷新后仍隐藏。
- **1.5.6 类型的默认视图**〔主会话〕
  做：类型描述带默认视图状态，随类型发布与安装（宿主补字段，`make contract`）；没有时用 describe 的默认列。
  验收：trunk：客户列表默认按 Name 排序并分组 Region。

## 1.6 构建者自举〔灵魂〕

目标：构建者的工具也由同一套界面生成。对象类型就是一条记录，在通用记录页上定义，这一点追平 Frappe（DocType 本身也是 DocType）；
发布之前就看见它的样子、知道发布的后果，这一点胜出。

- **1.6.1 宿主核对**〔主会话〕
  做：列出对象类型编辑动作的参数：字段明细行的子字段（名、标题、类型、必填、可搜、选项、引用、分节、旁栏、条件）、显示字段；
  状态与转换在哪个资源上定义。缺的补成编辑动作的参数，不另开接口；结论写进 [domain](domain.md)。
  验收：`make contract`；`make check`。
- **1.6.2 在记录页上定义字段**〔执行者〕依赖 1.4.2、1.6.1
  做：对象类型记录页的 Fields 分节是表：加字段、改类型、拖动排序；类型是选项，引用目标是引用输入。
  这里的字段列表是内置类型的 lines 字段，整表经编辑动作提交；与 1.4.2 用同一个表的表现，只是数据来源不同。
  选项值的标题写进租户词汇（同 1.2.2），不另设字段级的标题。
  验收：trunk：给 Contact 加字段 Mobile → 发布 → 联系人记录页有 Mobile。
- **1.6.3 在记录页上定义状态**〔执行者〕依赖 1.6.1
  做：状态（名、标题、语气）与转换（名、标题、从、到）也是明细行；不能形成从初始状态到不了的状态。
  验收：trunk：给 Contact 加状态 Active、Left 与转换 Leave → 发布 → 联系人记录页有 Leave 按钮。
- **1.6.4 有未发布的改动**〔主会话〕宿主
  做：宿主在对象类型记录上给出与已发布版本的字段级差异；页头状态旁显示“有未发布的改动”，页签“变更”列出差异。
  验收：trunk：改 Contact 的标题 → 页头出现提示 → 发布后消失。
- **1.6.5 发布前预览**〔灵魂〕依赖 1.2.1、1.6.2
  做：页签“预览”用草稿的定义经 describe 画出它的列表与记录页，配示例行；不写入任何东西。
  验收：trunk：草稿加一个字段 → 预览的列表里出现这一列。
- **1.6.6 发布的后果**〔主会话〕高风险：发布与安装
  做：发布确认写明影响：受影响的记录数，删除或改了类型的字段；不兼容时拒绝并给出原因。来自宿主已有的安装兼容性校验的试运行。
  验收：trunk：删除一个有数据的字段 → 确认里写出受影响的条数；过 critic。
- **1.6.7 门槛的前半**〔主会话〕
  做：trunk 新增从零开始的一条：新建类型 → 加三个字段 → 预览 → 发布 → 录入一条 → 流转。
  验收：`make trunk` 通过；负责人照着走一遍。

## 1.7 应用与插件〔灵魂〕

目标：装一个版本，业务成员在同一个工作台中看到新增入口，在原记录上直接用新能力。换角色或停用后，入口与动作随之变化。

- **1.7.1 交付与启用**〔灵魂〕
  做：复用产品版本与安装计划。“交付”分开查看市场、已安装版本与待配置能力；审阅时给出依赖、适用范围及停用影响。首个夹具不要求外部凭据。
  验收：trunk：管理员审阅并安装示例版本，返回安装页能看到版本并继续管理；已知无效的目标或依赖在审阅中给出原因。
- **1.7.2 一个外壳与首个扩展位**〔灵魂〕依赖 1.3.3、1.7.1
  做：宿主投影已安装且获授权的应用入口，以及记录动作菜单中的贡献；能力可以独立于菜单。用通用记录页、动作运行器与接受结果呈现。
  验收：trunk：安装后出现业务应用与原记录上的扩展动作；从“⋯”执行并看到记录更新。获授权成员只用键盘也能完成。
- **1.7.3 角色与停用**〔主会话〕高风险：授权
  做：让两个角色使用同一安装。停用贡献后保留原记录与历史；旧链接按宿主权限读取，直接执行仍由宿主拒绝。
  验收：trunk：授权角色可操作，受限角色看不到该能力；管理员停用后入口消失，已有历史可由获授权者查看；过 critic。

## 之后的行

1.8 到 1.10 到了再拆。切换时验证已有链接、所用角色与关键任务；回退只切前端入口，保持已接受状态。

## 后端

后端边界由 `make check` 守住：`platform` 不超过 8000 行且只保留应用 SDK，依赖例外、包名与目录名不一致、能力探测均为零。
宿主为上面某一项补字段或接口时，保持租户数据、凭据引用、授权、当前格式纪元内的历史字节与已接受结果；用 `make verify` 验收，
涉及并发、分叉或恢复时跑 K13 竞态检查或 `make verify-sql`（[architecture](architecture.md)）。
