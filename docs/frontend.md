# 前端

这份文档回答：界面代码放在哪，一个新界面怎样做出来，怎样确认它是对的。
界面该怎样用在 [ux](ux.md)，该是什么观感在 [design](design.md)。

## 规则

- 只有一个前端：`frontend/`。`web/` 冻结：不读、不改、不拿它当参考（见“旧前端”）。
- 界面由类型生成（D8）。不为单个类型写界面；一个类型缺什么，改表现或契约，让所有类型同时得到。
- 不从空白写页面。先找 Astryx 官方的模板与块，改造一次，之后所有类型共用。
- 组件只来自 Astryx，样式只用组件属性与主题令牌。不写裸元素、`className`、内联样式、具体的颜色与尺寸。
- 读取与写入只经 `src/host/`；别处不发网络请求。写入只有一种：提交一个动作。
- 每个可见字符串在源码里是英文，经 `t()` 显示，同时在 `src/i18n.ts` 加简体中文。业务数据不翻译。
- 手写文件不超过 600 行；不写代码注释。
- 依赖是固定的一组：Astryx（组件、官方主题、命令行，三者同一版本，一起升级）、StyleX、Heroicons、React、Vite、TypeScript；
  验收用 Playwright。画布、图表、代码编辑到用的时候各选一个专用库。新增任何依赖先问负责人。

## 三层

界面分三层，下层不知道上层。

| 层 | 是什么 | 位置 |
|---|---|---|
| 契约 | 宿主给出的形状：类型描述、记录、动作目录，以及唯一的写入 `submit` | `src/host/` |
| 表现 | 由一个官方模板改造一次得到的组件；只认契约，不认具体类型 | `src/pages/` |
| 入口 | 一句声明：哪个类型，用哪种表现 | `src/apps/<应用>/<入口>.ts` |

一个入口的全部代码：

```ts
import { recordList } from "../../pages/RecordList";

export default recordList({
  type: "build.connection",
  project: true,
  title: "Connections",
  about: "A connection is an external system this workspace reads from: a kind, an address and a credential reference.",
});
```

- 文件路径就是地址 `/<应用>/<入口>`，由 `src/apps/entries.ts` 自动收集，不在别处登记。
- 列、可分组的字段、新建与编辑的表单都取自类型描述。入口里不写界面代码。
- 归项目所有的类型写 `project: true`，新建时多一个必填的项目选择。
- 记录若指向另一处的一组记录（如对象类型指向它安装出的类型），写 `instances: { field, path }`，记录页多一个“打开记录”。
- 业务类型不需要入口：发布后它自动出现在“对象”里，得到同一套列表、看板、记录页与录入。
- 类型自己的视图定义（默认的列、保存的视图、默认布局）存在宿主，随类型一起发布与安装，不写在前端代码里。

## 目录

| 位置 | 职责 |
|---|---|
| `src/main.tsx` | 挂载：样式、主题、链接适配、外壳 |
| `src/router.tsx` | 地址即状态：读取路径、跳转、Astryx 链接的适配 |
| `src/apps.ts` | 应用清单：每个应用的图标、分节菜单与入口 |
| `src/apps/<应用>/<入口>.ts` | 入口声明 |
| `src/shell/` | 外壳：应用轨、应用侧栏、登录页、未重建入口的占位 |
| `src/pages/` | 表现，以及建在表现上的入口形状 |
| `src/host/` | 会话、读取、写入、契约类型；唯一允许网络调用的目录 |
| `src/templates/` | 刚落地、还没改造完的官方模板；改造完就删，不长期保留 |
| `src/i18n.ts` | 以英文原文为键的字典与 `t()` |

## 契约

| 要什么 | 从哪来 |
|---|---|
| 我是谁 | `GET /v1/me` |
| 类型描述：字段、字段类型、选项、显示字段、标准动作、状态 | `GET /v1/entities` |
| 动作目录：每个动作的参数 | `GET /v1/actions` |
| 租户中可见的应用与能力 | `GET /v1/applications`、`GET /v1/capabilities` |
| 记录集合 | `GET /v1/records/<类型>` |
| 单条记录 | `GET /v1/records/<类型>/<标识>` |
| 写入 | `submit(动作, 标识, 载荷, 期望修订, 幂等键)`，即 `POST /v1/submissions`；只由运行器调用 |

- 读取用 `useRead(路径)`，结果是加载、就绪、拒绝、出错四态之一；表现四态都要画。
- 写入被接受后，更新相关记录与列表的读取；未受影响的区域保留内容与焦点。被拒绝时，在发起处显示宿主可披露的原因。
- 契约类型 `Api` 由宿主类型生成（`make contract`），不手写。
- 表现需要宿主没给的东西，就给宿主加字段或接口；不在前端猜，不在入口里补。

## 运行时的核心

界面运行时是平台重生的地方：宿主给出类型，运行时给出应用。三样东西撑着它，每样只有一个实现，所有表现只经它们。

| 核心 | 是什么 | 位置 |
|---|---|---|
| 界面描述 | `describe(类型描述, 动作目录)`：表现要的全部布局决定 | `src/pages/describe.ts` |
| 动作运行器 | `useAct()`：一次改变的全部交互 | `src/pages/act.tsx` |
| 视图状态 | 一份带版本的结构：一个列表此刻的样子 | `src/pages/view.ts` |

界面描述：

- 给出显示字段；分节（按字段的 `group`，原序，未分组的归 Details）；旁栏字段（`aside`）；可编辑字段（编辑动作的可填参数）；
  受限字段按宿主给出的布局原位显示无权查看；引用字段用宿主返回的显示名，编辑用 Typeahead 搜索目标类型；只读字段；条件显示（`when`）；lines 字段的列（`fields`）；明细（父类型声明的 inverse 集合，按集合接口读取可见行、修订与合计；子对象的创建、编辑、归档走运行器）；生命周期；列表的默认列（显示字段、必填、可搜索、选项与多状态流程的状态，至多六列）。
- 给每个动作一个角色：创建、编辑、转换（生命周期里的）、其他（以一条记录为目标，进“⋯”）。
- 表现不直接读 `fields` 做布局决定。类型描述多了一个属性，只改 describe。
- 值怎样显示只有一个函数：`src/pages/values.ts` 的 `present`，与 [design](design.md)“数据怎样显示”逐行对应。

动作运行器：

- 有可填参数时按参数生成对话框。已有就地输入就用原控件。无参数的普通动作直接提交。
- 删除、发布、安装、发送等不可撤销的高影响动作，提交前说明对象、范围与后果，确认按钮写出动词。发布确认读取宿主预检的记录与字段影响，拒绝时禁用确认。
- 只有宿主声明对应回程动作时才提供撤销。撤销仍经同一运行器，按当前授权与修订提交。
- 就地编辑的字段：成功不打断；被拒绝时原因显示在那个字段上，输入保留。应用内换页前等当前提交结束，拒绝时由用户选择留下或放弃。
- 其余被拒绝：原因回到发起的地方（记录页头的横幅、对话框、批量结果）。
- 等待宿主接受时保留原位置与输入；响应丢失时用同一提交标识重试。修订不符时取最新记录，对比原值、我的值与已保存值，按选择提交。
- 表现与外壳不调用 `submit`，只调用运行器；字段的就地提交与表单对话框用运行器的 `send`。
- 一次意图一个幂等键：响应在路上丢了，用同一个键重试，宿主只接受一次。

视图状态：

- 结构 `{ version: 1, layout, columns, sort, filters, search, group, lanes }`；`filters` 保存控件的选择，取数前转成宿主 `domain` 的前缀条件。
- 可分享的视图状态用地址的 `view` 查询值编码，筛选、排序、分组、布局与列顺序即时写回；含敏感值的条件只经有权限的保存视图读取。列表按一页 100 条向宿主取数，带 `domain`、`sort`、`search`、`offset`、`limit` 与 `actions=1`，并显示已加载数与宿主总数。
- Astryx Table 的行窗口只接纳纯文本或已登记的首方单元；记录表要放链接、状态点与布尔图标，因此 ListView 在 ScrollableArea 中按固定行高只渲染视口与前后各十二行。滚到末尾加载下一页，当前页保留；滚动位置按规范化视图存在会话中，从记录页返回时先恢复位置。
- 进入列表时按地址、成员设定的默认、类型默认依次取视图。日常调整只改当前视图。显式保存才更新 `SavedView.state`，旧版本经同一个迁移函数读入。
- 对象类型的 `view` 随发布与产品包安装进入 `GET /v1/entities[].view`；没有该值或旧定义省略时，沿用 describe 的默认列。
- 页头的视图切换器提供默认、我的与共享视图，经 `work.view.save`、`work.view.share`、`work.view.remove` 和 `work.viewpreference.set` 保存定义、共享、改名、删除、置顶与个人默认。侧栏按当前对象类型列出可见保存视图，并按当前成员的置顶顺序排列；打开视图仍由宿主逐字段、逐记录授权。
- 对象类型记录页的转换明细直接创建或选择 `build.actiontype`：新建时写动作名称、标题、起始状态和只改状态的事务并发布；绑定对象后，对象发布把版本编入记录页的转换按钮。
- 对象类型记录页的“预览”页签用当前草稿字段、选项与状态构造临时类型描述，经同一个 describe 画出列表和记录页，并填两条示例行；预览只读，不提交记录。
- trunk 的构建者门槛从零走完整条路：新建对象类型、添加三个字段、定义两个状态与转换、查看预览、发布、录入记录并执行转换。

## 应用与插件

- Delivery 的“市场”列出可安装版本并打开同一份审阅：依赖、应用、连接、受影响记录与保留引用；有未满足条件的版本在审阅中说明原因并禁用安装。“安装”只列已安装版本，并从同一对话框查看生命周期、保留数据，执行待卸载与退役。安装状态由包目录持有，不伪装成普通记录修订。
- `/v1/applications` 的 `menu` 投影成应用轨与侧栏；有 `object` 的页面进通用记录页，退役后宿主移除菜单即从外壳消失。
- 产品版本分发应用根与能力。应用根声明入口；插件贡献可启用的能力。首个扩展位是记录页的动作菜单，后续扩展位随真实业务场景定义位置、上下文与可用组件。
- 宿主从租户已安装版本、启用状态和当前成员授权生成可见内容。每项贡献按安装来源与稳定声明标识定位；升级保持这些标识和资源链接。
- 扩展声明引用受支持的目标类型、界面描述与动作。发布与安装审阅核对目标、依赖和版本。前端用原有页面、Astryx 与动作运行器呈现，租户提交声明制品。
- 安装计划展示依赖、版本与所需配置；授权管理员可查看待配置的能力与停用影响。动作参数、权限与执行结果以宿主为准，切换身份或租户时按新上下文重新读取。
- 对外由 `/mcp` 按连接绑定的租户、成员和授权范围投影读取与动作提案；确认使用同一宿主动作契约。
- 首个客户端先交付结构化结果与资源链接；需要原位交互时，再用 [MCP Apps](https://apps.extensions.modelcontextprotocol.io/) 验证外部宿主中的界面。

扩展位参考 [DeepSeek Harness](https://deepseek-harness.github.io/deepseek-harness/en/reference/subsystems/slots) 与 [Shopify Admin UI](https://shopify.dev/docs/api/admin-extensions/2026-01)。
目录与分发参考 [Magpie](https://usemagpie.ai/docs/plugins)、[OpenAI 插件](https://developers.openai.com/plugins/concepts/plugins) 与 [Claude 插件市场](https://code.claude.com/docs/en/plugin-marketplaces)。

`objectBrowser`（所有已发布的业务类型）、`listPage`（任意读取路径）、`dashboardPage`。

## 做一个新界面

1. 定位：它属于哪个应用，是四种页面里的哪一种（[ux](ux.md)）。哪一种都不是，先改 ux，不先写界面。
2. 判断动哪一层。多数需求是“所有类型都该有”，那就改表现或契约；只有“多一个菜单项”才是加入口。
3. 找官方的：`astryx build "<想法>"` 给出该用的模板与缺的块，`astryx search "<要什么>"` 找组件。
4. 落地模板到 `src/templates/<id>/`，只做三件事：把示例数据换成契约；补上模板缺的表现；改造完删掉落地的原件。
   模板的框架、间距与交互不动。找不到合适的模板，才组合官方的块。
5. 用任何组件之前先读它的属性：`astryx component <Name>`。不凭记忆写属性。
6. 空、加载、拒绝、出错四态都画；文字过 `t()` 并加中文；对照 [design](design.md) 的“不许出现”。
7. 核对（见下），然后报告改了哪些界面、负责人该看哪个地址。

Astryx 的命令都在 `frontend/` 里跑：

```bash
pnpm --dir frontend astryx build "<想法>"
pnpm --dir frontend astryx search "<要什么>"
pnpm --dir frontend astryx template <id> src/templates/<id>
pnpm --dir frontend astryx component <Name>
pnpm --dir frontend astryx docs tokens
```

`frontend/AGENTS.md` 下半部分是 Astryx 生成的用法说明，只用 `pnpm astryx init --agent-docs-path AGENTS.md` 在 `frontend/` 里刷新。
不带参数的 `astryx init` 会改写仓库根的 `AGENTS.md`，不要跑。

## 核对

| 层 | 怎么做 |
|---|---|
| 静态 | `make check-frontend`：裸元素、内联样式、硬编码值、未批准的依赖与导入、没翻译的文字、注释、文件长度、类型检查与构建 |
| 真实数据 | `make frontend-host` 起夹具宿主（自带示例销售项目：客户与商机）；`frontend/.env` 写 `PLATFORM_HOST=http://127.0.0.1:18511`；`pnpm --dir frontend dev`，打开 `http://localhost:8496`，登录页选 `admin-1` |
| 主干验收 | `make trunk`：`frontend/e2e/trunk.spec.ts` 按阶段门槛的演示路径走，自己起内存宿主、灌示例数据、起前端。只走主干，不测单个组件；每做一行给它加一步，控件按角色与可见的名字找 |
| 观感 | 亮色与暗色、窄窗口、中文各看一眼；然后交给负责人按 [design](design.md) 的六步看 |

检查报错就按它说的改，不改检查脚本。没有在浏览器里看过的界面，报告里要说没看过。

## 旧前端

`web/` 是手写页面的旧实现，约 7 万行。它冻结到被删除为止（[plan](plan.md)）。

- 在 `frontend/` 工作时不读它，不把它的结构、命名与组件带过来。它的界面不是新界面的输入；输入是 ux、design 与官方模板。
- 只修让它起不来、或让 `make check` 过不去的缺陷。
- 删除它之前要先搬走三样东西：生成的宿主类型（现在在 `web/packages/api`，`frontend/` 以链接取用）、
  `make check` 里契约比对的路径、夹具宿主用的租户配置（`web/e2e/tenants.json`）。

## 易错点

- 模块加载时不调用 `t()`，切换语言不会更新：模块级的文字写英文原文，显示时再翻译。动态的键要在字典里列全取值。
- 入口文件名必须是 `src/apps.ts` 里已有的入口；辅助文件放进子目录。
- 同一行里夹在 `>` 与 `<` 之间的英文会被当成没翻译的文字，例如行内的 `Promise<unknown>`；给类型起个别名。
- 单条记录读到的小数是 `{kind, value}`，用 `src/pages/values.ts` 的 `plain()` 取值、`shown()` 显示。
- Astryx 的 `TextInput` 没有失焦事件，就地编辑靠外层容器的失焦收口；包在每个输入外面会破坏表单布局，只包一层。
- 会话存在标签页里：新开的标签页要重新登录。
