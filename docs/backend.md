# 后端

这份文档回答：Go 代码放在哪，守什么规矩，哪里容易错。
写入、读取与发布三条路径本身在 [architecture](architecture.md)，概念在 [domain](domain.md)。

## 规则

- 一个宿主进程服务多个租户。隔离计算与代码构建是受控的辅助进程，不是微服务。
- 包按服务边界划分。包之间只经接口调用，不共享内部状态，不成环。
- 权威写入只经接受路径：拥有者返回编辑与意图，不直接写存储。任何旁路写存储都是缺陷。
- 记录读取只经协调读取。读记录的 HTTP 路由只用 `rt.recordRead`。
- `RecordType`、`RecordTypeInfo`、字段与生命周期是 SDK 声明；从 Go 模型反射记录形状、别名、派生字段、
  enterprise use 与呈现绑定归 `kernel/records`，调用方不自行解释模型标签。
- 授权只经唯一的决定函数，不在调用点另写判断。
- 条件用 Expr，对象读取用对象集；不新增第二种过滤或查询语言。
- 拒绝带可翻译的英文原因；新的原因字符串同时加进前端字典。
- 协议、存储格式、接口类型都带版本，从单一来源生成。改宿主类型后跑 `make contract`。
- 没有功能在等的搬迁、改名与拆分保持冻结；为 [roadmap](roadmap.md) 的某一项补宿主时，只动挡路的那一块。

## 包

位置都在 `capabilities/server/`。谁可以导入谁，登记在 `capabilities/server/boundaries.json`，由 `make check` 核对实际导入；
那份文件是依赖方向的唯一事实，这里只说每个包管什么。
它的 `exceptions` 是已知的越界导入：只减不增，消掉一条就删一条。

| 包 | 职责 |
|---|---|
| `expr` | Expr 的解析、类型检查、求值与下推编译；前端经 WASM 复用 |
| `capability` | 运行能力契约、模块选择、绑定与依赖顺序；不依赖 SDK 或服务实现 |
| `kernel` | 提交接收、幂等、修订、接受结果编码、车道、重放与快照；存储与记录投影在它的子包里 |
| `kernel/values` | 值 schema、有界 JSON 解码与结构校验；不依赖 SDK 或服务实现 |
| `kernel/fileio` | 日志存储与本地制品共用的原子文件替换；不依赖服务实现 |
| `platform` | 应用 SDK 的契约：清单、调用者、动作目录、页面与应用声明、授权接口。稳定的叶层，不依赖实现 |
| `services/resources` | 资源标识、项目、文件夹、生命周期、工作状态、分支、提案；跨类型的发布编排 |
| `services/ontology` | 类型的元数据与类型检查 |
| `services/objects` | 对象投影、编辑事实、索引、对象集执行 |
| `services/actions` | 动作执行、提交条件、副作用调度；动作目录由类型声明生成 |
| `services/functions` | 函数制品、受控编译、隔离执行；代码函数与决策表的编写、发布、安装及历史版本 |
| `services/automate` | 自动化与其运行 |
| `services/apps` | 页面与应用的声明与运行 |
| `services/work` | 工作项、通知与投递 |
| `services/devops` | 产品、版本、安装、升级；测试计划与样本集发布，以及测试计划和评估集共用的记录与版本族 |
| `services/security` | 成员、团队、组织单元、业务角色、标记；授权上下文与唯一的决定函数 |
| `services/data` | 连接、数据源、数据集、管道、调度、回写、血缘与标记推导 |
| `services/ai` | 模型配置与网关、智能体编写、发布与运行、评估集发布、助手 |
| `hostroles` | 从已创建的应用中登记宿主所需的具名 owner 能力；只供租户装配，不执行业务规则 |
| `host` | HTTP 路由、身份接入、租户装配、部署、后台调度 |
| `cmd/*` | 二进制入口、契约生成器、受控的辅助进程；只做装配 |

- 租户的提交序列是 `kernel` 的类型。每个服务经同一个拥有者接口（决定、应用、分叉、读取）向它注册自己的状态。
- 服务可以导入 `kernel` 下四个叶层数据包：`kernel/records`、`kernel/acceptedformat`、`kernel/protocol`、`kernel/values`。
  数据服务的本地文件实现可使用 `kernel/fileio`；`kernel` 的其余部分与 `host` 不被服务导入。`kernel` 不导入任何服务。
- 服务之间的调用面写在被调服务的 `api.go` 里，装配在 `host` 完成。
  记录集的批量授权复用安全服务的一次遍历，遍历状态归安全服务。
  产品包的连接描述和变更影响由数据服务读取，交付服务使用其 API。
- 规则的 schema 校验、上下文构造、条件与决策表执行，以及观测规则执行由 `kernel/protocol` 提供。
  SDK 保留规则声明、表达式类型和调用所需的读取接口。
- 自动化与 AI 分别拥有执行实现。宿主装配使用的运行接口、Flow 实例和批次映像、智能体执行结果归 `kernel/protocol`；
  SDK 保留定义工作流和智能体所需的声明。
- 宿主管理、交付、审计和运行时的跨包映像归 `kernel/protocol`；应用 SDK 保留声明及应用调用面。
  日期与值约束复用 `kernel/values`，业务规则仍由对应服务执行。
- 页面与应用的草稿映像由 `kernel/protocol` 定义。应用服务拥有校验、公开视图、发布和恢复，资源服务经宿主装配的接口编排。
- 自动化草稿使用同样的装配边界，发布校验、计划和恢复由自动化服务执行，资源服务负责联合发布。
- 资源服务使用数据和本体的公开能力编排；数据服务使用本体的声明与编译能力。
  数据和本体通过独立的发布包实现钩子，不反向依赖资源作者包。
  血缘由宿主提供资源映像与分支版本，监控由资源服务投影数据运行状态。
- 操作定义在宿主装配时按应用登记；有版本的操作由拥有者读取保留版本，其余操作只从清单读取当前声明。
  分叉与模拟使用对应实例重新登记，不能沿用源实例的状态。
- 函数拥有者由宿主装配。`Build` 提供资源身份、权威、当前安装与联合草稿上下文，并保留路由和提交入口；
  AI 函数、代码函数、决策表的编写、发布、历史与编译结果归 `services/functions/authoring`。
  函数和编译制品的共享映像归 `kernel/protocol`；资源层经宿主注入的拥有者编排函数发布和分叉。
- 智能体编写、版本与运行归 `services/ai`；函数评估的记录、模型请求、答案结算与阈值判定也归 `services/ai/evaluation`，
  启动提交只由宿主把 DevOps 的候选、共享测试计划与函数版本装配成 AI 请求。
  测试计划和评估集继续共用 DevOps 的记录与版本族，DevOps 不反向依赖 AI。
- 自动化流程的编写、校验、发布、安装与运行归 `services/automate/authoring`；页面和应用的编写、发布、
  安装及运行时视图归 `services/apps`。应用 AI 视图只合并资源与评估结果，函数定义继续由
  `services/functions/authoring` 读取，智能体与函数评估报告由 AI 服务提供，资源服务保留装配适配。
- `Flow`、`Step` 与运行记录结构是应用 SDK 的线格式；连续 Flow 的 owner、frame store、准备结果与批次键归
  `services/automate/runtime`。数据流准备共用的重试校验与次数归 `kernel/protocol`，数据与自动化服务不各写一份。
- 应用 profile 的校验和由原始 `UIProfile`、变量与查询构造的页面声明归 `services/apps/pages`；
  ontology、publication 与 DevOps 只经宿主装配的回调使用该声明，不复制构造或校验。
- 对象、动作类型、对象执行形状、生命周期与约束编译归 `services/ontology`。资源服务只编排跨类型草稿、
  联合发布、页面覆盖、资源身份与安装；动作执行仍归 `services/actions`。
- 表达式引用遍历与类型合并归 `expr`；`Binding`、`Run` 的线格式留在 SDK，workflow 条件到 binding、
  校验和测试归 `services/automate/authoring`。页面只复用表达式遍历或页面拥有者的检查。
- 页面兼容生成物由 `services/apps/pages` 持有；通用小数文本格式与长度上限归 `expr`，
  `platform` 不读取页面契约，也不复制页面限制。
- 服务运行接口按决策、读取、操作、效果、记录、授权、组织、关系与 enterprise 使用拆分；
  服务运行调用只经 `Caller` 门面，不取得聚合运行时；需要校验的能力继续由装配时的接口收回。
- `BusinessTxn`、`TxnStep` 及其嵌套类型、严格 JSON 解码和 `RecordType`/`Action` 内嵌字段是 SDK 线格式；
  事务规范化、编号、步骤校验、遍历、生命周期目的地与对象/动作冻结描述归 `services/ontology`。
  事务执行与拒绝改路归 `services/actions`，资源服务提供保留版本、集成绑定和跨类型草稿上下文。
- 连接、数据源、数据集、管道、回写、确认和设备派发及其外部调用结算与补偿归 `services/data`；
  协议声明与校验归 `services/ontology`。资源服务只保留跨类型事务注册、发布资产绑定与路由适配。
- 分支记录、检查、提案、审批和合并归 `services/resources/merge`；资源服务只保留跨资源 RID 映射、
  草稿存储与分支入口适配。main 隔离、审批顺序和单条合并接受结果由分支服务本身保持。
- 发布声明与 protocol 描述归 `services/resources/publication`；`AgentReleaseDescriptor` 只保留 SDK 线格式，
  agent 校验、工具依赖与声明生成归 AI 服务，publication 经宿主装配的 resolver 回调使用。AI 提案消费归
  `services/functions/authoring`；蓝图补全与测试根草稿仍由资源服务编排。
- releases、apps 与 packages 使用装配时传入的 publication resolver，不在调用路径重新构造缺少能力回调的 resolver；
  租户分叉、控制映像和模拟视图保留同一 resolver。
- 产品与 ProductVersion 的记录类型、动作声明和版本视图归 `services/devops/descriptor`，候选冻结与产品包描述归
  `services/devops/packages`；资源服务只保留项目、资源范围校验和接受结果写入适配。
- 通用发布的草稿引用与差异、保留版本族读取、依赖展开和安装次序归 `services/resources/publication`；
  资源服务按类型收集候选、复用发布钩子并编排联合草稿、执行分叉和重装。publication 通过 ontology
  提供的对象/动作描述器读取冻结定义，不直接理解事务。
- 资产正文规范化、资源引用排序与 schema 内容身份也归 publication；`platform` 只保留资源引用、
  发布资产与候选等线格式。
- 属性、值类型、接口、对象组与关系的声明、转换和字段绑定校验归 `services/ontology`，关系数据迁移由对象服务执行。
- 查询记录、接口查询绑定、记录集校验、保留版本与重装归 `services/objects`；资源服务保留查询资源身份、
  联合草稿上下文和跨类型发布编排，查询读取继续使用唯一的对象集执行器。
- 产品包里的行业逻辑不进任何 Go 包。

## 并发

- 租户是唯一的提交序列。不引入对象锁、行锁、消息队列、分布式事务或工作流引擎。
- 车道只做提交：基准校验、追加、从已提交字节应用、发布映像、隔离判定。
  网络、外部进程、构建、模型调用、全量扫描、等待别的锁，都不得在车道内。
- 读取经映像：协调读取取最新已发布的映像，不取车道。映像发布后不可变；读取不得碰映像之外的可变租户状态。
- 决定是暂定的：在映像的分叉上计算并带基准位置，车道内基准等于已应用位置才提交；落后就作废重算，不做部分合并。
- 同一决定至多乐观重算两次，仍冲突就在车道内决定一次。任何路径都不会饿死。
- 决定必须确定且无副作用：同一映像、同一提交得到同一组字节。外部 I/O 先预留、车道外调用、再结算。
- 不以超时、重启、换进程或给锁加超时来“修”慢操作；把它移出车道。
- 乐观校验只在内核提交处实现一次，拥有者不写并发代码。
- Go 的映射并发读写会让整个宿主崩溃。任何移出车道的读取或决定，先证明它碰的状态在映像内或不可变，并在 `-race` 下过 K13。

## 代码规范

- 手写文件不超过 800 行（Go）或 600 行（TypeScript）。超出按职责拆，不按“工具函数”拆。
- 包名表达职责，并等于目录名。内核与服务的公开标识只用 [glossary](glossary.md) 的词。
- 最小完整改动：能不写就不写，能复用就复用，删除优先于新增。只有一个实现的东西不写接口，不留兼容分支。
- 校验只在信任边界：HTTP 入口、产品包导入、租户扩展与外部系统的返回、日志装载时的纪元校验。
  边界之内信任类型与不变量，不为不会出现的状态写分支，不吞掉错误换成默认值。
- 能力是否存在由注册时的类型决定，不在调用点用类型断言探测；可选参数经选项结构传入。
- 动态 agent 定义随 owner 装配登记，刷新、版本读取与变更判断只查索引，不在运行中探测应用类型。
- 不写代码注释；编译指令、生成文件头、shebang 保留。生成文件不手改，只改生成器或它的源。
- 观测与业务分开：业务事实、安全审计、运行事实、运营日志各只有一个事实源。
  日志不进业务日志，日志故障不阻断业务写入；审计不可采样、不可关闭；指标标签里不放成员、对象标识与地址。

## 形状上限

`scripts/shape-baseline.json` 记着五个数：`host` 与 `platform` 的行数、租户类型的字段数、
对具名类型的能力探测次数、包名与目录名不一致的包数。`make check` 不让它们变大。

- 新状态放进拥有它的服务，不加到租户类型上；新逻辑放进服务，不堆在 `host`。
- 数值降下来时把基线跟着调低。不为调低它单独安排工作。
- 一项功能确实要在 `host` 里加路由而超过上限时，在同一提交里调高基线，并在提交说明里写明加了什么。

## 内核不变量

在 `capabilities/server/host/*invariants_test.go`。它们守着内核；改内核语义时定点运行相关编号，断言不为迁就实现而改写。

| 编号 | 守什么 |
|---|---|
| K1 | 重放：同一日志重放两次，记录存储逐字节相同；纪元不符的日志拒绝装载 |
| K2 | 幂等：同一幂等键的重复提交返回同一结果，不产生第二条接受结果 |
| K3 | 修订：期望修订不符的提交被拒绝，拒绝同样封存 |
| K4 | 授权：拒绝带原因；标记未获准时集合读取过滤、单条读取拒绝 |
| K5 | 标记沿管道与数据源传播到对象类型 |
| K6 | 分支：分支保存不改变 main；合并是一条接受结果 |
| K7 | 产品版本：只从已保存的候选冻结；版本不可替换 |
| K8 | 系统包与行业包走同一条安装路径（尚无用例） |
| K9 | 产品包生命周期：同名项目拒绝、另起名字安装、退役、重装沿用名字、升级、降级、回滚与存储兼容检查 |
| K10 | 资源所有权转移只改项目归属与修订号 |
| K11 | 运营观测不越过租户与成员范围，不改变接受结果 |
| K12 | 血缘：保护标记不因未激活的改动降低；项目范围之外的资源身份不外泄 |
| K13 | 租户并发：读取不等车道；并发提交等价于一个串行顺序；`-race` 下无数据竞争 |
| K14 | 发布的字段位置随类型描述交付，移到右栏的字段仍可通过原动作写入 |
| K15 | 同一记录状态下，动作可用性复用提交决策，未授权的动作不可见 |
| K16 | 列表、单条记录与历史只返回可读引用目标的显示名 |
| K17 | 列表与单条记录的字段格式一致，规则只使用可读的字段 |
| K19 | 声明的反向集合只计入调用者能读的行与字段，并保留行修订 |
| K20 | 默认视图随类型发布，旧定义可省略，视图改动不改变业务动作契约 |
| K23 | 对象发布试运行只读，数据影响和安装拒绝来自同一版本的记录与发布决策 |
| K24 | 包安装后投影获授权的菜单与记录动作，退役撤回入口和动作、保留记录 |
| K25 | 两个项目各有同名类型，各自发布、录入、重放；命名空间不可借用、不可改 |
| K26 | 项目里的角色只作用于本项目的类型：本人范围只读自己的记录，未声明的角色不能授予，授予后才能在另一项目新建，重放一致 |

## 易错点

- 类型的拥有者只经 `platform.OwnerOfType` 求：前缀是宿主装配的应用就归它，否则是项目的类型，归 build。不要用前缀切分。
- 读记录的 HTTP 路由用了 `rt.handle` 会因“no consistent view”崩溃；必须用 `rt.recordRead`。
- 读取闭包使用参数里的租户与调用者上下文，不要捕获活动的租户、拥有者或 SQL 视图。
- `runtime.scoped` 只用于已持有车道或已有独立读取范围的内部调用；不能用“租户有打开的视图”来判断调用者持有范围。
- 授权的集合读取与单条读取都经 `authorizeDepth`；`held=true` 表示调用者已持有存储锁，不得再加锁。
- 归项目所有的资源，创建动作的载荷必须带 `project`；动作目录目前没有把它列为参数。
- 单条记录读取里，小数是带类型的值 `{kind, value}`，列表读取里是普通数字。
- 夹具宿主与本地数据随时可以清空重建；不要为了修启动问题去删配置或数据卷。
