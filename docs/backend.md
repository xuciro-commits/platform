# 后端

这份文档回答：Go 代码放在哪，守什么规矩，哪里容易错。
写入、读取与发布三条路径本身在 [architecture](architecture.md)，概念在 [domain](domain.md)。

## 规则

- 一个宿主进程服务多个租户。隔离计算与代码构建是受控的辅助进程，不是微服务。
- 包按服务边界划分。包之间只经接口调用，不共享内部状态，不成环。
- 权威写入只经接受路径：拥有者返回编辑与意图，不直接写存储。任何旁路写存储都是缺陷。
- 记录读取只经协调读取。读记录的 HTTP 路由只用 `rt.recordRead`。
- 授权只经唯一的决定函数，不在调用点另写判断。
- 条件用 Expr，对象读取用对象集；不新增第二种过滤或查询语言。
- 拒绝带可翻译的英文原因；新的原因字符串同时加进前端字典。
- 协议、存储格式、接口类型都带版本，从单一来源生成。改宿主类型后跑 `make contract`。
- 已授权的 U 系列按 [plan](plan.md) 收尾；其余没有功能在等的搬迁、改名与拆分保持冻结。

## 包

位置都在 `capabilities/server/`。谁可以导入谁，登记在 `capabilities/server/boundaries.json`，由 `make check` 核对实际导入；
那份文件是依赖方向的唯一事实，这里只说每个包管什么。
它的 `exceptions` 是已知的越界导入：只减不增，消掉一条就删一条。

| 包 | 职责 |
|---|---|
| `expr` | Expr 的解析、类型检查、求值与下推编译；前端经 WASM 复用 |
| `kernel` | 提交接收、幂等、修订、接受结果编码、车道、重放与快照；存储与记录投影在它的子包里 |
| `platform` | 应用 SDK 的契约：清单、调用者、动作目录、页面与应用声明、授权接口。稳定的叶层，不依赖实现 |
| `services/resources` | 资源标识、项目、文件夹、生命周期、工作状态、分支、提案；跨类型的发布编排 |
| `services/ontology` | 类型的元数据与类型检查 |
| `services/objects` | 对象投影、编辑事实、索引、对象集执行 |
| `services/actions` | 动作执行、提交条件、副作用调度；动作目录由类型声明生成 |
| `services/functions` | 函数制品、受控编译、隔离执行；代码函数与决策表的安装状态、历史查询及发布映像解码 |
| `services/automate` | 自动化与其运行 |
| `services/apps` | 页面与应用的声明与运行 |
| `services/work` | 工作项、通知与投递 |
| `services/devops` | 产品、版本、安装、升级；测试计划发布及其与评估集共用的记录和版本族 |
| `services/security` | 成员、团队、组织单元、业务角色、标记；授权上下文与唯一的决定函数 |
| `services/data` | 连接、数据源、数据集、管道、调度、回写、血缘与标记推导 |
| `services/ai` | 模型配置与网关、智能体编写、发布与运行、评估集发布、助手 |
| `host` | HTTP 路由、身份接入、租户装配、部署、后台调度 |
| `cmd/*` | 二进制入口、契约生成器、受控的辅助进程；只做装配 |

- 租户的提交序列是 `kernel` 的类型。每个服务经同一个拥有者接口（决定、应用、分叉、读取）向它注册自己的状态。
- 服务可以导入 `kernel` 下三个叶层数据包：`kernel/records`、`kernel/acceptedformat`、`kernel/protocol`。
  `kernel` 的其余部分与 `host` 不被服务导入；`kernel` 不导入任何服务。
- 服务之间的调用面写在被调服务的 `api.go` 里，装配在 `host` 完成。
- 产品包里的行业逻辑不进任何 Go 包。

## 并发

- 租户是唯一的提交序列。不引入对象锁、行锁、消息队列、分布式事务或工作流引擎。
- 车道只做提交：基准校验、追加、从已提交字节应用、发布映像、隔离判定。
  网络、外部进程、构建、模型调用、全量扫描、等待别的锁，都不得在车道内。
- 读取经映像：协调读取取最新已发布的映像，不取车道。映像发布后不可变；读取不得碰映像之外的可变租户状态。
- 决定是暂定的：在映像的分叉上计算并带基准位置，车道内基准等于已应用位置才提交；落后就作废重算，不做部分合并。
- 同一决定至多乐观重算两次，仍冲突就在车道内决定一次。任何路径都不会饿死。
- 决定必须确定且无副作用：同一映像、同一提交得到同一组字节。外部 I/O 先预留、车道外调用、再结算。
- 不以超时、重启、换进程或给锁加超时来“修”慢操作；把它移出车道。
- 乐观校验只在内核提交处实现一次，拥有者不写并发代码。
- Go 的映射并发读写会让整个宿主崩溃。任何移出车道的读取或决定，先证明它碰的状态在映像内或不可变，并在 `-race` 下过 K13。

## 代码规范

- 手写文件不超过 800 行（Go）或 600 行（TypeScript）。超出按职责拆，不按“工具函数”拆。
- 包名表达职责，并等于目录名。内核与服务的公开标识只用 [glossary](glossary.md) 的词。
- 最小完整改动：能不写就不写，能复用就复用，删除优先于新增。只有一个实现的东西不写接口，不留兼容分支。
- 校验只在信任边界：HTTP 入口、产品包导入、租户扩展与外部系统的返回、日志装载时的纪元校验。
  边界之内信任类型与不变量，不为不会出现的状态写分支，不吞掉错误换成默认值。
- 能力是否存在由注册时的类型决定，不在调用点用类型断言探测；可选参数经选项结构传入。
- 不写代码注释；编译指令、生成文件头、shebang 保留。生成文件不手改，只改生成器或它的源。
- 观测与业务分开：业务事实、安全审计、运行事实、运营日志各只有一个事实源。
  日志不进业务日志，日志故障不阻断业务写入；审计不可采样、不可关闭；指标标签里不放成员、对象标识与地址。

## 形状上限

`scripts/shape-baseline.json` 记着五个数：`host` 与 `platform` 的行数、租户类型的字段数、
对具名类型的能力探测次数、包名与目录名不一致的包数。`make check` 不让它们变大。

- 新状态放进拥有它的服务，不加到租户类型上；新逻辑放进服务，不堆在 `host`。
- 数值降下来时把基线跟着调低。不为调低它单独安排工作。
- 一项功能确实要在 `host` 里加路由而超过上限时，在同一提交里调高基线，并在提交说明里写明加了什么。

## 内核不变量

在 `capabilities/server/host/*invariants_test.go`。它们守着内核；改内核语义时定点运行相关编号，断言不为迁就实现而改写。

| 编号 | 守什么 |
|---|---|
| K1 | 重放：同一日志重放两次，记录存储逐字节相同；纪元不符的日志拒绝装载 |
| K2 | 幂等：同一幂等键的重复提交返回同一结果，不产生第二条接受结果 |
| K3 | 修订：期望修订不符的提交被拒绝，拒绝同样封存 |
| K4 | 授权：拒绝带原因；标记未获准时集合读取过滤、单条读取拒绝 |
| K5 | 标记沿管道与数据源传播到对象类型 |
| K6 | 分支：分支保存不改变 main；合并是一条接受结果 |
| K7 | 产品版本：只从已保存的候选冻结；版本不可替换 |
| K8 | 系统包与行业包走同一条安装路径（尚无用例） |
| K9 | 产品包生命周期：退役、重装、升级、降级、回滚与存储兼容检查 |
| K10 | 资源所有权转移只改项目归属与修订号 |
| K11 | 运营观测不越过租户与成员范围，不改变接受结果 |
| K12 | 血缘：保护标记不因未激活的改动降低；项目范围之外的资源身份不外泄 |
| K13 | 租户并发：读取不等车道；并发提交等价于一个串行顺序；`-race` 下无数据竞争 |

## 易错点

- 读记录的 HTTP 路由用了 `rt.handle` 会因“no consistent view”崩溃；必须用 `rt.recordRead`。
- 读取闭包使用参数里的租户与调用者上下文，不要捕获活动的租户、拥有者或 SQL 视图。
- `runtime.scoped` 只用于已持有车道或已有独立读取范围的内部调用；不能用“租户有打开的视图”来判断调用者持有范围。
- 授权的集合读取与单条读取都经 `authorizeDepth`；`held=true` 表示调用者已持有存储锁，不得再加锁。
- 归项目所有的资源，创建动作的载荷必须带 `project`；动作目录目前没有把它列为参数。
- 单条记录读取里，小数是带类型的值 `{kind, value}`，列表读取里是普通数字。
- 夹具宿主与本地数据随时可以清空重建；不要为了修启动问题去删配置或数据卷。
- Go 模块经 `GOPROXY=https://goproxy.cn,direct`；长命令一律加超时。
