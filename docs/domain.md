# 领域模型

这份文档回答：平台里有哪些概念，它们各管什么，彼此怎样作用。
它是承重决定 D2（一套模型）、D4（一种交付物）、D5（一个授权决定点）、D6（AI 是调用者）的细则。

## 规则

- 一切权威写入只经接受结果：动作的执行、数据同步与管道的事务、资源的保存。没有第四条路。
- 对象只经动作写入。界面、自动化、函数、智能体都调用动作；同步与管道写数据集，不写对象。
- 对象读取只经对象集（ObjectSet）；条件只用 Expr。
- 函数只计算，不写入。需要写入时返回编辑提议，由调用它的动作接受。
- 一个动作的全部编辑原子生效，且只在一个权威内。跨权威靠版本化协议与补偿，不做跨权威事务。
- 定义带版本；产品版本里的引用固定到版本。
- 规则求值、约束检查、授权、依赖解析各只有一个实现。
- 只有一套模型：资源、对象、动作。不保留与它并行的第二套说法。
- 每种记录只有当前格式；纪元之前的形状不读取。

## 地图

| 领域 | 拥有的概念 | 对外提供 |
|---|---|---|
| 资源 | 资源标识、项目、文件夹、生命周期、工作状态、分支、提案 | 创建、保存、移动、归档、引用解析 |
| 类型（本体） | 对象类型、属性、关系类型、接口、共享属性、值类型、动作类型 | 类型描述、类型检查 |
| 对象 | 对象、编辑事实、索引 | 对象集查询、对象读取 |
| 动作 | 动作执行 | 校验、执行、副作用调度 |
| 逻辑 | 函数与其制品；自动化与其运行 | 函数调用；条件监听与效果 |
| 工作 | 工作项、通知 | 收件箱、投递 |
| 组织与安全 | 成员、团队、组织单元、业务角色、标记 | 主体解析、授权决定 |
| 交付 | 产品、候选、产品版本、安装 | 打包、安装、升级 |
| 数据 | 连接、数据源、数据集、管道、调度、回写、媒体集、血缘 | 数据集读取、血缘、生效标记 |
| AI | 模型、智能体、检索源 | 模型调用、智能体运行 |

依赖方向：组织 ← 资源 ← 类型 ← 对象 ← 动作。数据经数据源喂给对象。逻辑、自动化、AI 只经动作与对象集使用对象。

## 资源

资源是一份定义。每个资源都有：不可变的标识 `ri.<服务>.<租户>.<种类>.<id>`、种类（决定谁编辑它）、
唯一的项目与文件夹、可被引用的稳定名、显示名、版本（每次保存到 main 加一）、状态与它自己的定义体。

- 状态：`new`（从未保存到 main）、`active`、`archived`。删除只对 `new` 开放；归档可恢复。
- 生命周期：新建 → 保存（main 上成为新版本；分支上写分支）→ 发布（编入生效的版本，业务用户此后才用到）→ 归档。
- 引用：资源之间按标识引用。保存时检查被引用者存在且调用者可见；被引用者归档时引用方得到提示，不级联。
- 权限归属跟项目走，不在单个资源上另设角色。

## 类型

- 对象类型：稳定名、显示名、复数名、显示字段、字段列表、状态与允许的转换、数据源（可以没有）。
- `GET /v1/actions` 公布 `build.object.edit` 的对象类型编辑参数。`display` 选择显示字段。`fields` 整表提交，行包含 `name`、`title`、`type`、
  `required`、`search`、`choices`、`ref`、`group`、`aside`、`when`。`states` 在同一对象类型记录上声明状态的 `name`、`title`、`tone`、`description`。
- 转换定义在 `build.actiontype` 资源上。`build.actiontype.edit` 的 `definition` 包含动作名、标题、起始状态 `from` 与事务 `transaction`。
  事务通过更新业务记录的 `state` 执行转换。对象类型用 `actionTypes` 绑定动作类型的资源引用，发布时使用绑定的版本。
  安装到没有这条动作类型的租户时，按包里随对象冻结的定义建出它，作为该租户的第 1 版。
- 一个事务可在同一权威里新建与更新多条记录，一次接受全部生效。没填的可选参数与条件不成立而跳过的步骤，其值为空；
  算出为空的赋值不写入：新建时字段留空，更新时保持原值。
- 对象自己声明的只读字段，人不能改，只由它的动作事务写入（公式与读别名除外）。
- 动作可声明 `open`：对象的一个引用字段。动作被接受后，界面打开这个字段指向的记录，例如事务新建并写进来的那条。
- 对象类型单条读取的 `changes` 比较已发布定义。字段用 `fields.<字段名>` 标识，新增、删除、修改分别返回 `added`、`removed`、`changed`。
- 字段类型：`text`、`longtext`、`integer`、`decimal`、`money`、`boolean`、`date`、`datetime`、`choice`、`tags`、
  `reference`（引用另一类型）、`references`、`member`（租户成员）、`lines`（明细行，行有自己的字段）、`attachment`、`json`。
- `choices` 用逗号分隔可选值；写成 `值:显示名` 给值起显示名。显示名随类型发布与安装，看板、筛选与输入框都显示它；存储与条件只用值。
- 成员字段保存成员标识，记录新建和编辑时核对标识属于当前租户。列表和记录读取在 `refs[字段][标识]` 中返回资料里的显示名，只为调用者可读的字段解析。
  租户成员通过 `GET /v1/member-directory` 查找有显示名的在职人员；这个读取只返回标识和显示名。没有显示名时，界面显示“未命名成员”。
- 字段可声明：必填、只读、可搜索、默认值、帮助文字、在另一字段取某些值时才出现。带 `when` 的必填只在条件成立时必填。
  一次编辑让某字段不再适用时，宿主把它清空，除非这次编辑同时给了它值。
- 字段可声明 `from`（表达式）：新建时字段为空就按它求值；编辑时它读到的字段变了、而这次编辑没有给这个字段值，就重算。字段仍可手改。
  例如商机概率随状态取默认值，赢单或输单时写入关闭日期。
- 作者可为对象字段声明 `group`（分节）和 `aside`（右栏）。这两个可选属性随类型发布，只改变呈现位置，字段的读写权限照常生效。
- 类型的可选 `view` 随发布与安装进入类型描述。它是带 `version` 的 JSON 对象，由前端解释；省略时使用界面默认值。
- 关系类型：两端的类型与基数。接口：一组共享字段的形状，类型声明实现它，对象集可以按接口查询。
- 共享属性与值类型：跨类型复用的字段定义与带约束的基础类型。对象类型组只用于浏览，没有语义。
- 状态是流程的唯一表达：类型声明一个状态字段与允许的转换，转换只由动作执行。
- 兼容性：删字段或改字段类型时，保存前列出依赖它的已发布下游。

## 对象

- 身份：类型 + 主键。
- 构成：数据源投影出的行，加上动作产生的编辑事实（按字段、只追加）。同一字段上编辑事实优先。
- 只由动作创建、没有数据源的类型是合法的；业务应用里的多数类型就是这样。
- 来源删掉某行时归档对应对象，除非它由动作创建；来源重新提供时恢复。存在映射错误或被拒绝的批次不据以删除对象。
- 索引是派生的，可重建，支撑筛选、排序、聚合与搜索。
- 保存视图默认仅自己可读。所有者可显式改成项目或租户共享，共享的是定义；底层记录与字段仍按调用者授权。
  置顶和个人默认按成员、类型保存；打开共享视图不写偏好。保存视图不进产品发布，项目里的对象集查询有自己的版本与权限。

## 动作

动作类型是独立的资源，有自己的版本；对象类型只保存对它的引用。发布时把选定的动作版本编入对象的执行映像，
历史执行与恢复不读最新草稿。交互调用者必须能读取动作的起始状态字段，才能预检或执行该转换。

动作目录中的可选 `reverse` 指向回程。作者定义的业务对象可归档和恢复；成对且只改状态的转换也有回程。回程仍需原记录与当前修订，按自身动作授权。

| 部分 | 内容 |
|---|---|
| 参数 | 带类型；默认值可以是常量、当前用户、当前时间、对象字段；可见与必填可依赖别的参数 |
| 规则 | 有序：创建、修改、归档对象；增删关系；累加数值；分配编号；有界循环；调用查询；函数支撑 |
| 提交条件 | Expr 条件，每条带失败时的文案；对参数、目标对象、当前用户求值 |
| 表单 | 参数的呈现顺序与分组 |
| 副作用 | 工作项、通知、回写 |

执行顺序：校验参数 → 授权（业务角色加目标对象的读写权限）→ 提交条件 → 规则得到编辑集 →
准备工作项与副作用意图 → 一条接受结果原子写入 → 调度副作用。每次执行有请求键，重复提交返回同一结果。

每个类型自带三个标准动作：`<类型>.create`、`<类型>.edit`、`<类型>.archive`。带状态转换的动作声明它从哪些状态可用。

## 逻辑、自动化、工作

- 函数：代码函数（受控编译、隔离执行）、决策表、模型调用块、逻辑流。输入输出带类型；无副作用；读取受调用者权限约束。
  每次保存生成不可变的制品版本。
- 自动化：条件（对象集变化、时间计划、阈值）加效果（执行动作、通知、回写、运行函数）。
  以发布它的成员的授权运行；发布者失去权限时暂停。告警就是带通知效果的自动化。
- 工作项由动作创建、由动作关闭；审批是带“批准”“驳回”动作的工作项。评论是内置动作产生的事实，显示在记录页的活动里。
- 通知由动作副作用与自动化效果产生，站内与邮件投递。
- 通知生产方写入 `category`。评论中的点名和关注记录收到的新评论是 `mention`，工作项、审批和接手指派是 `assignment`，
  记录变更、自动化告警、状态更新和提醒等是 `system`。旧通知缺少类别时读取为 `system`，保留原接受映像。

## Expr 与对象集

- Expr：带类型的表达式语言，用于提交条件、行策略、筛选、自动化条件、可见性、派生值。
  一个解析器、一个类型检查器、一个求值器，前后端共用。
- 对象集：起点（类型或接口）→ 筛选 → 沿关系转到 → 集合运算 → 排序、聚合、分页。授权在每一步生效。筛选条件写作 `[字段, 操作符, 值]`；操作符支持 `=`、`!=`、`<`、`<=`、`>`、`>=`、`in`、`not in`、`like` 及对应的前缀、后缀形式。
- `attachment` 的值是 `{mediaSet,item}`；上传先得到内容摘要，再把条目加入媒体集的新版本。记录读取与编辑使用同一对标识，文件字节仍按媒体集读取权限授权。

## 安全

任何主体对任何数据的任何操作，都由同一条决定路径给出允许或带原因的拒绝。

- 默认拒绝；每个拒绝带可翻译的原因。各层同时满足才允许。
- 标记是强制的：包括管理员在内，谁也不能绕过，只能被授予许可。
- 导出、派生内容（摘要、检索）、AI 上下文与直接读取适用同样的规则。
- 写入类决定与所有拒绝进入审计。

| 关口 | 判断 |
|---|---|
| 租户 | 主体与数据属于同一租户 |
| 主体 | 主体有效且活跃 |
| 动词 | 持有该动作的业务角色，或类型级的读写角色 |
| 项目 | 主体在资源所属项目里的角色足够 |
| 标记 | 主体获准数据上生效的每一项标记 |
| 行 | 对象满足行策略 |
| 字段 | 涉及的字段可读或可写；单条记录为受限字段保留名称、标题与位置供界面排版，值仍隐去 |
| 派生 | 派生内容的来源全部可读 |

三层权限互不替代，业务角色另管动作：

- 项目角色（管资源）：发现者只看到名称；查看者能打开；编辑者能改、归档、移动；拥有者管访问。可带截止日。
- 标记（管数据）：一个有序的分级 `internal < confidential < restricted`，加互相独立的专项标记。
  标记沿血缘向下游自动传播，取最严格者；只能经管道里显式的解除步骤移除。受限数据不导出。
- 对象策略（管行与列）：行策略是 Expr；字段声明读者与写者。策略随类型版本化，进入产品包。
- 业务角色（管动作）：由产品包或租户定义，可限定组织单元与起止日期。与项目角色互相独立。

访问申请：成员申请项目角色或业务角色，由拥有者或管理员审批；审批在同一条接受结果里写入授权，下一次请求即生效。
申请人不能审批自己的申请。

| 特殊主体 | 规则 |
|---|---|
| 自动化 | 以发布者的授权运行 |
| 智能体与助手 | 以调用者的授权读取；不可用于 AI 的字段隐去；写入只经动作并需调用者确认 |
| 支持访问 | 成员开启限时授权，到期自动撤销，全程审计 |
| 宿主运维者 | 默认读不到租户数据，只管租户生命周期 |

## 变更与交付

- 保存与发布是两步：保存改的是定义，留下的是草稿；发布把一组已保存的定义冻结并激活，业务用户此后才用到。
- 工作状态：宿主为每位构建者保留的一份未保存编辑，别人看不到；给要攒一批再保存的画布类编辑器用。
  由类型生成的界面不用它，字段就地保存。
- 分支只覆盖定义，不覆盖数据。分支上的保存只写分支；合并是一条接受结果，检查在分支的暂存世界里运行。
- 提案：请求把分支合并到 main，带差异、自动检查结果、审阅者。合并需检查通过并有一位非作者批准。
- 产品：一个项目里可交付资源的集合，加声明的产品依赖。候选：某一时刻内容的完整冻结。
- 产品版本：不可变、内容寻址、带语义版本号，记录内容哈希、依赖的版本范围、所需的业务角色与标记。
- 安装：只从版本目录选版本；先解出依赖闭包并在审阅里列出顺序与精确版本；各产品分别安装，失败停在当前产品。
  安装不自动授予角色，不写业务记录。
- 受管项目：安装进来的定义只读，只能被升级替换。连接地址与凭据引用是租户自己的配置。
- 客户扩展：放在客户自己的项目里，可实现受管接口、给受管类型追加字段、新增动作与页面、引用受管资源。
- 升级：算出新旧差异 → 检查每个客户扩展是否仍有效 → 审阅 → 一条接受结果切换。不兼容就阻止，并说明先改哪个扩展。

## 产品包

`GET /v1/applications` 和 `POST /v1/page-view` 中的应用共用 `menu`，按应用分节投影可读页面。每个入口有页面名及可选的对象类型。
包退役后撤回应用入口与贡献动作，保留记录与历史。已发出的应用记录链接经宿主校验读取权限后指向同一对象记录，直接提交退役动作会收到退役原因。

包拥有定义，租户拥有记录。安装、升级、卸载只改变定义与执行入口，不复制也不级联删除租户数据。

- 同一个 `id@version` 不能被替换。版本只能从已保存的候选冻结；市场只消费产品版本。
- 升级、降级、回滚是三个动作，都只替换受管定义。升级只允许新增可选字段；
  改类型、改必填、改约束、删非代码动作必须在接受前阻止。
- 卸载是归档：归档受管定义与项目，保留客户数据、引用、扩展、凭据引用、历史与包制品。
- 重装恢复同一精确版本的受管定义与项目，保持同一项目标识、资源标识与业务记录；不重跑初始化，不自动授权。
- 永久删除是独立的危险动作，只删包自己的归档物与安装记录，不删租户数据。
- 依赖的包先装，卸载按反向顺序。包里引用未声明的内部资源是发布错误。
- 行业包之间只经对象接口、动作或版本化查询协作，不共享内部资源。

| 类别 | 卸载 | 重装 | 永久删除 |
|---|---|---|---|
| 类型、动作、页面、连接定义、受管项目 | 归档 | 恢复本包的定义 | 只删包拥有的 |
| 对象与业务记录、数据集、媒体、文件 | 保留 | 继续使用 | 不级联删除 |
| 运行、接受结果、审计 | 保留 | 保留 | 默认不删 |
| 客户扩展、客户项目、连接地址、凭据引用、授权 | 保留 | 保留，需确认配置 | 不随包删除 |

作者态源：每个包在 `deploy/packages/<id>/`，一个资源一个文件；`make packages` 生成制品与锁文件，
`make check` 校验它们没有过期。顶层的 `deploy/packages/*.json` 是生成物，不手改。各个包自己的边界写在 `deploy/packages/README.md`。

外部定义的转换（Frappe 应用）是仓库里的构建工具 `scripts/frappe-read.mjs`，不是租户里的能力：

- 只读来源的定义，从不执行来源里的代码。能转的是结构；控制器、客户端脚本、报表、打印格式不转，行为用动作与函数重建。
- 许可随来源走：Framework、frappe-ui、Studio、Builder 是 MIT；ERPNext、HRMS、Lending、Webshop、Education 是 GPLv3；

## 数据

数据这一块冻结在现状（[plan](plan.md)），这里只记对象依赖的概念。

- 数据集是带模式的表，每次写入是一个事务，形成新版本，旧版本可读。
- 数据源按声明的连接与周期把外部系统的行拉进数据集或对象；管道是确定性的变换图，输入输出都是数据集版本。
- 血缘由这些声明推导。授权用的保护标记按已接受、已执行的定义推导，保存但未激活的改动不降低保护。
