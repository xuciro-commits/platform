# 架构

解释**当前真实存在的系统**：分层、模块、写入路径、数据归属与实现位置。稳定行为与不变量集中在 [OpenSpec 模块规范](../openspec/README.md)，内核精确语义仍归 [contract/spec](../contract/spec/README.md)。下一步做什么归 [WorkQueue](WorkQueue.md)，为什么做归 [Intent](Intent.md)，工作方式归 [AGENTS](../AGENTS.md)。发现代码与规范冲突时明确指出并修正；自动检查、实际运行、使用体验和生产容量分别确认，不能互相代替。

## 1. 分层

| 层 | 内容 | 位置 | 变更条件 |
|---|---|---|---|
| 内核契约 | K1–K9：身份、事实、决策、权威、租户策略、模式演进、连接器、工作所有权。语言中立 | `contract/`（protobuf、语义规范、JSON 向量、Go 参考实现、Lean 模型） | 语义确需演进时，先更新规范与跨语言向量 |
| 宿主运行时 | 租户组合、提交管线、持久化与重放、快照、记录存储、受属工作、效果分发、模型调用 | `capabilities/server/`（包 `platformserver`） | 平台需要新机制时 |
| 应用 API | 应用唯一可见的表面：`Member`、`Caller`、`Manifest`、生命/动作/读取/流程/智能体/作业/设置/效果声明、`Ledger`、`Runtime` | `capabilities/server/platform/` | 应用需要宿主尚未提供的能力时 |
| 平台应用 | 跨行业通用能力：`ai`、`build`、`core`、`enterprise`、`files`、`flow`、`knowledge`、`relations`、`work` | `capabilities/server/apps/<id>/` | 该能力所属的语义需要扩展时 |
| 协议 | 应用之间唯一允许的耦合：由资产声明版本化接口，平台检查契约和映射 | 应用包中的协议声明；`capabilities/server/platform/protocol.go` | 提供方或消费方的受控接口变化时 |
| 业务应用 | 通过平台声明表达业务任务；包内对象、动作、规则、流程与页面可由构建者修改 | `deploy/packages/` | 保留业务任务或通用构建能力变化时 |
| 部署装配 | 同一平台工厂装配能力，两个实例由租户与包配置区分 | `capabilities/server/composition/`、`cmd/platform-server/`、`deploy/local/` | 平台能力组合或部署配置变化时 |
| Web | 工作区、构建者应用、治理应用、共享 UI | `web/apps/`、`web/packages/` | 界面职责变化时 |

内部模块按职责分工，不各自建立提交或执行入口：

| 模块 | 实际责任 |
|---|---|
| `internal/construction` | 唯一构建声明、正规化、纯编译与变换；不持有 Tenant、网络或实时业务状态 |
| `internal/acceptance` | 结果封套、版本解码、共同变化计划及纯校验；租户锁、持久接受与应用仍由宿主协调 |
| `internal/records` | 冻结映像、历史引用、私有覆盖和索引；授权裁决和提交不由它另行承担 |
| `internal/enterprise` | 企业声明、元模型和纯关系规则；完整 UAF 原件保留，标准解析在生成阶段执行，运行加载生成数据 |
| `internal/agents`、`internal/aistate` | 已授权上下文编排、预算及纯计量变换；真实模型调用和运行仍归原应用/宿主 |
| `internal/host` | 宿主消费者所需的具名窄角色；不另存构建模型或复制应用执行器 |

Build 的有界区间、完整明细记账与余额结果引用仍由 `apps/build/transaction*.go` 的原事务解释器执行；集合迭代可沿类型化引用读取同一归属记录的完整声明集合，保存实际读取顺序，仍使用原权限与预算。纯日期/小时运算归 `internal/rules`，关闭期间策略归 Core。原事务编辑器直接编辑这些声明，生成的宿主类型与浏览器规则模块由原工具产生。联合发布在隔离安装视图登记完整候选后检查跨对象引用，不要求构建者先发布临时对象。

对象计算字段、业务约束与事务分别保存自己的集合读取绑定；原构建器可选择声明集合或查询的确切版本、主体记录键和完整/可见范围，表达式源码与可视化写同一草稿。查询主体键可以显式读取获权的 `$subject.field`；记录 `id` 是只读身份元数据，不伪装为可授权业务字段。Build 自己的原生确认记录仍由原权限投影，声明查询不赋予其他应用的内部读取权。已类型化草稿的正规化不要求依赖先发布，完整候选检查承担最终类型、集合和归属检查。

完整子决定在返回调用者前检查延期业务约束；子拒绝回退到原私有保存点，未完成的外层事务仍在自己的完成边界检查。事务集合见证按实际子收据和步骤归属封存，旧接受结果继续按原格式验证，不将旧历史重写成新格式。

每次实际授权仍执行原检查；封存时只合并请求、角色、决定及定义摘要完全相同的重复证据，不改变事务预算或省略不同结果。普通记录的空集合默认值不进入冻结的 `ReleaseAsset` 内容，确认与发布继续比较原描述的确切字节。

## 3. 写入路径

所有改变权威状态的新写入只走一条路径：

```text
调用者（成员 / 服务账户 / 智能体 / 连接器 / MCP / A2A）
  → 认证、当前角色与策略（需要审批的动作先保存审批请求）
  → 单租户提交范围内作私有决定、校验所有参与变化
  → 封存接受结果 → 持久接受 → 纯应用 → 返回原答复
```

- `Tenant.Submit` 与 `Tenant.Input` 是提交、输入入口；Work、Effect、Agent/用量、发布与宿主管理保存各自的接受结果，共用相同顺序，没有另一条普通直接修改路径。
- **只有实际需要外部读取、模型或制品 I/O 的执行**才先在锁内固定定义、主体、输入和世代，锁外完成有界 I/O，回锁复核当前权限、版本及前驱后接受；普通记录写入不必经过锁外 I/O。效果意图与业务结果先一起保存，实际投递随后进行。
- `accepted_*.go` 保留各结果族语义，`internal/acceptance` 承担共同格式与变化计划；存储接线不选择另一套业务规则。接受前失败丢弃私有变化，不提前发布通知或效果。
- 同一幂等键重试复用原答复，同键异内容拒绝；新事件不能仅因内容相同而复用旧身份。提交答复未知时先查询原键，不能当成确定失败重做决定；提交或应用状态无法确定时停止该租户，沿原恢复入口处理，其他正常租户继续服务。

## 4. 数据归属

| 类别 | 内容 | 位置与恢复责任 |
|---|---|---|
| 正式接受记录 | 顶级接受结果、原请求/答复（包括拒绝）、收据与租户日志位置 | PostgreSQL 日志及运行状态表；原字节和顺序保留，重试不能产生另一个结果 |
| 正式当前状态 | 当前记录映像、历史增量与链头、业务唯一键，以及原归属方封存的定义、编号、工作、效果与状态值 | 与接受结果在同一 PostgreSQL 事务保存；存储只保存归属方给出的变化，不解释业务。它们不是异步投影或可随意丢弃的内存副本 |
| 运行协调与恢复映像 | 定义目录、归属方私有运行状态、当前请求的记录覆盖 | Go 保留必要状态与工作集。SQL 检查点保存归属方状态、位置和记录摘要，并固定该位置的 SQL 读取归档；恢复再应用已保存的日志后缀并比较正式状态 |
| 可重建投影/索引 | `tenant_<id>` 只读查询表、知识向量及其来源 | 与正式状态区分；通过原定义、原数据重建，仍执行当前权限。向量重建可能需要嵌入成本 |
| 受控外部字节与部署配置 | 文件、数据集及编译制品字节；模型抄录按保留策略保存；凭据由平台加密托管或部署环境提供，定义只引用凭据名 | 数据表、RustFS/对象存储、部署环境；日志中的摘要和引用不能代替实际字节或凭据 |
| 易失状态 | 心跳、上次连接诊断、端点健康、个人读取审计（近 5000 条） | 内存；不代替已接受的工作进度、attempt、generation 或业务证据 |
| 代码声明与租户定义 | 代码应用的 Manifest/对象/动作/协议；构建者保存并发布的版本化声明 | 前者随二进制，后者归原定义 owner 及正式发布状态；租户定义不是重新编译进宿主的 Go 代码 |

业务记录与事实归各自权威，SQL 事务不扩大跨应用原子性。完整备份/恢复须同时安排正式数据库、引用的对象字节及必要部署配置；“备份日志”不等于备份完整运行环境。内存/文件模式保留原用途，共用相同决定与结果应用规则。

SQL 当前记录按固定事务视图分批读取，私有决定叠加本次变化；Go 不常驻完整当前记录或唯一键集合，也没有跨请求全局行缓存。数据库位置必须等于宿主完整应用的位置；提交后先完成应用，再允许下一次读取视图，不能过滤较新行来伪造旧视图。普通编辑只接续版本化历史后缀；显式历史读取、首次转换、检查点比较及复杂查询仍可能读取大量数据，不承诺所有查询只读一页或全宿主固定内存。

首次转换与兼容恢复在固定日志位置比较记录、历史、键和归属方状态；差异使该租户停止服务，不能覆盖差异后宣称恢复。SQL 检查点、可移植完整快照和旧日志恢复有各自格式责任；恢复资格取目标租户固定启动组合及归属方格式，未声明格式的归属方与旧快照保留原二进制限制，其他租户增删不决定本租户兼容性。

## 5. 并发与持久化

- **每租户单写者**。`mu` 拥有决策通道、已安装定义、智能体运行捕获与接受结果应用；`opsMu` 保护队列、连接器、设置、通知与效果。`mu` 可短暂进入 `opsMu`，反向不允许。来源运行器用 `streamMu.TryLock` 先于 `mu`；决策通道从不等 `streamMu`。完整义务见 `capabilities/server/doc.go`。
- **锁外 I/O**：只捕获固定定义、主体、来源与世代；回锁复核后再接受。没有统一的串行 I/O 执行器。
- **结果未知**：外部效果不承诺跨系统 exactly-once。允许幂等重送的操作沿原键重试；危险设备动作未知时转入回读或人工处理，不能套用自动重发。请求已送达、设备已执行、业务已确认是不同状态，各自保存证据。
- **确认完成**：声明可将完成动作限定为原 Confirmation 收据调用；普通目录不展示该动作，直接提交也不能伪造收据。原完成调用仍复核申请者的当前角色和记录权限，不提升为自动化身份。联合发布解析同一候选中的 Writeback/Source，运行使用原冻结请求及来源核对。
- **历史兼容**：旧日志、定义版本、映像格式、拒绝答复、幂等冲突及在途实例保留读取责任，退役不等于删除。旧格式先按原规则验证原字节，再由映像归属方显式转换；未知格式拒绝，不关闭严格解码、不改写原历史。新格式切换不自动允许旧二进制回退。

## 6. 执行边界

- 草稿可以修改；已发布的定义版本、已保存候选及其依赖闭包不可变，激活安装选定内容并更新当前指针，不改写候选。应用公共入口与租户发布声明仍交给原 owner 安装，不另建执行模型。审批绑定当时的动作/对象及发布版本，Flow 实例固定启动定义；定义升级不能悄悄把它们改成新版，迁移或重定向须经过原受控决定。包安装、发布、激活与卸载也不互相代替，退役保留依赖及历史责任。
- 应用包的 `blueprint.setup` 是可审阅的初始化输入；包准备页与 `make initialize` 以操作者身份逐项调用原 owner 提交入口，不安装后台任务或自动授予角色。浏览器沿原发件箱保存每一步的固定请求键，中断后核对同一请求，不重复已确认步骤。组织样本在 Enterprise、科目在 Core、业务样本在 Build 分别接受；安装与重启不播种。
- 候选试运行的显式合成组织由原 Enterprise owner 在隔离环境维护，成员仍使用当前角色；便携计划的空任职主体绑定选定试验成员。保留版本执行只保留业务定义，授权视图继续使用当前原组织目录，不冻结已过期任职或复制正式组织到试验环境。
- 宿主不执行租户脚本。租户代码经受控编译（Go/TinyGo → WASIp1 command）与隔离执行（wazero worker，无网络、只读根、限额）进入，产物纳入同一候选/激活与接受结果。
- 计算、长等待、状态变更、推断各有唯一 owner：状态变更归 Action/Lifecycle，长等待归 Flow/Work，计算归 Operation/Compute，推断归 AI；都复用 Work/Effect 与接受结果。
- Flow 的绝对时间等待使用获权的时间戳绑定，在进入等待时固定截止时间；无法读取时间戳时走原错误分支，不把未知时间解释为立即到期。记录状态启动保持每条记录一次；可重复的业务申请使用独立申请记录保留每次原始意图。
- Observation 的状态区间读取由 `platform/observation_intervals.go` 使用同一规则求值器处理有界窗口，返回来源修订、处理版本、开放边界与未知区段；原采样只存在于外部来源及读取期间的临时输入。读取沿原连接和权限复核，独立于业务接受；数值摘要继续使用原路径。原事务的 `intervals` 步骤将紧凑结果映射为声明对象，K1 校验连续及拆并，原关系保存前驱；Flow 从这些类型化对象继续工作。格式 10 保存依据和结果映像，恢复不读取外部采样。
- 出站凭据由原 Console 治理，`credentials.go` 管理元数据、使用绑定、版本和停用；AI、连接及投递共用解析，登录身份继续归原身份提供方。平台包拥有治理，能力包可提供外部凭据库适配，应用包只引用目标环境的凭据，不携带秘密。
- 在线 `/v1/credentials/seal` 只将瞬时输入封装为带格式版本的 AES-256-GCM 密文，关联数据绑定租户、凭据及完整配置。浏览器清空原值后才通过原提交保存密文；原值不进入离线队列、普通动作历史或导出工件。Console 的私有接受映像保存密文，恢复不解密或重新封装；普通读取只返回元数据。`PLATFORM_CREDENTIAL_KEY` 独立留在部署环境，完整备份须保留它；缺失时托管使用失败，已有密文仍可恢复。
- 凭据绑定具体 AI 提供方、连接或端点及目标 origin。替换和停用沿原版本与接受机制生效，停用、未授权或解密失败不回退同名环境变量。无平台凭据记录的既有部署引用继续沿原文件/环境解析，迁入平台管理须显式配置绑定。治理入口提供加密录入和部署引用；AI 提供方可编辑并保留启用模型，检查使用原模型目录刷新。
- 模型配置仍归原 AI 应用：`AIModel` 保存能力资料、来源时间和默认参数，修订取原 ChangeRecord 的目标修订；模型启用与更新继续使用 `ai.model.enable`。目录是临时读取，缓存按租户、提供方配置、凭据修订与值隔离；只有明确保存才采用能力资料。供应商事实、适配器已实现的选项和未知值分别表达，不按模型名猜参数。
- 默认用途仍由原设置 owner 保存 `ai/app-model`、`agent/model`、`knowledge/embedding-model`；前两项的参数覆盖放在同名 `-options` 设置。智能体明确选择 `@generation` 才沿用应用模型，旧空值不自动继承。原 `AIModel.Resolve` 是参数合并与约束检查的唯一实现，宿主只解析设置引用；`/v1/ai/model-selection` 投影用途、有效配置及获权引用，接入原实时读取通道，不建立模型配置服务或额外存储。
- 新 Agent 运行、函数 effect 与评估在原接受映像中保存实际模型、有效参数和配置身份。更改默认只影响新任务；派发继续检查当前权限、凭据与限额，不静默替换或降低已接受的参数。评估身份包含有效参数。协议续接的签名块和 reasoning 内容保存在原 Agent 记录的 `read:"-"` 字段，只供 owner 自动执行及恢复；普通读取与公开回答不返回原始思考。原日志和不含这些可选字段的旧状态保持可读，旧 chat `maxTokens` 的封顶解释保留；新 options 超限明确拒绝。输入沿原估算检查，不宣称精确分词或自动压缩。
- 知识索引重建仍使用原 Embed 工作和向量存储。`knowledge/embedding-next-model` 是明确准备的目标；建完后，原设置动作同时保存活动向量空间并清除准备目标。活动空间是同一设置接受映像中的元数据，恢复不重新计算。模型配置改变时保持关键词检索，须重新准备并启用后才恢复语义检索；按原模型配置身份隔离向量空间并检查维度，不混用旧向量。私有设置检查复用原向量存储核对完整度，不建立第二个索引或调度器。
- AI 没有额外特权：使用与应用相同的 API、权限、预算与审批；模型输出在采纳前是草稿或证据。
- 当前权限同样约束历史、字段、查询/导出、AI 来源、错误详情与派生数据；保留旧定义或旧证据不保留已经撤销的读取资格。自动执行在锁外等待后也要复核当前权限。
- 新接受结果恢复只应用已保存映像与原答复，不重新执行业务规则、授权、模型或外部请求。`replay.go` 仍有旧 `submission`/原输入等历史分支，按原归属方代码和原语义读取；这是明确保留的兼容责任，不接受新普通业务，也不能将其宣称为已封存结果的纯应用或在恢复中重发外部请求。

工作区为每个宿主提供一个 Web 入口，原生应用和租户发布的应用共用门户、导航、记录读取与动作权限。Build 在 Model、Logic、Interface、Integration、Release 五个工作域编辑受控草稿，`studio-model.ts` 的同一分类驱动菜单、应用资产树、创建和路由定位；Integrator 只进入原获权的 Integration 编辑范围。Data Connection 保留连接器与端点运维、观测和血缘，治理与运行状态仍在 Control Panel、Runs、Agents 和 Host Console。是否能读草稿、运行模型或历史内容仍由当前成员权限决定。

首页与门户共用 Shell 的获权应用目录：Home 聚焦业务应用、继续工作与紧凑待办，使用、构建、管理入口通过原门户筛选，不再次罗列全部工具。Build 项目首屏直接打开当前工作域资产，原生与构建应用的概览侧栏均只保留五域，进入资源编辑器后再显示原资源树；跨域导航进入目标概览，原编辑器会话继续保留。应用上下文和编辑 owner 保留。`RecordWorkspace` 未选择时使用完整列表宽度，选择后显示详情；返回只清除选择，列表实例及筛选保留。业务任务与菜单分组由构建者的应用和 Page 声明提供，不在 Shell 或共享组件固化行业流程。

可视化和源码编辑同一份草稿，保留撤销、未应用输入和保存冲突；已有可视化表单或画布的编辑器默认展示可视化。简单自动化不能表示的合法流程转到原 Flow 编辑器，不通过简化保存丢失高级字段。对象编辑沿同一草稿分成结构、行为、规则与访问、数据与预览四个主区，旧区段链接定位原内容。页面公共属性、配置归属、端口模式与作用域、常见计划窗口及实体字段角色使用现有 Widget 清单，专用检查器保留真实的绑定和跨资产语义，不建立另一套 Schema 或画布。页面和应用复用使用原生定义与受控包；旧 Workshop 私有 JSON 迁入器已退出。作者预览在原页面执行模式中向嵌套页面继承，发布应用或子页面不能抬升为正式执行；模式、读取世代或应用实例改变后，旧异步动作链及尚未提交的表单停止接续。真实写入验收从原正式使用入口进入，隔离试运行仍由原试验 owner 承担。

`EdgeClient` 在宿主确认租户和主体后绑定该宿主的持久发件箱；会话切换终止旧发送。存储失败阻止报成功，恢复中的在发请求通过原 K5 超时转换为未知，以原键、原版本和原输入核对。身份就绪和网络恢复时各接续一次未答复请求，发送沿原发件箱串行处理，已确认或拒绝的终态不自动重发。表单与发件箱消费同一请求状态；核对未知收据直接复用已保存请求，不经过当前表单校验，也不把旧请求显示为空白编辑表单。Work 的审批申请另归审批 owner。发件箱不是离线内容缓存；应用内容准备和本地表单草稿另有各自生命周期。

记录视图向本子树提供当前获权记录，自引用直接使用该记录，不再次读取整份详情；作用域不同不能复用。字段列使用稳定单元格组件，列配置重建不会卸载引用读者。同一客户端、身份、语言和读取世代内的相同获权读取共用一个在途 HTTP 请求；完成与失败后即释放，不另建记录标题缓存，实时快照仍归 `LiveReads`。刷新不复用旧世代的在途读取，切换身份中止原客户端的读写。保存只等待本请求的原回执，恢复发件箱逐条接续，不要求先排空其他请求；其他页面的重新读取在后台接续，不延迟表单完成。

工作区的离线应用入口显式保存确切应用发布、可读任务及有限记录窗口，`kernel/prepared.ts` 按宿主、租户、主体保存快照与本地表单输入；时间和版本随内容展示。公共 Service Worker 只保存工作区静态资源，API 数据与凭据不进入其缓存。原登录会话仍承担身份，快照不授予新身份登录能力。表单重开恢复原目标、定义及预期修订；提交继续走同一 K5 发件箱，未知请求使用原输入核对。未准备内容明确需要联网；实际权限拒绝不能被缓存结果替代。

## 7. 职责归属

平台包提供通用机制，能力包提供可组合技术扩展，应用包承载业务声明、样本与验收。三者按职责组合，行业不形成额外层级；可复用业务模板仍归应用。`PackageDescriptor` 沿用同一安装生命周期，`blueprint` 携带原 owner 的可编辑声明，`runtime` 携带可信驱动；不按行业增加分类字段或执行分支。

`platform/composition.go` 是现有描述的纯依赖投影：能力身份、接口/语义版本、作用域和替换方式分别声明，缺失、歧义、循环及作用域倒置均拒绝；不保存另一套业务状态。`RuntimeCapabilities` 为一个租户实例固定规则、授权和内核实现，私有决定与试验继承它；无全局可变选择器。`RuleEngine`、编译程序、`authz.Engine` 和 `KernelFactory` 都为类型化接口；默认提供方仍调用原算法。内核接收顺序归原 `kernel.Receiver`，其 Go 参数收窄为消费接口，K1–K9 未改变。封存结果恢复直接应用原映像，不再次执行候选规则、授权或原业务决定。Host Console 在原 host 接受结果中保存实现选择和停用的原生 owner，并暂停租户。基础实现采用维护重启：隔离构造、原 owner/内核格式核验、已保存结果恢复后才接入；缺少必需实现保持维护状态。宿主管理员仍能访问独立治理入口，候选授权实现不能批准自身切换。原 owner 的路由、监听和服务绑定退出，原 codec、账本及正式数据保留用于历史和恢复；重新启用通过相同恢复入口，不重新初始化业务。

包来源经 `package_sources.go` 的有界 HTTPS 读取或本地 JSON 描述/`platform.package.v1` 归档审阅（总输入上限 96 MiB），得到内容寻址候选；候选在原文件存储保存，正式包库引用仍通过 Console 接受结果保存。确认不再次下载，同版异内容拒绝，路径身份不得包含目录穿越。`capabilities` 声明所需平台契约，与原包依赖一并预检；归档的制品逐项核验声明、类型、字节预算和 SHA-256；原生程序仍须在部署受信目录按同摘要获准，上传字节不赋予宿主执行权。安装、建立应用草稿、发布、授权与初始化是不同决定。移除导入来源仅移除包库引用，不删除封存历史。Control Panel 的包管理通过可筛选目录选择一个包，单份详情审阅确切版本、预检、下一步和卸载影响，技术制品信息按需展开；内置模块投影只归原能力矩阵。三种来源和包使用指南继续说明使用、权限、凭据、卸载与恢复边界，并提供来源、安装、卸载和基础维护主题入口。应用蓝图生成的是独立 Build 草稿；之后经原发布形成的应用归 Build 及原资产所有者，不因来源包卸载而撤销。

应用包的准备入口由 `package_preparation.go` 从原包 owner 的完整描述与当前 Build、AI、成员记录投影，提前列出全部应用、外部连接、模型、角色及初始化；已安装版本读取原封存内容，不以公开视图中收窄后的 JSON 重新编译。准备读取加入原实时查询通道，配置、授权和发布后继续原任务。`package_drafts.go` 复用同名现有草稿，归档后明确重建才分配按原请求固定的新记录 ID；逻辑名及内部记录引用仍交原 owner 绑定。草稿归档不运行发布编译，已发布保留检查不变。已发布应用的入口撤回与恢复保存于原 Build 应用状态；发现缓存随应用记录更新失效，撤回不开放旧正式深链，恢复仍使用保留的发布内容。共享资产、业务记录和独立任务不随入口撤回销毁。包的交付验收覆盖安装、使用、放弃与再建；包安装或单项依赖检查通过不能代替这条完整路径。

运行资源由 `platform.Resources` 在取得时登记逆操作，排空拒绝新使用并等待原引用，逆序清理失败保留责任以供重试；不以共享快照覆盖其他实例的后续变化。共享资源按打开请求计数，单个使用者退出只释放自身引用，最后一个引用退出才回收；外部读取与后台任务均有等待退出路径。资源清理不撤销已接受数据、收据、已发送消息或外部事实。这一边界借鉴 [Cordis 论文第 5–6 节](https://arxiv.org/abs/2608.25512)：逆操作正确性仍由提供方负责，接口与清理机制不构成任意第三方代码的沙箱证明。

工作区按当前有效贡献建立视图与记录入口，贡献退出立即卸载其视图和订阅；其他贡献保留自身输入与组件实例。当前租户的暂停、退役及基础选择保存先复用 Workspace 的未保存输入检查，操作者可返回编辑或明确放弃后继续；治理表单本身仍保留未知请求的原输入以供核对。发布与试验检查使用所选规则实现，已保存发布映像的结构核验使用固定参考语法，不在恢复时调用当前提供方重判业务。


`JournalProvider` 复用原日志与正式状态接口，交付形态要求持久日志、同事务正式状态和固定位置读取；轻量文件只承诺其原日志/快照保证，开发内存只在进程内存在。存储选择由部署持有，租户不能卸载共享连接池。PostgreSQL 查询投影仍在原适配器；没有第二个接受入口。`deploy/local/storage_handover.py` 在全体写者退出后封锁源/目标库，沿原 PostgreSQL 备份恢复，核对全部表、结构、序列和文件摘要，再开放目标。失败保留封锁；原源库持续封锁，目标出现新后缀后必须从当前权威重新交接到空目标，不能直接解封陈旧源库。部署密钥和身份配置仍须单独原样保留，操作见 [本地环境指南](../deploy/local/README.md#能力维护与存储交接)。

包卸载检查实际连接修订、历史网关地址和未结束派发；排空停止新命令，清理向原网关核验。技术确认通过原 Console 接受结果保存，绑定本次安装与排空代际，追加失败可核对重试；未知命令仍阻碍卸载。网关持久保存排空意图，重启不恢复采样或重发命令。新连接和收据使用租户范围，多个租户可共享程序而不共享会话身份；历史无范围修订保持原字节和回读键，释放须由部署明确原所属租户。停用一方仅释放自身引用，不能清除共享程序或另一方的注册。

一个定义放在哪，由四个问题裁决：换一个行业是否仍成立；同行业转型后是否仍成立；是"必须如此"还是"若干实现之一"；谁有权写、谁有权发布、哪条不变量约束它、哪项能力执行它。

平台扩展的公共表面是 `platformserver/platform`，应用间耦合由原版本化协议声明表达，客户端公共表面是 `@platform/ui` 与 `@platform/app`。

记录引用的展示（chip、详情字段、卡片）按原记录源在当前作用域内解析标题：UI 层不持有跨作用域的标题缓存，读取、撤权与恢复沿每个源自身的许可与修订推进，引用值本身始终是原 ID。导航由原应用显式传入；样本源不因获得同一个组件而取得正式记录导航。

交付交接的原对象是完整类型化选择、封存候选与冻结批次：同壳视图间沿原视图调用传递完整选择（路由只承载票据与身份），发布者消费封存候选与正式应用名，批量请求冻结原复合键和精确内容，超限在原任务明确拒绝；只有宿主已保存的拒绝结果允许显式建立新意图，传输、追加或应用失败仍按未知结果沿原键核对。解码、预算与批次上限各自只有一个共享解释。

页面与应用会话的任务身份是宿主、租户与主体加上当前页面/应用的确切版本与实例；定义集合与修订是读取世代，只刷新或遮蔽敏感读取，不销毁输入与选择。切主体、退出贡献或撤权才按原保护退出并清理不可读快照。

工作区外壳按应用作用域保留各自的停靠视图实例：切换应用只改变哪个作用域在前，不关闭面板、不重载模型、不询问放弃；未访问的作用域不挂载，隐藏作用域以原可见性属主停止测量、订阅与地址发布。未保存登记、调用、标题和关闭操作由原 Shell 以应用作用域和面板身份共同定位；首次保存由原导航完成目标解析和打开，再通过原关闭保护替换来源面板。解析失败或用户已经转向其他任务不能先销毁来源或抢回前台。关闭、切换身份与退出贡献仍是真实的清理决定。

记录列表的筛选、排序、分页与导出只表达一次有效查询：呈现层把枚举筛选交回原窗口或列表自己的查询 owner 编译，保存视图保留原固定谓词、集合或遍历、时点及个人条件；失效的保存条件明确阻止读取，不能静默扩大结果。固定谓词或排序的窗口不提供它不能执行的控件。声明式页面与通用列表复用同一组导入、保存视图与逐行标准编辑投影，页面与区段的动作限制仍然优先。区段动作的省略与空集合沿声明、封存及草稿恢复保留，不在呈现时补猜。

行业定义、组织初始化样本和业务验收属于可编辑应用资产，不在宿主、测试或启动工具中另写行业实现。平台测试以独立最小声明验证通用机制，不加载某个应用包作为平台正确性的前提。共享声明和纯编译不另建执行入口。

## 9. 自举（system 作用域）

系统源码、变更、发布与激活是唯一 `system` 租户里的受控记录。人工编辑与 AI 工具提交都经原 `Tenant.Submit`、接受结果与恢复路径；直接保存源码不会修改正在运行的进程。

- **入口与角色**：工作区 `#/self-hosting` 提供源码、提案、审阅和激活；页内“Help: self-hosting / 帮助：系统自举”解释操作次序。`builder` 可编辑和提案，人工 `publisher` 可批准及激活；受管 AI 即使被错误授予发布角色也不能批准。人工发布者可以批准自己的人工提案，不额外要求双人审批。业务租户不装配 `apps/system`，操作前须选择获权的 `system` 租户。
- **源码基线**：部署参数 `-source-root` 指向种子源码目录，或含 `manifest.json`、`files/` 的封存源码目录。种子第一次捕获为 `.build/system/sources/<digest>/`；构建使用提案固定的 `sourceDigest`，不从当时的可变仓库补文件。代码发布保留完整源码快照，纯定义发布引用同一源码基线；内核可以只读，凭据与依赖缓存不进入索引。
- **读取与编辑**：`GET /v1/system-files?search=&offset=&limit=` 返回无内容的分页索引；`GET /v1/system-file?path=` 返回单文件内容。保存草稿覆盖运行快照，原源码修订为 `0`，后续保存检查确切修订；删除追加墓碑。未知回执复用原发件箱请求及输入，确定接受后才刷新自己的已保存内容。
- **提案与冻结**：`system.change.propose` 至少包含文件或 `assets` 之一。源码携带路径、内容、修订和摘要；`assets` 引用原 Build 草稿，原候选 owner 冻结定义和依赖闭包；候选内容保存为不透明字节，SQL JSON 投影不能重组其摘要身份。旧嵌入格式只通过原候选 owner 恢复并核对原身份，历史不重写。界面从既有 `/v1/releases/drafts/changes` 选择草稿，不把正在编辑的输入冒充已保存版本。提案同时保存基线文件的修改前内容，审阅用冻结的前后映像，不读取后来的草稿冒充原内容；旧提案缺少基线时明确显示未知。AI 运行链接只取原 Agent owner 绑定的调用上下文，不信任客户端 correlation 标签。
- **定义与混合发布**：纯定义提案批准后得到 `kind=definitions` 的发布，显式激活时沿原安装 owner 热生效，不编译或重启，因此没有代码切换的取消窗口。含源码的提案由 updater 构建；混合提案的冻结定义只在代码换版成功时随同安装，失败不提前安装定义。
- **内核闸门**：`internal/systemscope` 是路径规则的唯一实现，保存与构建均复核；冻结契约、提交与接受管线、授权、记录和持久化归属，以及闸门本身。修改依赖、路径或目录不能绕过冻结规则；预算为每文件 2 MiB、每变更 20 MiB、最多 2000 文件。
- **构建与换版**：`internal/systembuild` 从封存基线物化隔离工作树、叠加文件与墓碑，以固定 Go 和 Web 构建命令生成制品。`platform-updater watch` 接续已批准的代码提案；`serve -watch` 同时持有独立监督进程。代码激活保存真实 activation ID、来源发布、目标发布及窗口；窗口结束后监督进程核对制品与健康、排空和换版，失败回滚。`finished` 使用原激活身份与稳定键回报，回执丢失不重建或创造另一激活。
- **客户端换版提示**：`HostProvider` 初始化时、每 30 秒及窗口重新聚焦时沿原客户端核对 `/healthz` 的 `release` 与 `releaseDigest`。与页面初次观察的代码身份不同时显示英中双语手动刷新提示；不自动重载、不清空编辑、不刷新整工作区。此代码身份独立于 Build 的已安装候选 ID，纯定义热激活不会被误认为代码换版。
- **保留与导出**：`.build/system/{bin,web,releases,builds}` 保存发布制品，`.build/system/sources/` 保存完整源码；`current.json` 保存选择、回滚前驱和未回报结果。制品清理保护正在运行和可回滚的版本。`make system-export RELEASE=<n>` 校验完整封存源码后导出，独立于临时构建目录；旧发布没有完整源码时明确拒绝。
- **AI**：`agent.run.start` 启动真实 `system.architect`，界面链接确切运行记录；它通过参数化 `read:system-files`、`read:system-file` 读源码，再使用原保存与提案动作，不能批准或激活。`origin=prompt` 只是来源字段，不是模型实际调用或完成任务的证据。
