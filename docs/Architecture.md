# 架构

描述**当前真实存在的系统**：分层、模块、写入路径、数据归属与不可动的边界。这里只写代码里成立的事实；下一步做什么归 [WorkQueue](WorkQueue.md)，为什么做归 [Intent](Intent.md)，工作方式归 [AGENTS](../AGENTS.md)。实现以代码为准；自动检查、实际运行、使用体验和生产容量分别确认，不能互相代替。

## 1. 分层

| 层 | 内容 | 位置 | 变更条件 |
|---|---|---|---|
| 内核契约 | K1–K9：身份、事实、决策、权威、租户策略、模式演进、连接器、工作所有权。语言中立 | `contract/`（protobuf、语义规范、JSON 向量、Go 参考实现、Lean 模型） | 语义确需演进时，先更新规范与跨语言向量 |
| 宿主运行时 | 租户组合、提交管线、持久化与重放、快照、记录存储、受属工作、效果分发、模型调用 | `capabilities/server/`（包 `platformserver`） | 平台需要新机制时 |
| 应用 API | 应用唯一可见的表面：`Member`、`Caller`、`Manifest`、生命/动作/读取/流程/智能体/作业/设置/效果声明、`Ledger`、`Runtime` | `capabilities/server/platform/` | 应用需要宿主尚未提供的能力时 |
| 平台应用 | 跨行业通用能力：`ai`、`build`、`core`、`enterprise`、`files`、`flow`、`knowledge`、`relations`、`work` | `capabilities/server/apps/<id>/` | 该能力所属的语义需要扩展时 |
| 协议 | 应用之间唯一允许的耦合：版本化接口与一致性测试 | `protocols/` | 出现第二个提供方或消费方时 |
| 参考应用 | 用行业规则验证平台；**不是产品形态** | `apps/<id>/server/`、`web/packages/<id>/` | 等价构建产物验证通过且历史责任安排后退出 |
| 组合 | 每个宿主一个解决方案，装配租户、应用与协议 | `solutions/<name>/` | 交付形态变化时 |
| Web | 工作区、构建者应用、治理应用、共享 UI | `web/apps/`、`web/packages/` | 界面职责变化时 |

内部模块按职责分工，不各自建立提交或执行入口：

| 模块 | 实际责任 |
|---|---|
| `internal/construction` | 唯一构建声明、正规化、纯编译与变换；不持有 Tenant、网络或实时业务状态 |
| `internal/acceptance` | 结果封套、版本解码、共同变化计划及纯校验；租户锁、持久接受与应用仍由宿主协调 |
| `internal/records` | 冻结映像、历史引用、私有覆盖和索引；授权裁决和提交不由它另行承担 |
| `internal/enterprise` | 企业声明、元模型和纯关系规则；完整 UAF 原件保留，标准解析在生成阶段执行，运行加载生成数据 |
| `internal/agents`、`internal/aistate` | 已授权上下文编排、预算及纯计量变换；真实模型调用和运行仍归原应用/宿主 |
| `internal/host` | 宿主消费者所需的具名窄角色；不另存构建模型或复制应用执行器 |

## 3. 写入路径

所有改变权威状态的新写入只走一条路径：

```text
调用者（成员 / 服务账户 / 智能体 / 连接器 / MCP / A2A）
  → 认证、当前角色与策略（需要审批的动作先保存审批请求）
  → 单租户提交范围内作私有决定、校验所有参与变化
  → 封存接受结果 → 持久接受 → 纯应用 → 返回原答复
```

- `Tenant.Submit` 与 `Tenant.Input` 是提交、输入入口；Work、Effect、Agent/用量、发布与宿主管理保存各自的接受结果，共用相同顺序，没有另一条普通直接修改路径。
- **只有实际需要外部读取、模型或制品 I/O 的执行**才先在锁内固定定义、主体、输入和世代，锁外完成有界 I/O，回锁复核当前权限、版本及前驱后接受；普通记录写入不必经过锁外 I/O。效果意图与业务结果先一起保存，实际投递随后进行。
- `accepted_*.go` 保留各结果族语义，`internal/acceptance` 承担共同格式与变化计划；存储接线不选择另一套业务规则。接受前失败丢弃私有变化，不提前发布通知或效果。
- 同一幂等键重试复用原答复，同键异内容拒绝；新事件不能仅因内容相同而复用旧身份。提交答复未知时先查询原键，不能当成确定失败重做决定；提交或应用状态无法确定时停止该租户，沿原恢复入口处理，其他正常租户继续服务。

## 4. 数据归属

| 类别 | 内容 | 位置与恢复责任 |
|---|---|---|
| 正式接受记录 | 顶级接受结果、原请求/答复（包括拒绝）、收据与租户日志位置 | PostgreSQL 日志及运行状态表；原字节和顺序保留，重试不能产生另一个结果 |
| 正式当前状态 | 当前记录映像、历史增量与链头、业务唯一键，以及原归属方封存的定义、编号、工作、效果与状态值 | 与接受结果在同一 PostgreSQL 事务保存；存储只保存归属方给出的变化，不解释业务。它们不是异步投影或可随意丢弃的内存副本 |
| 运行协调与恢复映像 | 定义目录、归属方私有运行状态、当前请求的记录覆盖 | Go 保留必要状态与工作集。SQL 检查点保存归属方状态、位置和记录摘要，并固定该位置的 SQL 读取归档；恢复再应用已保存的日志后缀并比较正式状态 |
| 可重建投影/索引 | `tenant_<id>` 只读查询表、知识向量及其来源 | 与正式状态区分；通过原定义、原数据重建，仍执行当前权限。向量重建可能需要嵌入成本 |
| 受控外部字节与部署配置 | 文件、数据集及编译制品字节；模型抄录按保留策略保存；凭据留在部署环境，定义引用密钥名 | 数据表、RustFS/对象存储、部署环境；日志中的摘要和引用不能代替实际字节或凭据 |
| 易失状态 | 心跳、上次连接诊断、端点健康、个人读取审计（近 5000 条） | 内存；不代替已接受的工作进度、attempt、generation 或业务证据 |
| 代码声明与租户定义 | 代码应用的 Manifest/对象/动作/协议；构建者保存并发布的版本化声明 | 前者随二进制，后者归原定义 owner 及正式发布状态；租户定义不是重新编译进宿主的 Go 代码 |

业务记录与事实归各自权威，SQL 事务不扩大跨应用原子性。完整备份/恢复须同时安排正式数据库、引用的对象字节及必要部署配置；“备份日志”不等于备份完整运行环境。内存/文件模式保留原用途，共用相同决定与结果应用规则。

SQL 当前记录按固定事务视图分批读取，私有决定叠加本次变化；Go 不常驻完整当前记录或唯一键集合，也没有跨请求全局行缓存。数据库位置必须等于宿主完整应用的位置；提交后先完成应用，再允许下一次读取视图，不能过滤较新行来伪造旧视图。普通编辑只接续版本化历史后缀；显式历史读取、首次转换、检查点比较及复杂查询仍可能读取大量数据，不承诺所有查询只读一页或全宿主固定内存。

首次转换与兼容恢复在固定日志位置比较记录、历史、键和归属方状态；差异使该租户停止服务，不能覆盖差异后宣称恢复。SQL 检查点、可移植完整快照和旧日志恢复有各自格式责任；恢复资格取目标租户固定启动组合及归属方格式，未声明格式的归属方与旧快照保留原二进制限制，其他租户增删不决定本租户兼容性。

## 5. 并发与持久化

- **每租户单写者**。`mu` 拥有决策通道、已安装定义、智能体运行捕获与接受结果应用；`opsMu` 保护队列、连接器、设置、通知与效果。`mu` 可短暂进入 `opsMu`，反向不允许。来源运行器用 `streamMu.TryLock` 先于 `mu`；决策通道从不等 `streamMu`。完整义务见 `capabilities/server/doc.go`。
- **锁外 I/O**：只捕获固定定义、主体、来源与世代；回锁复核后再接受。没有统一的串行 I/O 执行器。
- **结果未知**：外部效果不承诺跨系统 exactly-once。允许幂等重送的操作沿原键重试；危险设备动作未知时转入回读或人工处理，不能套用自动重发。请求已送达、设备已执行、业务已确认是不同状态，各自保存证据。
- **历史兼容**：旧日志、定义版本、映像格式、拒绝答复、幂等冲突及在途实例保留读取责任，退役不等于删除。旧格式先按原规则验证原字节，再由映像归属方显式转换；未知格式拒绝，不关闭严格解码、不改写原历史。新格式切换不自动允许旧二进制回退。

## 6. 执行边界

- 草稿可以修改；已发布的定义版本、已保存候选及其依赖闭包不可变，激活安装选定内容并更新当前指针，不改写候选。应用公共入口与租户发布声明仍交给原 owner 安装，不另建执行模型。审批绑定当时的动作/对象及发布版本，Flow 实例固定启动定义；定义升级不能悄悄把它们改成新版，迁移或重定向须经过原受控决定。包安装、发布、激活与卸载也不互相代替，退役保留依赖及历史责任。
- 宿主不执行租户脚本。租户代码经受控编译（Go/TinyGo → WASIp1 command）与隔离执行（wazero worker，无网络、只读根、限额）进入，产物纳入同一候选/激活与接受结果。
- 计算、长等待、状态变更、推断各有唯一 owner：状态变更归 Action/Lifecycle，长等待归 Flow/Work，计算归 Operation/Compute，推断归 AI；都复用 Work/Effect 与接受结果。
- AI 没有额外特权：使用与应用相同的 API、权限、预算与审批；模型输出在采纳前是草稿或证据。
- 当前权限同样约束历史、字段、查询/导出、AI 来源、错误详情与派生数据；保留旧定义或旧证据不保留已经撤销的读取资格。自动执行在锁外等待后也要复核当前权限。
- 新接受结果恢复只应用已保存映像与原答复，不重新执行业务规则、授权、模型或外部请求。`replay.go` 仍有旧 `submission`/原输入等历史分支，按原归属方代码和原语义读取；这是明确保留的兼容责任，不接受新普通业务，也不能将其宣称为已封存结果的纯应用或在恢复中重发外部请求。

工作区为每个宿主提供一个 Web 入口，原生应用和租户发布的应用共用门户、导航、记录读取与动作权限。Builder 在 Ontology、Workshop、Automate、AI/Code 和应用工作区编辑受控草稿；Integrator 使用 Data Connection 的连接、来源、数据集、管道和回写；治理与运行状态在 Control Panel、Runs、Agents 和 Host Console。是否能读草稿、运行模型或历史内容仍由当前成员权限决定。

可视化和源码编辑同一份草稿，保留撤销、未应用输入和保存冲突；简单自动化不能表示的合法流程转到原 Flow 编辑器，不通过简化保存丢失高级字段。页面公共属性与检查使用现有 Widget 清单，专用检查器只保留真实的绑定和专业交互，不建立另一套 Schema 或画布。

## 7. 归属规则

一个定义放在哪，由四个问题裁决：换一个行业是否仍成立；同行业转型后是否仍成立；是"必须如此"还是"若干实现之一"；谁有权写、谁有权发布、哪条不变量约束它、哪项能力执行它。

- 应用只导入 `platformserver/platform`；跨应用只走 `protocols/`；客户端只用 `@platform/ui` 与 `@platform/app`。
- 缺少能力时在归属方补齐，不在应用里自造表格、面板、审批、文件或外部调用。
- 参考应用里的平台能力先迁回正确 owner，行业规则与界面才是退出对象。
- 一个语义只有一个实现：规则求值、约束检查、授权判定、依赖解析各一份。

## 8. 不可动的边界

改动前逐条核对；与任何"顺手优化"冲突时，以本节为准。

1. `contract/` 不含领域词汇；Protobuf 不定义业务含义。
2. 内核变更先改规范与向量，再改实现；Go、Rust、TypeScript 边缘跑同一套向量。
3. 一项决策只改一个权威；跨权威原子性不存在，跨应用用协议 + 补偿。
4. 权威状态的新写入必须经接受结果；没有旁路。
5. 已封存结果恢复不重跑规则、不重新授权、不发起外部调用；旧输入分支保留第 6 节的明确兼容责任。
6. 历史永远可读，已产生的字节不重写。
7. 每租户单写者与 `doc.go` 的锁义务不变。
8. 锁外 I/O 遵守 prepare → revalidate → accept；不宣称跨系统 exactly-once。
9. 生成文件不手改：`contract/go/gen`、`web/packages/kernel/src/gen/host.ts`、`web/apps/catalog/src/gen`。
10. `scripts/boundaries.sh`、`scripts/escapes.sh` 的已知逃逸只减不增。
11. 租户扩展只走受控编译与隔离执行。
12. 替换而非增量：被取代的旧路径同批移除，不长期并存。
13. 新能力必须能被构建器用出来，否则记为未完成。
14. 已发布的定义、已保存候选、审批绑定与在途版本不被升级静默改写；编号与包生命周期不新增旁路。
15. 正式 SQL 当前状态与日志同事务保存；异步投影不能代替正式状态，恢复差异不得覆盖。
16. 当前权限约束历史及派生信息；投递、设备执行、业务确认各守自己的结果语义。
