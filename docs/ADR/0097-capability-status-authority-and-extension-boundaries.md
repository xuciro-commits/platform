# ADR-0097 能力口径、权威登记与扩展/交付模式边界

**状态：** 已接受（2026-10-10）。承接 [SRS/SOW v1.0](../Platform-Refactoring-SOW.md) AR-01、AR-02、AR-05、AR-06、AR-17（阶段 A 的归属与口径部分）；F1 的能力状态分散、F2 的交付生命周期覆盖差异、F3 的扩展机制边界由本文给出唯一口径。本文只固定“谁负责、支持到哪里、证据在哪”，不改变内核契约、运行语义、发布流程或任何对外行为。执行顺序仍只在 [WorkQueue](../WorkQueue.md)。

## 1. 问题

同一份状态摘要在多处各自维护，必然滞后：审查基线 `95c3e1c` 时，Platform §2.4、WorkQueue、多份 ADR 状态行与 Web 治理应用的实时能力矩阵同时描述“做了什么、缺什么”，其中 ADR-0047 状态行与 ADR-0046 的持续性 Flow 摘要仍写“真实输入未接通”，而同文件 §13.5 已记录受控 PostgreSQL 输入已接原消费游标/窗口、未完成的是默认图完整算子链（E11）。此外能力地图缺列已交付能力（集成织物、决策表、过账、计算字段、模块模板、角色与范围、用户域等），`org` 应用已被 ADR-0067/0068 取代但仍在 Platform §2.1 列表中。结果：功能“存在”“局部实现”“可交付”“已被用户接受”难以区分（F1），交付人员需要同时读多套边界（F2），扩展承诺没有成文的支持范围（F3）。

## 2. 决定 A：能力矩阵只有一个维护位置

- **Platform §2.4 是能力矩阵的唯一维护位置。** 每行固定五列：**能力 · 归属（唯一负责方）· 支持状态 · 处置 · 摘要与验收证据**。入口、代码路径与 ADR 链接都写在最后一列，不再单独维护“入口”列。
- **Web 治理应用的「能力矩阵」**（`web/packages/platform/src/apps.tsx`，读 `/v1/apps*` 注册表）继续由 `platform` 应用 owner 维护，是**运行期实时投影**：提供/使用的能力、角色、读取与协议。它不承载支持状态与处置，也不与 §2.4 竞争同一事实。
- 应用清单（Manifest）在运行期是权威；§2.4 是其文档投影。二者冲突时以代码/清单为事实、以修正 §2.4 为动作，不新开第三处登记。

## 3. 决定 B：支持状态与处置的口径

**支持状态**（每项唯一值，按证据判定）：

| 值 | 含义 | 判定依据 |
|---|---|---|
| 已交付 | 声明边界内实现完成，且自动检查覆盖该边界 | 对应 owner 检查通过；无已记录的未闭合使用验收 |
| 受限 | 可用，但有已声明的未闭合边界（范围、消费者迁移或使用体验验收） | 边界写在摘要与对应 ADR 的 As built |
| 实施中 | 已开工、未完成 | WorkQueue 有实际任务与停止条件 |
| 未实现 | 只有设计，未开工 | 计划写在 ADR/WorkQueue，无实现证据 |
| 退役中 | 替代路径已存在，旧路径的消费者仍在迁移 | Subtraction 或对应 ADR 记录了迁移范围 |

**处置**（每项唯一值）：**保留**（现状正确，凭证据保留）· **补全**（本项目内闭合的缺口，对应 S-01–S-05 及其必要依赖）· **整改**（职责、权威或耦合需要修改）· **迁移退出**（替代后删除旧路径；旧路径的删除与调用迁移同步完成）· **按需触发**（无当前需求，按真实任务启动）· **取消**（业务责任已消失或有替代，完成清理）。

规则：

- “代码存在”不等于“已验收”。服务端行为证据、自动路线证据与负责人体验验收分开表达；使用体验未走查的能力标 **受限**，不标 已交付。
- 缺证据的能力不得标 已交付；证据只覆盖部分入口时，在摘要写明覆盖范围。
- 本项目义务对应的能力处置为 **补全**；WorkQueue 已有停止条件的能力状态为 **实施中**。两者都不豁免 §5.2 的必要依赖。
- **按需触发**不是缺陷、**取消**不是删除许可：取消需要确认业务责任消失或有替代，且历史读取、客户数据与兼容义务保留（SOW §5.3）。

## 4. 决定 C：文档职责（权威登记）

| 事实 | 唯一维护位置 |
|---|---|
| 产品宗旨、取舍与不变量 | [Intent](../Intent.md) |
| 当前架构、分层、能力矩阵与术语 | [Platform](../Platform.md)（能力矩阵固定在 §2.4） |
| 决策、决定状态、取代关系与 As built 边界 | ADR |
| 执行顺序、依赖与停止条件 | [WorkQueue](../WorkQueue.md) |
| 检查方法与证据边界 | [Testing](../Testing.md) |
| 可执行用法 | [Apps](../Apps.md) |
| 减法/取消依据与迁移范围 | [Subtraction](../Subtraction.md) |
| 运行期的能力/协议/角色声明 | 宿主注册表（Web 治理应用只读投影） |

另订两条书写规则，用于消除 E11 一类漂移：

1. **ADR 状态行只写决定状态、取代关系，以及指向本文 As built 的链接。** 实现进度写在 As built；运行承诺与停止条件写在 WorkQueue/Testing。状态行不复述进度摘要。
2. 后继 ADR 取代前者时，两处状态行互指（ADR-0080/ADR-0095 已是例子）；同一事实不在两个位置各写一份可独立变化的摘要，跨位置只用链接。

## 5. 决定 D：三类扩展/交付模式的适用边界

平台只承诺以下三种扩展方式；“可插拔”没有超出下表的含义。

| 模式 | 装配阶段 | 适用对象 | 权限与身份 | 版本与兼容 | 退出责任 |
|---|---|---|---|---|---|
| **原生包（代码组合）** | 构建与发布二进制；宿主或工作区重新装配 | 平台级应用（`capabilities/server/apps/*`）、业务应用（`apps/*`）、协议（`protocols/*`）、前端包 | 编译期决定；租户不可改；应用只导入应用 API，跨应用走协议（`scripts/boundaries.sh`） | 随宿主版本；代码包生命周期（预检/安装/升级/排空/退役，ADR-0008、ADR-0048） | 平台维护者执行；退役后所带内容仍可读 |
| **受控定义（租户编排）** | 运行期受控路径：草稿 → 候选 → 封存 → 激活 | 对象/字段、状态与动作、访问控制、页面、流程、决策表、函数、集成记录（Connection/Source/Dataset/Pipeline/Writeback/Matching） | 租户成员按角色；受控编译与隔离执行（ADR-0044），不得在宿主执行租户脚本 | 随候选封存与激活（ADR-0039）；**集成记录当前不在候选封存与晋级范围**，是 F2 指出的差异，属本项目 补全 项（S-01/S-02） | 定义退役需保证历史读取与在途实例的迁移 |
| **包安装（租户包索引）** | 运行期宿主预检后安装 | 索引中声明的交付包 | 宿主管理员/租户管理员；依赖预检 | 版本化安装/升级/排空/退役（ADR-0008、ADR-0048） | 退役不删除历史与已读内容 |

**不做**：运行时热插拔与通用插件市场（SOW §5.3）。客户扩展不得形成长期平台私有分叉；扩展的兼容责任按上表落在对应模式 owner，不落在单个客户页面。

## 7. 后果

- 能力状态、处置与证据此后只有一处维护位置；ADR 状态行不再复述进度，E11 一类漂移没有生长空间。
- 交付人员可以只读 §2.4 判断“选定应用需要哪些能力、哪些可直接交付、哪些受限、哪些不支持”，再按最后一列定位证据。
- 集成记录进入候选封存与晋级、完整应用交付、F4 变更影响证据、D-04 权威与状态流、D-05 扩展规范随 WorkQueue 第 1、3 块继续；本文不改变任何运行语义。
