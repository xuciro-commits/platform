# ADR-0125 — XXXL：平台架构减负与代码收敛

状态：负责人授权，2026-10-17，执行中。取代 ADR-0124 中“代码行数不是配额”的目标表述；ADR-0124 其余产品意图、保证和文档责任继续有效。本文是一次有明确减量目标的大型工程，不是已完成结论。

## 决定

围绕平台的核心交付——**让 FDE 构建、发布、运行和持续修改业务应用**——重审整个仓库。保留平台必须提供的契约、模型、受控扩展、构建、验证、发布、运行、授权和恢复；合并重复责任；删除被替代实现和不再支撑该交付的机制。不要把现有目录或 ADR 当作豁免理由。

方向：

1. 每项状态、业务语义、授权、发布、执行和历史各自只有一个权威 owner。客户端与 API 只投影、调用 owner，不复刻规则。
2. 先迁移消费者，再在同一工作块删除旧路径。保留的是可证明的产品/历史责任，不是“以后也许需要”的适配层。
3. 大文件按真实边界收敛，不为行数机械拆文件；只在职责能独立测试、依赖更清楚或热路径可测量时分包。
4. 性能变化须指向实际热点，先用代表性基准/调用路径确认，再优化；不能用额外缓存、索引或抽象制造新的状态权威。
5. 前端按用户任务而非包边界整理：发现应用 → 选择资产 → 构建/预览 → 验证/发布 → 运行/处理。导航、草稿和权限只由既有主人维护。

## 减量口径与停止条件

基线使用仓库 `scripts/code-size.py` 的分类与同一 cloc 版本，统计 Git 文件中的 code 行，分别报告 handwritten production、tests、generated、build/examples 和 docs/config/data。文件搬迁、生成物、空白压缩、注释和删除测试不计生产减量；等价重写按最终 code 行净差计算。每个 XXL 工作完成后记录基线、剩余量和差值。

本轮基线（分支起点 `b6585bb`，cloc 2.06，按现脚本相同分类）：手写生产 **159,977 code 行**。挑战目标为净减少至少三分之一，即达到 **106,651 行或更少**；计划目标不授权破坏有效能力。每项删除须列出旧 owner、迁移后的唯一 owner、保留功能及检查证据。若一个候选会破坏授权、租户隔离、持久结果、确定性恢复、历史字节/重放或受支持的业务工作流，则不得以数字为由删除；记录可证明的剩余差距并继续下一个候选。

## 工作顺序

由 [WorkQueue](../WorkQueue.md) 作为唯一队列维护依赖和当前施工状态。先完成 XXL-1 的一个端到端切片并复算；随后按照真实发现调整后续顺序。一个切片必须包含实现、消费者迁移、旧路径删除、针对性检查、code-size 前后测量；仅立 ADR、拆文件、补 facade、跑全量测试均不算完成。

## 已实施的首批切片（范围有限）

- `platform/ledger.go` 的标准实体动作与生命周期转换此前重复执行相同版本准备、计算、验证和存储检查。现在共同使用 `prepareEntity`，调用顺序及 CreateTxn 的检查例外保持原状。
- Web widget 编辑器此前调用 `createWidgetDefinitions` 动态建第二份运行时表；现在编辑器表由生成的 `WidgetID` 编译期穷尽检查，实际 renderer 仅保留 `WidgetRegistry`。为不破坏已发布的 `@platform/app` metadata API，`createWidgetDefinitions` 仍保留给外部调用，但不再处于编辑器/运行时主路径；Go `platform/pageui` 仍是持久页面合约的权威验证方。

当前工作树生产 code 行为 159,955（cloc 2.06；基线 159,977，净减 22 行；生成输出不计）。变更包含 widget/Build 注册、实体准备校验、记录详情列表和发布对象解码收敛；净代码减量仍远小于挑战目标，这是启动切片，不是 XXXL 完成。

## 验收与不做事项

- 每个 XXL 主题必须提交一项实质性旧职责退场，不以文档、测试删量或目录移动抵数。
- 只跑受影响模块与关键不变量检查；未能运行的验证标明原因，不以 typecheck 推断行为等价。
- 不为架构整齐重写内核契约，不引入泛化框架、第二 runtime、通用迁移引擎或新注册表。
- UI 以真实任务结果判断，不以组件数量或 CSS 断言代替体验。
- 未验证的真实设备、生产容量和客户交付仍标为未验证。

整体完成仅在达到减量目标，或已按各主题证明继续减量必然损害必要功能/保证并报告差距，且六个 XXL 工作都有可核对结果后声明。
