## 1. 问题、目标与文档责任

平台存在同一概念跨层维护、公共机制逐类复制、历史处理成本随运行时间增长，以及状态和方法散落在大型平铺包中的问题。审计提供了有价值的方向，但部分判断已经被后续实现解决，另一些把不同业务语义误认为重复基础设施。直接应用大删除补丁会破坏现有功能和历史责任。

本次目标是彻底清理已经确认的无用代码、重复规则、重复状态、无效包装及职责混杂，使新增能力需要人工同步的位置减少。**文件搬迁、缩短行数、新增统一入口和检查数量，本身不算完成。**

| 来源 | 继续负责什么 |
|---|---|
| 原 0062（已并入本文） | 全项目整理范围、文档分工和总体完成条件 |
| ADR-0010 | PostgreSQL 正式状态、原子保存和兼容恢复的决定与已实现范围 |
| 本文 | 审计逐项裁定、具体替代设计、目标代码职责及删除条件 |
| 原主题 ADR | 各能力的语义、历史责任和合并更新的 As built |
| WorkQueue | 当前施工顺序；完成即移除，不保存完成日志 |
| Testing / Subtraction | 原检查方法 / 尚需保留的替代关系与历史责任 |

本次允许内部包重划和内部接口调整，保留应用公共导入路径、现有公开入口与业务行为；不开展全仓公共 API 改版。完成既定 PostgreSQL 转型，不引入第二数据库或永久双写。MES 与供暖交付承诺保留，不以清理为由删去原生行业能力。

## 3. 不可破坏的行为与删除标准

### 3.1 保留的保证

继承 [ADR-0038 §9](0038-build-the-capability-to-build.md#9-不可动的边界) 全部 16 条边界，特别明确：

1. 一项决策只修改一个权威；SQL 事务不扩大跨应用权威范围。
2. 新写仍经过私有决定、校验、持久接受、纯应用。
3. 恢复应用保存结果，不重新执行业务规则、授权、模型或外部请求。
4. 原历史字节、定义版本、拒绝答复、幂等冲突及在途实例继续可读。
5. 当前权限约束历史读取、查询、导出、AI、错误详情与派生数据。
6. 单租户单写者、世代检查、取消及锁外 I/O 再校验继续成立，锁义务归宿主 `doc.go`。
7. 发布、候选、审批绑定、编号及包生命周期不新增旁路。
8. 效果投递、设备执行、业务确认不能当作同一种“成功”。
9. 内部包允许调整；默认保留应用公共导入路径、HTTP 路由、请求答复语义和既有客户端行为。

### 3.2 三类代码分别处理

| 类别 | 处理 |
|---|---|
| 无消费者、无公开职责、无历史义务 | 直接删除实现、重复测试准备、配置和导出。 |
| 有明确替代实现 | 同一整块迁移消费者并删除旧普通路径，不能只新增包装入口。 |
| 承担历史、在途或公开兼容职责 | 集中为明确的读取/适配责任；停止承接新业务，保留必要实现。 |

静态扫描只用于定位。删除前确认真实宿主、组合应用、测试、Wasm、动态注册、生成器及跨语言消费者；沿用已有工具与检查入口，不新增常驻扫描平台。公开 API、必要历史读取和一致性参考实现不能仅因静态匹配少而删除。

不采纳以下做法：直接合并原始大删除补丁；把全部 Inspector 换成通用表单；把多个结果文件塞入巨型文件；删关键测试断言凑规模；压缩 JSON 作为减量；将业务翻译搬进 UI 基础库；裁剪标准原件；删除生成物却不修生成链；放宽历史校验换取兼容。允许合并重复准备与重复验证，但原历史、权限、幂等和业务场景继续有对应检查。

## 4. 提交、历史与存储设计

### 4.1 Source/Pipeline：分开事件与重试身份

| 概念 | 用途 |
|---|---|
| 逻辑记录 ID | 确定更新哪条业务记录。 |
| 输入事件/执行 ID | 确定一次新输入，还是原操作重试。 |
| 内容摘要 | 检查同一操作身份是否携带不同内容。 |
| 定义与输入版本 | 固定映射、Pipeline 和数据集的实际执行依据。 |

有上游事件号或版本时，将来源、定义版本、事件号和目标记录纳入操作身份。没有事件号的快照来源先通过现有接受结果保存一次拉取执行身份，同次执行重启后继续使用原身份。Pipeline 执行固定定义版本和完整输入版本集合，主动再次执行与失败重试明确区分。

行写入身份由执行、目标和行身份构造；内容摘要只校验同键内容，不再充当事件版本。创建/更新不靠不断拼接 `:edit:<revision>` 修补。部分完成时复用已保存行答复，未完成部分继续，拒绝不推进成功游标。

未完成执行的输入必须固定为已有不可变数据集版本、受控制品或可重读的上游版本。来源不能提供固定输入时，显式结束旧执行再开始新执行，不能用原身份读取变化内容。进度、输入引用和行结果沿原接受过程保存，不增加第二个调度器、连接存储或重试队列。

旧内容键停止产生后删除其新写分支，保留原答复及历史键读取。A→B→A 必须接受第三次输入，同事件重试则必须返回原答复。

### 4.2 日志失败与目标租户恢复资格

生产 journal 只通过可返回错误的接受结果入口写入，删除两处致命接线。`Tenant.Record` 保持现有公共签名，供本地记录与现有消费者使用；生产持久化不再依赖它表达无法返回的存储失败。现有以 `Record != nil` 判断持久化的地方改为判断实际存储接线，保留时间精度和执行限制的原有目的。

| 存储结果 | 处理 |
|---|---|
| 确定未提交 | 丢弃私有变更，返回失败，不发通知和效果。 |
| 已提交但答复丢失 | 按原键读取持久答复，完成原结果应用，不重执行业务。 |
| 提交无法确定或应用失败 | 停止该租户接受新业务及后台执行，沿现有恢复入口处理。 |
| 其他健康租户 | 继续服务；共享数据库整体故障可能影响多个租户，不宣称进程级物理隔离。 |

不能只删 `Fatal` 后继续执行。测试必须经过真实 `attachJournal` 接线，而不是仅替换测试回调。

构建身份只表示二进制。恢复资格比较目标租户固定启动组合和 owner 格式，不比较当前全部租户列表。移除 `retryTenant` 的全注册表 `CodeOf` 检查；确有旧格式用途的兼容键单独明确为历史读取责任，不枚举租户前缀猜兼容性。旧快照、未声明格式 owner 仍按原读取限制处理。

### 4.3 历史增长与记录映像演进

增加内部记录变化表示，统一包含当前冻结映像及映像格式、前驱 revision、历史数量、历史链摘要、本次历史后缀，以及必要的旧版本读取投影。普通写入、Input、Effect、Work 和批次结果均使用，不只优化一种结果族。

新格式的普通写入不得为封存、前驱检查或应用调用完整 `recordHistory()`。行工作集保存历史引用与计数，追加只处理本次后缀。历史详情和确实依赖历史的业务规则仍按需读取，不能删这些规则达到性能目标。

历史链以带格式标识、确定编码的前驱和新增项计算。旧数据在固定日志位置分批建立初始链并核对原历史；这只产生派生元数据，不改原日志。随后当前映像、后缀、历史头、原答复和日志位置在原接受事务共同保存。内存/文件模式应用相同变化语义，不再复制全量历史来完成普通前驱校验。

格式兼容遵循：

- 各结果族增加自己的新版本，不以新摘要冒充旧版本的全量摘要。
- 旧格式先按原规则验证原字节，再转换为当前工作集；封存字节与查询 JSON 分开。
- 分清结果封套、宿主/owner 快照、受控定义、业务记录映像四种版本。已有声明和投影复用，不再加平行版本目录。
- 业务映像转换由模型归属方提供；存储层不推断字段改名、删除或类型变化，不重算和篡改旧结果。
- 未知格式明确拒绝，不全局关闭严格解码；仍承担历史责任的 decoder 集中为只读用途。
- 1 MiB 接受结果限制和已有制品机制保留，不提高限制掩盖完整历史复制。

切换后所有普通新写使用新变化表示；旧格式只用于历史读取。旧全量捕获和拼接退出普通路径，不能让历史 decoder 继续承接新功能。

### 4.4 唯一约束与剩余 Ledger 查找

唯一键的空值、零值、复合字段、scope、归档和权限隐藏行为沿用当前规则。内存/文件模式复用现有不可变索引；PostgreSQL 保存同一规则产生的派生唯一键，以事务读取加私有变化检查冲突。业务归属方仍裁决，数据库约束只检查保存一致性，不形成第二套规则。

索引统一在记录替换过程维护：移除旧键、检查并加入新键；私有决定失败整体丢弃索引变化。父级 scope 变化时利用引用索引更新受影响记录。定义替换和历史恢复允许一次构建，普通写入不扫描全表。保持当前约束检查时机，不因索引重构放宽事务语义。冲突不暴露无权读取的记录或字段。

PostgreSQL 模式不在 Go 另存完整唯一键集合，防止删除全量当前记录后又形成另一份全量内存状态。一对一关系已实现的增量维护保留。

`AcceptedFor` 的 byKey/SQL archive 保留。剩余驻留因果引用由派生 ID 索引查找，接受、恢复、Fork、Compact 在同一处维护；归档前缀继续按需查询，不装载全部历史 ID。内核行为不变，相应向量和归档测试继续成立。

### 4.5 accepted_*：共用变化计划，保留结果语义

公共机制负责封套字段、确定编码、摘要、大小限制，以及记录、owner 状态、序列、工作、效果和通知的变化计划。所有参与方先完成校验，再持久接受，再应用；重复识别、提交不明及应用失败沿同一处理过程。

| 类型 | 继续由原结果族负责 |
|---|---|
| Input | 来源、独立回调与原答复，不伪造 Submission。 |
| Work | owner、generation、取消、重试与过期结果拒绝。 |
| Effect | 冻结请求、attempt、outcome、unknown 和回调归属。 |
| 发布 | 不可变候选、依赖、版本、原子激活和审批绑定。 |
| 单记录/批次 | 实际记录变化与原收据，不把不同编码当成不同权威。 |

SQL 增量直接来自同一已验证变化计划，删除再解析结果推断变化的第二套解释。各生产者迁移完成后，删除重复的新写 seal/apply 协调；保留按原摘要读取历史格式的 decoder。

只提取已有重复步骤，不引入 `any` 驱动的大注册框架，不建第二事务管理器，不把全部文件合成巨型提交文件。

### 4.6 PostgreSQL：按需当前记录与可恢复工作集

沿 ADR-0010 完成正式状态转型：PostgreSQL 保存当前记录、历史增量、答复及位置；Go 保留定义、运行协调状态和当前请求/事务实际需要的记录。第一版不新增跨请求全局行缓存，先删除全量当前记录常驻及其同步机制。

普通查询分批读取候选，再执行原业务条件、派生与权限规则；私有决定保存读取视图和变化覆盖层，嵌套决定、撤销及 fork 继续作用于该私有上下文。SQL 条件缩小候选不能代替原权限和复杂业务条件，候选不足时继续读取；私有新行、修改及删除与基础视图合并。

一致读取采用数据库事务视图：

1. 在租户提交协调范围内建立一致读事务，并确认数据库位置与已应用位置一致；同次读取固定数据库视图和对应定义上下文。
2. 数据库提交、内存应用和位置发布之间不开放新业务读取视图。数据库已提交但内存未应用时，先恢复或停止该租户。
3. 已开始读取继续使用原数据库视图，不因下一次提交丢掉旧值；视图随原请求/私有决定释放，沿原超时和取消处理。
4. 不允许简单过滤“较新记录”隐藏下一次提交，否则会漏掉旧视图中本应存在的记录。

已转换租户从 SQL 分批核对、按需读取当前记录，不再以完整装载全部记录作为服务前提。owner 私有状态仍按原快照和日志责任恢复；不能宣称全部 owner 已数据库化。旧日志恢复继续作为历史恢复路径，常规启动不再同时维护全量当前记录内存副本。文件/内存模式保留原用途，共用相同决定、约束和结果应用规则。

“有界工作集”指当前记录不再永久全量驻留；定义、owner 私有状态、当前事务写集和调用者明确请求的大结果仍可能占用内存，不承诺全宿主固定内存。分页、聚合和内部扫描应流式处理能流式处理的内容，不以截断结果降低内存。

## 5. 代码职责与目录组织

### 5.1 目标内部模块与依赖

下面是目标职责，不是要求先创建全部目录。模块在对应实现实际迁移时建立，不能先造空层；目录移动必须连同状态、方法和消费者迁移。

| 模块（相对 capabilities/server） | 内容与边界 |
|---|---|
| `internal/construction` | 唯一构建声明、确定正规化、纯编译与数据变换；不接触 Tenant、网络和实时状态。 |
| `internal/enterprise` | 企业声明、元模型、纯关系检查及生成标准数据；企业决定仍由 Enterprise 应用承担。 |
| `internal/records` | 记录映像、历史引用、私有变化覆盖、索引及按需存储读取；不拥有第二提交入口。 |
| `internal/acceptance` | 结果封套、公共变化表示、版本解码和纯校验辅助；不拥有租户锁、调度或业务裁决。 |
| `internal/agents` | 已授权上下文的提示与历史消息编排、工具调用正规化及预算/观察结果边界；不取得记录读取、工具执行或调度权。 |
| `internal/host` | 按真实消费者需要定义的宿主角色，不再存放构建模型与运行实现。 |
| 宿主根包 | Tenant 协调、既有运行入口、公开宿主 API、HTTP 及部署装配，缩减为实际协调职责。 |

依赖方向如下，箭头表示“依赖”，各层不能因为共享一行位置而相互循环：

```text
HTTP / 部署 / 组合入口 → 租户提交、运行与恢复协调
租户协调 → 宿主消费者角色、记录模块、接受结果模块、纯编译模块
平台应用 → 所需宿主消费者角色、所属声明/纯编译模块、公共应用 API
内部声明与机制 → 所需公共应用 API / 内核契约 / 存储接口
公共应用 API / 内核契约 不反向依赖上述宿主和具体平台应用实现
```

构建声明和企业声明为单一来源，不放进公共 `platform` 包制造新的大杂烩。Build 负责作者输入正规化、编译检查、候选产生和受控声明安装；Host 负责当前主体授权、锁、接受结果、真实 I/O 及运行恢复。Source/Pipeline 的纯解码与变换可在构建归属内复用，网络读取、游标接受和重试仍归原运行者。

`apps/build/values.go` 及企业内部成套别名随真实消费者同批迁移后删除。类型移动保持 struct 字段顺序、tag、JSON 形状、反射生成名称及原冻结定义字节。必要授权、锁和原 owner 调用包装保留，不按是否“只是转发”判定其价值。

记录授权策略由原授权方通过具名窄接口提供，记录模块不接收能访问整个 Tenant 的巨大接口；接受结果模块只产生和检查变化，持久化与应用由原租户协调者承担。不为了破除循环增加第二套模型、无类型回调总线或逐字段转换。

在核对提交，宿主根目录直接平铺 226 个生产 Go 文件，公共 `platform` 包直接平铺 154 个。以下行数为已跟踪源文件的文本行数（含注释空行，排除测试及生成目录），仅用于定位，不代替 `make code-size` 的正式统计。

| `definitions.go` | 1,338 行 | 声明目录、跨引用检查、页面检查、安装协调分开，纯检查移交原定义归属。 |
| `apps/build/build.go` | 1,445 行 | 对象声明、模型检查、动态类型构造、安装分别承担。 |

不是平均切行数，也不按文件前缀机械建包。一个模块的状态与方法必须有共同归属，不能只把几段函数搬到新文件，而原文件继续任意读写其全部字段。

公共 `platform` 是稳定应用入口。只移走确实可独立的内部实现，不为减少文件数创建公共子包、巨型 `types.go` 或复制模型。用于稳定公开入口的一层适配与内部无价值别名区别对待。没有实际职责收益的平铺声明不强拆。

翻译文件不按体积判定为垃圾；只删失去消费者的词条及重复机制，业务词条继续属于原模块。生成文件由原生成器维护，标准数据和生成物不计入手写生产删量。

### 5.3 前端目录、Schema 与编辑器

页面模型编辑、Workshop 页面组装、源码导入按实际职责组织；同名目录只有职责和消费者相同时才合并。纯转导出目录迁完消费者后删除，不重复导出维持两份入口。

普通 Widget 属性、配置版本、端口和公共边界规则继续来自现有 manifest。公共 Schema 检查移回公共值 Schema 工具归属，页面不依赖 Flow 编辑器实现。前端即时提示和后端权威检查可以各自执行，但规则定义不能各自维护。权限、对象/动作存在性、查询和旧 UI profile 继续由原编译与运行者检查，不能由普通 Schema 替代。

标题、枚举、展示边界等普通属性交给 Schema Inspector；变量可达性、集合查询同源、模型选择、互斥修改、动作参数及专业预览继续保留专用编辑器。不把这些行为藏进通用表单的大 switch。

Process 的加载、修订、保存、发布及错误状态复用原 Build 草稿会话。重排、重命名和删除共用模型编辑命令，同时更新控制边与数据引用。简单视图先无损识别当前 Process，不依赖条件名称固定为 `when`；不能表示的合法图打开原 Flow 编辑器，不清除 `cases/branches/body` 等内容后保存。允许添加的步骤与原模型支持一致，包括合法 compute。两种视图和源码共用同一 ID、草稿、撤销及候选发布，不新增 Automation 资产、调度或执行状态。

### 5.4 外部协同、内核、身份与 UAF

**外部协同。** Effect 继续是唯一外部投递队列、尝试及退避机制。Confirmation/Dispatch 的 due、busy、预算、锁外读取和再校验在原执行位置共享；二者保留各自候选与证据解释，不建立可注册的通用协同框架。保持已冻结 Effect ID、Key、请求字节、版本绑定及回调归属；宿主内协议沿原 Caller.Request，不强制改成 HTTP。新旧回读循环不能同时消费。

**内核。** K1–K9 规范、向量、Go 参考实现和 Rust/TS 边缘映射保留；参考实现仅由一致性测试消费不等于无职责。Go 权威目录/接收检查与边缘提交 outbox 分开，宿主不持有自己不会使用的边缘提交状态，不改变外部契约。K5 提交未知时可按原键重送，因为 K4 返回原结果；危险设备动作未知时可能已经执行，必须回读或人工处理，两者不能共用自动重发政策。拟删实现逐项确认所有语言、业务、公开及历史消费者已有承接，不删规范和向量制造无引用。

**身份。** 登录成员归身份系统，组织、人员、岗位和任职时间归 Enterprise，业务人员字段归 Core。沿已有显式引用关联，不强制 ID 相同，不建“统一人员”同步表。OrgSeed、Units、Directory 是原调用者的投影与兼容读取，不拥有第二张组织图或写入账本。清理旧 Org 注释和无价值内部别名，不以任意日期删除公开投影。

**行业错误。** Core 提供稳定的结构化投递分类及可公开提示，沿现有结果机制保存；Host 只处理 delivered、retry、rejected、unknown 等通用结果，不以英文 `closed`、`fiscal period` 判断业务状态。不开账期仍可恢复等待，开放后原键只入账一次；Integrator 不因错误详情看到私密请求或答复。历史 Journal intent 解码和原键保留，不把仍有历史职责的代码一并删除。

**UAF。** 当前标准原件在 `internal/enterprise/uaf/spec/`，规范来源说明在 `docs/standards/uaf/1.3/`；迁移保留完整原件、来源和版本。解析放入生成阶段，输出带格式版本、标准版本和来源摘要的运行时元模型，完整覆盖发现 API、构造型、枚举、属性、泛化、bases、关系端点、说明、约束及 SDK 消费。生成确定、干净检出可重现；运行只加载生成结果，不保留 XML 解析普通备用路径。版本选择和历史模型语义不偷偷升级。未来 XMI 企业实例导入仍是适配器，输出原 Enterprise 决策，不属于本次新增功能。

### 5.5 目录迁移不能绕过现有规则

扩展原边界检查以覆盖目标内部模块、子目录和全部生产源码（含当前平台不编译的 build tag）。禁止新模块反向依赖宿主根包或具体平台应用实现；已有应用公共导入、跨应用协议和授权边界继续生效。

目录移动时同步更新 Makefile、生成器、Catalog、Wasm、部署、动态注册及原组件地图，不能让只查旧根目录的脚本因为文件搬走而失效。每个模块迁完即删除原实现和失效转导出，不长期保留两套普通运行位置。原有边界检查中依赖文件路径的规则同步迁移，而不是豁免新目录。

## 6. 实施整块、依赖与迁移退出

下表定义可交付的责任边界和停止条件，**不保存执行顺序或完成状态**；当前顺序只归 WorkQueue。

| 整块 | 主要交付 | 完成与删除条件 |
|---|---|---|
| **A：正确性修复** | Source/Pipeline 执行身份、日志失败处理、目标租户恢复资格；修复简单流程视图破坏高级内容。 | 新写停止错误身份；生产追加失败不退出进程；其他租户变化不干扰恢复；合法流程不被简化保存破坏。 |
| **B：公共声明与构建器职责** | 构建声明归属、内部别名退出，Widget 剩余公共规则及 Process 编辑生命周期。 | 新字段不再逐层补别名；普通属性只声明一次；原复杂交互及发布可用；旧包装与转导出删除。 |
| **C：接受结果与历史** | 公共变化计划、新历史前驱格式、映像演进、唯一索引及剩余因果查询。 | 新写覆盖各结果族；普通编辑不读取完整历史；旧版本恢复保留；重复封存和应用路径退出。 |
| **D：宿主模块与协同整理** | 提取记录和接受结果内部模块、拆大文件、合并回读公共步骤、移除行业字符串判断、身份包装及 UAF 生成。 | 原实现和无效目录删除；边界检查覆盖新位置；不同业务状态和完整标准语义保留。 |
| **E：完成 SQL 按需工作集** | 按需当前记录、一致读视图、私有覆盖、SQL 派生索引及常规启动。 | PostgreSQL 普通路径不再完整装载当前记录和唯一键集合；记录、历史与答复进入同一正式状态机制。 |
| **F：旧实现退出与完整任务** | 删除已无职责的兼容包装、配置、依赖和词条；补数据映射与复杂编辑任务的具体缺口。 | 完整构建任务可用；剩余历史代码有明确格式责任；没有两套普通写入、执行或发布路径。 |

A 的正确性修复不与大规模目录移动混合提交。E 依赖 C/D 的记录和变化边界，但不是 B 及其他整理的前置条件。B 提取声明归属，D 再据实际依赖提取机制；相同职责不在两块里各建一个替代者。每块完成替代和删除后及时交付，不把全部清理积成一次大补丁。

迁移以租户为单位暂停写入，固定日志位置，分批建立派生数据、比较后切换。差异时保留原数据并停止切换，不能覆盖差异后宣称成功。新旧存储或新旧表达不永久双写。历史读取责任保留，原生应用按 ADR-0053 的等价与历史条件退出。

格式/存储切换必须说明回退资格：旧二进制不能读取新结果时，保留数据并使用兼容版本或向前修复，不无条件回滚。数据库备份与数据卷沿原运行方法保留，清理不引入删卷或重建真实客户数据的步骤。

## 7. 必要检查与完成标准

### 7.1 受影响行为

| 领域 | 必须覆盖的场景 |
|---|---|
| 输入身份 | A→B→A；同事件重试；同键异内容；部分行完成后重启；定义或输入版本变化；拒绝不推进游标。 |
| 日志失败 | 真实生产接线注入；确定失败、提交未知、提交后应用失败；另一租户继续工作；不提前暴露状态、通知或效果。 |
| 恢复资格 | 增删其他租户、改变注册顺序；目标组合不兼容；同格式跨构建；旧格式限制保留。 |

### 7.2 检查范围与发布

文档落盘只检查链接和 `git diff --check`，不运行业务测试或部署。代码每个完整整块结束后，按根 Makefile 和 Testing 运行适用检查：Go 宿主用 `make check` 与对应 owner 测试，应用/协议补组合检查；Web 用 `make check-web`，交付节点选受影响浏览器任务。纯目录移动不新建行为测试，也不因新文档重跑无关任务。

类型、Catalog、UAF 生成物变化用原生成流程；新 UAF 生成步骤接入原构建/检查入口，不手改生成文件。main 代码更新沿原脚本更新酒店 8495、制造 8490，核对版本、健康、实际页面资源并保留数据卷。自动检查、浏览器观察、负责人体验、生产容量分别报告；未配置真实数据库导致跳过的测试不算数据库检查通过。

### 7.3 性能、减量与扩展成本

采用固定数据和同一统计口径，集中检查：

- 单记录历史为 10、1,000、100,000 条时，下一次普通编辑实际读取历史数量、字节及分配量；结果大小随本次变化，不随完整历史增长。
- 总记录增加而本次任务规模不变时，实际装载记录数仍由任务需要决定；不以截断结果伪造改善。
- 普通唯一约束写入只处理旧键、新键及实际关联记录，不全表扫描。
- 新增一个 Source 字段、一个普通 Widget 属性、一个事务步骤，比较前后需要人工同步的独立职责位置；复用真实变更，不为指标新增产品功能。
- 使用 `make code-size REVISION=<提交>` 与同口径当前统计；手写生产、测试、生成物、标准数据、翻译分别说明，搬迁与压行不计删除收益。

历史读取量和分配量采用结构指标，必要时另测时间；不把易波动的耗时阈值塞进全部日常测试。报告原称约 17.9 万行和删除三分之一不是当前规模事实或强制配额；三分之一仅作进取方向。

整项完成必须同时满足：**确认的问题已处理，替代后的旧普通实现已删除，现有功能和历史保证保留，真实扩展成本下降，实现与文档一致。**

完整任务采用现有应用：数据接入和映射 → 对象/关系 → 动作/事务 → 页面与复杂绑定 → Flow/AI → 试跑 → 候选发布 → 操作及后续修改。检查包含原版本与当前权限、失败后重试和历史读取；不以预先改生产数据、隐藏 URL 或行业旁路完成。MES 原界面退出继续需要原有等价确认，自动检查不替代负责人体验。

## 9. 复杂度预算

第 1–8 节解决"哪些代码该删"，没有解决**为什么越删越多**：一轮审计净减 72 行，同期文档涨了数千行、入口继续增加。原因是每轮都用"再审计一次 + 再写一份结论"对付复杂度，而复杂度正由这些审计和结论维持。

本节换一种做法：把复杂度变成可执行的数字，只减不增。

### 9.1 决定

`scripts/budget.mjs` 读取仓库根 `.budget.json`，测量下列数字并与上限比较；任一数字变大即失败，进入 `make check`（`make budget` 单独运行，`--update` 写下新上限）。

| 分组 | 指标 | 说明 |
|---|---|---|
| 文档 | `docs.adr`、`docs.adrLines`、`docs.longestAdr`、`docs.statusLine`、`docs.topLevel`、`docs.lines` | 份数、总行数、最长一份、最长状态行、顶层文档数 |
| 入口 | `ui.definitions`、`ui.apps`、`ui.navItems`、`ui.navItemsMax`、`ui.views` | `defineApp` 定义数、不同应用 id 数、菜单项总数与单应用最大值、视图总数 |
| 代码 | `code.largestGo`、`code.largestTs`、`code.fullestPackage`、`code.goProduction`、`code.goFiles`、`code.tsProduction`、`code.tsFiles` | 最长 Go 文件、最长手写 TS、最拥挤目录、手写 Go/TS 生产行数与文件数（不含测试与生成物） |

规则：

1. **新增必须等量删除。** 加一个入口、一个菜单项、一份 ADR，就在同一次改动里减掉等量。
2. **`--update` 只能向下写。** 确实需要临时上调的，本次改动必须写明被删除的等价物，并在同一次改动里完成删除；不接受"以后再减"。
3. **文档预算与 ADR 索引一致。** 一份 ADR 只回答一个问题、状态行 ≤ 2 行、新 ADR ≤ 150 行。
4. **预算不是目标。** 它不衡量代码质量、功能完成或用户接受度，只阻止在同一方向上继续变大。

## 10. XXXL 重构大纲（当前主线的总纲）

本节替代"再写一批 ADR 描述怎么重构"的做法。**不新增 ADR 文件**：新开二十份互相引用的文档，正是要消除的形态。范围、顺序和验收只在本节与 WorkQueue 各出现一次。

### 10.1 方法：先量，再合并，最后删

每一块按同一顺序走完，不做只到"识别出问题"就停的交付：

> 量基线 → 找到唯一权威 → 合并实现 → 迁移调用方 → 删掉旧路径 → 跑该层能跑的检查 → 用预算锁住新数字

反模式优先级（按本仓实测，不按通用清单）：

| 优先级 | 形态 | 本仓证据 | 处理 |
|---|---|---|---|
| 1 | **同一能力两处实现** | `data-connection`、`agents` 各有两个 `defineApp`；21 个定义对 18 个应用 | 一个应用一处身份，另一包只加视图 |
| 2 | **同一职责三个入口** | 应用分类曾有：首页两网格 + 门户筛选层（已删） | 一份分类，一处渲染 |
| 3 | **巨文件承担多职责** | `Workspace.tsx` 935、`compile.ts` 882、`Records.tsx` 865、`enterprise/index.tsx` 857 | 按职责切，按测试守 |
| 4 | **平铺巨包** | `capabilities/server` 423 个文件同层 | 按协调职责分组，不按文件类型 |
| 5 | **转发层与别名** | `apps/build/public.go` 249 行纯别名，其中 109 条无人引用（已删） | 消费者直连唯一模型，只留跨模块读到的名字 |
| 6 | **完成记录冒充文档** | 本文 §8 曾有 6.3k 字逐块日志（已删） | 事实归 As built，过程归 Git |
| 7 | **双通道机制** | 前端曾同时有 `location.hash=` 与 `open()`（已并） | 一条通道，其余删除 |

**不采纳**：机械拆大文件换行数、把复杂度搬进新层、为凑指标删断言、把生成物/文档删量算作生产代码减量。

### 10.2 硬约束（不可为减量而破坏）

继承 §3.1 与 ADR-0038 §9 全部边界。特别重申四条：写入仍只有一条路径；恢复只应用已存结果、不重新裁决；历史字节与已发布定义继续可读；租户隔离与单写者不因重构放宽。

### 10.3 验收口径

- **代码量**：只统计手写生产代码，分 Go / TypeScript；生成物、测试、文档单列，不混入。
- **性能**：只在有代表性负载与前后测量时才声称改善；无测量则写"未测量"。
- **等价性**：类型检查与测试通过**不等于**行为等价；改到写入、恢复、发布、权限时，必须指出对应的既有测试或明确写"未验证"。

### 10.4 预算的例外

`make budget` 统计入口、菜单、字数、Go 生产行与最大文件。上调上限的唯一条件见 §9.1 第 2 条；做不到就缩小该块范围，而不是放宽规则。

### 10.5 本节的退出条件

当 §9.3 的条件成立（入口降到个位数、`ui.navItemsMax` < 12、不再需要上调任何上限），本节并入 ADR-0018 的界面结构说明与 WorkQueue 的常规条目，本文回到纯减法主题。

### 2. 同一职责只有一个实现

能力归属按实际写入权威、权限、定义版本、生命周期与运行责任判断，不按菜单名称或目录名判断。共享实现留在原归属方，使用方只引用；统一导航不转移资产，统一依赖描述不增加第二个注册表。

能力目录、版本详情与调用结果读取复用原授权引擎，按当前有效角色和原 owner 的策略判定；不能在这些入口另用单个主角色字符串决定可见性。历史版本保留其确切声明，但读取资格仍取当前权限。能力描述直接投影原定义，不能重复解析另一份当前定义或让目录可见性替代执行时授权。

应用成员按完整 AssetRef 呈现，不能因编辑器没有本地记录种类而从资产树消失。添加已有资产同时提供可读草稿与已发布的非导航资源；共享引用沿原应用成员修改和候选发布，不转移 owner、复制定义或增加权限。没有本地草稿的成员进入同一只读定义详情，显示名称、原版本、声明能力与依赖；正式编辑仍由原编辑器承担。

| 内容 | 收敛原则 |
|---|---|
| 平台包 | 提供契约、宿主与通用构建/运行原语，不加入行业词汇 |
| 能力包 | 提供按需安装的技术能力，沿原包、依赖、配置与运行声明参与应用 |
| 行业包 | 保存对象骨架、规则、页面、样本与行业判断；不永久寄生在行业 Go/React 应用中 |
| 应用包 | 保存客户应用及其差异，复用平台和行业资产；交付仍走原候选、版本和环境绑定 |
| 定义、配置、运行数据 | 分别由定义 owner、环境绑定和运行 owner 管理；不能为了统一资源列表混成一种可任意编辑的资产 |
| 原生参考应用与历史读取 | 等价替代前保留有效能力；替代后停止普通新写入，仍履行旧日志、旧定义和在途实例的读取责任 |

已替代的普通执行分支与其重复配置同批删除。确实承担历史责任的代码注明输入格式和用途，不借“兼容”承接新业务。找不到真实调用者或责任的抽象直接删除，不先增加包装层或通用迁移框架。

每块功能整合都要说明原来的重复职责退出在哪里、现在由谁唯一承担，并用原任务检查能力保留。只补连接而保留两套普通实现，不算代码收敛完成；确因不同语义或历史责任保留的路径须有具体依据。代码行数不是机械配额，但新增功能、通过检查和 As built 篇幅不能代替实际删除、合并和简化。
