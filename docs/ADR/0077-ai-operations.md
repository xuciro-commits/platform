# ADR-0077 — AI 运营：构建器声明的智能体、告警规则、数据集起草（ADR-0069 Ⅲ）

状态：接受并实施 · 2026-10-06 · 承接 ADR-0021（智能体）、ADR-0029 D6（评测）、ADR-0033（派生读权限）、ADR-0069 §4、ADR-0071（数据集）

## 决定

ADR-0069 §4 列的三件事，大半在平台里已有骨架：智能体运行时（每步入账、草稿需人确认、A2A、记忆）、AI 函数与评测、用量与费用计量、页面上的 AI 助手与观察组件。Ⅲ 不另起炉灶，只补三处"没有代码就做不到"的缺口：

### 1. 智能体由构建器声明：`build.agent`

此前智能体只能由 Go 应用在 `Manifest.Agents` 里声明。现在构建者在 **Functions → Agents** 里声明一个：

- 名称/标题/对外描述/私有指令；
- **工具** = 已发布对象的动作（`build.<object>.<action>`）与已发布查询（`query:<name>`）；上下文、搜索、知识、记住、提问、结束始终可用（ADR-0021）；
- **预算**：模型轮数、token、动作数、美元；
- **检查点**：即使智能体自主运行（不为某个人）也必须等人的工具——不可逆的那些；为某人运行时沿 ADR-0021 D6 一律起草待确认，不另加一层；
- **移交角色**：运行停止时接手目标、它不为任何人运行时问题去向的构建器角色；
- **评测用例**（数据而非 Go 闭包）：目标、记录、结果必须包含的文字、必须提问、必须/不得采取的动作。编译成 `platform.Case.Check`。评测由 agent 管理员显式运行，每个用例试跑三次；发布不自动执行评测，也未以评测结果阻断发布。

发布先保存接受结果，提交后安装 `build.agents[name]` 进入 Builder 的 `Manifest().Agents`；宿主的 agent 应用按 Builder 的 **stamp**（名称@版本集合）懒加载重声明（`Agents.def()`），因此发布立即生效、重启后从 inventory 恢复、不需要另一条注册路径。私有指令只对构建者或 agent 管理员可见；一般使用者的智能体目录不包含指令。运行绑定启动时的已发布版本；重新发布后，旧运行在下一步停止，旧草稿确认返回冲突，要求新建运行。当前不保存旧定义供旧运行继续执行。智能体 ID `build.<name>`，和代码声明的智能体走同一条 `agent.run.start` / 评测 / A2A 卡片。

### 2. 告警规则：`build.alertrule`

SAP Fiori 的 "Situations" 在这里是一条规则：对象 + 字段 + 运算符 + 值 + 消息 + 通知的角色 + 是否每次。宿主在每个被接受的决策之后（`raiseAlerts`，与观察者同一处）对该对象的活动规则求值，命中则给角色持有者一条带 `Ref` 的通知；通知按 `alert:<rule>:<record>` 去重（"每次"时再加 change id），回放不会重复通知。不建第二个事件引擎：它就是一次 `Notify`。

### 3. Builder Assist 的第一步：从数据集起草对象

数据集页多一个按钮 **Draft an object from this schema**：按推断出的列与类型生成一个对象草稿（一列一属性，类型映射 string→text、number→decimal、boolean、date、json→longtext），打开对象类型编辑器让人命名、修形、发布。不调用模型：这一步靠 schema 就够，模型版的"从描述生成"等真实任务的评测集到位后再做（Platform.md §10.6 AI 门禁）。

### 4. 没做的

- 不做智能体之间的编排（A2A 已覆盖外部智能体，流程覆盖内部步骤）。
- 不做"建议"作为独立对象：告警 + 智能体草稿已经是建议的两种形态。
- 不做告警的聚合/抑制窗口：先用"每条记录一次"。

## 验证

- `capabilities/server/ops_test.go` `TestBuilderAgentsAndAlerts`：未发布动作作工具被拒；草稿智能体不在列表；发布后 `build.expediter` 出现，预算默认值补齐，用例要求提问；告警规则引用不存在的字段被拒；50 不触发、150 触发并只通知 desk 一次、160 不再通知、构建者不被通知。
- 同一用例覆盖直接与接受结果路径、全日志与快照重放、私有指令读取隔离、自主检查点守卫、重新发布后旧草稿确认被拒。
