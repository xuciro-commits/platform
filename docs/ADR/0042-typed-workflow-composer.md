# ADR-0042：类型化工作流编写 / Typed workflow composition

## 状态 (Status)

Accepted implementation scope (2026-09-29, #132)。负责人在本会话授权持续按活动队列推进并直接在 main 工作；本批将 ADR-0031 D3、ADR-0040 D4 和 ADR-0020 D6 已接受的类型化可视化编排、唯一 Flow 运行时及实例版本语义落到具体编写路径。下方选择属于该授权范围内的实现选择，不变更平台方向。实现证据仅在“实际构建”记录。

## 背景上下文 (Context)

代码声明的 `platform.Flow` 已由 `apps/flow` 执行，人工任务由 `apps/work` 执行，受支持工作通过已接受结果恢复。构建器已拥有标准记录、对象动作、页面、固定样本测试及候选发布。实施前 `apps/build/process.go` 是未登记的在途草稿，没有编辑器、结果发布恢复或候选资产；不以该草稿充当租户可用流程。

2026-09-29 查阅一手依据：

| 参考 | 稳定原则 | 本批采用 |
|---|---|---|
| [Salesforce Flow 管理](https://help.salesforce.com/s/articleView?id=platform.flow_considerations_manage.htm&language=en_US&type=5) | 新激活版本用于新运行，已有运行保持启动版本；暂停实例限制版本删除 | 保留已发布流程版本，不以草稿改写旧实例 |
| [ServiceNow Workflow Studio](https://www.servicenow.com/docs/r/build-workflows/workflow-studio/flows.html) | 记录触发、受控动作编排及明确执行身份/角色 | 编译到已有运行时，权限与运行主体显式，不引入其脚本模型 |

厂商材料只提供交互/工程参考，不能证明本平台行为。

## 我们的约束条件 (Our constraints)

- `build` 拥有租户定义，`flow` 拥有运行，`work` 拥有人工任务；代码与可视化共享原生语义与权限，不新建执行器或任意租户代码。
- 先暂存、入账、安装；恢复安装已提交镜像，不重跑发布动作或外部调用。版本镜像有界且不递归包含旧镜像。
- 首批以同构建器对象的状态触发、人工任务、原生动作及类型化答案分支串起完整任务；更多节点沿相同能力主人扩展。
- 动作依赖、实例版本和操作者权限均须验证，不能只保存画布坐标或把节点图当成另一份流程语义。
- 不修改内核，不新增第三方依赖或日志类别。页面/AI/物理沙箱的年度承诺保持原范围。

## 设计方案 (Design)

1. **定义与版本。** `build.process` 是构建者私有的标准记录，指名已发布的同构建器对象、触发状态、步骤及答案到步骤的显式映射。原生创建/编辑保存草稿，发布将完整定义作为下一流程版本保存，历史镜像只包含其单版定义。已发布身份不能静默重命名或删除。
2. **规范运行与持久化。** 编译为 `platform.Flow` 的原生 Ask/Act/Choose，动作仅引用被声明的对象动作，人工收件箱及步骤追踪复用 Flow/Work。已接受发布镜像安装版本，快照先安装对象及全部流程版本，再校验运行实例。追加失败不得暴露新版本。实例保留启动版本，发布/对象演进不得悄悄改变其依赖语义。
3. **编辑与测试。** 构建者在共享 NodeCanvas 中编辑步骤/分支，在检查器中选对象状态、动作和人工角色；保存与发布使用同一记录和服务端校验。隔离测试安装相同候选定义、固定样本及人工答案，展示原生实例/任务/追踪；无生产凭据、记录或真实效果。错误、冲突、键盘、中文、窄屏与恢复都是旅程的一部分。
4. **发布闭包。** 流程资产及对象/动作依赖参与现有候选闭包、差异诊断与保存/激活。开发期安装与不可变候选激活仍按 ADR-0039 区分；不在此处伪造激活即安装或更广升级保证。完整依赖/运行绑定接入前，不把首批登记与恢复称为完整发布旅程。

## 决策点 (Decision points)

| # | 抉择问题 | 备选选项 | 采用 |
|---|---|---|---|
| D1 | 定义和执行归属 | `build` 标准记录编译至 `platform.Flow`；独立图执行器 | 已接受归属上的编译；拒绝第二执行器 |
| D2 | 答案分支表达 | 类型化映射；字符串表达式/脚本 | 显式映射，拒绝任意表达式执行 |
| D3 | 版本恢复 | 保存单版镜像及历史版本；用最新草稿重建旧实例 | 单版镜像，沿 ADR-0020 的启动版本运行；坏依赖失败封闭 |

## 影响与后果 (Consequences)

构建者可在既有对象/动作/发布基础上编写人机协同流程。成本是版本历史、依赖检查与构建器体验的维护；广义 BPMN、任意租户脚本、跨应用私有写入及自动实例迁移不在首批。完整目标保持于 Platform §10 与活动队列。

## 实际构建 (As built)

### 23a：原生定义与恢复准备 (Native definition and recovery preparation, 2026-09-29)

- `apps/build/process.go` 已登记 `build.process` 的构建者私有记录与原生创建、编辑、发布；步骤使用类型化答案映射，编译为已有 Flow/Work 的状态启动、人工任务、答案分支和同对象动作。发布校验已发布对象/状态、步骤及路径、同家族身份、名称唯一性、全量读取角色；拒绝需要审批或必填输入的动作。每家族最多 64 个平坦版本，每租户最多 1000 个流程定义；跨 500 条读取页完整检查与恢复，超界失败封闭。不提供归档/删除或迁移旧实例。
- `Build.AcceptedPublicationSchemas`、验证/应用及 `Reinstall` 接入保存的流程镜像。追加前只校验，追加后安装；恢复按旧到新安装全部已保存版本，未完成/无效草稿不能改写运行版本。缺失 Flow 应用或损坏版本家族拒绝恢复。
- `flow.Install/Validate` 共用代码声明校验，保留原生实例启动版本。`HasRunningSubject` 分页检查 running/waiting/compensating/stuck；对象定义发生变化时，已有非终态流程阻止安装该变化，原样重复发布允许。这是保守的源定义保护，不是精确不可变依赖绑定；终态实例不阻止后续变化。
- `TestTenantProcessPublicationAndRunningVersionsRecover` 覆盖追加失败不安装、同键重试、私有/跨租户/非构建者权限、原生收件箱、等待中源动作变更拒绝、旧实例继续 v1/新实例使用 v2、无效草稿快照恢复、非法分支/角色/动作/路径、混合 `CheckReplay`；`TestProcessChecksBeyondFirstReadPage` 覆盖第 501 条的名称冲突/等待实例和终态放行。`publication_test.go` 核对版本镜像不递归增长，以及缺失版本、错误指针、身份变更、版本跳号和递归镜像拒绝。标准编辑替换缺陷的规范归属见 ADR-0016。
- 本机 `ci web pms` 通过，包括固定 Lean 证明、全部既有真实浏览器路线、Rust K5 与 PMS 流程；最终代码的 `format capabilities composition` 另复核。未执行本增量的 PostgreSQL 崩溃或 Docker 重启演练。

**未完成：** 23b–23c 的专用编辑器、隔离流程用例、流程发布资产/精确依赖及相应双行业浏览器任务和新恢复演练。当前仅后端准备；既有浏览器路线通过不证明新的工作流编写旅程，负责人尚未验收该体验。
