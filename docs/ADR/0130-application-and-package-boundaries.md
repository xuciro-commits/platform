# ADR-0130 — XXL：平台能力、参考应用与交付包边界

状态：接受执行（2026-10-17），归 ADR-0125 XXXL。调整现有四层包/原生参考应用的实现边界，不改变客户已发布资产身份。

## 目标模型

平台交付的是可构建业务应用的能力。平台 runtime/kernel、技术能力包、行业可复用资产、客户应用分别有 owner；CRM/CSM/ERP/HCM/MES/PMS 等本仓应用仅作为验证载体，不得永久决定平台语义。重复业务机制迁往其通用 owner 后，原应用删除重复实现。必要的真实业务流程保留在可交付的行业资产/solution 中。

## 原生应用退出决策

- 不按目录名/代码量直接删模块。每个候选需要等价 application artifact/行业包，包含对象、动作、规则、页面、角色、迁移和验收样本。
- 先迁移 solutions 与全部 Go/Web/CLI consumers；验证新旧行为、权限、历史读取、接受结果与在途流程；发布切换之后冻结旧新写。
- 有旧记录/定义/运行仍需读时只保留精确历史 adapter，明确输入边界并拒绝普通新调用。数据迁移先 dry-run、审计数目与逐项失败，再执行可恢复迁移；不双写。
- 当候选尚未由构建器产物替代时，记录是产品验证载体，不得伪称“多余”。反过来，等价包已具备且 consumers 已迁移后，不继续养护第二套业务实现。

## 施工范围

检查 workspace packages 的重复壳层、平台 app、行业 app 的定义建造方式、`solutions/` 的组装与 deployment。统一包身份与 loader，不增加安装 registry、兼容 launcher 或第二级生命周期。比较 `@pkg/*` 的代码职责与 server module：薄转导出仅保留公共合同真实需要的部分，其余内联消费者并删除包装层。

## 验收

每个退休模块有完整替代矩阵与历史读写边界；role availability 与授权仍由宿主提供；应用安装/升级/撤回不更换稳定身份；独立的 code-built app 与声明式 app 都能沿同一发布/运行过程。当前真实客户/设备/迁移证据未知时明确标未知。逐模块记录节省的手写 production code，不计移目录与生成物。
