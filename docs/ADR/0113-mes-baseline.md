# ADR-0113 — 完整 MES 基准：以探针反向要求通用能力

状态：已接受（2026-10-12，负责人指令，ADR-0098 §1 的落地，F 块第一份）· 取代 ADR-0057 的 WMS 探针与 ADR-0069 §1 的"SAP 之上"探针作为**唯一验收判据**：两者保留为集成织物的局部探针，MES 成为平台能力的完整基准 · 与 ADR-0114（退出）、ADR-0115（自举）配套

## 0. 意图

ADR-0098 §1 定的是：**唯一验收对象是完整 MES**，不是"能跑三道工序的演示"。八个范围（基础主数据、工艺管理、生产管理、现场执行、异常与质量、生产追溯、资源约束、跨系统协同）不是要写进内核的功能清单，是**反向要求平台具备通用能力**的探针。

本文把这件事变成**可执行、可判定、不可自欺**的路线。

**判据**：一名没有参与底层开发的 FDE，按业务需求从空白项目构建、测试、交付并升级这套 MES，全程不写行业 Go/React 代码。

## 1. 基准的形态

### D1 八个范围，逐项给出"构建者做什么"与"平台上要靠什么"

| # | 范围 | 构建者要建的 | 依赖的平台能力 | 依赖的 ADR |
|---|---|---|---|---|
| 1 | 基础主数据 | 产品、物料、设备、工作中心、生产组织 | 对象与字段、共享本体（`core`）、企业模型、**主数据落库** | 0058, 0067/0068, **0103** |
| 2 | 工艺管理 | 工艺路线、工序、工步、参数、版本 | **业务版本**、约束（唯一、区间）、界面 | **0103, 0102**, 0109 |
| 3 | 生产管理 | 计划、工单、拆批、派工、执行 | **业务事务**（拆批是一次多行变更）、集合迭代、编号 | **0100, 0104** |
| 4 | 现场执行 | 工作站、开工、过站、报工、完工 | 事务、状态、参数呈现、专业组件配置 | **0100, 0110**, 0109 |
| 5 | 异常与质量 | 暂停、返工、报废、检验、质量处置 | **返工是一次状态+关联业务变化**（事务 + 约束），不是新的执行器 | **0100, 0101, 0102** |
| 6 | 生产追溯 | 批次、人员、设备、物料与操作历史 | 记录历史（已有）、因果链诊断、集合查询 | 0104, 0107 §D3 |
| 7 | 资源约束 | 设备能力、占用、人员资质、产能规则 | **能力匹配是集合量词表达式**（今天在 `apps/mes` 的 `canDo` Go 函数里） | **0101, 0104** |
| 8 | 跨系统协同 | ERP、WMS、APS、设备 | **Confirmation、补偿、对账** | **0112** |

**第 7 行是本基准的核心价值**：ADR-0088 D4 今天用"服务端算、服务端拒"的 Go 实现 `canDo`，这是对的临时做法；基准要求这条规则**由构建者声明一次**，在页面候选、服务端拒绝、AI 工具三处共用同一实现。**如果配不出来，要研究的是关系与约束能力，不是给 MES 加代码。**

### D2 探针有明确的反例清单

基准不只是"能建出来"，还包括**这些都不能发生**：

| 反例 | 为什么它是失败证据 |
|---|---|
| 任何 MES 专用代码进入 `capabilities/server`、`apps/build` 或 `@platform/ui` | 违反 ADR-0098 §4 |
| 把 `apps/mes` 的 Go 规则翻译成等价的 Go 后放进客户应用 | 同上（换个位置不等于通用能力） |
| 为了通过基准而放宽某条约束/权限 | 违反 ADR-0098 §0 的第二判据 |
| 构建过程中需要修改内核 `contract/` | 说明通用能力不足或探针设计错（见 D4） |
| 需要"操作工手输一个数组下标"这类在服务端可以算出来的输入 | 违反 ADR-0088 D2 已经修掉的教训 |
| 基准通过但只在一个工厂的配置下成立 | 需要第二个配置的复核（见 D3） |

### D3 两个工厂配置，证明不是硬编码

基准必须跑**两个语义不同的工厂配置**（沿 ADR-0088 的种子设计：不同工作中心、不同能力集合、不同工艺路线版本）：

- 配置 A：装配为主，工序要求多项能力，能力匹配不平凡（沿用 ADR-0088 D4 的 ASM-1/ASM-2 设计）；
- 配置 B：加工为主，有返工路径与外协工序，跨系统协同更重（外协要等 ERP 与供应商确认）。

**两个配置用同一套定义机制、同一套组件、零代码差异。** 只有配置不同。这条是对 ADR-0098 §4"不硬编码 MES 规则"最直接的检验。

### D4 撞墙的处理规则

撞墙时按顺序走：

1. **先查是不是已有能力没用上**（复用主人，ADR-0098 的规则 3）；
2. 若是通用能力缺失 → **记录为能力缺口**，在本 ADR 的 As built 里登记，进入 WorkQueue；**不在探针里绕过**；
3. 若确认需要新原语 → **新原话必须由 ADR 立**，且新原语必须**在第二个业务语义下也成立**（否则它不是通用能力）；
4. **不允许**的第三条路：在行业 Go 代码里实现后宣称基准通过。

**第 2 条是本 ADR 真正的产品**：撞墙清单就是平台下一阶段的需求来源，比任何需求文档都可靠。

### D5 基准的完成不与"交付"混同

- 基准完成 = **构建者能建出来、能正确运行**（ADR-0098 判据 1 与 2）；
- **长期维护与演进**（判据 3）由 ADR-0106/0107/0111 的能力加一次真实的升级演练证明；
- **独立 FDE 交付**（第四阶段）由 ADR-0114 判定，本 ADR 只负责"构建得出来"。

## 2. 与现有 MES 参考应用的关系

- `apps/mes`（含 `apps/mes/server/mes.go`、`erp.go`）**保留为对照实现**：它不是要被模仿的对象，而是"同一件事的 Go 写法"，用来对照构建产物的语义是否等价；
- **不允许**把 `apps/mes` 的页面/组件搬进工作台（ADR-0098 §4 第二条，ADR-0110 D5 的机制防线）；
- 退出路线归 ADR-0114：先有等价的构建产物，再有退出。

### D6 等价性的判定人与形式

**谁判定**（这是 ADR-0114 退出能否真实发生的关键，必须有名有实）：

| 角色 | 职责 | 不得是 |
|---|---|---|
| **构建者**（未参与底层开发的 FDE） | 从空白项目建出基准；报告撞墙点 | 平台开发团队的人 |
| **对照测试** | 同一场景跑原生实现与构建产物，逐个断言接受/拒绝、记录变化、拒绝码一致 | 只比"能跑通" |
| **负责人** | 判定是否语义等价、是否允许退出 | — |

**判定形式固定为三件，缺一不算**：

1. **逐场景对照清单**：每个能力单元（如 `canDo`、`reworkable`、`DemoMaster`）列出它覆盖的业务场景，原生实现与构建产物**各跑一遍**，结果并排。
2. **不等价的显式登记**：任何不一致的项**必须写出来并判定**是"构建产物更正确"（则原生实现是 bug，记录之）还是"构建产物缺失"（则退出中止）。**不允许"差不多"**。
3. **负责人的一次走查**：由负责人实际操作构建产物完成基准任务，记录观感与阻断。

**判定人不得是作者本人**：实现该能力单元的人不能判定它等价；构建者不能判定自己的产物等价。这条与 §D3 的"两个工厂配置、由不同的人写"同源。

## 3. 后果

- 基准的范围与反例清单成为**评审依据**：一次走查报告如果只是"跑通了"而没说明撞墙与做法，不算证据；
- 撞墙清单（D4 第 2 条）成为 WorkQueue 的需求来源，替代"我们觉得缺什么"的猜测；
- 基准需要**两套工厂配置的数据**（种子或样本集），归 ADR-0111 的样本集资产；
- 风险：基准变成"通过导向"（为了通过而放宽）。防线是 D2 的反例清单 + D4 的处理规则 + ADR-0115 的自举约束。

## 4. 验收

1. 一名 FDE（未参与底层开发）从空白项目建出配置 A 的完整八范围 MES，**记录全程**：任务、耗时、编写的行业代码量（目标为 0）、引发的平台改动次数、返工原因。
2. 配置 B 用同一套机制重建，证明无硬编码；两份配置的差异仅在数据与配置。
3. 反例清单逐条检查：行业代码为 0、内核未改、无"服务端能算的输入让操作工填"、约束与权限未被放宽（用 `git diff` 与边界脚本证明）。
4. 撞墙清单：列出全部撞墙点、处理方式（复用/记缺口/立原语）、对应 WorkQueue 项。
5. 三个关键规则由构建者声明并证明三处共用：设备能力匹配（`canDo` 的等价物）、返工限制（`reworkable` 的等价物）、完工的关联业务变化。
6. 演进：对配置 A 做一次真实模型变更（加字段 + 重命名 + 退役一个动作），在途工单继续按旧语义跑（ADR-0106 的验收在 MES 语境内重跑一次）。

测试：`make check` 全量 + 两行业 `scripts/verify.sh composition` + `make rehearse` 的 MES 场景 + 浏览器路线的 FDE 走查；`docs/Testing.md` 增"MES 基准"路线与手测行；`docs/Apps.md` 增可执行用法。
