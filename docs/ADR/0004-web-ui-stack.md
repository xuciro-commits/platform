# ADR-0004: 统一面向所有业务领域客户端的 Web UI 组件库

> **由 [ADR-0031](0031-ai-application-platform.md) 修订，2026-09-27。** 纯代码维度的 UI 编排已被扩充修订：已注册的类型化组件亦可经由受管的页面定义与可视化构建器进行编排；统一的共享 UI 技术栈与组件归属保持不变。此注记记录最终目标；下方的历史决策与实际构建依然真实反映其所处时代的技术切片。

**状态：** 已接受 (2026-09-24)

**背景上下文。** 酒店管理、离散制造与后续其他业务领域虽然在行业逻辑上大相径庭，但在数据组织范式上高度统一：主数据（产品、物料、工艺路线、工作中心；客房、房型）、组织架构（部门、岗位、员工）、硬件设备与采集读数（门禁、摄像头、温湿度、PLC 状态），以及在各状态间流转流转的单据（工单、客房预订）。若每个垂直切片各自手写界面，势必会导致表格、表单和状态呈现的重复建设并最终分化漂移。平台负责人要求为高信息密度的操作级企业软件打造一套共享组件体系，明确拒绝了 Ant Design，倾向于采纳 shadcn/ui 规范或类似 Palantir 的交互质感。

**决策。** `web/` 是一个 pnpm 工作区。`@platform/ui` 是平台的专属组件库，基于 shadcn/ui 设计约定构建——采用 Radix 原语、Tailwind CSS v4 样式令牌、组件以源码形态归属平台——并具备类似 Palantir Blueprint 的紧凑高密度质感（28px 行高、等宽数字、语义状态色调、深浅色模式切换）。其领域中立的基础通用组件包括：`DataTable`（基于 TanStack Table + TanStack Virtual：支持多维排序、多重过滤、10 万条以上海量记录的虚拟滚动）、`StatusTag`（业务领域将其业务状态映射至五种语义色调；内核发件箱状态内置集成）、`EntityForm`（基于 react-hook-form + zod：强类型字段、模式级实时校验）、`EntityCard`/`PropertyList`、`PageHeader`、`Sheet` 抽屉及各类基础图元；统一外壳 `Workspace`：顶部菜单栏 (Radix)、分组导航栏、可停靠工作区 (dockview，其多标签页均为类型化路由，每个路由命名一个具体实体，并支持浮动或拖出为独立窗口)、快捷命令面板 (cmdk)、全局通知 (sonner) 以及多租户/身份切换器；布局按应用隔离持久化，当前活动路由实时同步至 URL。应用采用 React 19 + TypeScript + Vite 技术栈；桌面端客户端直接将该产物打包于 Tauri 外壳中。`apps/gallery` 陈列室聚合展示所有组件在制造、酒店与物联网设备数据下的表现形态。

**字段类型体系**（借鉴 Airtable、Directus、Notion）：每种字段类型（`text`、`number`、`currency`、`percent`、`duration`、`date`、`datetime`、`checkbox`、单选与多选 `select`、`email`、`url`、`phone`、`barcode`、`rating`、`attachment`、指向另一实体路由的 `link`、只读计算的 `formula` 以及系统级 `timestamp`）精确裁决其数值如何展示、如何编辑输入、如何由 zod 实施校验、如何排序、如何过滤（各自专属的操作符）以及如何进行全文搜索。业务包在 TypeScript 中通过 `defineEntity` 声明实体；`columnsFor`、`RecordForm`、`FilterBar` 以及在 `DataTable` 中的单元格就地即时编辑均直接由该声明推导生成，`EntityForm` 亦复用完全相同的编辑器。

组件最初由类型化的领域代码进行编排。它们不是由一套庞杂的动态配置语言驱动的：当界面需要分支判断条件或循环时直接写代码表达 (Platform.md §6, 风险 4)。

**影响与后果。** 每个业务领域的 Web 客户端均导入 `@platform/ui`；全新的跨领域通用组件仅在有两个不同业务领域同时需要时方可沉淀进该库。当客户端后续需要直接发送内核底层报文时，将从 `contract/proto` 自动生成对应的 TypeScript 契约类型（当前由 Tauri 后端直接处理）。我们不直接依赖 Blueprint 源码库本身，从而使自研组件库拥有百分之百的样式掌控力，并能完美适配每个租户的企业品牌定制。

**重新评估时机：** 当虚拟化数据表格无法满足极端真实业务数据吞吐量时，或者某个垂直领域需要组件库无法承载的全新组件家族（如复杂交互图表、甘特排程视图、GIS 地图）时。

## 实际构建（As built，2026-09-28，#123 前端整合）

`@platform/ui` 的表格、表单、记录页和错误展示已补齐加载、空、失败/重试等状态；`DataTable` 支持网格方向键、Home/End、Enter 编辑、Escape 撤销、Tab 单元格移动，并保留虚拟滚动。知识文档通过共享的 `Markdown`/`MarkdownEditor` 展示与编辑，不在应用包内自建解释器。`apps/gallery` 按基础部件、反馈、知识与可视化展示代表性状态；`@platform/app` 的记录读取失败可重试。合并后的 `scripts/verify.sh web` 包含组件测试与真实浏览器路由；这些是自动化行为证据，不是负责人对 N4 视觉、无障碍、窄屏及完整岗位任务的验收，也不证明十万条真实数据的操作性能。
