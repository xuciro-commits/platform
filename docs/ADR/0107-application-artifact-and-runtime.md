# ADR-0107 — 应用工件与运行形态：一个应用是一件可交付的东西

状态：已接受（2026-10-12，负责人指令，ADR-0098 C 块第二份，对应后端第 6 项）· 修订 ADR-0036（租户交付的应用）与 ADR-0055（项目 = Application）的口径：应用从"页面编组"升为**完整工件** · 与 ADR-0106（演进）、ADR-0111（发布体验）配套

## 0. 意图

今天"应用"这个词指三件不同的东西：

| 说法 | 实际是什么 | 证据 |
|---|---|---|
| 平台应用 | Go 清单 + UI 包（`platform.App`） | ADR-0010/0025 |
| 租户交付的应用 | `platform.Application`，**页面型定义 profile 只支持页面与共享资源编组** | ADR-0036；Platform §2.5 的 Application 行明写"当前 `build.app` / `platform.Application` 是页面型定义 profile，并不等价表示所有原生应用" |
| 构建项目 | Build 的任务组织与草稿上下文，不是发布边界 | ADR-0055；Platform §2.5 的 Project 行 |

客户要建的"一套管理系统"不属于其中任何一个：它是**对象模型 + 规则 + 页面 + 集成 + AI + 权限 + 生命周期**的集合，有版本、能交付、能运行、能升级、能诊断。

**判据**：客户能用一句话说清"这个应用包含什么、现在跑的是哪一版、上一版是什么、怎么回到上一版、它现在健康吗"。

## 1. 决定

### D1 应用工件（Application Artifact）是交付单元

```go
// 构建者所构建、发布、交付的东西。不是 Go 包，不是页面集合。
type Artifact struct {
    ID        string          // 稳定标识（租户内唯一）
    Version   string          // 内容版本（内容哈希，沿 revision.go 的内容 ID）
    Model     []AssetRef      // 对象类型、关系、属性类型、共享类型引用
    Rules     []AssetRef      // 事务、约束、决策表、告警规则、计算字段、生命周期
    Pages     []AssetRef      // 页面、模块、应用外壳
    Flows     []AssetRef      // 流程、自动化
    AI        []AssetRef      // AI 函数、智能体、评测集
    Integrations []AssetRef   // 连接、来源、数据集、管道、回写、匹配
    Roles     []RoleRef       // 它声明的角色与范围（授权仍由 admin 授予，沿 ADR-0066/0078）
    Depends   []AssetRef      // 跨应用与共享类型的显式依赖
    Env      []Binding        // 环境绑定（地址/密钥**不进入**工件，沿 ADR-0047/0048）
}
```

- **`Artifact` 取代"项目"作为发布边界的正式概念**。项目（ADR-0055/0047 §4.1）保留为**组织与草稿上下文**，不承担交付语义。两者可以一一对应，但不再混用。
- 工件是**自闭合的**：从它出发可达的每一个引用必须解析到兼容的不可变版本或显式声明的环境绑定；悬空引用在发布期拒绝（这是 Platform §10.3 已有的"发布自闭合性"职责的落地形态）。
- **凭据与环境地址永不进入工件。**

### D2 运行形态：一个应用是一个运行单元

这里的 Application 是逻辑交付单元，不自动建立新的事务权威。动态对象的业务数据、提交与恢复仍归 `build` 权威；同租户的多个 Application 可以显式引用同一 `AssetRef`，也因此共享该对象的数据与当前安装版本。应用工件固定自己的依赖版本，但不会为共享对象复制一份独立数据库；升级共享资产必须检查已安装的依赖方，移出应用或退役应用也不删除共享数据。权限由原 owner 的角色、行/字段范围及管理员授权决定，加入应用不授予权限。租户承担运行隔离与日志恢复，应用运行页只投影相关结果；应用的容量、保留与 RPO/RTO 声明不是独立资源配额或独立恢复承诺。Package 分发可复用能力和定义，Release 固定其候选版本，两者都不取得业务数据的所有权。

应用在宿主上运行时有明确的、可查询的形态：

- **实例（Instance）**：一个租户安装的一个应用版本，有状态（健康/降级/隔离）、当前活跃版本、上一版本、依赖版本集合；
- **入口（Entry）**：它向成员提供的页面/应用外壳、向 AI 提供的工具、向协议提供的操作——三者来自同一份定义（这是"统一语义"的具体含义）；
- **数据（Data）**：属于它的对象类型与记录、它拥有的关系、它的集成资产与运行数据；
- **运行物（Runs）**：流程实例、作业、外部效果、AI 调用、计算——全部带**所属应用**标签，并能按应用过滤（今天 Runs 有应用归属但未作为应用视图的主轴）。

### D3 应用级的运维面

ADR-0098 后端第 6 项要求"独立发布、运行、升级、监控、诊断、恢复、长期维护"。逐项落地为一个**应用视图**（前端归 ADR-0108）：

| 能力 | 内容 |
|---|---|
| 发布 | 工件的候选 → 试装 → 激活（复用 ADR-0039/0048/0097，不新建） |
| 运行 | 该应用的全部运行物，按类型/状态/时间过滤，失败优先 |
| 升级 | 迁移计划（ADR-0106）与应用版本的关系；升级前后的差异与影响面 |
| 监控 | 该应用的拒绝率、约束失败、效果积压、AI 用量与预算、流程滞留 |
| 诊断 | 单条记录/单个流程实例的完整因果链：它是哪个决策、哪个定义版本、哪些依赖产生的 |
| 恢复 | 该应用的恢复状态：前驱完整、是否有未完成的外部效果意图、是否有隔离批 |
| 长期维护 | 变更历史、退役清单、扩展与保留状态 |

**关键约束**：这些视图**必须由已有 owner 的数据投影出来**，不新建第二套运行状态。新增的只是"按应用聚合"的视图与查询维度。

### D4 独立交付：交付物是工件 + 环境绑定 + 迁移计划

- 一次交付的产物：**工件（不可变）** + **环境绑定（每个目标环境一份）** + **迁移计划（从上一版到这一版的必要数据变更）**；
- 交付到目标环境时：重新验证本地绑定与权限（沿 ADR-0097 §7"目标 Connection 必须是唯一同名、同 kind、已就绪的本地配置"）、执行迁移、激活；
- **不支持的迁移必须可见地拒绝**，不降级为"部分安装"。

### D5 容量与保留承诺按应用声明

今天的容量/保留/RTO/RPO 是平台级未验收项（Platform §10.2/§10.6）。本 ADR 要求**每个应用能声明自己的预期规模与保留策略**：

```go
type AppProfile struct {
    ExpectedRecords   map[string]int64   // 按类型
    ExpectedRuns      int64
    Retention         map[string]Duration // 运行物、日志、效果
    RPO, RTO          Duration
}
```

这些声明**不自动成为保证**；它们是构建者与环境之间的约定，实际保证按实际演练证据（`make rehearse`）声明。但声明是必要的：没有它，客户不知道自己的应用能长到多大。

### D6 应用与原生应用的关系

- 客户构建的应用**与原生应用同级运行**：同样的权限、同样的恢复、同样的运行面；
- 原生应用是**平台自带的应用工件**（由 Go 代码提供而非由构建者定义），两者在宿主里的角色一致；
- ADR-0114 定义原生参考应用退出的路线：不是删代码，而是**让等价的构建工件存在并接管**。

## 2. 不做

- **不做应用市场/公共分发**（ADR-0008 §1：第三方生态待平台内部成熟后再考虑）。
- **不做"一个应用一个进程/容器"的强制隔离**：运行形态是逻辑单元；物理隔离按 Platform §10.3 D 的租户级承诺（有界进程隔离），不在应用粒度承诺。
- **不把项目（Project）改造成发布边界**：它是草稿上下文。
- **不做应用的自动依赖升级**：依赖版本在工件里显式固定，升级要显式计划。

## 3. 后果

- 前端需要"应用"作为一等导航对象：一个应用视图承载它的构建面（设计台）、运行面（运维）、交付面（发布）；归 ADR-0108。
- 客户端入口（工作区的应用门户）从"页面型 Application"扩展为"完整工件"；ADR-0052/0055 的门户与项目口径需要在对应 ADR 补一句指向本文。
- Host Console 的环境/晋级能力与本文的应用交付物对齐（已有基础，ADR-0047 §6.3）。
- 运行面的"按应用聚合"需要在运行物写入时保证应用标签的完备性——今天部分运行物可能没有应用归属，需要一次核对。

## 4. 验收

1. 构建者在一个应用里定义模型/规则/页面/流程/AI/集成，发布为一个工件，版本可查、内容可查、依赖可查。
2. 该应用在运行面上显示全部运行物（流程/作业/效果/AI/计算），能按类型与状态过滤。
3. 诊断：从一条业务记录出发，能看到它由哪个决策、哪个定义版本、哪些依赖产生，以及相关的运行实例。
4. 交付：同一工件交付到第二个环境，重新验证绑定与权限，执行迁移并激活；不支持的迁移被拒绝并有明确原因。
5. 恢复：应用级的恢复状态可见（前驱、未完成效果意图、隔离批）。
6. 容量声明：应用能声明预期规模与保留；超过声明规模时**明确告警而不是静默降级**。
7. 反例：工件含悬空引用、含凭据字段、两个类型同名冲突 → 发布期拒绝。

测试归发布 owner、宿主与平台应用包；`make rehearse` 覆盖两环境交付；`docs/Testing.md` 增"应用交付"手测行。

## 5. 实际构建（As built）

当前受支持 profile 的应用工件与运行闭环已完成工程验证，使用原候选、接受结果、定义、记录、Flow/Agent/Compute、效果和调度 owner；没有新增应用状态账本或执行器。提交检查、全量宿主与组合检查、应用竞态检查、私有 PostgreSQL 完整交付路线、两条应用浏览器路线及两行业 `make rehearse` 均通过；生产与体验承诺按本节证据边界判断。

决策表通过既有 `compute` 资产携带完整原生规则计划；告警配置通过 `alert` 资产携带对象、条件和收件角色。它们可以成为应用成员，由同一候选完成复制、升级和回退；回退安装保留版本，不能只改应用指针。告警执行只读已封存配置，保存草稿、修改启用状态都须发布后才影响运行。旧未版本化告警继续读取原配置，首次编辑先在同一接受结果中冻结原版本；旧日志不改写，通知去重身份保留。没有增加规则求值器、发布协调器或通知投递器。查询、AI 函数、共享属性、关系、代码与智能体的保留候选重新激活时，同样安装其封存定义；当前运行版本与最高历史序号分开，回退保留原可编辑草稿和全部历史，后续发布使用新序号。归档不作为退役已发布定义的捷径，移出一个应用不改变其他应用的成员或共享数据。

- `platform.ApplicationArtifact` 从应用根的原不可变候选闭包投影模型、规则、页面、流程、函数/智能体/评测集、集成、角色、跨 owner 依赖与环境要求；内容版本是闭包内容 ID。`Application.Profile` 可声明记录/运行规模、保留、RPO/RTO；保存校验格式，发布拒绝闭包外类型、未知字段与凭据字段。支持只有资源、没有页面的应用。
- 评测集复用原 `build.testplan`：发布保留完整版本族，冻结合成用例、阈值、明确模型名称及函数版本，不携带本地草稿 ID。候选检查用例与函数类型、依赖和来源版本；新环境激活检查本地模型与成员权限。原评测器执行冻结策略，后续草稿编辑不改变既有报告依据；候选声明的每个评测集都须有对应通过报告。未包含评测集的旧候选继续使用原计划校验，历史字节不改。
- 原 Flow owner 为代码 Flow 提供声明投影，保存启动条件、控制图、连续窗口、预算、重试、超时、迁移映射及其编译 owner 的版本依赖。目标必须已有匹配的可信代码 owner，不能从租户工件注入 Go 回调；声明不同拒绝。原生 Flow 的新实例也绑定闭包，旧未绑定实例保留精确兼容入口。缺少隔离 owner 夹具的原生 Flow 仿真明确拒绝，不调用生产回调。
- 原 Agent owner 的工具、预算、检查点、交接角色与评测用例进入 `agent` 制品；Build 的原版本、发布、候选试装、目标草稿引导与纯恢复继续执行它。新目标需要已有 Agent runtime。此处没有复制原 Agent 的模型执行或评测器。
- `/v1/applications/{app}/{name}/runtime` 返回实际安装闭包、原接受的激活版本/上一版本、获权记录计数、规模告警、原接受/拒绝与约束失败计数、效果/流程积压及已报告 AI 用量；预算直接读原 AI owner 的本人共享配额与冻结的智能体单次预算，不建立应用专属计费或配额状态。维护面投影原迁移进度、退役项、扩展来源和保留声明，不把声明当自动删除。指标遵循当前读权限；Agent 费用报告未被证明完整，明确计入未完整计量。租户隔离时只有原管理员权限可读隔离状态，前驱标为未确认，不返回部分记录或冒充恢复成功。
- Flow、Agent、AI 函数、计算和外部效果在原创建结果/意图里记录应用内容绑定，调度工作在原工作结果里捕获当次服务的应用；启动时不补写作业标签，保留历史未标记的初始前驱，新标签只随原工作结果接受。纯恢复保留这些标签并校验结构及原前驱，旧作业到新标签的世代转换与错误前驱拒绝均有回归证据。原应用 Runs 查询汇集六种运行物，按类型/状态/时间/主体过滤、失败优先；已记录绑定优先，资源移出应用不隐藏旧运行，后加入共享资源的应用不取得此前运行归属。旧未记录字节保留共享资源/owner 关联，标签不授予访问权或推断独占发起来源。内部汇总一次选择原 owner 的获权映像，删除 10000 项读截断与逐页重排；公开记录分页边界保持。项目与应用门户复用 `@platform/app` 的同一运行面。
- 新接受结果在原紧凑结果及多决策批里保存 `DecisionDefinition`：原动作、schema 内容/family、可闭合的依赖及应用绑定。`committed` 只为这些原结果建立按决策标识的诊断索引，随原快照与纯重放恢复，核对原收据；不保留第二份完整记录结果。旧字节不改，未记录的信息显示未记录。不可移植的原生定义依赖明确标为不可用，诊断信息不成为新的业务准入条件。
- 审批选择曾激活且与原动作/对象当前完整依赖相同的候选；全租户最近激活了无关应用时，不再把它误当作审批版本。历史流程发起的审批继续固定原流程候选；待处理审批仍遵守原升级和迁移检查，不通过取消版本绑定绕过。
- 记录诊断从原历史读取逐次决策的上述依据与原相关运行，不按日期推测执行版本。历史 Flow 的诊断捕获沿它已选定的原不可变闭包，继续保持 ADR-0106 的旧版迁移映像、当前权限及原写映射。
- 两环境应用升级路线覆盖容量声明、超限告警、确切记录决策、上一版本和快照/日志尾恢复；智能体应用路线覆盖无页面应用、原制品晋级、目标工具安装、Flow 过滤和重放一致性。完整组合工件另在私有 PostgreSQL 中贯通模型/规则/页面/流程/函数/智能体/评测集/接入，缺失目标模型或连接时整件拒绝，目标绑定后同内容安装；联合升级在三行数据上执行三批迁移、目标测量评测、激活、维护投影与快照/日志恢复。该路线的 HTTP 模型是有成本回报的受控测试提供方，证明评测与交付机制，不证明生产模型质量。读汇总反例核对 10002 条运行仍有容量告警；这是读边界证据，不是生产容量基准。检查方法归 Testing，外观仍归负责人走查。

**证据边界：** 当前容量与恢复声明不构成生产容量、RPO/RTO 或自动保留删除保证；共享 AI 配额也不构成应用专属预算。代码工件依赖已安装的可信 owner，租户描述不能携带或执行宿主回调。更大规模、实际模型品质和真实用户设计台走查分别归容量证据、评测任务与 ADR-0108，不从构建/测试通过推导。
