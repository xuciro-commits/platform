# ADR-0043: 类型化 AI 函数 (Typed AI functions)

**状态 (Status)：** 已授权方向内的实施设计（2026-09-29，#133）。依据 ADR-0031 §10.3 C、活动队列，以及负责人要求直接在 main 持续推进。下列选择细化既有的受控类型、唯一执行路径和发布治理；不扩张为任意租户代码、独立 AI 执行器或不可逆动作自动执行。首批依赖修复不等于函数旅程已完成。

## 背景上下文 (Context)

`platform.Request/Prompt` 已允许应用在接受动作后请求模型；`aicall.go` 的 `planModelRequest/sendModel` 复用效果队列、统一模型门禁和 I/O 通道。`acceptedEffect` 已保存请求回答、用量和受支持 Reply 子决策，重放直接应用保存结果。`platform.Agent` 提供受管工具循环，`platform.Flow` 提供等待/重试/人工任务；Build 原生流程已有固定计划、候选闭包和精确实例绑定（ADR-0042）。它们尚不构成可复用的类型化 AI 函数。

开始本项时发现：应用留空 `Request.Model` 时，默认值到派发才解析。因此请求入账后修改 `ai/app-model`，会改变旧请求的实际模型。这个缺口先在现有模型请求归属方修复。直接 Chat/智能体步骤/评估仍有各自的 #135 余项，不能把模型效果路径的保存保证扩大到这些入口。

| 官方标杆（2026-09-29 查阅） | 可借鉴机制 | 本平台边界 |
|---|---|---|
| [Palantir AIP Logic](https://www.palantir.com/docs/foundry/logic/getting-started) | 声明输入、逻辑块与输出；同一函数可由页面与动作调用；保存固定输入并查看运行过程 | 借鉴类型化编写/运行/诊断旅程；不引入其对象模型或展示模型私有思维链 |
| [Palantir AIP Evals](https://www.palantir.com/docs/foundry/aip-evals/overview) | 固定测试案例与评价函数、比较函数版本的表现 | 每次结果关联精确函数/模型配置和样本；替身的通过不代替真实模型质量验收 |
| [ServiceNow AI assets](https://www.servicenow.com/docs/r/application-development/dev-get-start-ai-assets.html) | 将记录输入、摘要技能、智能体与工作流区分为可组合资产 | 搜索结果可读取，正文此次打开失败；只采纳其记录输入/输出的概念，不据此声称其权限或恢复实现 |

共同原则是具名类型接口、受权数据和可复用调用。供应商产品文档描述自身产品，不是本平台已实现或已验证的证据。

## 我们的约束条件 (Our constraints)

- 复用应用 API、AI 模型门禁、效果派发与原生 Flow/work；不能新增一套工作队列或图解释器。内核契约不变，无新第三方依赖。
- 调用前完成成员租户、源记录视野和字段权限检查；派生输出按 ADR-0033 在读取时重查来源，不能因结果记录可读而泄漏源内容。
- 已确认输入、版本和回答属于持久结果；恢复不访问模型、不按新提示词重判已保存回答。外部调用完成但结果未成功入账的窗口仍可能重试，不承诺模型物理调用恰好一次。
- 模型标识是管理员配置的 `provider/model`，不证明上游模型权重不可变。提供商路由返回的 Served 与请求模型区分，环境端点/密钥不属于租户函数代码。
- 产品文案提供英文与简体中文；共享组件由 `@platform/ui`/`@platform/app` 归属。不把编写器预览或单元测试当作负责人体验验收。

## 设计方案 (Design)

1. **唯一归属。** 应用 API 定义声明，代码应用与 Build 拥有各自函数资产；宿主 AI 路径解析已发布定义、读取授权输入并校验类型。模型推断沿已有 `Request → model effect → Reply` 路径。长等待、重试和人工复核继续由 Flow/work 拥有，不转入函数自有编排系统。
2. **首个有界函数。** 从“记录摘要与复核建议 (Record summary and review advice)”开始：选一条记录的显式字段，输入有界，输出为声明过的摘要、建议类别与复核标记。酒店与制造使用同一语义路径；函数本身不修改业务状态或执行外部动作。未知字段、类型错误、非法类别及超界输出拒绝，不把任意文本当作成功的结构化结果。
3. **授权与预算。** 人员调用按其源记录/字段权限取材；流程和代码调用显式保留其授权主体。保留来源引用与请求预算，当前模型启用和租户限额在物理调用前再次检查。函数预算不能被页面或节点参数放宽；声明外工具和任意代码拒绝。
4. **精确绑定。** 入账前解析默认模型；函数调用保存定义内容摘要、输入/来源和预算。新调用解析精确发布，旧调用不跟随活跃指针、默认模型或草稿改变；禁用旧模型仍可停止尚未发送的请求。候选发布复用 ADR-0039 的资产与依赖闭包，而非新建 AI 专用发布账本。
5. **一条可操作旅程。** 代码、页面和 Flow 调用同一具名函数，查看输入、授权来源、类型验证与保存结果。构建者在共享编写器修改定义、保存固定案例、测试精确候选后发布；操作员复核建议，通过原有业务动作作决定。展示调用阶段和拒绝原因，不展示模型私有思维链。
6. **评测与隔离。** 固定样本/身份/时钟及替身回答复用候选测试机制，不复制生产数据或凭据、不派发生产效果。模型方差另用明确模型配置的多次评测；保存案例与精确版本相关联。无权、错误输入、无模型、禁用、超预算、非法输出、持久化失败和恢复都属于交付条件。不可逆协议动作仍以 F-29 为前置门禁。

## 影响与后果 (Consequences)

模型请求的空 Model 语义变为“接受时使用默认模型”。已保存的旧空模型效果不会在派发时自动跟随默认；没有可验证绑定时拒绝，不追加兼容执行器。开发期日志的重置遵从既有边界，不据此取得删除真实客户数据的许可。

首批函数只能生成受权建议；更复杂的知识/关系检索、确定性变换及动作提议在真实任务触发时沿同一归属扩展。本 ADR 不把 #133、W2 或全部 AI 结果入口标成完成。

## 实际构建 (As built)

**24a：模型请求的接受时绑定（2026-09-29）。** `aicall.go` 的唯一 `planModelRequest` 在接受动作时解析显式或默认 `provider/model`，保存到既有模型效果 Body；`sendModel` 只使用这份绑定，仍检查当前模型启用、提供商熔断与应用配额。没有增加日志类别、队列或公共响应类型。旧空模型效果不跟随新默认；无绑定时原路径拒绝，完整客户升级不由本批保证。

`TestAcceptedModelDefaultIsPinnedBeforeDispatch` 使用实际设置/模型动作和本地 OpenAI 线路替身，覆盖默认、显式覆盖及无默认三种输入；改设置后的派发、禁用后的拒绝、待派发快照/重放以及回答/Reply/用量结果恢复。`TestAcceptedModelRequestsPersistWithoutCallingProvider` 与既有模型结果/用量故障测试继续通过；未扩大直接 Chat、Agent 步骤或评估的保存边界。

该检查点运行 `scripts/verify.sh format capabilities composition deploy` 全部通过。一次性项目完成实际 CSM 模型请求、酒店/制造快照重启、新 PostgreSQL 卷备份恢复、应用输入崩溃恢复、隔离租户原地重建和原生流程旧/新任务继续；这不是新增类型化函数的双行业旅程证明。24a 未改 Web，也未执行新浏览器/真实模型质量或负责人体验验收；当时 24b–24c 尚未实现。

**24b：受权类型化函数与双行业代码探针（2026-09-29）。** `platform/function.go` 的 `AIFunction` 定义直接标量来源、提示词、严格输出字段、角色和输入/输出字节与输出 Token 上限；`Manifest.Functions` 注册为 `AssetFunction`，沿既有代码描述符与候选闭包绑定源对象，不新增执行器或日志类别。`Caller.RequestFunction` 仅在启用受限接受结果的动作中规划意图；同对象自动 Reply 防止人员伪造回答。当前仅支持显式人员、本应用单条记录的非派生标量字段，不支持 Flow 自动化代人调用、关系/知识检索或工具调用。

宿主 `function.go` 在暂存记录库按成员源记录/字段和函数角色读取输入；调用拒绝使整个暂存决定失败。既有 `modelAsk` 保存完整函数声明、接受时输入、人员、来源、定义/依赖闭包/输入摘要及模型。派发重查当前来源权限、模型启用与应用限额，不以新代码提示词或当前记录数据替换已接受输入。输出只接受一份有界 JSON 对象，未知/重复键、缺失必填字段、null、类型强转、非法选择值、工具调用及报告的输出 Token 超限都拒绝。实际模型回答及其用量仍沿 `acceptedEffect` 和自动 Reply 一起保存；非法回答只保存拒绝及已消耗用量。输入/输出字节是平台强制界限，Token 上限传给提供商并核查其报告，不证明上游未报告的消耗。

共享 `RecordAdviceFunction`/`RecordAdvice` 被 CRM 商机（标题、阶段）和 MES 工单（产品、数量、状态）通过相同规范调用路径采用；两者是各应用拥有的声明，不是已发布的全局函数资产。它们仅保存建议和定义/模型/来源标识，声明 `Entity.Derived`/`Withheld` 由宿主按读者当前来源权限收窄输出；商机仍开放，工单仍待生产，业务决定通过原有动作进行。

`TestFunctionOutputIsStrictAndBounded`/`TestFunctionScalarNumbersDoNotCoerce` 验证输出语义；`TestAIFunctionUsesAcceptedInputAndStrictOutput` 覆盖记录/租户拒绝、提交与结算追加失败、输入改变与代码提示词升级后的旧待发请求、非法回答、输出预算、来源授权撤销及结果 `CheckReplay`；`TestAIFunctionRefusalsAndModelGates` 覆盖私有字段、输入超限、无模型、禁用及应用配额；`TestAIFunctionDiscoveryAndDependencyBinding` 覆盖按源字段授权的发现和完整候选依赖。`TestTypedFunctionOnOpportunity`/`TestTypedFunctionOnOrder` 在实际行业装配中通过替身线路取得结构化建议，核查业务状态未变、自动 Reply 不可伪造、待发与已完成 `CheckReplay`，恢复不请求模型。

当前树执行 `scripts/verify.sh format capabilities mes composition web deploy` 通过；新增函数边界测试另通过 `go test -race`。部署演练以实际 OIDC 身份和本地模型替身完成两行业建议调用，来源/定义/模型/回答与用量纳入快照重启、新 PostgreSQL 卷备份恢复及隔离后全量重建比较；同轮 PostgreSQL 条件测试 `TestJournalAcceptedFunctionCrashBeforeApplication` 在回答结果追加后、应用前注入崩溃，证明回答、自动 Reply 与用量一同恢复且不重新调用模型。`web` 验证现有路线，未新增或人工走通函数 UI；模型替身只验证协议与治理，不验证真实模型质量。代码升级探针只修改提示词，源对象和 Reply 保持兼容；不兼容数据类别/Reply 迁移及完整客户升级矩阵仍属于 #136 的交付边界。24c 的 Build 编写、固定案例评测、页面/Flow 显式绑定及测试→候选发布旅程仍未实现；负责人体验未验收。
