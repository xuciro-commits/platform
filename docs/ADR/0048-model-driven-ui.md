# ADR-0048 — 模型驱动的界面构造：让组件读懂业务模型

<a id="adr-0048"></a>

**状态：** 现行 · 工程已实现，构建者体验待验收 · 模型驱动界面、统一输入与专业组件（并入原 0036、0049、0021）。

## 0. 意图

原页面配置依赖裸字段名、一跳引用和应用代码预计算业务字段。现行模型引用允许构建者在原对象、关系与规则上配置页面，不为每个业务问题新增后端字段；具体支持范围与上限见 §5。

**判据**：构建者在页面上绑定一个选择器时，能直接使用模型里的关系与规则（ADR-0040 的表达式、ADR-0043 的集合），不需要重写前端逻辑，也不需要后端为它加一个字段。

## 1. 决定

### D1 绑定从"字段名数组"升级为"模型引用"

```go
// 页面/组件对业务模型的绑定（取代定义里的裸字段名与 path 字符串）
type ModelBinding struct {
    Type    string        // 对象类型（或 Interface，沿 ADR-0020 §3.1）
    Set     *RecordSet    // 集合定义（ADR-0043）：来源关系/查询 + 过滤 + 排序
    Fields  []FieldRef    // {Name} 或 {Path} 沿声明引用取值（深度有界）
    Where   []Expr        // 过滤（ADR-0040）
    Label   Expr          // 显示文本的表达式（"PO-{code} · {supplier.name}"）
    Options *OptionsRef   // 选择器候选的来源集合
}
```

- **`FieldRef.Path` 允许声明引用**（不再限一跳）：超过一跳时由**前端按声明逐跳读取**（今天 `CreateForm.tsx:21-32` 已在做逐跳 `source.get()`），并有明确的加载/失败状态。
- **`OptionsRef` 就是 ADR-0043 的集合**：设备选择器的候选 = "该工序要求能力 ⊆ 该设备能力"这个 `Where` 表达式的结果集合。**规则一处定义**（ADR-0040），页面、服务端校验、AI 工具三处共用。
- 绑定的**发布期校验**：类型存在、路径每一段是已声明引用、表达式类型匹配、字段可读（ADR-0044）。今天 `installed.go:597-603,745-753,811-817` 已经在校验"字段属于该对象"，本 ADR 把它扩展到整套绑定。

### D2 从模型推导默认，构建者覆盖

组件在**没有配置**时的行为必须是有意义的默认：

| 组件 | 默认来源 |
|---|---|
| 表格列 | 对象类型的字段（沿 `columnsFor` 的既有实现，`ui/src/fields/entity.tsx:24`） |
| 编辑器 | 按 `FieldInfo.Type` 分派（沿 `Records.tsx:119-152` 的既有实现） |
| 选择器 | 引用字段的 `ref` 目标类型 + 可读范围 |
| 表单 | 动作的 `Payload`（今天 `payloadSchema` 已从 `ActionDeclaration.payload` 推出，`app/src/actions/actions.tsx:16`） |
| 过滤 | 字段类型对应的运算符集合（沿 ADR-0018 的字段类型体系） |
| 状态 | 对象的 `lifecycle`（`FieldInfo.lifecycle`） |
| 详情页 | 对象字段 + 已声明关系（沿记录页标准布局，ADR-0018 §3.4） |

**默认必须可见可改**：构建者能看到"这是从模型推导的"，也能改成显式绑定。**不允许"看不见的默认"**——那会让页面行为无法解释。

### D3 关系与集合在界面上是一等的

- **关联列表**：从"一跳取值"扩展到"声明集合"（子记录、反向引用、命名查询、过滤集合），带分页与权限过滤（ADR-0043 D5）；
- **关系导航**：从一条记录可以沿声明的关系跳转（今天记录页有 `RecordLinks`，`platform/page_record_links.go`），并保留每跳的可见性与面包屑；
- **关系上的字段**：允许显示（"供应商的国家"），由绑定声明，不由组件自己猜父类型（今天 `parentTypeOf` 的猜测被显式绑定取代）。

### D4 权限在界面上是可见的，不是隐形的

- 组件读取被裁剪的数据时，必须声明它在"部分可见"状态下的行为：显示计数差、显示"部分不可见"标记、或整块隐藏——**由构建者选择默认严格**（整块隐藏或显示标记，不显示猜测的占位）；
- 编辑控件在字段不可写时**禁用并说明原因**（原因来自 ADR-0044 的 `Reason`），而不是静默忽略输入；
- 页面不重新实现权限判断（ADR-0057 既有原则）；它消费 ADR-0044 的判定结果。

### D5 页面模型本身的收敛

- `PageDocument`（v2，`platform/page_document.go:19-33`）与 `Section`（`definition.go:120`）**继续用**，不新建第三套页面格式；
- 但 `Section` 里的裸字段名、`object`/`relation`/`parentSelection` 的组合（`definition.go:240-247`）收敛为 `ModelBinding`；旧的 V1 Sections 由既有迁移路径（`pages/pageDocument.ts`）继续解码；
- `PageExpression`（`page_variables.go:12`）迁到 ADR-0040 的 `Expr`（同一迁移，见 ADR-0040 §D5）。

### D6 租户模型安装到原记录运行时

`build.object` 是 Build 拥有的普通记录，类型身份为 `build.<name>`；构建者编辑，正式成员按对象的授权使用。发布安装由原候选接受过程完成，动态 Go 类型嵌入 `platform.Record`，带稳定模型身份，结构相同的两个对象不能合为同一类型。生成的读写动作、表单、搜索、聚合、导入导出、关系、评论、文件与默认记录页均使用原基础能力，不增加动态对象专属存储或执行器；这些业务词不进入内核。

恢复按保存的发布定义安装类型，再恢复动态记录；快照中无人安装的类型明确报错。日志按安装顺序重放，K7 的 `SchemaRegistry.Learn` 允许启动后学习模式。当前草稿不替代保存的发布声明。原直接重装、删除字段丢值、所有 Build 成员共用粗权限和一次性数据方案已退出；不可变候选、按对象权限及字段迁移/退役分别由 ADR-0045、ADR-0044、ADR-0045 管理，禁止据旧切片删除客户数据。

### D7 页面是绑定组件的声明布局

`platform.Page` / `PageDocument` 声明布局和组件；`list-detail` 保留为默认记录页的简写，组合页面由共享 `ComposedPage` 渲染。组件展示、记录、动作、聚合、历史、任务各归原共享组件，不在 Build 中复制运行实现。页面声明不授予权限，每次读写按当前主体检查；未知组件、字段、动作、绑定或不支持的配置在发布时指出位置，拒绝不影响已发布页面。

表格选择、对象过滤和父子选择使用同一 PageSession；父来源变化清除其下游选择及关联表单，独立选择保留。关联创建使用子对象原创建动作和声明回指，缺失/无权来源不能创建。详情部件只呈现记录身份及所选字段，动作、历史与任务由显式部件承担；完整记录页继续提供其原通用能力。画布以同一渲染器读取授权数据并阻止写入，样本隔离另归 ADR-0050。

最初六组件、固定两列、单一页面选择、没有嵌套/变量/表单等限制已由 ADR-0018 的 PageDocument 和现行绑定取代，不再是待施工清单；各组件实际表达范围仍由原契约决定。

### D8 模板生成普通页面草稿

应用内 Templates 提供 list report、object page with items、worklist、wizard、board 五种业务形态，另保留通用 record handling。模板通过原 `pageTemplates` / `templateDraft` 生成可编辑 `build.page`，不存在第二种页面语言或发布路径。子对象模板仅提供持有声明回指关系的对象；字段、动作、关系都由模型决定，不把行业词写入通用模板。对象和页面可以在同一明确选择的候选中发布，不要求先发布模型。

手持/PDA 专用模板、打印布局以及额外 PDF/Excel 模板输出没有在这里承诺为已实现或自动加入队列；现有扫描、导出能力沿各自原归属使用。

## 2. 不做

- **不做前端保留的"业务逻辑脚本"**：页面不能有自己的规则执行器；所有判断走 ADR-0040 的服务端同一实现（预览态也需要同一实现，见 ADR-0050）。
- **不做页面级的数据写入**：写入只能通过动作/事务（ADR-0039）。今天的 `page_table_edit.go`（单元格编辑）保持"暂存 + 显式提交 + 每行一个标准动作 + 不宣称多行原子"（ADR-0018 §6.47/§6.50 的既有边界），不改。
- **不做任意深度的关系遍历**：深度有界，超出拒绝。
- **不做"组件读懂任意模型外的东西"**：绑定只能引用声明的模型元素。

## 3. 后果

- 75 个 widget 的**契约不变**（`pageui/widgets.json` → `host.ts` 的生成链不变，ADR-0018 §8），变的是**它们消费的绑定形态**与 Inspector 的表达方式。
- Inspector 需要从"字段名下拉"升级为"模型元素选择器 + 表达式编辑器"（复用 ADR-0040 的语言编辑器）；归 ADR-0047 的 Interface/Behavior 工作区。
- 后端 `installed.go` 的发布期校验扩展；`page_compute_resource.go:28` 的"只接受一跳"限制放宽为"沿声明引用，深度有界"。
- 现有页面定义在保存时升级到新绑定形态；旧发布字节保留只读（沿 ADR-0037 §3.5）。

## 4. 验收

1. 构建者在页面上配一个设备选择器：候选由"工序要求能力 ⊆ 设备能力"的表达式集合给出，与服务端 `start` 动作的拒绝规则**是同一段规则**（用一条测试证明改一处两处都变）。
2. 表格的列、编辑器、过滤算子、状态显示在**零配置**下从模型推导出有意义的结果，且构建者能看到并覆盖。
3. 关联列表支持子记录、反向引用、命名查询与过滤集合，分页与权限过滤正确。
4. 权限：部分可见的集合显示明确的"部分不可见"标记；不可写字段被禁用并说明原因；页面不自行判断权限。
5. 跨一跳的关系字段正确显示，加载与失败状态明确。
6. 迁移：既有 V1/V2 页面定义读入后保存为新绑定形态，渲染结果与迁移前一致（同一 e2e 路线对比）。
7. 反例：未声明的路径、超深引用、类型不匹配的表达式、引用不可读字段 → 发布期拒绝并指出位置。

测试：`make check-web` + 一条 e2e 路线；`docs/Testing.md` 增"模型驱动界面"手测行。

## 5. As built

ADR-0064 对原场景属性清单补齐图层和映射的真实字段，移除 ValueSchema 不支持的 additionalProperties 占位；已存在的非空图层/映射不再被误拒绝。前后端使用同一份原遥测页面数据检查合法结构，额外未知属性仍拒绝，不放宽通用对象规则；专有场景语义继续归原 PageSceneConfig 与渲染器检查。Record list 的 grid/list/tiles 枚举只在原组件属性 Schema 声明，运行发现的 layouts 由其派生，专用 Inspector 也读取派生值；保留公开发现字段，删除第二份枚举，原八条记录和固定排序条件继续检查。

公共值 Schema 校验归 `build/src/shared/value-schema.ts`，页面声明、模块导入与 Flow 编辑直接引用唯一实现；页面不再依赖 Flow 目录，旧校验文件与转导出已删除。

组件清单现在从同一声明产生 `authoringFields`、允许字段、端口、配置版本及普通属性 Schema。Web 的作者类型按 `widget` 区分配置，运行期及历史仍读取原扁平 Section；不引入另一套 DSL。普通标题、说明、分隔与间距属性复用 Schema Inspector，专用业务绑定保留原编辑器。注册表只声明专用交互，不再逐项抄写普通属性和版本；原空文档校验的长分支由声明中冻结的历史允许字段代替，旧输入的接受/拒绝范围保留。保存模型绑定时前后端都保留较新的声明 profile，只在原绑定确需更高版本时提升，不把 `v2.111` 降成绑定最低要求 `v2.110`。

页面能力与 profile 要求集中在原清单投影；新普通属性不要求修改全局微版本或另补字段名单。复杂业务约束仍由原编译器检查，历史 profile 与组件配置版本不改写。作者类型和普通属性由声明推导不代表全部复杂 Inspector 已生成，也不把 Go/React 实现反向转换为配置。JSON/YAML 与原画布共用草稿、撤销和正式发布路径。类型、端口、历史允许字段和 Schema Inspector 的检查与浏览器用法归 [Testing](../Testing.md)。

PageEditor 的保存/发布禁用与 Problems 共用 `pageDraftDiagnostics`，错误带原组件或布局节点位置，点击后进入原检查器。原布尔标志、禁用长表达式和另一份提示映射已删除；作用域、节点查找与同类输入检查复用，组件自身约束和服务端发布检查保留。原来只有禁用、没有原因的组件配置现在给出可定位说明。行内编辑检查复用原模型字段展开，默认字段不会被误判为不可见；自动保存开始时已发生的输入仍进入原草稿历史，旧保存回复不会覆盖这些后续编辑。

RecordList 的状态来自明确 lifecycle 或显式看板配置；应用层按当前动作目录提供迁移命令，展示层不从 choice 字段、参数名称猜业务状态，也不在空命令列表时补动作。保留已有列表、看板、聚合与原动作表单；失效的保存视图回到可用列表。页面内短表格随内容收缩，保留原 320px 滚动窗口上限，不再挤远下方的明细和操作。

平台与构建器 Section 的前 100 个相同配置字段统一归 `platform.PageWidgetConfig`，后 33 个字段保留各自引用类型与编辑元数据。原 descriptor / pageDraft 直接传递共有配置，保留原切片克隆；前端构建期 Section 引用生成的 Api.Section，只区分 object / query / actions / function / inlineEdit 五种表示。新组件配置不再增加三份手写字段声明和前后端逐项复制清单。原 JSON 字段顺序、扁平形状、组件版本、API 输出和冻结历史不变；此整理不把通用模型绑定等同于全部组件配置规则。

现有 `PageDocument` / `Section` 使用 `platform.page.v2.111`，对象绑定写入 `Section.model`。`FieldRef` 保留原组件端口，组件配置版本与执行 owner 不变；旧字段名只在解码和组件端口投影中出现。Build 保存 V2 时收敛绑定，V1 沿原 `pageDocumentFromSections` 提升后保存；历史发布、候选、接受结果不改写。冻结候选激活及恢复保留模型引用。

- **同一条规则**：`OptionsRef.rule` 引用原动作及页面输入映射。动作与候选读取共用 `RuleCriteria` / `EvaluateRule`；该计划是原动作 owner 的私有执行元数据，不增加 Action 发布字节。规则改动只修改原动作。候选成立不授予执行权限，状态、动作授权、审批及写入仍由原动作处理。
- **默认与覆盖**：表格、详情、表单、过滤字段按可见模型推导，编辑器继续按原字段类型及动作 Payload 分派。状态跟随原 lifecycle；模型详情沿原记录页呈现属性与已声明关联。记录页、历史与待办共用 UI 的 `useRecordView`，历史/待办原独立读取 effect 已删除；记录页在同一记录刷新时保留原内容，历史/待办等待本次读取完成，切换记录或成员范围立即隐藏旧内容，隐藏页签释放订阅。读取仍归原 scoped `RecordSource` / PageSession，历史确认、条数限制、任务权限与预览只读不变。Data Inspector 显示推导来源，模型元素选择器逐段选择字段；显式字段和组件端口可覆盖默认。通用表达式编辑器编辑原 Expr，类型检查复用 Go/Wasm 编译器；动作条件与页面过滤/显示标签共用该编辑器。
- **集合**：模型记录窗口引用原声明集合或固定版本命名查询，经原记录/关系/查询 owner 读取，再过滤和分页。子记录、反向引用、过滤集合保留声明；集合与命名查询的声明排序保留，计数只来自实际可见结果。原聚合组件继续使用已有聚合端口，不在浏览器对窗口求业务全集。Interface 延续原固定查询的公共字段及具体记录身份，不把 Interface 注册成对象或获得写入权威。
- **关系字段**：发布期沿声明引用校验最多 16 段，逐跳验证可读字段。宿主用原读取确认权限，浏览器沿同一声明逐跳 `source.get()`；加载、失败及上下文变化移除旧关系值。计算资源的 subject 输入也允许有界声明路径，最终字段仍须匹配原操作输入类型。
- **权限**：缺省隐藏不完整组件，构建者可选择明确的“部分不可见”标记；不暴露隐藏记录的数量或身份。原授权 owner 返回每行字段的写入判定和原因，原表格编辑控件据此禁用并解释，不在页面重做角色规则。输入记录、成员/定义范围、所属浮层或候选条件失效时，原 PageSession 清理候选及选择。

模型引用、表达式类型、路径、原集合/查询版本、规则输入映射和发布者可读性由原发布链校验。读取为只读 `POST /v1/page-model/read`；草稿预览需要 builder 权限，运行态以可见发布页与内容版本为依据，不信任浏览器提供的记录字段。边界为 64 个字段引用、32 个过滤 Expr、16 段路径、原集合最多 10,000 条、单窗口最多 200 条、选择器原 20 条窗口及 8 MiB 结果预算，超界拒绝。

行为证据归 `page_model_test.go`、`platform/page_model_test.go` 与 `model-driven-ui.spec.ts`：同规则修改同时改变候选/动作、零值、声明集合与查询分页、原发布恢复、路径/权限反例、V1 保存迁移、三段关系值与真实逐跳读取失败。实际构建者体验和生产容量不由这些自动检查代替。

## 并入：手持与打印（原 0021）

现场设备的窄屏形态复用同一页面模型与组件，不另建一套移动界面。

### 1. 立场

工厂一线用的是扫码枪、PDA 和标签打印机，不是鼠标。这一块不新建"移动端"，而是让同一张组合页面在三个点上长出一线能力：**输入可以是扫出来的**，**页面可以按手持终端排版**，**详情可以打成标签**。三者都只是呈现契约（`pageui/widgets.json`）的扩展，业务绑定、权限与查询不变，与 Foundry Workshop "同一模块、不同布局" 的做法一致。

### 2. 契约

- **扫码输入**：`input.inputKind = "scan"`。绑定与 `search` 完全相同（页面/浮层作用域的文本状态变量 → 同 owner 查询的 `search`），只是读法不同：扫码枪键盘楔入（输入 + Enter）即提交并全选，便于连续扫；浏览器有 `BarcodeDetector` 时提供摄像头按钮。宿主 `checkInputPresentation` 对 `scan` 用 `runtime.input.scanRequiredUIProfile`。
- **设备**：`PageDocument.device ∈ {"", "handheld"}`（`runtime.device`）。`handheld` 由前端以 `data-device` 落到页面根：单列、放大字号与点击目标、扫码框更大。不改节点树，桌面与手持是同一文档。
- **标签**：`PageDetailPresentation.barcode`（一个文本字段或 `id`，以 Code 128 B 绘制为内联 SVG）与 `print`（打印按钮；`@media print` 只打印该详情区块）。宿主 `CheckDetailBarcode` 要求字段存在且为 text。

### 3. 工作台

页面设置新增"设备"；`input` 组件的呈现下拉新增"条码扫描"；`detail` 检查器新增"条码"与"提供标签打印"。

### 4. 不做 / 后续

- 不做 ZPL 直连打印机：浏览器打印到标签纸已覆盖探针场景；ZPL 作为外部效果（E 块的外部效果通道）再议。
- 不做 QR 生成（Code 128 足够承载编码；二维码读取由 `BarcodeDetector` 覆盖）。
- WMS 探针的"收货作业"页面可把 `line` 选择改为扫码输入 + 手持设备，作为验收路线；本批未改探针定义。

## 并入：统一输入与专业组件（原 0036、0049）

表单、动作参数、Inspector 与专业组件是同一份模型驱动绑定的四种呈现，共用一套控件与校验；不再各自定义输入语义。调研过程与迁移流水归 Git 历史。

### 5. 决定

### D1 语义、展示与编辑会话各有唯一归属

| 内容 | 归属 | 边界 |
|---|---|---|
| 记录字段类型、真实引用与不变量 | platform.Entity / FieldInfo、受控对象/共享属性 owner | 标准动作从原声明投影 |
| 动作参数、特有约束、提交条件 | platform.Action / Field、build.Input 与原规则 | 本次操作的参数关系与诊断位置 |
| 控件、顺序、分组、区间配对、提示 | 动作所属表单展示声明；实体标准表单从字段投影 | 必须引用真实字段，不增隐含载荷或放宽约束 |
| 页面/Inspector 位置、预填、上下文 | Page/Section 与各工作台 | 装配公共表单/字段片段，不重新定义业务规则 |
| 控件、解析、标签/错误/焦点、密度 | `@platform/ui` | 原字段词汇和专用 editor，一套协议 |
| 操作草稿、提交结果、选择来源 | `@platform/app` | 原读取/decide/invoke/outbox，受身份和操作 scope 限定 |
| 设计文档、Undo/Redo、保存/发布 | `@pkg/build` 原 DraftSession / owner | 公共输入适配，不再每个 Inspector 自建框架 |
| 权限、并发和动态业务裁决 | 宿主与原业务 owner | 提前提示不授权、不预占库存、不替代最终决定 |

内核 K1–K9、Protobuf 和 contract 不增加表单含义。诊断/展示是应用 API 与宿主协议。ADR-0018、ADR-0047 产品结构、ADR-0014 归属、ADR-0018 widget 权限/变量/发布契约继续有效。本 ADR 补输入机制；迁走实现即删重复路径，不整份取代上述 ADR。

### D2 同一字段编辑协议，原文与解析值分开

扩展 FieldType/editor 与 InspectorControls，不新增平行字段词汇。协议含字段身份、raw draft、解析状态（empty/incomplete/valid/invalid）、解析值、touched、错误、可编辑状态、onChange/onBlur、焦点句柄和实际控件描述。FieldFrame 统一标签、帮助、必填、单位、错误，Inspector 用紧凑样式。

`-`、`1.`、未写完 JSON、精确 decimal 和日期不能在按键时变为 0、NaN、null 或最后合法值。先保留原文，解析成功才形成可提交值；0、false、空值、null、未提供不同。整数检查安全整数，decimal/money 用原精度/币种口径；不全部 Number 转换。civil date 不补当前日，datetime 保留 owner 偏移/精度；企业 tagged value 先核对元模型的 date/instant 含义。

业务表单沿原 RHF 值与校验适配；Inspector 把合法修改交原 DraftSession，未解析原文挂在所属文档会话 edit-buffer。原文缓存是编辑状态，不是第二份实体、文档或发布定义。

### D3 可声明约束贯通代码、构建器与运行表单

增量扩展原 FieldInfo/Field/build.Input 的有限约束，生成宿主类型，投影 UI schema。首版覆盖必填/空白口径、整数、上下界/包含性、文字 min/max length、choices、civil date、显式 datetime 和已有条件必填。保持既有 UTF-16 长度语义，不升级成另一种字节/字符口径。

跨字段首版支持同类型直接比较（depart > arrive、cutoff < arrive），声明依赖与错误归属，可关联两条实际日期路径。沿原 build 条件/守卫扩展直接参数关系；不添加任意表达式、JS、SQL 或第二业务执行器。复杂动态规则留 owner，用诊断说明；本批不建设自动调用动作的“校验接口”。

Go 在原授权之后、业务执行之前统一检查纯声明约束；Web 消费同一序列化声明。不能从 Description 猜限制、在 CRM TSX 重写日期规则。变化随定义版本/候选/激活封存；历史沿原恢复，不重跑新增校验。迁入声明后删重复检查，保留库存/状态/并发规则。

标准实体动作继承字段约束；特定动作可以明确收窄，不能通过展示配置扩大允许值。纯参数约束无读取副作用，引用/状态条件仍沿原受权读取与 owner 检查。首版约束预算沿对应定义预算，新增种类必须显式版本化，不以未知规则默认通过。

### D4 展示声明属于动作，页面负责装配

首版展示配置是有界 field/group/date-range 和已有专用 editor 引用；标准实体表单从原字段/动作生成。没有独立 Form 业务实体、注册表或执行器。页面引用动作并给展示子集、布局、原默认值；Inspector 选择对应文档属性并适配。

动作编辑器 Form 区与运行时共用投影/预览，编写分组与区间。未知字段、端点类型不符、字段重复、依赖循环、私有字段展示、默认值不符由原保存/发布检查。新 Page 绑定/profile 沿原版本规则，旧封存页不靠“最新控件”改语义。未展示的必需字段必须有合法受控绑定，否则指出配置错误。

### D5 校验时机、诊断与定位统一

初次打开不把未触碰字段全标红；首次失焦或选择完成后检查，已有错误随修改重检，跨字段在依赖可解析时重检。提交检查全表、定位首错。pending/无资格/明确不可执行可禁按钮，但必须说明原因；不靠静默禁用代替反馈。中文 composing 期间不提交或破坏原文。

诊断形状包含 `code`、`message`、类型化 `path`（字段/稳定行身份）、可选 `relatedPaths`、`severity`、`source`（parse/local/owner/conflict/transport）、校验/提交 generation。路径从真实声明解析，文案双语；不解析拒绝句子猜字段。无法定位的拒绝是表单级原因。

FieldFrame 与 Problems 共用诊断；点击可打开 Inspector Tab/Disclosure、选中组件/步骤/行、聚焦控件。旧校验/提交答复不覆盖新输入，按依赖和 generation 判断错误是否失效；不能改一个字段便清所有服务端错误。字段撤权不得通过诊断泄露值。

重复行的编辑身份使用稳定本地 row key，提交时冻结 key→载荷索引映射；owner 的行路径通过该快照映射回原行，重排不把错误贴给另一行。行 key 是编辑身份，不擅自写进业务载荷。

宿主 SubmissionAnswer/ErrorBody 与实际 Reply 统一为 typed DTO，带可选 issues 并生成 host.ts；原 code/HTTP/outbox 分类不变。owner 在本次决定上下文报告诊断，不用全局 last-error/共享缓存，也不重执行规则补理由。持久拒绝若加 issues，使用宿主封套新版本并纳入摘要，同 key 返回原诊断；版本 1 字节/摘要仍按原解码读取，不改日志，不为此改 kernel.Error/Protobuf。诊断有数量/大小预算，协议/嵌套决定关联到本请求。

### D6 操作会话表达确认、拒绝与未知结果

Host.decide 扩为 typed outcome：confirmed（注明审批等待）、rejected、pending/unknown，附本请求 key、诊断和回执。旧 boolean 如保留，只是同一结果路径的便捷投影，无第二发送逻辑。editing/submitting/rejected/pending/confirmed/conflicted 状态、锁、冻结 payload、baseline revision 与 scope 由公共会话管理。

明确确认才执行关闭/清空。拒绝、异常或读刷新保留窗口、值与原因；pending 显示等待确认并按同 key 重试，不能重新生成动作。明确拒绝后修正载荷是新提议，用新 key。审批等待只能说已提交审批。成功后读取刷新失败不能伪装成业务未提交，要保留已确认结果并提供刷新。

表单请求原位错误时 Host 不重复弹同一失败 toast；无表单调用沿全局通知。生成创建弹窗也接外层 busy、关闭保护和焦点，不只让 RecordForm 的按钮知道 pending。

### D7 草稿身份稳定，Inspector 原文随文档存活

业务会话身份是租户、主体、入口实例、目标 type/id、动作和声明版本；Inspector buffer 再加文档、稳定选中项、属性路径。普通 revision/数据刷新不建新草稿，打开时冻结 baseline。元数据更新比较内容/版本；真正撤权或改定义时标待确认，不暗中用新字段提交旧草稿。

切节点、Tab、折叠或主区显示方式只拆呈现，不删原文和诊断。登记归文档会话，卸载只撤焦点句柄。raw 计 dirty/离开保护；真正删字段/节点才显式销毁其 buffer，与 Undo/Redo 配套。冲突保留原文，可查看当前值再选择采用，不能后台 rebase 后提交。

保存捕获 snapshot/generation，确认只标该 snapshot 已保存，保留请求中的后续编辑。扩展原 AutoSave 的 raw/parse/transport-safe 门禁、锁、捕获 revision、失败退避，同一失败草稿不循环重发。可保存草稿与可发布分开：不完整业务配置可保存合法设计草稿；非法原文不能被忽略后显示“全已保存”。首版有非法 raw 时暂停该文档自动保存并说明；运行/发布仍全量 owner 校验。

首版在工作区会话内存活，主体/租户退出退役、撤权沿原边界处理；不把业务原文、凭据写入 localStorage，不新建服务端个人草稿档案。不承诺整页刷新、进程关闭或跨设备恢复，此类持久草稿需独立权限/保留设计。

buffer 按所属定义的字段/节点预算及原文大小限额有界；超限要明确阻止新增输入并说明，不静默淘汰尚未保存的内容。文档重命名沿稳定节点身份迁移路径，不能因为改了字段显示名而清空原文。

### D8 日期区间与关联选择是共享能力

日期区间对应两条真实字段：单入口、起止标签、跨月、连续高亮、悬停预览、鼠标拖选及键盘选择，窄屏单月。起点未完成可保留，完成后整体写回两端；无效原文有修正入口。不能以拖动作为唯一操作，也不能选起点即关闭。

声明明确 civil date/datetime、空端点、终点 inclusive/exclusive、最短跨度。住宿 `[arrive, depart)` 显示晚数；请假保留原包含端点口径，不从名字猜配对。截止日独立，其范围来自参数关系。首版公历日区间；小时住宿先在版本化 lodging 明确时间单位，再接 datetime 区间，不能截时间强套日历。

复用 RecordLookup、Semantic/Member/Role/Protocol 和 enterprise query/resolve，统一来源适配。显示名称与辅助身份，提交真实 id 或 type/id。少量静态值用 Select，大记录用受权搜索/分页；旧选中值独立解析/标注，未在列表中不清空。loading/error/empty 分开，失败不降级自由 ID。上游变化明确重检旧选择，不静默换首项。

跨应用目录沿 protocols 注册有界 typed 来源，前端不能指定任意 URL。住宿试点扩版本化房型目录/提供方适配，CRM 只依赖协议，候选冻结来源版本/绑定。无提供方的电话/邮件旅程显式标人工来源，保留原 owner 的人工标识输入；不伪造权威下拉，不禁掉原人工旅程。

### D9 编辑策略显式声明

| 策略 | 场景 | 口径 |
|---|---|---|
| 确认业务动作 | 弹窗、页面、业务 Inspector、AI 确认 | validate → 原 decide/invoke → outcome，确认才关/清空 |
| 编辑设计文档 | Workshop / Ontology / Flow Inspector | 合法值修改原文档/Undo，原保存策略与发布门禁 |
| 单字段即时提交 | 明确配置的设置、轻量开关 | 独立字段 scope、pending/拒绝；审批/多字段事务转确认 |
| 浏览状态 | 搜索、过滤、日期筛选、读者布局 | 原 PageSession/浏览状态，不发业务决定 |

不把所有 onChange 自动保存，不把 Inspector 等同无确认业务写入。上传、签署、密码/令牌、代码、Markdown、图像保留专门 owner，接共同输入/结果边界。

### 8. 未采纳与代价

- 逐应用补日期/下拉/Zod：没有解决声明和生命周期分叉，新应用还会复制。
- 换库或把所有 Inspector 改 EntityForm：现有 RHF/Zod 已够，文档/画布/复合属性仍有主人。
- 错误只 toast、关窗重开：无法保留上下文与修正输入。
- UI 复制所有业务规则、逐键远程试提交：规则漂移且可能产生效果，只同步有限声明。
- 全局持久存全部草稿：超出本批权限、隐私、保留范围，首版保证同会话编辑连续。

代价是打通声明、编辑协议、文档 buffer、typed outcome 和真实入口迁移，并处理拒绝封套/页面 profile 演进，不能只按控件数量估算。业务与 Inspector 的区别在策略/文档归属，通用行为只有一份。

### 1. 决定

### D1 专业组件 = 通用视图 + 业务模型绑定，不是专用代码

任何一个"专业"呈现都可以分解为**一个通用视觉结构** + **一组模型绑定**：

| 专业呈现 | 通用结构 | 模型绑定 |
|---|---|---|
| 工艺路线图（制造） | **分层有向图**（已存在：`FlowCanvas`/`BlockCanvas` + `FlowSteps` 的泳道，ADR-0033） | 节点=工序、层级=工作中心、边上叠当前状态 |
| 组织与汇报关系图（任意行业） | 同上（分层有向图） | 节点=组织单元、层级=上级结构、边上叠生效期 |
| 配送/供应链网络（贸易、物流） | 同上（分层有向图） | 节点=站点、层级=区域、边上叠线路 |
| 合同审批链（专业服务） | 同上（分层有向图） | 节点=审批阶段、层级=审批人角色 |
| 工作站（制造） | **表单 + 集合 + 状态条**（已存在：`editor` 三栏 + 表格 + `StatusBar`） | 当前工序、参数、可用设备、报工输入 |
| 受理台（酒店、服务台） | 同上（表单 + 集合 + 状态条） | 当前单据、服务项、可选资源、登记输入 |
| 批次谱系（制造） | **有向无环图（树/图）**（已存在：`Graph`/`NodeCanvas`） | 批次关系的方向与标签 |
| 单据版本沿革（任意行业） | 同上（有向无环图） | 版本记录的方向与标签 |
| 能力/资质矩阵（制造、服务业） | **矩阵/交叉表**（需新增：通用交叉表） | 行=资源、列=能力、单元格=表达式结果 |
| 报价/费率对照表（贸易、专业服务） | 同上（矩阵/交叉表） | 行=客户或方案、列=计费项、单元格=表达式结果 |
| 产能/排程负荷（制造） | **时间轴 + 条形**（已存在：`RecordGantt` 的时间轴） | 资源为行、占用为条 |
| 房态/工位占用（酒店、服务） | 同上（时间轴 + 条形） | 资源为行、占用为条 |
| 检验/质量图表（制造） | 图表族（已存在：`page_histogram/trend/scatter/heatmap` 等） | 度量与分组 |
| 满意度/成本趋势（任意行业） | 同上（图表族） | 度量与分组 |

**关键读法**：左列是**同一批通用结构**在不同行业语义下的呈现；真正的通用结构只有六类（分层有向图、表单+集合+状态条、有向无环图、矩阵/交叉表、时间轴+条形、图表族）。**构建者用配置把左列的任意一行做出来，组件代码零改动**——这就是"专业组件"的含义，也是 ADR-0038 §4 禁止"把 MES 页面搬进通用库"的原因：搬走的是左列的名字，通用性在右列。

**结论**：今天缺的不是"MES 组件"，缺的是：
1. **通用交叉/矩阵视图**（唯一真正缺失的视觉结构）；
2. **把已有通用结构配置成专业呈现的能力**（依赖 本文 的模型绑定）；
3. **专业呈现的密度与信息层级**（视觉规范，不是新组件）。

### D2 组件注册契约扩展：允许"结构 + 绑定"的复合组件

`pageui/widgets.json`（`capabilities/server/platform/pageui/widgets.json` → `page_widgets.go:14` → `host.ts`，ADR-0018 §8 的单一契约来源）增加一类组件：**复合视图（composite view）**。

```json
{
  "componentID": "layered-graph",
  "configVersion": 2,
  "propsSchema": { "layers": "binding", "nodes": "binding", "edges": "binding", "overlay": "binding" },
  "inputPorts": [{"name":"selection","type":"record"}],
  "outputPorts": [{"name":"selection","type":"record"}],
  "events": ["select","activate"]
}
```

要点：
- **绑定是契约的一部分**（`"binding"` 类型的属性），因此 Inspector 能生成模型选择器，发布期能做校验（本文 D1）；
- 复合视图**不拥有业务语义**：它不知道"工序"是什么，只知道"节点有层级、节点有边、节点可叠状态"；
- 同一个 `layered-graph` 既能画工艺路线（层级=工作中心），也能画组织架构（层级=部门）、配送网络（层级=区域）、审批链（层级=阶段）。

### D3 MES 的专业呈现由配置产生，代码不搬

- `RoutingFlow`（`web/packages/mes/src/index.tsx:226`）**不作为组件迁移**。它的呈现由 `layered-graph` + MES 应用的绑定配置产生；
- MES 应用（无论是原生参考应用还是客户构建的应用）通过**配置**表达"工序图的层级是工作中心"；
- 原生 MES 的 `RoutingFlow` 在 ADR-0053 的退出路线里随之退役；**在构建侧的等价呈现可用之前不删**（这是硬要求：不能先删再看）。

### D4 视觉规范与信息密度

专业呈现的品质不靠"更多组件"，靠规范：

- **密度**：沿用 `@platform/ui` 的紧凑信息质感（ADR-0018 的 28px 行高、等宽数字、语义色调）；
- **信息层级**：每类专业视图有明确的"一眼看到什么、二次点击看到什么"（沿 ADR-0022 §D7 的"每块写清它证明了什么"）；
- **状态色**：业务状态映射到五种语义色调（`StatusTag` 的既有机制），构建者声明映射，不硬编码；
- **窄屏**：专业视图在窄屏降级为列/表（今天记录工作区已有此行为，保留）。

视觉规范归 Catalog（ADR-0014）；**不写像素断言**（ADR-0029）。

### D5 组件的门槛

新增一个通用组件的门槛（沿 ADR-0018 的"两个业务领域同时需要"规则，在本文收紧为**可验证的形式**）：

1. 它在**至少两个不同的应用配置**里被使用，且这两处配置由不同的人写；
2. 它不包含任何业务词汇（"工序"、"库位"、"床"等等不得出现在组件代码与 props 名里）；
3. 它的绑定是模型引用（本文），不是硬编码字段名；
4. 它的默认呈现从模型推导（本文 D2）。

**不满足四条的一律不进 `@platform/ui`。** 这条门槛是对 ADR-0038 §4"把原生 MES 页面迁入 Workshop 冒充通用组件"的**机制性防线**：想搬可以，先在两个行业里各配一次。

### 2. 不做

- **不把业务专用页面搬进通用组件库**（见 D5）。
- **不建第二套 UI 库**（ADR-0018 的归属不变）。
- **不做 GIS/3D/甘特的深度专业实现**：只在具体任务需要时进入队列（沿 Platform §10.3 B 的既有边界）。
- **不做组件的可视化搭建器**（拖组件搭新组件）：复合视图由**配置**产生，不由嵌套搭建产生。
