# ADR-0040: 关系、动作与应用组合的统一语义模型

**状态：** 已接受 (2026-09-28, #138)。项目负责人授权直接执行或在对抗性自审后执行；D1–D4 连同下述实现边界一并被接受。ADR-0031 的平台方向和 ADR-0037 的有界单记录动作保持已被接受；本决策对它们进行扩展。

## 背景

上层设计已经命名了对象**与关联 (and link)** 类型、动作/函数、页面/组件、流程/智能体、AI 函数、集成/查询以及应用/包资产（Platform.md §10.3）。而当前的构建器（Builder）导航展示的是对象、流程与访问控制、页面和应用（`web/packages/build/src/index.tsx`）。这是第一个垂直切片，而不是完整的本体 (ontology) 或应用工作室。

当前代码事实 (2026-09-28)：

| 领域 | 当前运行的内容 | 对构建者的差距 |
|---|---|---|
| 对象与关系 | `build.Object` 拥有包括一个 `reference` 在内的具类型字段；`relations.Link` 可以连接任意两条记录，`Caller.Links` 读取可见的邻居记录 | 没有具名的关联类型 (link-type) 资产、反向名称、基数/所有权规则、具类型遍历、依赖影响或关联编辑器。通用关联缺乏声明的业务含义 |

共同的原则是多个编写与操作界面共同消费一个**具类型的语义图**。这并不需要抄袭 Foundry，也不需要将所有平台概念塞入同一个编辑器菜单中。

## 我们的约束

- 应用 API 拥有公共资产契约和具类型代码扩展；宿主负责校验、鉴权和执行；`build` 拥有租户草稿/编辑；`relations` 拥有记录关联存储与遍历；`@platform/app` 拥有 UI 绑定，`@platform/ui` 拥有组件。不引入并行的记录/动作/关联执行器或应用私有的表达式解释器。
- 不得将业务领域词汇引入 `contract/`。业务含义驻留在具名、版本化的资产中。跨应用状态修改遵从动作与协议；一个构建器动作不能直接写入另一个应用的私有状态。
- 代码、可视化和 AI 编写在同一套资产标识、权限和发布检查上收敛。不存在任意租户代码。预览绝不调用在线效果或向生产环境写入。重放不向外部调用任何内容；已提交结果恢复和不可变修订版是独立的 #135/#136 门禁。
- 编辑器质量要求完成经实测观察的构建者任务与操作员任务，具备逼真的记录、中文支持、键盘操作与窄屏状态。单纯的浏览器测试或生成的屏幕并不代表视觉验收通过。

## 设计

1. **语义图与所有权。** 向应用 API/注册表添加 `LinkType` 资产，具备稳定的限定标识、版本、源和目标对象类型、每个遍历方向的名称、基数、必填性、权威以及删除/演进规则。`reference` 字段和通用记录关联在适当时是该契约的输入或实现，而不是其替代品。`relations` 通过宿主的规范鉴权存储/查询实例。构建器展示依赖图、其依赖关系以及某项变更会破坏什么。第一个简单的切片支持由引用支持的一对多关系；后续的多对多或带属性关联需要明确的存储/动作契约。准确记录提交时强制执行的约束。
2. **动作语义。** 保留 ADR-0037 的单记录转换作为受支持的小型用例。赋予每个动作具类型的输入/结果与效果摘要、经服务端校验的规则操作数、显式权威和失败提示消息。后续同一权威下的多记录/关联动作使用 #135 的原子已提交结果边界；跨应用工作使用已声明的协议与流程。可复用的纯函数/查询是单独命名的资产，可通过具类型输入和经授权的输出被动作、页面、AI 逻辑和代码调用。不要通过在租户端链式表单写入来伪造跨对象原子性。
3. **页面组合即绑定。** 扩展 `platform.Page`/已注册组件契约，包含具类型页面变量（选择项、过滤器、路由输入和有界派生查询）、部件输入/输出绑定和声明的事件（设置变量、导航、提交具名动作）。关联遍历绑定关联列表/详情和主/从任务。为代码页面、可视化工具和 AI 提议复用相同的绑定；在源头拒绝类型/权威/依赖错误。避免照搬 Workshop 的整个变量系统或 Appsmith 的 JavaScript 表达式。
4. **一个产品，两个创作空间。** 使用诸如**应用设计台 (Application Studio)** 之类的统领名称来代表构建者旅程，以**业务模型**（对象、关系、动作/规则、权威、数据源）和**用户体验**（应用、页面、组件、绑定）作为其主要工作区；**测试与发布**暴露校验、候选 diff、依赖关系、隔离预览和激活。“状态与动作”归属于对象行为视图内部；访问控制具备清晰的所有权/作用域视图。名称和导航属于产品文案，而非新的运行时契约。渐进式检查器优先展示常用动作路径（何时、谁、结果），然后是输入、规则、审批和高级效果；展示紧凑的前后对比/示例和内嵌行内错误。
5. **预览、发布与演进。** 诚实地将当前组合画布标记为经授权的实时数据、只读编辑视图。由独立固定数据支持的预览/模拟使用隔离的候选版本，并且可以展示拟定动作的结果而无需进行生产环境写入/效果派发。#136 拥有不可变修订版、依赖闭包和激活；本 ADR 的关联/函数/页面契约必须参与其中。重命名、删除、基数和权威变更在激活前必须报告受影响的页面、动作、AI 工具和运行中工作。
6. **使用实证。** 酒店业和制造业极简探针各自定义或复用一个对象，将其与另一个对象关联，在页面和受治理动作中使用该关系，并完成操作员任务。相同的资产在代码/API 中可发现，且仅通过声明的权限向 AI 开放。与负责人一同衡量编写完成度/错误率以及操作员任务完成度；应用特定的业务功能深度暂缓。
7. **具类型图表界面，而非图执行引擎。** `@platform/ui` 拥有基于 React Flow 的画布和受控节点目录：每种节点类型声明其类别、语义资产引用及版本（如果可用）、具名输入/输出端口、端口类型和连接容量。语义所属主件提供从其规范定义到画布节点/边的适配器，并将校验后的编辑应用回该定义。画布位置、选中状态和缩放是展示元数据；它们无法赋予执行或访问权限。目录按平台能力扩充：对象/关联拓扑、生命周期/动作、流程、AI 函数/智能体以及后续的有界媒体或物理世界模型均可以拥有各自的适配器、校验和控件。结构化对象图可以成环；生命周期可以重访状态；确定性数据流需要明确的环路/延迟规则。通用渲染器绝不能将一个图的执行语义强加给另一个图。FDE 获得节点列表、具类型连接反馈、可检查配置、依赖影响、键盘替代方案和版本化变更；客户编辑受限于已授予的节点类型。现有的只读 `Graph` 保持为操作视图。[React Flow 的自定义节点与句柄](https://reactflow.dev/learn/customization/handles)以及[连接校验](https://reactflow.dev/examples/interaction/validation)提供交互底层基座；我们的目录和宿主契约提供业务含义。

## 负责人决策点

| # | 问题 | 选项 | 推荐方案 |
|---|---|---|---|
| D1 | 具名关系是否是一等公民的版本化语义资产？ | 具有双向名称、基数和权威的 `LinkType`；或继续使用 `Field.Ref` 加上通用的 `platform.link` | 一等公民。当前的组合无法表达或校验 UI 和 AI 必须共享的业务关系。从引用支持的一对多切片和真实的强制执行语义开始。 |
| D2 | 租户编写的动作可以多大程度上改变状态？ | 仅保留同记录转换；或在 #135 之后添加同权威对象/关联编辑，而跨应用工作保持基于协议/流程 | 在原子提交边界之后添加有界的同权威编辑。针对常见用例保留简单的转换编辑器，并拒绝不支持的跨应用原子性声明。 |
| D3 | 页面部件在选择/过滤之外如何协同？ | 共享页面契约中的具类型变量与声明事件；或累积更多硬编码的部件耦合 | 具类型变量/事件，由一条基于关系的 master/detail 旅程引入。这是最小的共享契约，能够自然扩展而无需为每个部件引入新特例。 |
| D4 | FDE 如何在不碎裂平台语义的情况下编辑不同含义的图？ | 可复用的具类型节点目录与 React Flow 画布，配备按能力的适配器；或各应用自有的独立图编辑器 | 单一 UI 套件画布与目录契约。语义资产与宿主校验保持权威性；适配器负责各图的合法编辑、持久化与环路规则。首个生命周期适配器编辑现有的 `Action.From/To`，随后关系、流程与 AI 适配器跟进其平台所属主件。 |

已拒绝的方案：Foundry 形态的数据库、所有领域逻辑作为工作流、任意租户 JavaScript、第二套仅用于构建器的运行时，以及宣称当前的实时数据画布是隔离预览。现有的 ADR-0038/0039 负责人决策保持独立，并在注明处作为前提条件。

**实施前的对抗性审查 (2026-09-28)。** D1 的首个关系切片是由引用支持的，并且最初可以是只读的：展示声明绝不能暗示通用的 `platform.link` 记录或引用字段已经在强制执行具名关联的基数、删除或鉴权规则。只有当规范写入路径实际检查这些规则时，才能将它们报告为保证。D2 无法通过顺序调用两个现有动作来实现：没有 #135 的原子结果边界，可能会产生部分可见状态；跨应用工作保持为协议/流程工作。D3 的页面变量图必须在每个边缘使用调用者作用域的读取和动作声明；仅仅隐藏部件并不是访问控制规则。D4 拒绝将无类型的节点图作为新的业务解释器：渲染的节点解析为受治理的资产或具类型草稿，任何拖拽/连接手势都不得绕过现有的动作、流程或 AI 执行路径。这些限制收窄了第一批切片，而没有逆转 D1–D4。

## 后果

公共模型扩展至四种资产类型之外，因此兼容性与依赖检查变得更为严格。具名关系和具类型页面变量提升了复用性，但需要对现有的引用字段和通用关联进行深思熟虑的迁移。现有数据和 ADR-0037 行为保持有效，直到出现明确受支持的演进路径；不暗示对已发布的客户数据或在途工作进行自动重新解释。构建器可以渐进式重组，但最终完成度以整体构建和操作员旅程来评判，而非导航条目的数量。

## 实施现状 (2026-09-28, #138 21a 第一切片)

宿主拒绝分配给不兼容字段的动作输入，根据目标字段检查选项输入值，拒绝无币种的金额比较，并在发布前按声明的类型检查条件操作数和有序运算符。运行时比较使用该类型，对于畸形值不回退为文本排序；日期值从存储的时间戳规范化为其日历日。应用设计台（`build` 应用 ID）在单个编辑器中打开对象的字段、生命周期和访问控制；其动作检查器保持常用路径可见，并折叠审批及输入/规则细节。早期的编辑器提示能够暴露常见的规则错误，而宿主依然保持权威。UI 套件的 `NodeCanvas` 和 `NodeCatalog` 校验具名端口、匹配类型、重复边和连接限制。首个适配器将状态/动作节点和连接映射到现有动作的 `From/To` 声明；删除连接会编辑这些声明。其节点位置属于本地视图状态，并非已发布的语义资产。**在此第一切片检查点处，开放的正确性技术债：** 省略的可选标量字段此前被具现化为其 Go 零值，因此条件无法区分缺失的可选数字与显式的零。下方后续的 21a 增量解决了此问题。本切片未实现具名关联资产、具类型页面变量、不可变版本或通用流程/AI 图编写；这些保留在 21b–21d 以及 #133/#135/#136 中。

负责人反馈暴露出存在缺陷的首个画布：节点作为受控 React Flow 数据传递而缺少 `onNodesChange`，端口位于被裁剪的行内，语义边编辑反复替换节点状态并重置视口。修复后的 UI 套件使用 React Flow 的受控节点/边变更回调、可直接测量的句柄，以及与其只读 `Graph` 相同的 `CanvasFrame`、自适应行为、控件和分层布局。两个图表界面均可垂直调整大小或展开；生命周期连接更改其规范动作声明，而不会位移正在编辑的节点。先前恢复的**流程与访问控制 (Process and access)** 导航条目现已恢复并打开对象选择器。`/v1/definitions` 现在返回空的 `requires` 数组而非 `null`；工作区亦兼容较旧的 null 响应。图契约保持特定于能力：共享框架并不是工作流、审批、路由或智能体解释器。

验证情况：在修复后的代码树上通过了 `scripts/verify.sh format`、`capabilities`、`composition` 和 `web`；全部 21 条浏览器路由均通过。路由 34 连接生命周期端口，检查拖拽的节点及其边是否一同移动，调整画布大小，发布并完成操作员动作。路由 24 和 27 检查共享画布展开以及具有空依赖关系的定义目录；路由 34 检查恢复后的菜单。使用修复后的两部分重新构建了 8495 Docker 酒店宿主，重放了 76 个现有酒店日志条目，通过了 `/healthz`，并提供与本次构建完全一致的工作区资产哈希。负责人对视觉和体感交互的验收仍处于待定状态。

下一个 21a 正确性增量在其生成的记录类型中为可选的租户定义标量字段赋予了 nil 状态。应用 API 仍将它们描述为 integer、decimal、boolean、money 或 datetime；宿主的校验和比较路径解包存在的值。省略可选整数或布尔值的记录现在在序列化时不包含该字段，而显式的 `0` 和 `false` 依然存在。动作条件和有序记录查询在省略值上安全关闭（包括在日志重放之后），并可以接受显式值。共享的可选布尔值编辑器允许用户清除值，并在视觉上区分 false 与缺失。`NodeCanvas` 在手势结束时通过无障碍警示提示无效连接的端点、端口类型、重复或容量原因，而在指针移动期间不更新 React 状态。这并未关闭负责人观测的键盘、窄屏、中文和体感交互审查。`TestTenantDefinedActions` 覆盖了省略、零、false、动作拒绝/接受、有序记录查询和重放；画布校验器的单元用例覆盖了连接原因，浏览器路由 34 测试了可见的重复边拒绝。`scripts/verify.sh format`、`capabilities`、`composition` 和 `web` 在此增量上均通过。8495 Docker 酒店宿主再次重新构建，重放了 79 个现有条目，通过了 `/healthz`，并提供与本地工作区构建相同的 index 和 entry 资产字节。

窄屏走查发现，两个编辑器在其三栏堆叠后仍保持宽屏固定高度，将画布和检查器压缩成嵌套的小型滚动区域。`PageEditor` 和 `ProcessEditor` 现在允许工作区在宽屏断点以下滚动完整堆叠，而宽屏依然保留独立滚动的窗格。浏览器路由 30 和 34 在 390×780 分辨率下断言了堆叠窗格顺序和实用的画布/检查器高度；`scripts/verify.sh web` 通过。8495 Docker 酒店宿主基于该工作区重新构建，重放了 79 个条目，通过了 `/healthz`，并提供与本地构建相同的 index 和 entry 资产字节。这是布局修正与自动化实证；负责人对视觉和体感交互的验收仍处于待定状态。

**21a 走查结论（2026-09-28）。** 负责人在上述修正后完成桌面端、窄屏、中文、键盘及画布交互走查，反馈没有问题，接受本切片的编辑体验。此结论来自负责人实际操作，不是本次文档更新重新执行的自动化测试；仅关闭 21a 的体验验收，不代表具名关系、发布版本、物理隔离沙箱、其他业务旅程或 §10.6 全面前端门禁通过。#138 的下一切片为 21b。

**21b 首批（2026-09-29）。** 引用字段可声明具名反向关系（代码标签 `inverse:"…"`，构建器字段的“在对方记录中显示为”）；宿主只接受引用字段上的小写名称。被引记录页按该名称列出引用它的记录，包括其他应用的记录；成员须能读取两端类型，无声明的跨应用引用仍不外露。CRM 商机对客户声明 `opportunities`，MES SFC 对工单声明 `sfcs`。组合页面分区可设置 `relation`：只有表格、图表、指标可跟随关系，发布时宿主校验分区对象确实声明了从页面对象出发的该关系，运行时按所选主记录过滤；页面编辑器在“经由”中列出关联对象声明的关系。酒店组合测试覆盖跨应用列出、无权成员不可见、非法关系名、未声明关系与不支持的部件被拒。**尚未完成**：关系作为独立版本化资产（基数、删除规则）、关系发现 API、AI 工具按关系读取、制造操作员主从任务与浏览器路线；现有基数仅为引用隐含的一对多，不宣称强制删除或基数规则。

**21c 首批与 21d 起步（2026-09-29）。** 租户动作可声明 `creates`：在同一次决策中创建本构建器另一对象的记录，经由该对象指回当前对象的引用字段。发布时拒绝其他应用的对象、对象自身、未发布对象、非回指引用及不存在的字段；执行时关联记录在 `Do` 中构造并校验（必填与创建角色生效，任一拒绝即拒绝整个动作），在 `After` 中以同一变更写入，因此与主记录同属一个已接受结果，追加失败两者都不可见，重放与快照一致（`TestActionCreatesRelatedRecordAtomically`）。跨应用原子编辑不支持并被拒绝。应用清单可声明具名查询（`platform.NamedQuery`，资产类别 `query`）：固定条件、排序及可选“按记录运行”的引用字段；`GET /v1/queries/{app}/{name}?for=` 以调用者自身读取执行，组合页面表格分区可绑定查询（发布时校验查询存在、对象一致、按记录的引用指向页面对象），智能体以 `query:<name>` 工具为其所代表的成员运行；CRM 声明 `open-opportunities`，MES 声明 `released-orders`（`TestNamedQuerySharedByPageAndMember`）。21d 起步：`POST /v1/simulate` 仅限构建者，以指定成员身份在私有暂存决策中判定一个走已接受结果路径的动作，返回将写入的记录或拒绝原因后丢弃，不产生日志、记录、通知或效果（`TestSimulateIsDiscarded`）。**尚未完成**：试运行界面与固定测试数据隔离、完整构建→试运行→发布→操作员浏览器旅程、纯函数（非查询）资产、负责人体验走查。

**21c 检查补齐（2026-09-29，工作树）。** `PageReleaseAsset` 将表格分区绑定的具名查询纳入发布依赖闭包；候选字节校验拒绝描述符绑定了查询但遗漏该依赖的输入。`TestReleaseCandidateIncludesQueryAsset` 覆盖构建器页面闭包，`TestReleaseCandidateRefusesUnclosedAndAmbiguousAssets` 覆盖遗漏查询依赖拒绝；新增 HTTP、未知智能体查询工具与制造工单探针通过，浏览器路线 40 实际运行通过，验证选定客户后仅展示其进行中商机。该检查补齐不表示租户工作流草稿已接入或负责人已验收体验。

### 21d 首个固定数据切片（2026-09-29，实际构建）

沿已接受的 D2 与隔离预览设计边界（本 ADR 设计第 2、5 项），宿主复用发布审查生成保存对象草稿的精确受影响闭包（含对象、动作和依赖页面/应用描述符），在全新的内存租户中安装这些定义；测试租户仅接收定义字节与当前被选成员的角色，不接收任何生产记录、日志、设置、端点或凭据。候选准备仍复用发布审查的当前定义/安装兼容性校验（可能读取现有行以验证类型转换）；测试步骤自身不读取这些行，不能把此边界描述成整个请求完全不触达生产控制面。应用 API 的原生生命周期、动作、创建权限、读取视野与字段脱敏仍然生效。构建器给出固定时钟及最多 20 个类型化动作输入，以创建动作建立样本数据，再执行成功/拒绝步骤；每次运行都从空记录开始。涉及同构建器关联创建的对象加入闭包；跨应用依赖、审批和组织目录依赖在首批明确拒绝，不能降级为生产调用。运行结果仅展示被选成员可读的数据，并校验沙箱快照恢复前后相同。首批是进程内独立租户与内存状态隔离，不宣称操作系统进程隔离；没有导入生产数据的入口。在此首批检查点，页面和 AI 沙箱、测试集持久化以及负责人体验仍是余项；计划持久化的后续实证见下文。

交互由 `build` 编排共享 UI 的选择器、输入框和结果卡片：选择已保存对象草稿、指定实际成员、编辑固定时间与动作计划，运行后展示候选标识、逐步接受/拒绝和恢复校验；键盘、中文与窄屏由浏览器路线验证。参考 [Palantir 固定模拟对象](https://www.palantir.com/docs/foundry/functions/unit-test-stub-objects) 与 [对象查询桩](https://www.palantir.com/docs/foundry/functions/unit-test-object-searches) 的可控测试输入原则（2026-09-29 查阅），不引入其 SDK 或租户代码执行模型。

`POST /v1/simulate/candidate` 由宿主拥有，`CandidateTest` 仅组装固定输入，不执行租户代码。测试与发布审查使用同一候选 ID，回归覆盖依赖的已发布页面/应用；浏览器在发布前后核对该 ID。页面描述符在测试租户安装，但尚不提供有状态页面画布。每个接受步骤返回该成员当前可读的样本记录（不是生产差异），拒绝步骤保留前一步的测试状态。`TestCandidateSimulationUsesOnlyFixedData` 覆盖同一生产记录 ID、草稿与已安装规则不同、重复确定性、关联创建失败/成功、字段脱敏、动作权限、跨租户/非构建者拒绝、审批失败封闭及 HTTP 输入边界。酒店 `TestTheHotelTestsASavedObjectWithoutProductionRows` 和制造 `TestInspectionActionCreatesFinding` 覆盖双行业、跨应用依赖拒绝与重放。浏览器路线 41 走通固定数据成功/拒绝/恢复、键盘启动、390×780、中文以及随后发布、保存不可变候选、激活并由前台关闭真实记录；该路线沿现有 20b 机制先完成开发期安装，再激活一致的闭包，**不证明激活即安装**。`scripts/verify.sh format capabilities composition web` 验证本切片；没有新执行 Docker 部署或负责人走查。此首批测试集仍在当前界面内存中，未持久化；不能据此关闭整个 21d、#132 或年度物理隔离门禁。

**旧单动作试运行的权限收口（2026-09-29，#130）。** `/v1/simulate` 仍是针对现有生产记录的只读试运行，不是固定数据沙箱。宿主现在先校验构建者所属租户，在租户锁内解析成员与动作，并克隆提交后改写试运行身份；返回记录通过私有记录视图的规范 `Records` 路径裁剪到请求构建者的记录视野、字段权限和派生来源限制，不因模拟了更高权限成员而扩大读取。隐私读取审计留在私有视图并丢弃。`TestSimulationResultsUseBuilderReadPermissions` 覆盖同单元可读但 lead 字段不可见、另一单元记录完全不可见、跨租户拒绝、提交与生产快照未变；`TestSimulateIsDiscarded` 保留成功/拒绝及日志不变验证。


### 21d 固定测试计划的持久化（2026-09-29，实际构建）

`build.TestPlan` / `build.testplan` 保存对象草稿引用、计划名称、固定时钟、成员 ID、1–20 个候选对象动作输入及每步接受/拒绝预期。归属 `build`，复用标准创建/编辑/归档、引用和修订校验及已有 `accepted-result` / 快照；未新增日志类别、私有配置解释器或运行时。默认不可读，仅构建者可读写。宿主统一提交入口的成员租户补强与重复答复边界记于 ADR-0038 本日实际构建。

`CandidateTest` 可命名保存、刷新后选择、显式重载并重跑；并发编辑拒绝保留本地输入，重载取得新的修订号后才继续保存。编辑输入会清除旧结果。每次运行仍按当前保存对象草稿生成精确候选 ID，并从空样本状态开始；各步匹配期待的接受/拒绝，只有每步均声明预期时才返回总体匹配。旧调用未声明预期不会得到隐含通过。计划不是不可变发布资产，不保存运行结果，不断言具体拒绝码或记录字段值，不对未来草稿保留通过承诺。

`TestSavedCandidatePlansUseRecordsAndAcceptedRecovery` 验证追加失败不可见、重试与重复、拒绝无权成员读取/编辑及其他租户同名成员、修订冲突、非法固定输入、恢复后重跑一致与草稿变化导致重新匹配；`CheckReplay` 覆盖计划记录。酒店/制造已接受结果探针均从保存计划读取并运行，验证测试不改变正式快照或日志。路线 42 走通键盘保存、刷新重载、相同候选重跑、错误预期、并发冲突/重载/再保存、普通成员不可读、中文及 390×780；桌面输入/结果、中文和窄屏截图已检查。`scripts/verify.sh format capabilities composition web` 通过。未新执行 Docker 或负责人走查；页面/AI 沙箱、物理隔离、激活即安装和完整 21d/#132 仍未完成。
