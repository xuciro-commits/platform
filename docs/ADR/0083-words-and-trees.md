# ADR-0083 一种语言写名字，分组看资源：多语言租户定义与构建器清单

状态：租户词典、能力矩阵和资源分组已实施（2026-10-08）；负责人整体体验验收不由类型检查替代。

## 背景

负责人走查提出七条：租户自定义名称只能"EN/中文"拼在一个名字里；日志类型、函数类型、能力模块仍是英文；术语表与血缘不知道连到哪；能力矩阵标签重叠、不知道页面干什么；动作类型是否该列系统默认动作；对象类型等资源是平铺网格；整体拥挤。前五条根子是同一件事：**宿主有一套完整的声明翻译（ADR-0023），但租户在构建器里写的声明没有进入它**，于是人把两种语言塞进一个标题。后两条是构建器清单从未分组。

## 决定

### D1 租户词典：第三层字典，不是第二套名字

ADR-0023 的翻译器按语言合并字典：平台字典（通用词）→ 应用字典（行业词，按租户启用顺序）。本 ADR 加第三层——**租户词典**（`capabilities/server/words.go`）：`language → text → translation`，管理员通过 `platform.translation.set`（目标 = 语言标签，载荷 `text`/`translation`，译文为空即删除）写入；进快照 `words`，重放后 `translator.reset()` 重建缓存。它压在应用字典之上，所以同一个词在不同业务里可以不同（"Order" 在酒店是订单、在工厂是工单），而通用词只在平台字典里写一次。

因为租户定义的对象类型、字段、状态、动作、应用、页面都从 `/v1/definitions`、`/v1/entities`、`/v1/actions` 等已翻译的路由出去，`walkTexts` 对 `title/plural/description/help/synonyms` 一视同仁，**租户写的名字从此与内置名字走同一条翻译路**：名字用一种语言写一次，其他语言在词典里给。`GET /v1/words?app=`（管理员）列出一个应用的全部声明文字（`Texts(app)`；`build` 另加租户已安装定义的文字），每条带各语言当前读法与租户自有词条。

工作区：控制面板 → **语言与用词**（`platform/src/words.tsx`）：选来源应用（默认"租户定义"）、选语言或加语言标签、搜索、只看未翻译、逐行回车/失焦保存，来源列标明"自定义/内置/缺失"。对象编辑器对混用两种语言的标题给出警告（`build/src/editor/names.ts`：同时含 CJK 与小写拉丁词；"WMS 仓库"这类缩写放行），指向该页面。不自动拆分已有的"EN/中文"名字——这是改名，由人做。

### D2 剩余英文的来源与去处

字面 `t("…")` 全部有 zh-CN 词条（脚本核对为 0 缺口）。剩余英文来自**值**而非文案：审计表里的动作 schema、模块 ID；代理页的信号/记忆状态标签；能力名。处置：审计显示成员目录中的动作标题（宿主已按语言翻译）并以小字保留 schema，应用列显示模块标题；代理标签过 `t()`；能力见 D4。宿主侧新增的动作/字段文案补入 `i18n/zh-CN.json`。

### D3 术语表与血缘各连到哪

- **术语表**（`knowledge.term`）：三处读它——搜索（`names()` 把术语与同义词当作实体名候选）、代理（`glossary(app)` 进入提示词）、人（问"这里的 PO 是什么"）。它不改名；页面说明现在直说这一点并指向"语言与用词"。
- **血缘**（`build/src/ontology/lineage.tsx`）：从集成定义本身读——连接 → 数据源 → 数据集 → 管道 → 对象 → 回写，没有第二套模型；一个对象的上游是喂它的数据源/管道链，下游是把它的动作送往连接的回写。不改。

### D4 能力矩阵与软件包页

能力是动作声明上的一个字符串标签（`Catalog.Capabilities()`），本身没有标题，所以工作区命名它（`platform/src/apps.tsx` `capabilityTitle`，zh-CN 在包内字典）。矩阵不再是定高行的表格（标签换行即重叠），而是**每模块一张卡**：左"提供"（能力与动作数、角色、读取、协议、效应、接口），右"使用"（消费协议、协议动作、订阅、连接器输入），上方筛选。`AppInfo` 新增 `title`（经翻译）。

两页分工：**软件包** = 版本、依赖、安装/升级/排空/退役（决策）；**能力矩阵** = 每个模块提供什么、用什么（说明）。软件包页的"内置模块"段只列标题与能力名，不再重复矩阵。

### D5 动作类型：列出系统默认动作，但分开、折叠、只读

同一页两段：**本组织声明的**（可编辑，按对象类型/项目/状态分组）与**宿主与模块自带的**（默认折叠，只读，按对象类型/模块分组；点击打开对象类型的只读模型视图）。理由：构建者在声明前应看见已有的新建/编辑/归档和模块动作，但它们不能混进可编辑清单。

### D6 资源清单是树，不是换个文件夹继续平铺

`@platform/ui` 新增 `GroupedList`：分组标题带计数可折叠，搜索跨组过滤，"分组依据"可切换。应用于：

- 对象工作台左栏：按**项目**（代码对象按归属模块、标"内置"）/ 归属模块 / 状态；
- 动作类型（D5）；
- 15 个 `RecordList` 清单（查询、数据集、管道、函数、代码、决策表、代理、告警、关系、共享属性、连接、数据源、匹配、回写、流程）换成 `build/src/editor/ResourceList.tsx`：树（按项目 / 对象类型 / 状态 / 不分组）与表格（原 `RecordList`，保留排序分页）一键切换。

"项目"分组只用 `build.app.resources/pages` 的事实；不在任何项目里的列为"未归入项目"，**不猜**。

### D7 布局

卡片内用 `dl` 事实列表与换行列表，不再有定高单元格里的标签流；状态只出现一次（行尾），标识用等宽小字。

## 后果

- 契约：`AppInfo.title`、`WordsView/Word`、`platform.translation.set`、`GET /v1/words`；`host.ts` 已重生成，`TestAPIContract`/`TestLanguages` 通过。
- 测试（ADR-0082）：新增一条长期不变量 `TestTenantWords`（租户词条压过内置、模式仍生效、删除即消失）。
- 不做：自动把已有"EN/中文"名字拆成词条；按名字前缀猜项目；给能力加宿主侧标题（它只是标签）。
