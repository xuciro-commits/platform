# ADR-0057 — 用一个工作台构建完整应用：升级浪潮的顶层分块

状态：提议（顶层分块待负责人排序后逐块立 ADR）· 2026-10-06 · 承接 ADR-0053/0054/0055/0056

## 0. 问题与判据

今天的工作台能定义对象、动作、页面、流程、函数并发布，但 FDE 若要**完全不写代码**地交付一个 WMS/MES/HR，仍会在十几个地方撞墙。本 ADR 不逐条修补，而是先回答两个顶层问题：

1. 一个"完整应用"由哪些块构成（对标 Palantir Foundry/AIP 的应用解剖，与 SAP 一个业务模块的解剖）；
2. 每块我们有什么、缺什么、放在哪一层补（后端 `capabilities/server` / 前端 `@platform/*` / 工作台 `build`）。

**验收判据只有一条**：以 WMS 为探针，FDE 在工作台内从空项目出发，做出可上线的收货→上架→拣货→发运应用，其中员工、组织、物料、库位等主数据来自**共享本体**而非 WMS 自造；全程不进入代码。每块的"完成"都以这条路线上的断点消失为准。

## 1. 对标的解剖图

| 层 | Palantir Foundry / AIP | SAP（一个模块，如 EWM） | 我们今天的对应 |
|---|---|---|---|
| 数据接入 | Data Connection、Pipeline Builder、Datasets→Object backing | IDoc/BAPI/OData、批输入、CDS | 托管连接器（K8）、CSV 导入导出；无可配置数据源 UI（#134 待做） |
| 本体 | Object types、**Interfaces**、Link types、Shared properties、Value types、Actions、Functions | 业务伙伴、物料主数据、组织单元、Append/扩展结构、Customizing | 对象/关系/共享属性/动作/查询齐全；`org` 应用有组织模型；**无 Interface、无跨应用扩展字段、无共享主数据包** |
| 界面 | Workshop、Object Views、Quiver、Slate、Carbon 工作区 | Fiori 模板（List Report / Object Page / Worklist / Wizard）、打印表单 | 页面编辑器 + 75 原生插件、应用页眉/导航、Carbon 式工作区；**无交易模板、无手持/扫码、无打印** |
| 逻辑 | Automate、Functions（TS/Python）、Ontology edits、Notifications | 工作流、编号范围、凭证过账、条件技术 | Flow/自动化、生命周期/审批、序列、通知；**无定时触发、无规则表、无过账/台账模型** |
| 安全治理 | Markings、Organizations、Roles、Projects、Checkpoints | 授权对象、角色、公司代码/工厂范围 | 行/字段/动作权限编译、项目委派 API；**工作台无角色/范围设计面** |
| 交付 | Branching、Checks、Marketplace、Upgrade、Environments | 传输请求、三系统景观 | 候选/发布/升级/环境 API 齐全；**环境晋级/包生命周期无 UI** |
| 运维 | Job tracker、Health、Alerts、Usage | 作业监控、SM37/应用日志 | 遥测、运行记录；**应用关联运行面未接（#141-C）** |
| AI | AIP Logic、AIP Assist、Agents、Evals | Joule | AI 函数、智能体、评测、MCP/A2A；**工作台内无 Assist** |
| 开发者 | OSDK（按本体生成 SDK）、Webhooks | OData、RFC | 宿主 API 生成 TS 类型；**无按应用生成的 SDK** |

## 2. 顶层分块

每块给出：目标 · 对标 · 已有 · 缺口（后端 B / 前端 F / 工作台 W）· 规模（S/M/L/XL）。

### A. 共享本体与跨应用（你提出的点，也是整条线的地基）— XL

**目标**：组织、员工、联系人、业务伙伴、物料、库位、计量单位、币种、日历这类主数据只定义一次，MES/WMS/HR 共用；应用可以**扩展**而不能**复制**它们。

**对标**：Foundry 的 Ontology 是租户级单一本体，项目只是引用；Interfaces 让"可发运的东西"这种抽象跨对象类型复用；SAP 的业务伙伴/物料主数据 + Append 结构。

**已有**：对象类型已是租户级、按所属应用命名空间（`hcm.employee`、`build.xxx`）；项目通过 `resources[]` 引用（ADR-0055）；`org` 应用有带时间维的组织单元/架构；关系可跨应用并绑定版本。

**缺口**：
- B：**基础本体包 `core`**（Party/Person/Employee、OrgUnit（沿 `org`）、Partner、Site/Location/Bin、Material/Item、UoM、Currency、Calendar）作为平台包随宿主安装，租户可引用；
- B：**Interface**（`AssetInterface`）：一组属性/动作签名，对象类型声明实现，查询/页面/关系可以面向 Interface；
- B：**扩展字段**：租户在工作台给代码定义或他人定义的对象类型追加字段/动作（存储于扩展记录，读取时合并；权限随扩展方），这是 SAP Append 的等价物；
- B/W：**归属与影响**：共享类型有 owner 项目；工作台显示"被哪些应用使用"，修改时列出受影响发布（沿 Lineage）；
- W：项目主页"添加已有"已能引用，再加"从 core 引用"快捷入口与 Interface 工作台。

### B. 本体深度 — L

**目标**：对象类型工作台覆盖 Palantir Ontology Manager 的常用面。
**缺口**：B 计算属性（把 `Derivation` 开放给租户：表达式 + 引用聚合）；B 值类型/单位（数量+UoM、金额已有）；B 多对多关系的**关系属性**；B 时间序列属性（有界：按记录的度量序列，复用聚合窗口）；W 对象类型的图标/颜色/标题模板/格式化；W 动作类型的**副作用**面板（通知模板、Webhook、写入关联对象）与动作日志视图。

### C. 数据接入与主数据 — L

**目标**：不写代码把外部系统的数据接成受控对象，并持续同步。
**对标**：Data Connection + Pipeline Builder（有界版）；SAP 批输入/IDoc。
**已有**：K8 连接器、游标、幂等、CSV 导入导出、`transfer.go`。
**缺口**：B 可配置数据源（HTTP JSON / CSV 定时拉取 / 数据库只读表；#134 的第一个 profile 扩成三个）；B 字段映射与清洗规则声明（类型转换、查表、去重键）；B 定时同步 + 失败隔离；W 接入向导（预览→映射→试跑→发布）；F 主数据维护页模板（见 D）。

### D. 界面：交易模板与车间终端 — L

**目标**：工厂里的人用得上。
**缺口**：W **模块模板**（SAP Fiori 五型：清单报表、单据头+行项目、工作清单、向导、看板/大屏）一键生成并可改；F/W **手持模式**（PDA 布局、大按钮、扫码输入组件：条码/二维码进字段、扫码触发动作）；B/F **打印**（标签 ZPL/PDF 模板，绑定对象，打印动作作为外部效果）；F 报表导出 PDF/Excel（Excel 沿 CSV 导出扩展）；工业皮肤（ADR-0056）作为这些模板的默认外观。

### E. 逻辑：触发、规则与台账 — M

**缺口**：B **定时触发**（cron/日历，沿 `Manifest.Jobs` 开放给租户自动化）；B/W **规则表**（决策表：条件列→结果列，动作/自动化引用，替代 SAP Customizing 的大半）；B **台账/过账模型**（数量/金额的借贷式累计，库存台账、累计收货由此而来，解决 #138 暂缓项）；W 通知模板编辑（已有通知系统）。

### F. 安全与治理设计面 — M

**缺口**：W **角色与范围设计器**（应用级角色→对象行范围/字段/动作，编译到现有 Scope/Standard，不新建权限引擎）；B/W 项目成员委派 UI（#141）；B **Markings** 的有界版：数据分级标签贯穿读取/导出/AI；W 审计查看。

### G. 交付：环境、包与升级 — M

**已有**：候选/发布/升级/环境/包 API 全部存在。
**缺口**：W 环境晋级与数据迁移面（队列 #6）；W 包生命周期（#5）；W **解决方案包**：把一个项目连同 core 引用导出为可安装包（`solutions/wms` 的无代码版）；W 固定数据测试（testplan）工作台。

### H. 运维：应用关联运行 — M

**缺口**：W #141-C（应用→Flow/Agent/计算运行→失败实例→原编辑器）；F 告警规则（阈值→通知）；F 用量/健康卡片进项目主页。

### I. AI：工作台内的 Assist — M

**已有**：AI 函数、智能体、评测、MCP。
**缺口**：W **Builder Assist**：从描述生成对象类型/页面/动作草稿（只生成草稿，走原发布）；W 智能体作为应用资源（项目可拥有并发布智能体）；B 对象级 AI 函数绑定到动作副作用。

### J. 开发者出口 — S

**缺口**：B **按应用生成 TS SDK**（OSDK 等价：对象/动作/查询的类型化客户端，用现有 `api-types` 生成链）；B Webhook 订阅（沿外部效果）。

## 3. 排序建议

依赖关系：A 是地基（C/D/E 都要共享主数据）；D 与 ADR-0056 直接决定一线观感；G/H 是已有后端的"接前端"，便宜。

| 浪潮 | 块 | 为什么现在 |
|---|---|---|
| **W1** | **A** 共享本体（core 包 + Interface + 扩展字段 + 归属影响）；**D1** 手持/扫码/打印；**G1** 环境晋级 UI | 没有 A，WMS 探针继续自造员工/物料；D1 是工厂场景的硬需求；G1 几乎零后端 |
| W2 | **C** 数据接入三 profile；**E** 定时 + 规则表 + 台账；**H** 运行面 | 真实数据与真实运行，闭环才成立 |
| W3 | **B** 本体深度；**D2** 五型模板；**F** 角色设计器 | 把"能做"变成"做得快、做得对" |
| W4 | **I** Assist；**J** SDK；G2 解决方案包 | 放大器 |

每块立独立 ADR（0058 起），按"后端契约 → 生成类型 → 工作台 → WMS 探针验收"交付；每块都遵守做减法：被替代的旧路径同批删除。

## 4. 不做

- 不做连接器市场、不做通用 ETL 引擎（C 只取三个有界 profile）；
- 不做第二套权限模型（F 只做设计面，编译到现有门禁）；
- 不做自由脚本（E 的规则表、B 的计算属性都是声明式、可校验的）；
- 不承诺行业语义（台账是通用借贷模型，不是 SAP MM 的全部）。
