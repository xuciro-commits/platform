# ADR-0080 — 已完成的代码结构整理

状态：已完成（2026-10-07）；后续宿主与资产职责由 [ADR-0097](0097-submission-assets-and-host-boundaries.md) 接续，整体整理由 [ADR-0124](0124-platform-consolidation.md) 负责。本文不再保留已完成的波次、目录草图、逐提交清单和临时同步指令。

## 1. 保留的决定

- 单一职责与真实依赖决定目录；不为文件数、方法数或行数目标拆包，不建立 `util/common/shared` 工具箱。
- Tenant 保留身份、提交管线与组件持有；状态与锁按真实归属划分。当前地图与锁规则见 [宿主 doc.go](../../capabilities/server/doc.go)，不以改接收者冒充职责迁移。
- 整理不改变公开 API、动作/读取名、账本格式和恢复含义；检查按 [Testing](../Testing.md)，不沿用本轮临时全量命令。
- 旧日志解码与前驱兼容不是死代码。`legacy_console.go`、`legacy_agent_context.go` 保留各自文件头声明的历史读取责任；旧 core 种子角色只在移除未显式授予的角色后与原前驱精确匹配时兼容，不能自动授权或容忍无关漂移。

## 2. 已实施与不再重开的方案

`journal`、`idp` 已成为独立包；租户中的发布存储、工作、审计、通知、配额等状态归各自组件。Web 代码按原职责组织，构建器的旧 `shared/` 已解散。现行职责由 doc.go、[Platform](../Platform.md) 与 ADR-0097 描述，不在此复制文件清单。

当时拟议的 `accepted/console/integration/pages` 分包没有作为目标继续推进：接受结果依赖根包的记录、任务与暂存类型，Console 与 Tenant 互相依赖；`platform/pageui` 又与 `Definition.Page`、`Section`、`Runtime` 双向引用。只搬目录会引入循环或扩大内部类型的公开范围，未获得相应职责收益，故关闭该方案。未来若真实边界改变，再按新事实判断，不恢复旧包数和接口方法数指标。

## 3. 已交付应用生命周期

### 3.1 定义、发布、晋级与恢复

[ADR-0047](0047-platform-composition-and-workspaces.md) 的应用交付已通过 `environment_lifecycle_test.go` 与 `environment_http_test.go` 检查：定义 → 联合候选 → 封存 → 激活 → 业务操作 → 同宿主另一环境晋级 → 记录迁移 → 受支持升级 → 快照与日志恢复 → 普通成员首次打开。当前升级范围归 [ADR-0106](0106-data-and-definition-evolution.md)，不再沿用本次首版仅加可选标量字段的限制。

这些保证继续成立：

- 保存的候选可以封存和晋级，目标仍需原授权与自己的激活/升级计划。空目标需要的草稿由原创建路径派生；只有发布权限不能借此获得构建权限，拒绝后的另一成员授权重试不被旧键阻塞。
- 同键同请求返回原结果，异请求拒绝；晋级来源与迁移审计能够恢复。源环境不因晋级获得第二套状态写入，去向由目标的原来源记录派生。
- 迁移保留只读状态与原业务历史；失败、重启、旧候选补封和操作者首次读取沿原实现处理。当前方法与范围见 [Apps](../Apps.md)、ADR-0097 与对应发布/恢复测试。

## 4. 仍适用的交互与运行保证

- 编辑器只有实际输入才成为待保存改动，未修改时跟随原记录；多个挂载编辑器不得互相回写旧值。相同身份、租户和资源的元数据更新保留现有视图与输入，跨身份或撤权不能继承内容。
- 账户会话结束后保留一天的结束标记，再按原读取规则清理；不把会话消失当作结束反馈。
- 本地演练使用独立的 `platform-rehearsal` 数据范围，不得挂载或删除两台日常宿主的数据卷。运行与检查方法见 [本地部署说明](../../deploy/local/README.md)。
