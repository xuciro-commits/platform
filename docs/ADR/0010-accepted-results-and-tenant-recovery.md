# ADR-0010: 已提交结果与租户恢复

<a id="adr-0010"></a>

**状态：** 已接受 (2026-09-28, #135)。项目负责人按推荐方案接受了 D1–D4。ADR-0038 已经接受了基于结果的恢复、PostgreSQL 以及全新的一次性开发基准。本阶段准入关卡在实施前确定提交单元、状态暂存、故障边界和数据格式。接受本 ADR 并不直接改变当前运行的日志机制。

**后继决定：** [ADR-0037](0037-submission-assets-and-host-boundaries.md) 收敛全部权威状态新写入口，取代本 ADR 的选择加入式增量迁移安排；本 ADR 的持久接受、纯应用、租户隔离、结果族格式及当前 As built 继续有效。七类接口退出须先迁移其账本/状态/事实/发布等义务；历史输入与旧结果格式的必要恢复保留，不删除 journal 存储，不把仅记录目标说成已统一实现。

## 背景

目前 `Tenant.Submit`（`capabilities/server/host.go`）允许应用修改租户状态，随后才调用 `journal`，其 `Record` 回调将 `Entry` 追加到 PostgreSQL（`deploy.go`，`journal.go`）。`Entry` 保存输入、成员和流转版本；`Tenant.Replay` 再次调用当前的应用代码。`CheckReplay` 验证同代码重构与出站静默，快照绑定到写入它们的代码（`snapshot.go`）。追加失败会通过 `log.Fatalf` 终止进程，而不会回滚内存中的更改。审批、工作任务、出站效果、序列号、动态定义和智能体执行结果目前已经跨越输入路径，因此单记录补丁无法建立目标保证。当前的代码事实与目标承诺在 Platform §2.7–2.9 与 §10.3 D 中作了区分。

| 当前参考依据 (2026-09-28 调研) | 对此处的贡献 |
|---|---|
| [PostgreSQL 事务](https://www.postgresql.org/docs/current/tutorial-transactions.html) 与 [WAL](https://www.postgresql.org/docs/current/wal-intro.html) | 单一数据库事务内数据的确认持久写入与原子可见性。这无法回滚 Go 内存或外部调用。 |
| [Datomic 的事务日志](https://docs.datomic.com/datomic-overview.html) | 不可变、有序的事实依据与历史事务视图。我们保留具类型的记录和 PostgreSQL；不提议通用的 datom 存储。 |
| [Temporal 工作流执行](https://docs.temporal.io/workflow-execution) | 记录执行进度并在重放时不重复调用外部活动；长生命周期工作需要具备版本感知的延续性。其命令匹配式重放与应用我们保存的业务结果属于不同的保证级别。 |

共同的原则是明确持久化边界，然后从跨越该边界的数据中派生出可见状态与后续工作。输入与已提交结果是不同的对象。

### 当前写入路径的对抗性审查 (2026-09-28)

`Tenant.Submit` 延迟 `enqueue`，调用应用，然后记录接受的输入。`runtime.Put` 立即写入记录存储；`hostView.Submit` 调用另一个应用而无需打开单独的日志条目。因此，嵌套决策可能会在外层追加成功之前更改记录、工作状态或已安装的定义。`Tenant.Input`、智能体/模型产出、协议应答和工作分发也会通过公共提交方法以外的路径进入。在 PostgreSQL 宿主中，追加错误会在这些内存更改发生后终止进程。`Tenant.Replay` 目前会针对提交和输入再次调用应用。这些是客观代码事实，现有的同代码重放测试未涵盖这些边界。

第一批切片必须清查**每一个**入口点和可变归属主件，包括 `recordStore`、构建器的 `Install*`、工作/流程状态、幂等性收据、生成的 ID、审计、模型用量和出站意图队列。处于已提交结果边界之外的入口点必须被禁用或明确排除在此保证之外；部分迁移的宿主绝不能汇报拥有完整保证。嵌套调用贡献给其父级的暂存结果，而后期的异步响应、作业或分发则是带有自身结果的新顶级输入。被拒绝的输入不会留下任何暂存状态或可派发的意图；重复输入会返回持久的先前收据，而无需重新运行决策代码。追加提交之后，即使进程在回复前崩溃，恢复机制在逻辑状态下对结果执行且仅执行一次应用。这些是 D1–D3 的可测试条件，而非断言当前已存在暂存机制。

**19a 入口点与状态变更清单（修改日志机制之前）。** 第一个暂存路径必须指名其支持的动作族；在迁移之前，所有其他行均保留其现有的输入重放保证。在形成已提交结果之后，暂存路径不得静默回退到直接修改器。

## 我们的约束

- 重放或投影重建绝不向外部调用、不对历史进行重新鉴权，也不调用当前的业务决策代码。日志必须保持足够的有界性以便重放；快照和投影重建与业务决策彻底解耦。
- 代码与受控的具类型定义共享语义校验、权限和发布控制（ADR-0038）；不存在任意租户代码执行，且 `contract/` 中不包含业务领域词汇。
- PostgreSQL 保持为事务性存储。现有的 K5/幂等性和每租户单一权威机制保持不变；外部出站效果在 PostgreSQL 之外保证至少一次交付，并具备稳定身份标识。
- 项目负责人允许采用全新**可丢弃的开发**基线，但不允许删除客户历史。任何服务不得确认或分发非持久化的结果。

## 设计

1. **每个顶级租户输入对应一个已提交结果。** 宿主拥有版本化的结果封套：租户和提交 ID/序列号、具作用域的幂等性标识和请求摘要、操作者/权威、接受/拒绝产出、用于举证的输入和定义引用、经过校验的记录/状态变更、生成的 ID 和序列分配，以及持久化的工作/效果意图。嵌套的应用和工作决策合并到该结果中，而不是创建第二个独立确认的结果。拒绝具有明确小巧的收据；校验失败绝不包含部分接受的变更。
2. **暂存、追加、应用 (Stage, append, apply)。** 宿主为决策代码提供租户本地暂存视图。应用 API 写入、账本决策、生成的 ID、工作、通知、出站意图和动态安装均落入其中。宿主校验完整结果并在更改可见状态、发布订阅、向客户端确认或分发效果之前将其追加。追加后，应用该结果具有幂等性且不调用决策代码；追加与应用之间的崩溃通过应用已保存的结果进行恢复。追加失败会丢弃暂存结果。在宣称满足保证之前，必须对仍在此暂存区外进行修改的生产路径进行清查和设防隔离。
3. **PostgreSQL 提交。** 每租户有序插入和幂等唯一性，加上任何所需的持久游标/发件箱行，在单一 PostgreSQL 事务中提交。保存的封套起初可以直接保存意图；工作协程从已提交结果中派生其队列。不假设任何 SQL 行能够在事务上保护 Go 内存或其他系统。结果和模式具有明确的格式版本和大小限制；大对象通过不可变摘要和经验证的存在性进行引用。
4. **恢复与时间。** 在受支持的结果版本下满足 `recover(log ++ [c]) = apply(recover(log), c)`。结果应用重建权威状态和工作意图。投影、搜索索引和快照具有各自的版本和重建路径。记录/事务时间、源时间和业务有效时间仅在需要时采用不同字段；本阶段门禁不承诺完整的双时态 (bitemporal) 查询模型。`CheckReplay` 获得结果应用和崩溃点测试，而旧的输入重放保留为临时对比工具，随后在已接受历史中移除。
5. **租户监督。** 结果格式错误、依赖损坏或不可恢复的租户本地投影将隔离该租户：写入与其工作协程停止，健康检查汇报原因，操作员在纠正后可以重试恢复。其他租户在其共享进程和 PostgreSQL 正常时继续运行。进程崩溃 (panic)、资源耗尽和全库级故障仍然是独立的、有记录的故障边界；“重启”无法修复不一致的已接受状态。
6. **构建者/操作者实证。** 租户构建的对象/动作/页面变更、审批、连接器输入、延迟效果和流转等待在追加前、追加后应用前，以及应用后分发前的强制崩溃中均能存活。构建者在恢复后看到完全一致的接受/拒绝产出以及记录的历史；当一个租户被隔离时，另一个租户继续运行。酒店业和制造业提供最小的跨行业实证；应用程序不获取私有提交路径。

## 后果

这是一次带有持久化格式承诺的宿主/应用 API 重构。它使得 #136 的不可变发布激活以及后续 AI/工作版本绑定成为可能。在每条受支持路径跨越新边界之前，Platform §2 必须将该保证称为部分满足，并将旧日志称为开发基准。第一批切片应足够狭窄，以便在广泛替换之前暴露能力逃逸。

## 实际构建 (As built)

当前实际新写入口的统一提交归 ADR-0037；长期决策 D1–D4、原结果格式和历史读取义务保持不变。

- **提交单元：** `acceptedBatch` 暂存多应用账本/收据、记录历史与前序、编号、通知、出站意图、观察投影及构建器安装映像，PostgreSQL 单行入账后才应用。`record-batch` 格式 2–4 只保存本次新增历史及原前缀长度，原完整记录/历史的规范前驱摘要仍须精确匹配；恢复接续原历史，不复制旧历史到每个新结果。格式 1 的完整历史仍按原校验恢复，不重写已接受字节，1 MiB 结果上限保持。前驱或前缀长度错误在暂存视图拒绝，不部分应用；拒绝路径统一由同一持锁作用域释放。业务拒绝保存原请求/时间/原因；子拒绝丢弃保存点，未支持效果失败封闭。幂等与恢复使用保存结果，不重新裁决。
- **接入范围：** 全部实际 Submit/记录型 Input、审批/协议、Work/Effect、Agent/模型计量、Compute/连续来源与发布/组合/宿主管理的新写结果；完整契约及参与者见 ADR-0037。审批分别保留原请求与执行答复身份。`AcceptedStateApp` 是显式私有状态协议，不是全租户克隆。
- **记录暂存与派生索引：** `recordStore.forkRecords` 共享不可变的记录、知识脏项和近期变更索引，不遍历或序列化租户记录。平衡索引按修改路径复制，只有实际写入记录的值、历史与迁移投影需要私有副本；类型元数据、已构建引用索引的表头和最多 10,000 项的近期变更顺序仍复制。引用索引归源类型所有，`setRow` 只更新变化的引用桶和活跃计数，无关写入不使它失效；查询仍走成员过滤，关系约束使用完整 owner 数据。普通提交的最终一对一/归档校验只检查修改的关系键；新声明与整体类型替换仍做全量准入。读取 API 返回私有可变值，安装、迁移与恢复替换记录而不改共享前驱；保存点丢弃、世代冲突与持久化后提升保持原边界。完整快照与类型转换收集私有映像、按 ID 批量建树，不保留逐条插入的中间根。索引仅为内存实现，日志/快照格式与历史接受字节不变；无序旧快照继续按原映像恢复，重复或空 ID 拒绝。单记录长历史复制、通用业务约束与首次集合读取的成本仍不代表生产容量已验收。
- **历史流程读取：** 原 retained executor 的单条 `Get` 只解码该记录；集合读取与类型检查的完整中性视图在同一数据快照内复用，源 store、类型或任一记录索引根变化即失效，包括没有增加世代号的迁移投影替换。缓存不保存成员或授权结果；每次受保护读取仍按当前身份、字段权限和原迁移映像裁决。它只减少解码，不另立旧版本执行器；首次完整视图及变更后的重建仍可能扫描相关类型。
- **输入与效果：** ERP 计划订单、MES 设备状态、PMS 渠道预订的事实/业务结果及 K8 游标通过 `input-result` 同批保存；受属工作的 K9 世代/重试及结果通过 `work-result` 保存。`effect-result` 保存尝试、受支持 Reply/子决定与模型用量；Build 函数/评测回答已接入。恢复不重新请求提供商。新声明持久输入未接入结果协议时拒绝，旧格式仍按旧路径恢复。ADR-0008 收窄读取范围后，旧流程智能体的初始上下文可能少了所属流程摘要；仅当封存历史证明差异恰好是这一份所属流程摘要、其余上下文一致且还原后的完整记录/历史精确匹配原前驱摘要时，结果恢复才接纳它。其他状态、历史或摘要差异继续拒绝；新模型调用重新通过当前读者取得上下文，不使用历史缓存扩大读取范围。
- **隔离与重建：** 日志/快照/应用失败隔离租户。管理员 `POST /v1/recovery/retry` 从完整日志建立新代际、修复投影/派生快照后替换；坏权威日志不能用删快照绕过，重建失败保留隔离。共享进程、在途 I/O 和全库故障不在逻辑隔离保证内。
- **身份：** Submit 和控制入口先检查成员所属租户，外租户同名/同角色不能写入、读取重复收据或移动发布指针。

证据入口：`accepted_*_test.go`（输入/工作/效果/发布） 及酒店/制造 `CheckReplay`；PostgreSQL 条件测试和 `deploy/local/rehearse.sh` 核对追加失败、提交后未应用、重启/备份/完整日志与租户重建。函数评测断点见 `TestJournalAcceptedJointFunctionActivationCrash`。测试范围不能外推为生产容量、全部升级故障矩阵或负责人验收。

**剩余边界：** 旧格式历史仍按原语义读取；初始 Install 归组合/定义 owner，生产直接安装仍受 profile 控制。统一新写已由 ADR-0037 接续；资产生命周期与角色收敛、正式升级全故障矩阵和真实操作员诊断体验仍待各自整块验收。不可变定义发布归 ADR-0011，活动顺序只在 WorkQueue。

## 身份、持久边界与证据口径

### 保序日志与 OIDC

原输入日志被结果保存替代，是因为仅存内核 ChangeLog 无法恢复领域 ID、重定向、游标与状态；已保存的旧输入仍保留其原语义读取。每租户严格保序，追加检查期望序号，第二写者不能交错提交。微秒级时间和原主体随历史保存；连接器心跳不进日志，重启后健康要等新心跳。输入重跑或追加失败即全进程退出不再指导新写，当前故障范围由本 ADR 和 ADR-0037 定义。

身份复用 OIDC 提供商，不自建密码系统。校验签名/JWKS、issuer、过期和访问令牌类型，不把 ID Token 当 Access Token；主体按 user/email 或 client/id 解析，租户成员资格由平台目录判定。浏览器沿授权码与 PKCE。历史选 Rauthy 是基于带密码、MFA/Passkeys 与单容器交付需求；仅 Passkeys 的替代者不适配共享车间终端，选型理由不变成永远锁死厂商的契约。部署配置、备份和恢复方法归现有 deploy 文档，不在 ADR 重列运行命令。

### 对外承诺按实际入口说明

每种日志、输入和权威路径只在原归属声明已验证保证与未覆盖范围；平台摘要不代替入口证据，也不再复制全入口矩阵。内部接受结果的原子追加与幂等应用，不等于跨权威 ACID 或全系统“恰好一次”：外部效果为至少一次加稳定键，模型/Wasm 物理调用不承诺只执行一次，投影不是第二权威。

旧历史格式按原输入代码恢复的部分不能追认结果语义；ADR-0037 已统一实际新写入口，因此不能把旧文档中的可选迁移范围当新写旁路。对有证据的缺陷直接修复，不为静态怀疑另建检查层、队列或停工条件。

可读数据默认可发往租户管理员配置的 provider，受启用、预算和留存控制；这一点不自动授予数据读取权。字段 `aiInput` 与后继授权/AI 声明的现行限制继续优先，不把早期默认策略当绕过来源或分类限制的许可。通用逐标签禁止外发策略、HA/多区域、客户进程资源隔离和生产 RTO/RPO 未由此获得保证。

内部走查、固定样本、参考应用和编译不能证明客户业务价值。只有真实用户完成真实任务的可复验结果才能支持完成率、正确率、人工时间、接受/拒绝/接管、权限、错误副作用、延迟与 Token/USD/unknown 成本的声明。既往 PostgreSQL 检查和演练只支撑当时覆盖的入口，不能替代本次变更检查或真实生产证明。
