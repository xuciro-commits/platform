# ADR-0063 — PostgreSQL 运行状态与兼容恢复

状态：决定已接受（2026-10-19，负责人技术转型计划）；实现状态见本文 As built，施工顺序只归 WorkQueue。局部取代 ADR-0010 中正式 PostgreSQL 部署必须以全量内存状态恢复的实现安排，不改变内核、单租户单写者和已接受结果语义。

## 决定

PostgreSQL 逐步承担正式状态与查询，Go 保留工作集。日志、幂等请求及原答复、租户日志位置、当前记录及历史增量、编号、工作状态、定义和外部效果意图在原接受事务中保存。增量由原归属方产生，存储层不解释业务，不把异步 SQL 投影当作正式状态。

数据库提交之后更新内存及通知。提交答复未知时沿原键查询；内存更新失败时重新载入或停止该租户，不能重新执行业务决定。封存内容与查询用 JSON 分开处理，历史字节与原读取规则保留。

迁移按租户暂停写入，在固定日志位置回填、比较后切换。当前值、历史及幂等查询都须接入，不能增加一份 SQL 副本后继续把全部历史留在内存。生产路径退出启动时 DROP 重建；轻量文件模式保留原用途，共用同一业务规则。

快照声明宿主格式、归属方恢复格式、应用组合及日志位置。构建摘要保留作诊断，不再单独决定兼容性；没有明确格式声明的归属方仍按原二进制资格读取。旧快照保持原规则；格式或组合不兼容时转换或全日志恢复，不无条件接受旧状态。恢复继续核对已接受结果及原恢复顺序。

向量属于可重建的检索索引，在既有 PostgreSQL 中保存来源、段落、模型及维度并用 pgvector 查询。词检索与中文行为保留；租户与来源条件在查询中限定，结果按原权限检查，候选不足时继续读取。PDF/OCR 不属于存储迁移。

普通写入历史成本、按需当前记录、一致读视图、私有变化覆盖与常规启动转型由 [ADR-0064 §4](0064-architecture-subtraction-and-code-organization.md#4-提交历史与存储设计) 细化，施工顺序只在 WorkQueue。已实现范围见下方 As built，不增加第二套存储或永久双写。

## As built

记录状态、历史引用和纯查询编译归 `internal/records`；宿主继续选择 SQL 候选、应用当前权限和派生规则，并在原提交范围管理私有变化。排序与分页复用同一纯组件，接口查询在原授权读取后仅做一次跨对象排序；PostgreSQL 当前记录使用同一模块的来源集合与不可变私有覆盖，读取不建立跨请求行缓存。

ADR-0064 已移除生产追加回调中的进程退出。存储无法解析提交答复时返回明确的 commit-unknown 错误，宿主停止该租户；确定未提交的失败允许原键重试。在线重建只比较目标租户的固定启动组合和 owner 格式，包括尚未声明快照格式的应用组合；旧快照的二进制资格仍保留。旧写者若在 SQL 位置之后保留了连续接受结果，启动先恢复到原 SQL 位置逐项比较，再在原租户事务内按原日志顺序补状态和答复；末态再次比较一致后才发布新位置。较新快照不能替代原位置的独立比较，原位置损坏、非接受结果后缀、增量错误或恢复期间日志变化均拒绝且整事务回滚；不重执行业务规则、不改原日志，也不只推进位置。真实 work-result、原答复、重复恢复及上述拒绝场景已在专用 PostgreSQL 检查。普通写入的历史前驱与共同变化计划已按 ADR-0064 调整，范围见下文；按需当前记录和 SQL 检查点启动已实现，边界见下文。

PostgreSQL 的原 `AppendAccepted` 事务同时保存日志、原请求答复、租户位置、记录当前映像与历史后缀、原收据、定义及归属方封存的状态/工作/效果信息。封存字节与查询 JSON 分列保存；存储不裁决动作。首次转换或旧格式恢复时在原提交锁内按固定日志位置回填并逐项比较；已转换租户使用下述 SQL 检查点与后缀比较。差异使该租户停止服务，不覆盖差异数据。提交失败不推进位置；提交后应用失败仍沿原停止与恢复方式处理，同键查询复用原答复。

ADR-0064 的新结果族使用版本化历史引用：单记录 5、批次 8、Input 2、Work 3、Effect 4 起；当前 Effect 新写为保存安全公开提示的格式 5。当前映像、映像格式、历史后缀与链头、原答复及日志位置沿原接受事务保存；Input/Effect/Work 的公共状态和记录变化与 SQL 存储地址来自同一具类型计划，批次及单记录通过原类型解码，不再使用通用 JSON 字段表重新推断变化。旧结果先按旧格式验证原字节；实体归属方通过 `RecordFormat`/`RecordImages` 声明映像转换，转换不得改变记录身份或历史印记。原日志不重写，未知格式拒绝。首次建立旧历史链、快照及 SQL 固定位置的全量一致比较仍可读取完整历史；正常新写只接续本次后缀。

发布安装的冻结映像也是正式当前记录变化。原接受事务按安装中保存的前驱摘要核对记录，只替换业务映像，保留映像格式、投影、历史数量和历史头；重启时使用同一替换表示。固定检查点后的查询同时包含已应用日志后缀中的记录，不能只从旧归档枚举候选而漏掉新增 Flow 或其他定义。Source 在同一次准备读取中选择已发布配置，网络请求仍在锁外执行。迁移完成后的私有安装按目标声明读取 SQL 冻结映像，再执行原严格转换，避免先用旧 Go 类型解析新字段；旧 Flow 的保留投影来源不被替换。

SQL 当前投影采用格式 3。首次 SQL 写者曾保留安装结果却未替换当前元数据；转换格式 1/2 时暂停服务，使用完整原日志恢复 owner 状态，逐项比较原映像、完整历史、键和 owner 值。仅当差异与原接受结果中的最后普通记录映像及其后保存的安装完全对应时，才在同一事务更新派生当前映像和格式号；安装映像的转换仅适用于原格式 1。其他差异拒绝并整事务回滚；不更改日志、原答复或收据。旧 SQL 读取归档随这次已验证转换失效并重建，可移植快照保留。格式 3 的常规启动不再重复全量转换。

AI 的直接用量、Effect 用量及 Agent 用量也沿同一接受事务更新正式 AI owner 值：根包从已验证结果取得原用量，SQL 只调用 AI 归属方提供的纯状态变换，复用 `internal/aistate` 中的唯一计量步骤，AI 应用自己的 `Meter` 也使用它；该组件同时承担原状态格式及严格解码，AI 仍拥有决定、实时预留和临时调用状态。宿主不导入具体 AI 应用，不复制预算、按日总数或保留规则。变换在该结果的完整 owner 映像替换之后应用；检查点后缀校验使用同一变换。旧格式 1/2 遗漏的用量投影只能在当前值与原日志最后完整 AI 映像（没有时为官方初态）完全一致、其他状态也已逐项核对后转换；原用量答复、日志、收据和记录历史不改写。不往每次用量结果塞入完整配置与历史，也不重新调用模型。

业务唯一键由记录归属方生成，逐记录完整替换键集随接受事务保存。内存/文件模式使用原不可变索引，PostgreSQL 模式用 SQL 查原键并叠加本次私有变化，不在 Go 再保留全量唯一键表。SQL 在同一读取事务内检查数据库位置与租户已应用位置完全相等；不能靠过滤较新键假装取得旧视图，因为旧键可能已被替换。归属方继续裁决空值、零值、复合字段、scope、归档和不可见冲突，数据库表不成为第二套业务判断。首次格式建立、定义替换和恢复比较仍可完整生成派生键；差异拒绝，不覆盖原数据。上述行为已用专用 PostgreSQL 检查，包括无记录接受结果完成后的位置推进、未应用结果与未知提交保持旧位置、唯一键冲突/私有失败/重启，以及旧映像转换后的跨页查询；一致查询视图和按需当前记录的边界见下文。

安装 SQL 历史读取器保留显式历史数量，不能对尚未安装读取器的新当前映像用空后缀重新计算数量。旧实现曾因此生成历史为空的快照；此类快照与正式 SQL 历史不一致时仍严格拒绝，使用原租户恢复入口从完整日志重建并修复快照，不把 SQL 的差异覆盖掉。真实 PostgreSQL 测试覆盖隔离、完整日志重建和修复快照后的再次启动，逐次核对原日志、SQL 当前映像和历史没有改变。

记录历史、收据、提交答复与对应定义改为 SQL 按需读取；普通读取不把查出的完整历史安装成另一个缓存。读取有已应用位置限制，数据库已提交但内存尚未应用的下一条记录不能成为旧工作集的历史。答复与定义同样带提交位置，未知答复重试先按原结果完成应用，不把 SQL 中尚未应用的答复直接当成功返回；找回原答复时恢复宿主的日志位置，之后的新写入仍可继续。物理字段的文本、引用、日期和标签相等/集合条件使用 SQL 索引缩小候选，再由原集合及授权规则决定结果；声明 `RecordImages` 的实体仍分批读取 SQL 候选，但不按当前字段提前筛选原始映像，转换后由原 Go 条件及权限筛选，避免旧字段改名导致漏行；私有写集加入同一候选集合，再执行原派生、权限与业务条件。记录值按需解码；普通分页最多保留 offset+limit 个排序候选，精确总数及复杂权限仍可能扫描全部候选，不承诺所有查询只读取一页，也不承诺全宿主固定内存。

ADR-0064 E 的 PostgreSQL 正常路径不再常驻完整当前记录或唯一键集合。一次协调读取/决定在原租户锁内建立 repeatable-read 视图，要求数据库位置等于完整应用位置，定义与记录共享同一范围；嵌套读取、私有 fork、保存点及撤销沿原上下文进行。接受事务提交后先完成原结果全部应用，再清除记录覆盖并允许下一读取视图；不能过滤新行伪造旧视图。HTTP 取消释放事务与持有的记录锁；详情、定义发现和其他按需读取在错误退出时也释放锁，避免后续查询与后台执行永久等待。普通临时读取错误允许后续重试，位置不一致及提交/应用不明仍停止该租户。拒绝升级、业务拒绝查询与发布追溯在 SQL 先按原封套字段选择相关候选；原格式部分索引排除普通答复，归属方仍解码原字节并裁决，不在每个后台轮次重新加载和解码全部普通答复，也不新增升级队列。Source/Pipeline、计算和模型调用只在准备/复核时读取，实际网络与制品 I/O 留在锁外。固定读取视图使用同一 PostgreSQL 的独立只读连接池，原接受连接池保持可用，避免多租户各持读取连接却同时等待提交连接。两池沿原配置，快照复用本次读取视图并在锁外编码结束后释放。只读投影也通过该范围读取，失败保留待刷新记录。

常规 SQL 检查点保存 owner 原状态及记录摘要，并在同一数据库事务中归档该位置的记录映像、历史头、派生键和状态值，沿原策略只保留最近两个检查点。历史字节和收据仍共享原追加表；摘要覆盖原收据前缀，历史链逐项核对。普通写入只更新正式当前表，不更新归档。恢复按检查点固定来源读取，纯应用原接受结果后缀；临时 SQL 表比较全部最终记录、键、状态值与收据，差异拒绝且不覆盖正式状态。原答复、拒绝及决定定义从同一归档按需读取，不进入 owner 快照的全量历史映像；普通批次原 SQL 字节保留，可移植快照只投影实际保存的答复。Go 不先装载全量当前记录。后缀触及的记录和原 owner 私有状态仍可能占用内存。

SQL 检查点使用独立 `platform.tenant.sql.v1` 资格；可移植 `Snapshot` 仍为原完整导出格式。未声明 owner 格式时 SQL 检查点也绑定原构建；未知格式拒绝。首次转换及明确的旧日志/旧写者恢复保留原完整重建责任，`SnapshotEvery=0` 不使用 SQL 检查点。新格式切换不赋予旧二进制回退资格；旧二进制不能读时使用兼容版本或向前修复，保留数据。

PMS/MES 的事实日志沿原归属方封存格式按需读，保留原键、事实引用、时间和已应用前缀。归属方快照或私有输入准备仍可能临时解码完整事实映像。启动使用兼容检查点与日志后缀恢复原归属方，再核对 SQL 当前映像；没有把任意旧日志或私有 Go 状态自动转成 SQL 启动器，也没有声明恢复时完全不读取历史。

显式快照格式包括宿主格式、各归属方格式、启动应用组合和日志位置；已声明格式的兼容构建使用同一资格，构建摘要只作诊断。未声明格式与旧快照保持原二进制资格。启动组合在租户构造时固定，不随租户随后发布的 Build 类型变化。原恢复顺序、前驱与结果检查继续执行。酒店组合的第二住宿提供方 `memstay` 也声明原 Ledger 快照格式；组合检查要求每个实际提供方都有声明，不能只覆盖平台应用。只读 SQL 投影保留原表与历史，按变化 ID 更新当前行并追加尚未写入的历史；声明删除或限制的列随原定义移除，生产启动不再 DROP 整个租户 schema。

生产知识检索使用 pgvector，在 SQL 中按租户、模型、维度和应用来源条件计算距离；支持索引的维度使用 HNSW 及迭代扫描，过滤后不足时补精确查询。最终原记录/文件读取资格检查后不足则继续读取候选。中文词检索保留原实现；嵌入生成只查询缺失内容，不取回全部向量。旧 bytea 向量按批次转换；文件/轻量模式保留原小规模检索实现。派生来源可重建，标题变化和归档会更新来源。PDF/OCR 未增加。

相关自动检查覆盖固定位置迁移及差异拒绝、事务失败与原键重试、已提交未应用的恢复、历史前缀、兼容快照、投影复用及过滤后的向量召回。检查方法归 [Testing](../Testing.md)，2026-10-19 的 `6ce1868b` 已沿原脚本更新两宿主，保留数据卷；酒店 3 租户、制造 1 租户均为正常且未隔离，版本与 Vite 页面资源已核对。酒店首次转换因 `memstay` 原先没有格式声明读取 2,111,643 条旧日志；补齐后四租户均从快照恢复，本次后缀均为 0。酒店该次二进制的启动记录为 15:54:50–15:54:51（本地时间）；随后进程常驻内存抽样约酒店 75 MiB、制造 60 MiB。这是本地已有数据的观察，不是容量或固定恢复时限承诺。更新证据由原脚本写入 `.build/local-update/<revision>.json`。真实客户容量、峰值查询、模型供应商和设备现场效果仍不由本次检查证明。
