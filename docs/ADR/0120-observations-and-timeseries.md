# ADR-0120 — 观测与时序：外部存储、只取结果

状态：已接受（2026-10-12，负责人指令）· 承接 K2/K3（事实、观察、断言）的既有规范与 ADR-0033（派生声明来源）；**明确不把高频观测放进租户决策日志** · 与 ADR-0119（能力包）、ADR-0121（设备派发）配套

## 0. 意图与负责人的口径

第一次交付是楼宇供暖，链路是：**采集设备 → 时序数据 → 抓关键信息（设备预警）→ 给 MES；抓水表 → 给 ERP；自己也存，也进看板与报表平台。**

负责人对这件事的口径（2026-10-12）：

> "遥测数据肯定是独立存储的，怎么可能和系统数据存到一起呢？那个东西没有复杂度，但是它迟早会把你撑爆。实现又简单，甚至包括下游的协议也要独立封装，成千上万的设备有各种各样的协议，光一个西门子的就上百种，你都要去存到系统里，系统就要爆炸掉了。**这种用外加的库就行了，我们只要结果。采集的过程实现太复杂了，你不要去考虑这些。**"

这份 ADR 把这条口径写成机制，并划清"我们只要结果"的确切含义。

**判据**：一个每秒产生数千点的楼宇系统接入平台后，**租户决策日志的体积不随点数增长**；业务记录里只有判定结果与聚合值；断电重启后不重放任何原始点。

## 1. 分界：观测是事实，不是决策

平台今天有两种入账：

| | 决策（decision） | 观测（observation） |
|---|---|---|
| 是什么 | 一次**权威变更**：谁、在何时、把什么改成了什么 | **来源处真实发生的事**：某设备在某时刻的读数 |
| 内核 | K4 变更记录 | K2/K3 事实日志（observation/claim） |
| 现状 | 全部业务写入 | **已有类型，但实际使用极少；规范自己写明"高频观察的批量聚合处于开放状态"** |
| 体积 | 随业务操作增长 | **随点数增长** |

**决定：原始观测不进租户决策日志。**

原因不是性能调优，是**语义**：决策日志的可恢复性、幂等性、前驱校验（ADR-0038/0097）是为"权威变更"设计的。把每秒一个温度点写成决策，等于让恢复时间、日志体积、快照大小全部随**物理采样率**增长——而这些点**不改变任何权威状态**。

## 2. 决定

### D1 三样东西分开放，各有归属

```text
采集侧（外部，不在平台内）
  设备 / 网关 / 采集器 / 协议适配库（西门子上百种协议等）
     │  只上传：结果与聚合
     ▼
平台侧
  ├─ 观测存储（外部依赖，非租户决策日志）
  │    时序点、原始读数、保留与降采样策略
  ├─ 业务记录（租户日志）
  │    判定结果：预警、告警、工单、聚合值、状态
  └─ 判定（平台内，声明式）
       阈值、趋势、组合条件、误报抑制 → 走 ADR-0101 的规则语言
```

| 层 | 归属 | 谁的职责 | 本 ADR 是否实现 |
|---|---|---|---|
| 设备协议、采集、边缘缓冲 | **外部**（既有采集器/网关/库） | 采集侧 | **不实现**（§3） |
| 观测存储 | **外部依赖**（时序库，如负责人既有实践所用的 TSDB/物联网平台） | 运维与采集侧 | **不实现**：只定义平台的**连接方式与读取形状** |
| 观测 → 判定的规则 | 平台 | 构建者声明 | 实现（D3） |
| 判定结果 → 业务记录 | 平台 | 平台（事务，ADR-0100） | 实现（D4） |

### D2 观测存储是环境绑定，不是内置

- 观测存储的**地址与凭据是环境绑定**（沿 ADR-0047/0107：凭据永不进入工件）；
- 工件里声明的是**逻辑连接**（"这个应用需要一类时序源"）与**读取形状**（某设备的某个测点在某时间窗的序列/聚合）；
- 平台**不规定**用哪个时序库。更换时序库是环境变更，不是应用变更。
- **不在平台内实现第二套时序存储**（AGENTS 硬规则 6、ADR-0098 §9.5 一个语义一个实现）。

### D3 判定在平台内，用同一门语言

"抓关键信息"（设备预警、水表超限、趋势异常）是**判定**，走 ADR-0101 的规则语言，读的是**声明过的观测**：

- 阈值：`value > limit`、`within-period`（已有算子）
- 趋势与速率：需要新的观测算子（`rate`、`delta`、`over-window`），**须按 ADR-0101 的规则扩展算子表**，不建第二套求值器
- 组合与抑制：`any`/`all` + 抑制定时（复用 ADR-0060 的定时自动化）
- **预警不是告警记录**：判定产生的是**业务记录**（预警/告警/工单），进 ADR-0100 的事务

**观测的可读性受 ADR-0105 的同一套授权**：观测数据不是"随便读"的，它按声明的来源与调用者权限收窄（K2/K3 的来源语义 + ADR-0033 的派生声明）。

### D4 只把结果写进业务记录

判定产生的结果进入业务记录的形态有三类，**都不含原始点**：

| 结果 | 形态 | 举例 |
|---|---|---|
| 聚合值 | 记录字段（由 ADR-0101 的聚合算子算出） | 当日累计用水量 |
| 状态变化 | 生命周期迁移（ADR-0037） | 设备状态：正常 → 预警 |
| 下游指令 | 事务步骤或外部效果（ADR-0121） | 给 MES 报设备预警、给 ERP 报水表读数汇总 |

**原始点永不进入业务记录。** 需要追溯原始点时，**按声明回到观测存储读取**（带对象与测点标识），而不是在记录里留存副本。

### D5 保留、降采样与"多久"

- **保留策略归观测存储**（外部），工件里声明它**期望**的保留与粒度；实际保留由环境实现。
- **降采样归观测存储**。平台不实现降采样。
- **平台侧只保留判定结果与聚合**；聚合的历史保留按业务需要（例如"三年的月度用水量"），归业务记录的保留声明（ADR-0107 §D5 的 `AppProfile`）。
- **超出保留的原始点不可恢复，且不宣称可恢复**——这与业务记录的"历史永远可读"（ADR-0098 §9.2）**不是同一件事**，必须在使用文档里讲清，避免客户以为"平台什么都能查"。

## 3. 明确不做的（这是本 ADR 的主要篇幅）

按负责人口径"采集的过程实现太复杂了，你不要去考虑这些"，以下**全部不在平台范围**，且**不做预留**（ADR-0119 §6：没有命名的交付不留）：

- 设备协议适配（西门子上百种、Modbus、BACnet、OPC UA 等）——**外部库/采集器的职责**；
- 采集器的部署、边缘缓冲、断线续传、时钟同步——**采集侧职责**；
- 时序库自身的实现、索引、压缩、降采样——**外部依赖职责**；
- 边缘规则引擎——判定放平台（D3），采集侧只做必要的安全联锁（ADR-0121 §D3）。

**"我们只要结果"的准确含义**：平台要的是**判定结果与聚合值**，以及**回到原始点的读取能力**（D4）；不要的是**采集与存储的实现**。

## 4. 与既有能力的关系

| 既有 | 关系 |
|---|---|
| K2/K3 事实、观察、断言 | **沿用语义**（观测量来源、时间）；本 ADR 不改变内核 |
| `AggregateWindowMaxRows = 100000`（`aggregate_window.go:17`） | 保持为**聚合读取**的上限；观测的原始序列**不走聚合读取**，走外部时序源（D2/D4） |
| ADR-0070–0075 集成织物（Source/Dataset/Pipeline） | **低频关系数据**仍走集成织物（水表台账、设备清单）；**高频时序不走**——这是本 ADR 与集成织物的分界线 |
| ADR-0117 拒绝与纠正 | 预警被判定为误报时的处理（抑制、驳回）走既有拒绝路径 |
| ADR-0119 | 时序视图、观测统计、时序库连接器属于**能力包** |

**分界线一句话**：**能作为一条记录有意义地存在的，是集成织物；只作为序列存在的，是观测。**

## 5. 后果

- 第一次交付（楼宇供暖）的可行性取决于 D2：环境里必须有可用的时序存储与采集侧。**这是环境前置条件，不是平台能力**——若缺失，属于部署问题。
- 平台侧新增的是**观测的引用与读取形状**（一个声明："这个应用读这类时序源"），不是时序实现。
- ADR-0101 需要扩展观测算子（`rate`/`delta`/`over-window`），按算子表的规则扩展并登记。
- 需要在使用文档（`docs/Apps.md`）里写清 D5 的最后一条：原始点的保留取决于外部存储，**不承诺与业务记录同等的历史保证**。

## 6. 验收

1. 一个楼宇应用接入一个声明过的时序源，声明一个判定（阈值 + 趋势），产生业务记录（预警）。
2. **体积断言**：接入高频源并运行一段时间后，**租户决策日志的行数与体积不随点数增长**（用测试或演练证明）；业务记录只含判定结果与聚合值。
3. **恢复断言**：断电重启后不重放任何原始点；判定结果与业务记录按 ADR-0038/0097 恢复。
4. **读取断言**：需要原始点时按声明回到观测存储读取，带标识与时间窗；权限按 ADR-0105 收窄。
5. **分界断言**：低频关系数据（设备清单、水表台账）仍走集成织物；同一批数据不出现"既进集成织物又进观测存储"的双路径。
6. **环境前置**：更换时序库只需改环境绑定，不改应用定义（用一个替换演练证明）。
7. **反例**：把高频点写入租户日志、在平台内实现时序存储或降采样、为采集协议预留形状（违反 ADR-0119 §6）→ 分别拒绝。
