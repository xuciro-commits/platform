# ADR-0120 — 观测与时序：外部存储、只取结果

状态：已接受（2026-10-12，负责人指令）· 协议“不开发/不预留”的范围由 ADR-0123 部分取代（2026-10-15）· 承接 K2/K3（事实、观察、断言）的既有规范与 ADR-0033（派生声明来源）；**明确不把高频观测放进租户决策日志** · 与 ADR-0119（能力包）、ADR-0121（设备派发）配套

范围修订：负责人于 2026-10-15 指定自行开发按需加载的协议包，[ADR-0123](0123-pluggable-protocol-packages.md#11-as-built) 取代本文“不开发/不预留采集协议”的范围限制；独立网关、模拟包与 S7 只读子集已实现，原始时序外存与业务日志边界保持。

## 0. 意图与负责人的口径

第一次交付是楼宇供暖，链路是：**采集设备 → 时序数据 → 抓关键信息（设备预警）→ 给 MES；抓水表 → 给 ERP；自己也存，也进看板与报表平台。**

负责人对这件事的口径（2026-10-12）：

> "遥测数据肯定是独立存储的，怎么可能和系统数据存到一起呢？那个东西没有复杂度，但是它迟早会把你撑爆。实现又简单，甚至包括下游的协议也要独立封装，成千上万的设备有各种各样的协议，光一个西门子的就上百种，你都要去存到系统里，系统就要爆炸掉了。**这种用外加的库就行了，我们只要结果。采集的过程实现太复杂了，你不要去考虑这些。**"

这份 ADR 把这条口径写成机制，并划清"我们只要结果"的确切含义。

**判据**：一个每秒产生数千点的楼宇系统接入平台后，**租户决策日志的体积不随点数增长**；业务记录里只有判定结果与聚合值；断电重启后不重放任何原始点。

## 1. 分界：观测是事实，不是决策

平台今天有两种入账：

| | 决策（decision） | 观测（observation） |
|---|---|---|
| 是什么 | 一次**权威变更**：谁、在何时、把什么改成了什么 | **来源处真实发生的事**：某设备在某时刻的读数 |
| 内核 | K4 变更记录 | K2/K3 事实日志（observation/claim） |
| 现状 | 全部业务写入 | **已有类型，但实际使用极少；规范自己写明"高频观察的批量聚合处于开放状态"** |
| 体积 | 随业务操作增长 | **随点数增长** |

**决定：原始观测不进租户决策日志。**

原因不是性能调优，是**语义**：决策日志的可恢复性、幂等性、前驱校验（ADR-0038/0097）是为"权威变更"设计的。把每秒一个温度点写成决策，等于让恢复时间、日志体积、快照大小全部随**物理采样率**增长——而这些点**不改变任何权威状态**。

## 2. 决定

### D1 三样东西分开放，各有归属

```text
采集侧（外部，不在平台内）
  设备 / 网关 / 采集器 / 协议适配库（西门子上百种协议等）
     │  只上传：结果与聚合
     ▼
平台侧
  ├─ 观测存储（外部依赖，非租户决策日志）
  │    时序点、原始读数、保留与降采样策略
  ├─ 业务记录（租户日志）
  │    判定结果：预警、告警、工单、聚合值、状态
  └─ 判定（平台内，声明式）
       阈值、趋势、组合条件、误报抑制 → 走 ADR-0101 的规则语言
```

| 层 | 归属 | 谁的职责 | 本 ADR 是否实现 |
|---|---|---|---|
| 设备协议、采集、边缘缓冲 | **外部运行**（既有采集器或 ADR-0123 的独立网关与能力包） | 采集侧 | 本文不实现；自研按需协议包见 ADR-0123 |
| 观测存储 | **外部依赖**（时序库，如负责人既有实践所用的 TSDB/物联网平台） | 运维与采集侧 | **不实现**：只定义平台的**连接方式与读取形状** |
| 观测 → 判定的规则 | 平台 | 构建者声明 | 实现（D3） |
| 判定结果 → 业务记录 | 平台 | 平台（事务，ADR-0100） | 实现（D4） |

### D2 观测存储是环境绑定，不是内置

- 观测存储的**地址与凭据是环境绑定**（沿 ADR-0047/0107：凭据永不进入工件）；
- 工件里声明的是**逻辑连接**（"这个应用需要一类时序源"）与**读取形状**（某设备的某个测点在某时间窗的序列/聚合）；
- 平台**不规定**用哪个时序库。更换时序库是环境变更，不是应用变更。
- **不在平台内实现第二套时序存储**（AGENTS 硬规则 6、ADR-0098 §9.5 一个语义一个实现）。

### D3 判定在平台内，用同一门语言

"抓关键信息"（设备预警、水表超限、趋势异常）是**判定**，走 ADR-0101 的规则语言，读的是**声明过的观测**：

- 阈值：`value > limit`、`within-period`（已有算子）
- 趋势与速率：需要新的观测算子（`rate`、`delta`、`over-window`），**须按 ADR-0101 的规则扩展算子表**，不建第二套求值器
- 组合与抑制：`any`/`all` + 抑制定时（复用 ADR-0060 的定时自动化）
- **预警不是告警记录**：判定产生的是**业务记录**（预警/告警/工单），进 ADR-0100 的事务

**观测的可读性受 ADR-0105 的同一套授权**：观测数据不是"随便读"的，它按声明的来源与调用者权限收窄（K2/K3 的来源语义 + ADR-0033 的派生声明）。

### D4 只把结果写进业务记录

判定产生的结果进入业务记录的形态有三类，**都不含原始点**：

| 结果 | 形态 | 举例 |
|---|---|---|
| 聚合值 | 记录字段（由 ADR-0101 的聚合算子算出） | 当日累计用水量 |
| 状态变化 | 生命周期迁移（ADR-0037） | 设备状态：正常 → 预警 |
| 下游指令 | 事务步骤或外部效果（ADR-0121） | 给 MES 报设备预警、给 ERP 报水表读数汇总 |

**原始点永不进入业务记录。** 需要追溯原始点时，**按声明回到观测存储读取**（带对象与测点标识），而不是在记录里留存副本。

### D5 保留、降采样与"多久"

- **保留策略归观测存储**（外部），工件里声明它**期望**的保留与粒度；实际保留由环境实现。
- **降采样归观测存储**。平台不实现降采样。
- **平台侧只保留判定结果与聚合**；聚合的历史保留按业务需要（例如"三年的月度用水量"），归业务记录的保留声明（ADR-0107 §D5 的 `AppProfile`）。
- **超出保留的原始点不可恢复，且不宣称可恢复**——这与业务记录的"历史永远可读"（ADR-0098 §9.2）**不是同一件事**，必须在使用文档里讲清，避免客户以为"平台什么都能查"。

## 3. 明确不做的（这是本 ADR 的主要篇幅）

本 ADR 不把以下内容放进业务宿主或内核。原先“采集协议不开发/不预留”的范围已由 ADR-0123 的新指令替代：

- 设备协议适配——**独立协议能力包或外部库/采集器的职责**，按 ADR-0123 按需开发，不承担全型号历史兼容；
- 采集器的部署、边缘缓冲、断线续传、时钟同步——**采集侧职责**；协议包安装与部署配置设计归 ADR-0123，不在业务宿主中运行采集循环；
- 时序库自身的实现、索引、压缩、降采样——**外部依赖职责**；
- 边缘规则引擎——判定放平台（D3），采集侧只做必要的安全联锁（ADR-0121 §D3）。

**"我们只要结果"的准确含义**：业务宿主要的是**判定结果与聚合值**，以及**回到原始点的读取能力**（D4）；采集实现归独立网关/能力包，时序存储仍为外部依赖。

## 4. 与既有能力的关系

| 既有 | 关系 |
|---|---|
| K2/K3 事实、观察、断言 | **沿用语义**（观测量来源、时间）；本 ADR 不改变内核 |
| `AggregateWindowMaxRows = 100000`（`aggregate_window.go:17`） | 保持为**聚合读取**的上限；观测的原始序列**不走聚合读取**，走外部时序源（D2/D4） |
| ADR-0070–0075 集成织物（Source/Dataset/Pipeline） | **低频关系数据**仍走集成织物（水表台账、设备清单）；**高频时序不走**——这是本 ADR 与集成织物的分界线 |
| ADR-0117 拒绝与纠正 | 预警被判定为误报时的处理（抑制、驳回）走既有拒绝路径 |
| ADR-0119 | 时序视图、观测统计、时序库连接器属于**能力包** |

**分界线一句话**：**能作为一条记录有意义地存在的，是集成织物；只作为序列存在的，是观测。**

## 5. 后果

- 第一次交付（楼宇供暖）的可行性取决于 D2：环境里必须有可用的时序存储与采集侧。**这是环境前置条件，不是平台能力**——若缺失，属于部署问题。
- 平台侧新增的是**观测的引用与读取形状**（一个声明："这个应用读这类时序源"），不是时序实现。
- ADR-0101 需要扩展观测算子（`rate`/`delta`/`over-window`），按算子表的规则扩展并登记。
- 需要在使用文档（`docs/Apps.md`）里写清 D5 的最后一条：原始点的保留取决于外部存储，**不承诺与业务记录同等的历史保证**。

## 6. 验收

1. 一个楼宇应用接入一个声明过的时序源，声明一个判定（阈值 + 趋势），产生业务记录（预警）。
2. **体积断言**：接入高频源并运行一段时间后，**租户决策日志的行数与体积不随点数增长**（用测试或演练证明）；业务记录只含判定结果与聚合值。
3. **恢复断言**：断电重启后不重放任何原始点；判定结果与业务记录按 ADR-0038/0097 恢复。
4. **读取断言**：需要原始点时按声明回到观测存储读取，带标识与时间窗；权限按 ADR-0105 收窄。
5. **分界断言**：低频关系数据（设备清单、水表台账）仍走集成织物；同一批数据不出现"既进集成织物又进观测存储"的双路径。
6. **环境前置**：更换时序库只需改环境绑定，不改应用定义（用一个替换演练证明）。
7. **反例**：把高频点写入租户日志、在业务宿主内实现采集、时序存储或降采样 → 分别拒绝。按 ADR-0123 声明独立协议能力包不再属于反例。

测试归宿主与集成 owner 包；`docs/Testing.md` 增"观测与时序"手测行。


## As built

新增 `observation` 资产，由 Build 的 `build.observation` 持有草稿、不可变发布与保留版本。描述固定逻辑连接、原对象/设备字段、测点、单位、时间窗及外部保留/粒度期望；地址和凭据仍只在原连接环境中。发布、联合候选、目标连接映射、安装与纯恢复复用现有集成 owner。应用资源可引用该资产，统一依赖描述提供只读 query 和显式 evaluate operation；没有新内核类型或时序存储。

ADR-0123 在同一读取结果增加覆盖范围、完成时间、截断与质量计数；协议来源强制使用完整、质量合格的窗口，普通适配器可通过 `requireComplete` 开启。旧不可变定义保留原语义。模拟器能生成确定性窗口；真实 S7 最近值不冒充历史窗口，生产历史仍需外部存储。

供暖装配暴露的实际采样新鲜性要求已补在同一规则上下文：`observation.lastat` 是汇总中最后样本的实际时间，空窗时为 missing；它可与原业务请求时间比较。查询截止时间或目标值相等都不替代本次命令之后的新鲜证据，前端仍用原表达式选择器配置。

外部读取形状为 HTTP 适配器：向逻辑连接下的相对路径 POST `{device,signal,since,until,mode,limit}`。`summary` 返回固定大小的 `window`（count、首尾时刻和值、min/max/sum/mean、unit）；`points` 按请求返回至多 5000 个 `{at,value}`。范围为 `[since,until)`，十进制保留精确值；空窗不制造零值。汇总由外部存储/适配器提供，平台不对原始点做采集、聚合存储或降采样。适配器不属于采集协议，也不规定后端 TSDB 厂商。

`GET /v1/observations` 及 `/read` 读取原成员可见的来源和对象字段；锁外请求前固定成员、记录、定义、连接与凭据，回锁核对变化。`/evaluate` 用 ADR-0101 同一编译器的 `delta`、`rate`、`over-window` 与原记录字段评估条件，最终仍由原业务动作检查权限、输入、事务、约束和审批。仅紧凑标量进入动作；接受结果保存来源/版本、设备/测点和固定大小窗口证据，诊断读取再次核对原来源与字段权限。相同请求键返回原答复，不重读后来到达的点；恢复应用已保存结果，不访问观测服务。

“Evaluate completed windows automatically / 自动判定完成的窗口”默认关闭。启用后复用既有锁外来源循环，每个完成窗口以发布者当前权限发起原决定；使用固定窗口身份，原记录状态/动作规则可抑制重复预警。调度记忆不持久化，未命中不写租户日志，重启也不重放原始点。没有新增调度服务、采集进程或第二业务队列。

构建器在原 Data Connection 进入观测源编辑器，选择连接、对象、设备字段和原动作，通过同一表达式编辑器定义阈值/趋势与紧凑输入，再沿原候选发布。业务人员从设备记录的完整详情、只读详情侧栏或运行中的记录工作区进入 Observations，保留原记录；查看协议当前读数、外部汇总和精确点表/图，或提交已声明判定。入口只使用原成员可读的来源，普通成员不依赖管理员菜单。协议来源提供 `latest` 读取模式，只返回原记录对应的一个数值测点及质量、采样/接收时间和绑定修订；沿同一记录与字段授权在锁外读取后复核，不写入租户状态。当前值不生成历史窗口，不参加窗口判定；坏质量或缺失数据不制造零值。旧记录集合观测组件保留为低频业务记录的显示；高频外部序列走本资产，不转成 Source/Dataset 行，也不复制到旧记录窗口。

验证覆盖外部读的千万样本计数不增加租户日志/快照、仅结果入账、纯恢复无外部请求、相同键无重复读取、锁外记录变更拒绝、定时抑制、来源停用与两个独立 HTTP 环境替换而不改应用描述。Build 测试检查保留字节、连接环境映射/安装与非法动作输入。本地 S7/Modbus 服务与真实驱动二进制另检查普通成员的当前数值读取、未授权拒绝、不写租户状态及不冒充历史；质量与精确值检查归原平台测试。集中 Go/Web 检查和 `observations` 浏览器路线通过，桌面/窄屏已查看。HTTP 服务是受控外部适配器；真实客户 TSDB、采集器与实际保留策略仍是部署前置条件，本批没有声称已接通楼宇现场，也没有重跑 PostgreSQL 故障恢复演练。
