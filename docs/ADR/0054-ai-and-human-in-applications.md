# ADR-0054 — AI 与人工在业务应用中的位置：提议、检查点与接管

<a id="adr-0054"></a>

状态：已接受，工程已实现；统一受管智能体与类型化 AI 函数的有效运行决定。模型与运营配置归 ADR-0008；本文统一规定 **AI 运行、应用装配、提议采纳与人工接管** · 与 ADR-0039（事务）、0041（约束）、0055（异常）配套

## 0. 意图

现有 AI 能力是**可用的**：模型接入与预算（ADR-0008）、类型化 AI 函数（ADR-0054，页面与 Flow 可复用、有版本、有评测）、智能体（ADR-0054，受管主体、工具、草稿确认、追踪、记忆、评测、暂停）、构建器声明的 `build.agent` 与 `build.alertrule`、数据集→对象草稿按钮（ADR-0008）。权限与预算沿同一套治理（Intent §不变量"受治理 AI"）。

原先分散的提议、业务事务、人工接管和应用用量现已沿同一归属实现装配，支持范围见 §5。它们不构成新的业务写入或发布途径。

**判据**：构建者在装配应用时，能把 AI 放进一个业务流程的指定环节，指定它在**不改变任何权威状态**的前提下产出提议，并且由人（或另一条受权路径）决定是否采纳；采纳时与人工操作**走同一条提交路径**。

## 1. 决定

### D1 AI 在业务应用里有四种位置，只有一种能写

| 位置 | 形态 | 能否改变权威状态 |
|---|---|---|
| **读**（assist） | 在页面上回答"这个字段什么意思"、"这张单为什么不一致" | 否 |
| **提**（propose） | 产出类型化建议：字段值、下一步动作、分类、草稿记录 | **否**（草稿不是记录） |
| **行**（act） | 通过受权动作或事务提交变更 | **能**，但走与人工完全相同的路径 |
| **自主**（autonomous） | 在声明的预算与范围内连续执行"提+行" | **能**，但每次"行"仍是一个受权提交 |

**关键**：`提` 与 `行` 之间必须**显式**。今天 AI 函数"输出是类型化建议，不授予业务动作权限"（Platform §2.5 的 Typed AI function 行）——这条原则保留并强化：**建议到达业务记录的唯一通道是采纳**。

### D2 采纳（Adoption）是一等的业务操作

```go
// 建议的采纳：把提议变成一次正常提交。
type Adoption struct {
    Proposal  ProposalRef   // 提议的标识（版本化、可追溯）
    By        string        // 采纳者（成员，或受权主体）
    Amend     []Set         // 人类修改后的值（修改即采纳的一部分）
    Txn       TxnRef        // 采纳后执行的事务/动作（ADR-0039）
}
```

- **采纳是一个普通业务动作**：它有角色、有约束检查（ADR-0041）、有事务（ADR-0039）、有历史。它不是"AI 专用提交"。
- **AI 不能自称采纳者**：采纳者必须是成员或显式声明的受权主体；智能体自主执行时，其主体身份与预算在 ADR-0054 的既有语义内，**且每次提交仍过 ADR-0044 的同一决定点**。
- **修改即采纳**：人改了建议的值再提交，历史里记的是"人采纳了 AI 的提议并修改了 X"，不是"AI 写了 X"。这让审计上能区分责任。
- **提议必须可追溯**：提议记录保留输入、模型与参数、当时的定义版本、引用来源（沿 ADR-0054 的既有"完整声明与接受时输入/来源/模型绑定"）。

### D3 提议是记录，不是易失状态

- 提议按其**使用面**落为业务记录或标准记录：需要人工裁决的（检验判定、返工申请、分类结果）是**业务记录**，参与集合查询与看板；纯交互的（页面问答）是标准记录（沿 ADR-0016 的既有形态）。
- 提议有状态：待裁、已采纳、已驳回、已过期。**状态属于记录**，因此可查、可统计、可恢复。
- 提议**不占业务编号、不触发业务效果**（除非被采纳后的事务触发）。

### D4 检查点、接管与人工任务

- **检查点（checkpoint）**：不可逆效果前的人工确认已有机制（ADR-0009、ADR-0008 的"不可逆效果需人批"，`platform/effects.go` 的 held 状态）。本 ADR 要求它**在应用里可声明**：构建者指明"这个事务的这一步不可逆，需要谁确认"。
- **接管（handover）**：置信度不足或超出范围时交给指定角色，走 **work 应用的任务**（ADR-0007 的既有实现：任务、审批、升级、收件箱）。**不新建接管机制**。
- **人工任务与事务的关系**：审批是"事务在审批之前完整构造（暂留），放行后以申请人身份执行整个事务"（ADR-0039 §D5）。**AI 提议 + 人工裁决 + 事务执行**是同一形状：提议暂留 → 人裁决 → 事务执行。
- **AI 与人工的协作（评论、提及、关注）**：复用 relations 的既有能力（ADR-0038 的记录动态/评论/提及/关注者）。**不新建协作机制**。

### D5 AI 的输出受同一套规则约束

- **AI 不能绕过约束与权限**：智能体在业务规则体内的调用是 `Probe`（只读，ADR-0006 §设计 1 的既有机制）；它提出的变更在采纳时过全部约束（ADR-0041）与授权（ADR-0044）。
- **AI 的输入受同一套读取边界**：知识检索、字段读取、关联引用按调用主体权限收窄（Intent §不变量"检索、引文、追踪遵循数据读取边界"）；ADR-0044 §D4 的"未声明来源的自由文本在派生上下文中遮蔽"适用于 AI 生成内容——**AI 生成的字段必须声明它的来源**。
- **AI 的用量按应用归属**：模型调用、预算、成本按**应用**标签归集，进 ADR-0046 §D3 的运行面（由原 `usage` 分录保留应用绑定）。
- **评测按能力边界声明**：AI 函数的评测与版本绑定（ADR-0054 的既有门禁）；本 ADR 要求**应用层面能看到"这个应用里的 AI 在哪些环节、用了什么模型、评测结果是什么"**，并在评测未通过时**阻止该环节被激活**（沿 Platform §10.6 的"AI 品质与治理掌控"）。

### D6 装配：AI 在五工作区里的位置

按 ADR-0047 的五工作区：

| 工作区 | AI 的位置 |
|---|---|
| Model | 声明哪些字段/关系**允许** AI 提议（不允许则 AI 不能读取该字段作为上下文） |
| Behavior | 在事务/动作上声明**检查点**（哪一步需要人确认）、**采纳动作**（谁可以采纳） |
| Interface | 页面上的 AI 呈现（三种原生呈现已有，ADR-0015 §6.80）、建议的并排显示与差分 |
| Assemble | 模型与工具、预算与配额、知识来源、评测集 |
| Verify | 用样本试跑 AI 环节（**提议可试跑，采纳不执行**，沿 ADR-0050 的隔离语义） |

### D7 智能体是受管主体，步骤与结果可以恢复

智能体声明系统指令、允许工具、预算、守卫与升级角色，随代码资产或受控 Build 版本审查发布；不允许管理员绕过候选直接修改已发布行为。主体身份为 `agent:<app>.<name>`，工具必须属于声明目录。代表成员运行时取智能体与被代表人的权限交集，协议操作还需提供方角色；宿主在推理请求前与工具执行前重查该成员存在且仍有原应用角色，吊销后终止，不能退化为应用级自主运行。当前失去应用角色者也不能读取旧追踪或系统指令。

`agent.run` 是标准记录；宿主调度模型步骤，保存工具、参数、公开理由、结果、来源及计量，每次业务操作仍是独立的原动作提交。恢复应用保存步骤，不重新请求模型或重判原结果。工具限平台目录与授权的 context/search/query/read/knowledge，不能任意联网、读本地文件或执行代码。完整对话保存在有保留期的派生存储，公开理由不等于模型私有思维链；来源变化后的逐条观测清理不能从已实现的应用角色吊销检查推定为完整保证。

代表个人的操作先按该人员权限检查并保留草稿，只有该人员能确认、修改或拒绝；确认重新走原动作，拒绝反馈给原运行。Flow 可以按原主体在声明范围内自主调用，但不可逆效果、声明检查点和业务审批始终保留人工确认。`ask` 通过 work 任务挂起/答复，预算不足、模型连续失败、无模型或守卫拒绝时停止并移交原人员/角色；Flow 的 Agent 步骤沿原等待、答复与 Fault 分支继续，没有第二调度器。

运行追踪保存启动时 `seen` 与已确认/修改/驳回草稿的 signals。历史模型评估使用最近有信号的运行，重用当时已保存的上下文/读取，其他读取仍受当前授权；写操作只检查不提交，报告和用量保存。它与 §5 的新候选固定用例评测用途不同，不能互相替代激活凭据。挂起外部效果的废弃与业务决定撤销尚未普遍接为反馈信号，不因此增加新的业务撤销系统。上下文图谱、搜索与运行详情均复用原授权读取，原始追踪不能因列表可见而绕过来源权限。MCP 与 A2A 的外部边界沿原协议与出站效果，知识和记忆的来源保留归 ADR-0009。

### D8 类型化函数沿原模型效果执行，版本和评测精确绑定

`AIFunction` / `RequestFunction` 声明显式受权的标量输入、严格 JSON 输出、选项、字节与 Token 上限；函数输出是建议，不直接写源记录或取得动作权限。宿主拒绝未知/重复键、缺失/null、错误类型、非法类别、工具调用和超预算。调用保存定义、原输入与来源、授权主体、模型、预算与精确版本；流程引用固定原 `SourceVersion`，同候选的同名函数不能混入多个版本。新草稿、新发布和新默认模型不改变旧调用。

默认模型在接受请求时解析；派发前仍检查启用、配额、熔断和当前来源权限。旧请求缺少可验证绑定时拒绝，不在派发时自动补新默认。提供商的 served model 与请求模型分别记录，配置和端点不能证明上游权重永久不变。代码、页面和 Flow 使用同一函数 owner 与 `Request → model effect → Reply`；长等待、重试、人工复核归 Flow/work，自动 Reply 不允许伪造。结果、Reply 与用量属于同一保存结果，追加失败不可见，恢复不重呼模型；外部调用完成但未成功保存的窗口仍可能重试，不承诺模型物理调用恰好一次。

Build 使用原 `build.function` 保留最多 64 个发布版本，调用记录保存阶段、来源、回答/拒绝及度量；读取时重新检查派生来源。Token、时延和提供商费用区分未报告与零值；固定回答的度量只能说明机制，不代表真实模型质量。函数候选、来源闭合与保存结果继续用原发布和持久化机制，不另建 AI 账本。

正式评测从保存候选和样本计划读取精确声明；每个样本重复三次，保存严格输出、Token、时延、费用报告和实际模型。报告绑定候选、函数版本/摘要、计划修订/摘要及模型配置，缺费用、缺判据、类型失败或不达阈值均不能通过；配置或当前样本改变不能沿用旧通过。固定替身测试与真实模型评测明确区分，JSON 匹配不等于开放式语义质量。合成提供方能证明装配、权限、提交与恢复，不替代负责人体验或真实模型质量验收。

## 2. 不做

- **不做"AI 直接改数据"**：任何改变权威状态的路径都要经采纳与受权提交。
- **不做 AI 专用权限**：智能体是受管主体，参与普通授权（ADR-0054、ADR-0027），无额外特权（Intent §不变量）。
- **不做新的对话/助手界面体系**：页面上已有的 AI 呈现（`page_ai.go` 的既有实现、ADR-0015 §6.80）继续用。
- **不做模型的统一抽象层之外的新供应商机制**（ADR-0008 保持）。
- **不做"AI 生成的应用"**：构建器辅助（ADR-0008 的 Builder Assist）生成**草稿**，走同一候选与发布门禁；这不改变 AI 在运行时的位置。

## 3. 后果

- 智能体与 AI 函数的**运行时不变**，变的是它们在应用工件里的装配位置与采纳的表达；`build.agent` 的检查点/移交字段与本文对齐。
- **用量包含应用维度**：原 `usage` 分录与聚合保留应用绑定，运行投影归 ADR-0046 §D3；旧无绑定用量不猜测归属。
- **AI 生成内容必须声明来源**（D5）会让部分现有 AI 字段在派生读取里消失——与 ADR-0044 §D4 是同一条要求的两个面，需要一次核对。
- 评测未通过阻止激活（D5）会让"先上 AI 再补评测"的路径关闭。这是有意的：ADR-0038 §0 的第二判据要求正确运行，AI 环节没有评测就不能算。
- 与 ADR-0055 的接口：AI 提议被驳回后进入异常路径（返工/重新提议），见该 ADR。

## 4. 验收

1. 构建者在一个业务应用里装配一个 AI 环节：某对象上的"建议"字段由 AI 函数产生，采纳动作由指定角色执行，采纳走一个 ADR-0039 事务。
2. 采纳前后：AI 提议**不改变任何业务记录**（用测试证明提议期间记录字节不变）；采纳后历史显示"由 X 采纳了 Y 的提议，修改了 Z"。
3. 权限：AI 的上下文读取按采纳者/调用主体权限收窄；不可读字段不能成为上下文；AI 生成字段声明来源，且在派生上下文中按 ADR-0044 §D4 处理。
4. 检查点：不可逆步骤在声明需要确认时，事务暂留等待人工；人工放行后以申请人身份执行整个事务。
5. 接管：置信度不足时进入 work 任务，指定角色在收件箱中裁决；裁决结果回到原业务对象。
6. 用量与评测：应用运行面显示该应用的 AI 用量与成本；评测未通过的环节不能被激活。
7. 试跑：在 ADR-0050 的隔离试跑中，AI 提议可以产生并被检查，**采纳不执行**。
8. 反例：智能体绕过约束写记录、AI 内容未声明来源进入派生读取、无评测的 AI 环节被激活 → 分别被拒绝并留下原因。

测试归 agent/ai owner 包与宿主；`docs/Testing.md` 增"AI 在应用中的装配"手测行；`docs/Apps.md` 增可执行用法。

## 5. As built

Agent 的提示文本、历史消息编排、工具调用正规化、UTF-8/JSON 观察结果边界及预算计算归 `internal/agents`。该纯模块只接收原 owner 已授权的上下文和历史投影；运行状态、并发占用、工具执行、模型 I/O、授权复核和接受结果仍在原 Agents/Tenant 协调位置，不新增调度器。历史运行、单调用格式和公开 API 保留。

**完整模型调用与恢复。** 智能体保存一轮的全部工具调用及供应商调用 ID。首次调用与完整列表一起接受，余下调用保存在原运行；每个调用独立沿原动作提交并保存结果，人工确认/等待后继续余下列表，重启复用已完成结果。结束、取消和撤权为未执行调用保留明确结果。连续知识读取可并发等待，写入保持原顺序，不产生跨权威事务。旧单调用步骤仍按原格式读取与应用；模型步数和费用只计一轮。

Agent、MCP 从原动作与字段声明投影输入描述，标准新建/编辑保留获权字段、枚举、金额、嵌套行、引用与条件，不增加第二份业务校验。新模型工具参数保留整数值，完整 JSON 对象经过解析才执行。上下文按字段/记录裁减为合法 JSON，文本保持 UTF-8，截断结果说明继续读取方式。原工作调度接收合并唤醒并保留每秒补扫；没有第二个 Agent 调度器。

OpenAI/Anthropic 原适配器提供正文与工具参数增量，完整回答后才返回可执行调用；截断不当作完成。最终用量保留报告/估算区别，缓存读写计数与价格缺失分别表示；Anthropic 输入总数包含缓存输入。Agent 稳定前缀启用原供应商缓存配置。MCP 协商实际支持的 2025-06-18 / 2025-03-26，普通 JSON 响应与既有工具能力不变。测试使用模拟供应商，不代表真实模型质量或真实供应商计费验证。


页面旧 `function` 与 `ai-assistant` 的函数调用统一由原 `AIWidget` / `createAIReader` 承担，旧 `FunctionAdvice` 及其启动、读取、刷新、忙碌/错误和结果状态已删除。旧页面种类和版本不改写，仍消费原选中记录；调用历史继续按记录、函数和版本读取，打开原函数调用详情查看计量及提议。计量只在原详情展示，保留未报告与不可读来源的区别。人工采纳仍沿原 `ProposalReview`、审批与业务事务，不增加 AI 执行或授权路径。

**归属与装配。** `AIFunction.Proposal` 声明移交角色、置信度输出/阈值与 1–604800 秒有效期；业务提议复用原 `build.function-call`，模型回答仍走原 AI effect 与接受结果。原输入、来源、函数/模型版本之外，保存输入字段原值、`pending/adopted/rejected/expired` 裁决、实际裁决人/时间、采纳动作/收据及修改值。低置信度只派原 work 任务，裁决后关闭同一任务；评论、提及和关注继续走原记录协作。没有独立提议仓库、审批器或模型执行器。
