# ADR-0055 — 拒绝、异常与纠正：失败是业务的一部分

<a id="adr-0055"></a>

**状态：** 现行 · 已实现，真实体验待验证 · 拒绝、纠正与重复升级是业务的一部分。

## 0. 意图

ADR-0038 §1 把"异常与质量"（暂停、返工、报废、检验、处置）列为 MES 基准的一个范围，并明确要求：**"如果无法配置返工，就研究状态与业务决定能力"**。

今天"失败"只有一种形态：操作被拒绝，返回一个错误码，事务消失。这是正确的**原子性**语义（ADR-0039 §D3），但它把三类完全不同的失败混成了一件：

| 失败 | 例子 | 今天的处理 |
|---|---|---|
| **策略拒绝** | 你没有权限、字段不可写 | 返回 `POLICY_DENIED`，界面禁用控件（ADR-0048 D4） |
| **约束拒绝** | 数量为负、编号重复、已下达不可改 | 返回约束错误（ADR-0041 D6） |
| **业务拒绝** | 设备不支持该工序、批次已报废、物料被冻结 | 无区分；与上面两类一样只是"失败" |
| **技术失败** | 外部系统超时、集成错误 | 进入效果重试/`unknown`（ADR-0051） |

**业务拒绝不是错误，是业务的正常结果。** "这台设备不能加工这道工序"不是系统故障，是业务事实；它需要被**记录、呈现、驱动后续动作**（改派、返工、降级、让步接收），而不是只变成一个红色提示。

**判据**：构建者能声明"这个操作在什么条件下被拒，被拒之后业务上发生什么"；被拒的事实留下痕迹；纠正后能重试且不产生重复。

## 1. 决定

### D1 业务拒绝是一等结果

业务事务的每一步可以声明**拒绝出口**（`Refusals`）：

```go
type Refusal struct {
    When    *Expr    // 不成立即继续；成立即按 Level 处理
    Level   string   // block（阻止事务）| flag（继续但记录）| route（转到另一条路径）
    Code    string   // 稳定码：供界面区分与统计
    Message string   // 给人读的原因（英文 + zh-CN）
    Route   *TxnRef  // Level=route 时：改走哪个事务/动作
    Record  *TxnStep // Level 时：要留下什么记录（如不合格品记录）
}
```

- `block`：整个事务拒绝（今天的语义），但与约束拒绝**区分码**；
- `flag`：事务继续，但在记录上留下可见标记（让步接收、超差放行）。**这是今天完全没有的能力**，而它正是制造业真实运作的一部分；
- `route`：改走另一条业务路径（返工、降级、改用替代工艺）。**这就是"返工"的一般形态**——返工不是特例代码，是"被拒之后走另一条事务"。

### D2 三类失败的处理位置不同

| 层 | 谁处理 | 在哪声明 |
|---|---|---|
| 策略拒绝 | 平台（ADR-0044 的单一决定点） | 不可声明；它是门禁 |
| 约束拒绝 | 平台（ADR-0041 的约束） | 对象类型上（模型的一部分） |
| **业务拒绝** | **构建者的业务逻辑** | 事务/动作上（本 ADR） |
| 技术失败 | 平台（ADR-0051 的效果/作业机制） | Confirmation / 效果声明上 |

**不允许**把业务拒绝实现成约束拒绝（用约束表达"设备不支持就比较复杂了"会把业务规则塞进模型层）；也**不允许**把它实现成策略拒绝（那就成了权限问题）。

### D3 纠正与重试的语义

一次被拒的操作，人改了输入再来一次——这必须是明确的：

- **输入被修改后重试：新的幂等键**（这是新的意图，不是重试）。历史里两次都能看到，且能看到第二次基于第一次的哪些修改。
- **定义与输入未变的重试：同键返回原答复**（K4 幂等性），不产生第二次拒绝也不产生第二次变更。请求已明确拒绝且定义已刷新时，相同输入可用新键提交关联纠正；结果未知时仍只能确认原请求。
- **拒绝不消耗资源**：不占编号（沿 ADR-0026 编号的既有语义"拒绝不占号"）、不产生外部效果意图、不留下部分状态。
- 界面上的"重试"必须区分"原样重试"与"改了再试"，并在改了再试时保留原值作为参考（今天 `DraftSession`/history 已有草稿与历史，`ADR-0048 §9`）。

### D4 异常的可见与升级

- **拒绝必须可见且可查**：按应用、按类型、按码统计（这是 ADR-0046 §D3 运行面的一块：拒绝率与主要拒绝码）。
- **重复拒绝触发升级**：同一记录/同一操作反复被拒可以声明升级（通知角色、创建任务，走 work 的既有机制）。
- **拒绝不是丢弃输入**：被拒的输入保留在草稿与拒绝答复里（沿 ADR-0037 §3.4 的"拒绝不留下可见变更或效果；同键同内容返回持久的原答案"）。
- **暂停（hold）**：业务对象可以进入一个"暂停"状态（等待裁决、等待物料、等待检验结果），由生命周期表达（已有的状态机），并**到时间触发升级**（沿 ADR-0007 的定时自动化）。

### D5 纠正路径本身要有历史

- 让步接收（`flag`）必须在记录上留下：谁批的、依据什么、什么时候、原值是什么。这不是"悄悄通过"。
- 返工（`route`）创建的返工记录与原始记录之间**有声明的关系**（ADR-0043 的集合），因此"这个批次返工过几次、每次因为什么"可查。
- 报废与让步在同一个对象上有不同的后续语义（报废进报废台账、让步入正常流程但带标记），由**事务的目标状态**表达，不新增执行器。

### D6 与 AI、人工的接口

- AI 的提议被驳回：进入本 ADR 的拒绝路径（重新提议、升级人工、或按 `route` 改走别的路径）。**驳回不是错误**，是提议生命周期的一个状态（ADR-0008 §D3）。
- 人工裁决（审批、接管、让步接收）走 work 的既有机制（ADR-0007、ADR-0008 §D4），本 ADR 只要求它们在**业务对象上留下可见结果**，而不是只留在任务收件箱里。

## 2. 不做

- **不做补偿式回滚**（ADR-0006 D1(c) 已否决；ADR-0039 §3 重申）。业务拒绝不留痕迹，不需要补偿。
- **不做重试策略的通用编排**：重试是效果/作业的既有机制（ADR-0051、ADR-0007），本 ADR 不管传输层重试。
- **不做异常工作流引擎**：`route` 就是指向另一个事务，不必引入状态机描述语言。
- **不做"自动纠错"**：平台不猜业务上该怎么办。

## 3. 后果

- 事务定义多了 `Refusals`；ADR-0039 的 `BusinessTxn` 相应扩展（`Guard` 是"不成立即整体拒绝"，`Refusals` 是"分级处理与改路"，两者语义不同，不能合并）。
- 界面上需要区分四类失败并给出对应动作（重试、改了再试、改派、升级、让步），归 ADR-0048 的权限与错误呈现。
- 让步接收与返工的历史要求让"记录上的标记"成为审计对象，需要在运行面可见。
- 这一条直接支撑 ADR-0060 的"异常与质量"范围：暂停、返工、报废、检验、质量处置**全部落在本 ADR 的表达里**，不写 MES 专用代码。

## 4. 验收

1. 三个级别各一例：
   - `block`：设备不支持 → 事务整体拒绝，不占编号、无记录、无效果；
   - `flag`：超差但让步接收 → 事务完成，记录上有标记（谁批、依据、时间）；
   - `route`：返工 → 走另一条事务创建返工记录，与原记录有关系可查。
2. 区分码：策略拒绝、约束拒绝、业务拒绝分别返回可区分的码与原因，界面据此给出不同动作。
3. 纠正：改了输入重试产生新意图（新键），历史可看到两次的关系；原样重试返回原答复，不重复。
4. 暂停与升级：对象进入暂停状态并到期后升级（通知或任务），裁决结果回到业务对象上可见。
5. 统计：运行面能看到该应用的拒绝数与主要拒绝码分布。
6. AI 驳回：提议被驳回进入拒绝路径，提议生命周期状态正确，不产生业务记录变更。
7. 反例：用约束表达业务拒绝、用策略拒绝表达业务规则、`flag` 却不留痕、`route` 未声明目标事务 → 发布期或运行期明确拒绝。

测试归 build 与宿主 owner 包；`docs/Testing.md` 增"拒绝与纠正"手测行。

## 5. As built

业务拒绝声明归 `BusinessTxn.Refusals` 与步骤 `Refusals`，同一个 Expr owner 求值，声明包含稳定码与英中原因。发布期检查三个级别、记录/动作引用、同权威、输入/状态兼容、改路环、原记录关系，以及受控预算；缺翻译、flag 缺记录、route 缺目标事务均明确拒绝。拒绝记录使用原 create 权限与约束，没有私有写入入口。

- **分级与原子性。** block 丢弃本次全部私有行、编号及意图，保存原拒绝答复。flag 继续事务并要求一条引用原业务记录的可见处置记录。route 用原保存点丢弃当前分支，再执行声明的另一事务；目标仍检查当前动作权限、输入、生命周期和逐步骤授权，原分支编号/新建 ID 不能被改路记录消费。所有成功处置仍是一次接受结果，未增加异常执行器。
- **审计与读取。** `BusinessRefusalFact` 保存级别、稳定码、原值、输入、操作者、时间、步骤、关联记录与改路动作。block 进入原 refusal 封套格式 4；成功处置进入原 record-batch 格式 7，旧格式保持可读。保存点复制/探测隔离事实；只把拒绝诊断返回原申请，不把已回滚的行与效果带出。恢复只应用保存映像，不重新求规则或权限。`GET /v1/business-refusals` 是上述封套的纯读取投影，不是第二份拒绝权威；行/字段和派生来源权限按当前状态收窄，其他成员不能取得原提交输入。
- **纠正与同键。** 原样重试从原 K5 outbox 发送相同请求，终态保留；修改输入或刷新已拒绝请求的定义后创建新键，原 `Submission.CorrelationId` 保存 `correction:<原键>`。宿主验证原拒绝属于同主体/动作/目标，输入或封存定义确已改变；HTTP 兼容 header 与正文关联必须相同。请求摘要包含纠正来源，同键不能改换来源。历史显示两次请求、原值和逐字段变化；缺失字段与 null 不混为一值。表单保留原输入，明确区分“Retry original inputs”与“Submit with refreshed definition”，不把结果未知的请求自动改用新键。
- **构建器与操作界面。** 原 Transaction 编辑器配置事务/步骤拒绝出口，使用原规则编辑器。普通动作、生命周期、创建、编辑与页面事件共用拒绝呈现和纠正提交；`ActionDialog` 的独立创建/编辑提交函数、请求快照、回执、字段错误与拒绝状态已删除，由原 `DeclaredActionForm` 同一提交函数承担。生成记录表单保留条件字段、嵌套行和输入原文，声明参数表单保留固定参数、日期/选项来源与预览；不合并不同输入能力。原样重试固定原目标、输入、修订号和键，同目标修改才关联纠正，更换 ID 是独立意图，本地拒绝不锁成未知状态。记录页与应用记录工作区读取同一拒绝/处置历史；应用运行面按可读模型、类型、类别与稳定码汇总，flag/route 也有审计计数。拒绝接受后发原 live 变更，历史和统计随之刷新。
- **重复拒绝与暂停。** 构建者可配置次数、时段与复核角色；声明随原事实保存。原 Work 作业按不同提交计数，达到阈值创建普通任务和通知，原样重试不重复计数，任务完成后不重开。复核者仍须当前可读业务记录。暂停使用已有状态、Process 等待步骤和 Work 审批：到期申请人工裁决，再以原业务动作更新业务记录，没有新增定时执行器。
- **AI 与审批。** AI 驳回沿原 `build.function-call.review` 更新提议生命周期，并保存 `AI_PROPOSAL_REJECTED` 审计结果，业务源记录保持原值。审批放行后的 flag/route 事实归实际申请人的业务子决定，随原 Work 接受结果保存；审批前的 block 保留其业务诊断。人工让步与改路仍过原业务动作/审批权限。

**替代与历史：** 保留 Guard 的前置判定与步骤 When 的跳过语义；业务条件不满足与策略门禁分开呈现。新分级处置替代把业务失败混作红色权限提示的旧入口；新的显式原样重试/纠正替代明确拒绝后不分内容反复新建键。约束继续表达模型不变量，授权继续归单一引擎，未用新 Refusals 删除这两类语义。`apps/mes` 的退出仍须 ADR-0053 的等价构建产物，本块不改造或删除原生行业应用。

**实现 profile：** route 当前指向同一主体的另一普通事务，目标不能有 Approval 或 Adoption；这是原同权威事务的分支选择，不是跨权威调用。处置记录必须显式引用原主体；专业返工单字段与流程由构建者声明。接受结果仍受原字节预算，超限拒绝不截断业务证据。实际设备/ERP/WMS 和负责人质量处置走查不由内部夹具替代。

PostgreSQL 模式的重复拒绝升级先按保存结果的 `business` 字段选择候选，再由原 Work 决定解码、分组和检查原冻结政策；普通答复不再每轮全量读取和解码。SQL 当前与检查点读取共用相同选择规则，未改原历史字节、去重身份、升级次数或任务完成后的不重开规则。内存/文件模式复用原事实与同一筛选，不新增升级队列。

**检查范围：** 已检查三级处置、目标权限和输入、审批、原样重试与新键纠正、原输入/关联读取、重复升级、暂停到期裁决、文件与 PostgreSQL 关闭重开，以及原日志/快照恢复。浏览器已完成配置拒绝码、操作员纠正、让步、返工和按码查看统计；桌面与窄屏截图已查看。具体命令归 [Testing](../Testing.md)。实际行业处置与负责人使用体验仍须真实操作，自动检查不代替该结论。
