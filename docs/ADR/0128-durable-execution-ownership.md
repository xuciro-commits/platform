# ADR-0128 — XXL：持久执行、事务与外部效果的单一职责

状态：接受执行（2026-10-17），归 ADR-0125 XXXL。既有 ADR-0038/0100/0101/0102/0112 的语义约束继续有效；本文要求合并重复实现，不重定义协议。

## 核心边界

将“决定要改什么”“记录已接受结果”“推进持久工作”“发送外部效果”分开，但每一类只保留一个主实现：

- Transaction 负责一个 owner 内确定性的业务状态决定、约束和原子入账。
- 接受结果/Journal 负责持久输入与恢复；恢复只应用保存结果，不重新求值、授权或发送外部请求。
- Flow 负责等待、人类/代理任务、超时、审批及可恢复的多步工作。
- Effects/dispatcher 负责已入账外部效果意图的幂等发送、读回、补偿和人工恢复入口。
- Work 与 Inbox 是任务读/答 API，不是第二套执行器或第二份状态机。

## 要清理的问题

审查 `apps/flow`、`apps/work`、`platform` transaction、host staged/accepted-result、`effects.go`、`agent_engine.go` 的状态副本、状态映射、retry/timeout、授权和执行回调。若同一工作状态被多个包重新解释、同一决策既从 flow 又从 transaction 普通执行，必须选一个 owner 并迁移消费者；不同语义不得仅因代码相似合并。

## 迁移规则

1. 对照每种状态与日志字段，而不是从目录名推断重复；列出产生者、持久化字节、读取者、恢复动作和外部副作用。
2. 选择上表的权威实现；调用侧只传稳定 ID/已接受输入，不保存影子状态，不直接写另一 app 的记录。
3. 将进行中的 flow、pending task、outbound intent 和旧 receipt 迁移/读取责任纳入测试。无明确转换则保留历史读取器，不保留旧普通新写分支。
4. 删除 superseded executor、adapter、状态镜像和重复定时器；不能只增加兼容 facade。

## 不变量与验收

决策原子性、tenant/owner 隔离、Authorization-before-effect、稳定幂等键、未知外部结果不得伪报成功或自动危险重发、补偿留痕、审批身份与版本固定、确定性恢复、不可变历史。覆盖接受前失败、提交后崩溃、恢复重放、重复请求、拒绝、超时、取消、部分批次和外部状态未知。性能验证聚焦恢复每个 accepted result 的分配/解码和调度扫描，不凭设计猜测锁优化。

此项涉及核心保证，按一条端到端执行路径逐步交付；不得以追求减量合并不同 owner 的原子边界。
