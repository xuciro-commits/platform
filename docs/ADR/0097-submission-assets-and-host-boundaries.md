# ADR-0097：提交契约、资产生命周期与宿主角色收敛

**意图：** 当前平台已经有契约内核、自治应用、受控定义和不可变候选，但提交覆盖、资产安装和宿主角色仍靠多处特例连接。本次把这些连接收敛到明确的提交契约、原资产模型的生命周期契约和按消费者需要提供的角色边界；业务语义、执行 owner 与产品入口保持原归属。

共同标准是**权威唯一、行为一致、变化局部**：相同保证覆盖全部适用入口；不同领域保留自己的语义和执行过程；重构以实际调用、故障行为及变更影响验收。统一 Go 返回类型、字段数量或一个巨大注册表不能替代这些结果。

**状态：** 已决定重构方向（2026-10-11）；提交预检隔离、完整结果封存及嵌套决策/保存点正式契约已实施，范围见 §7，其余提交、资产与角色收敛尚未完成。具体接口签名、结果格式和兼容迁移随所属整块落实，不能以本文替代实现或验收。实施直接按已确认问题推进，必要核查随代码迁移，不设全平台盘点前置。

**基线：** `40fc87bce03ec65a81f1cc4d7e16b21b01c0f42d`，本地 `main` 静态代码阅读。原评审及另一 AI 的“100% 吻合”审查分别作为待核对材料；没有把对方声称的运行失败、代码行号或工期当作本次证据。

**取代关系：** 接续 ADR-0038 的选择加入式分批迁移，明确统一新写入的最终契约及旧路径退出；取代 ADR-0047 §10.2 的历史实施排序。保留两者的接受结果不变量、现有成果与持续 Flow 接受条件。扩展 ADR-0039 的资产生命周期覆盖，保留规范字节、版本、原子激活与环境绑定语义。ADR-0080 的零行为结构整理已经关闭；本文接续处理它有意未改变的契约耦合，不重开其搬文件任务。Shell/门户/投影及编辑器仍分别归 ADR-0052、0053。

## 3. 唯一新写入提交契约

1. **入口显式。** 所有改变租户权威状态的 Submit、connector Input、审批、订阅/作业、模型/Agent 结果、外部效果应答和运行管理动作，都进入同一暂存 → 校验 → 持久接受 → 应用管线。统一的是接受、拒绝、幂等、恢复及外部效果保证，不强制所有 App 改为同一个 Decision 返回类型。现有类型化收据可保留，完整记录/状态/意图由本次暂存区收集并校验封存；编码由格式能完整表达的内容决定，不能因动作名字或返回类型丢失状态。应用不能绕过宿主校验或提交任意 journal 字节。
2. **能力显式。** 当前匿名暂存能力迁到命名契约，受权读取/查询迁到相应读取契约；具名角色接口检测可以保留。缺必需能力时组合预检或调用明确拒绝，不以调用 live runtime 兜底。撤掉租户全局 probing，审批预检使用只读声明及私有 fork/savepoint，不写共享状态。
3. **状态完整。** 账本、owner 私有事实/状态、发布定义、投影通知、序列、工作/效果意图和幂等收据都有具类型的参与者与原子边界。七个选择加入接口在其消费者及保存映像迁移完成后退出；必需的 Validate/Apply/Fork 等纯状态能力以正式契约保留，不能为了“Accepted 字符串归零”删除恢复职责。
4. **拒绝与重试。** 拒绝不留下可见变更或效果；同键同内容返回持久的原答案，异内容冲突。嵌套决定并入父级结果，允许显式可回滚 attempt；异步应答是新的顶级结果，不建立跨远程系统事务。
5. **持久与恢复。** 有序 journal、版本化结果族、前驱校验、1 MiB 接受结果限制及原制品预算保留。内存开发也走同语义的接受存储；不能因为没有持久回调就使用另一套直接修改器。历史 submission/input 解码、旧 record/batch 格式及其必要版本仍保留读取/恢复义务，直至有可验证迁移依据；停止产生旧业务输入条目不等于删除 journal 存储。
6. **外部效果。** 恢复只应用已保存结果，不重新裁决、调用模型或发送请求；恢复完成后的 dispatcher 可继续交付已持久的未完成意图。外部系统通常是至少一次交付，必须用稳定身份、接收方幂等或对账处理结果不明；不宣称仅靠统一提交实现远程 exactly-once。

迁移按实际依赖和状态 owner 分组，不机械照抄评审的应用名单。每组须证明正常接受、拒绝无写、追加失败无暴露、追加后崩溃、快照/日志尾及全日志恢复、重复/冲突、权限/撤权和旧版本读取；随后关闭该组旧写入口。全部状态写入口迁完后退出选择式分流；中间版本继续公开实际覆盖范围。

## 4. 复用现有资产模型，统一生命周期协调

**注册的是可信 owner 能力。** `AssetKind` 保持现有身份类型；新增生命周期参与者注册，由可信应用/宿主能力实现，租户只提交受控描述符。注册表不得执行租户钩子、脚本或从 Body 加载任意代码；名称、重复归属、版本和支持操作在组合期检查。

生命周期契约覆盖：完整类型化描述符的校验与规范化、显式依赖/环境绑定要求、私有试装及兼容/迁移计划、已接受安装映像的纯应用、定义状态的快照/恢复。各 kind 声明支持/拒绝哪些操作；序列、接口、原生回调、Agent 和只读行为声明不因 Manifest 有切片就自动成为可发布租户资产。Manifest 可保留有业务语义的类型化声明；用于交付的共同描述符统一投影为已有 ReleaseAsset，不强制把清单压成一个无类型 Assets 切片。

候选封存、依赖闭包、安装审阅、激活和晋级复用 `Candidate` 与原发布存储，在通用协调层按注册能力工作。类型特定的校验/解码保留在 owner；删除重复的逐类编排，不把“全仓无 kind switch”当成果。计划必须验证整个集合及相互依赖，再一次提交；不得逐 kind 安装到 live 状态后才发现后续失败。

Connection/Source/Dataset/Pipeline 的**定义描述符**及选定任务必需的 Writeback/Matching 等依赖按原 owner 接入共同闭包。凭据值、来源游标、数据集实际内容、Pipeline 运行记录和外部回执分别属于环境或运行/数据 owner，不放进可移植定义，不在晋级中偷偷复制。定义固定版本和支持的兼容关系；目标环境重新验证绑定及权限，不支持的连接/数据迁移显式拒绝。

发布回退与数据迁移分别审阅：切回定义版本不保证数据或外部效果可逆。测试覆盖草稿→候选→激活→目标环境晋级→受支持升级/失败保留或回退、缺依赖/缺绑定拒绝、历史读取与运行版本保持。不支持的迁移必须有可见拒绝，不能通过注册一个 Migrate 方法就声称通用升级完成。

运行 frame/checkpoint 的引用与清理由 Flow、原制品 owner 及持久清理意图治理；定义快照接口不能替代在途引用、历史保留和 GC 安全检查。引用查询失败、截断或提交结果不明时保留制品，不推断未引用并删除。

## 5. 宿主角色与并发边界

宿主内部公共面按真实消费者分出权威/声明、身份/受权读取、定义生命周期、提交/协议路由及运行/任务角色。名称与数量按调用关系确定，不为满足五个接口或单接口方法数上限造分层。平台应用只接收必要角色；Console/Agents 的状态迁回应用 owner，身份读取、审批暂留、Agent 声明/运行与 Flow 预备能力通过具名契约接入。

消除根包生产实现对具体平台应用包、类型与私有状态的依赖；组合入口和测试可导入实现，但不应嵌入提交/恢复管线。先盘点所有反向边，再迁消费者与原状态/历史；组合的 Attach→全部声明就绪→Ready 时序须明确并可验证，替代 Console 的 defer 初始化，不改变权限装载时机。

`boundaries.sh` 在原 Makefile/check 路径增加反向依赖、具体应用断言和公共 API 匿名 runtime 探测检查。迁移期逐路径/符号列明例外并阻断新增，不能只按总数“一个新增抵一个删除”；消费者迁完即删除例外，目标运行实现不再保留这类逃逸。当前仅标签 CI 运行，规则必须首先进入本地 `make check`，不把常规推送当 CI 验证。

**保留每租户单写者。** 逐调用核对并记录哪些状态受 mu、opsMu、streamMu 和组件锁保护，哪些组合禁止同持、哪些短时嵌套合法，以及谁能调用已持锁的方法。不得直接照搬评审锁层级。锁外 I/O 是共同的 prepare→revalidate→accept 规则：只捕获固定定义、主体、来源和 generation/ticket；锁外读写有界不可变字节；回锁复核当前权限、版本、实例和前驱后接受；过期结果拒绝/回收，提交不明保留。来源读取、Compute、外部投递及制品清理按各自语义遵守规则，不强制经过唯一串行 I/O 执行器。沿现有 owner 测试加入必要的 race 检查、锁边界/撤权时序断言；race 无报告不等于已证明不存在死锁。

## 6. 迁移、验收与文档归属

实施顺序、当前状态和停止条件只归 [WorkQueue](../WorkQueue.md)。本 ADR 说明结构决定与兼容义务，产品要求仍归 [SRS/SOW v1.1](../Platform-Refactoring-SOW.md) 的 AR-01–17、S-01–05、D-01–10；产品域是覆盖维度，结构根因是工程组织依据。已有能力与 77 项目录继续逐项有 owner、支持边界和证据，不能只盘点本 ADR 涉及的接口。

持续 Flow 完整交付依赖它实际使用的状态、提交、资产与 I/O 契约收敛，不要求先迁完全平台所有无关应用才修复一个已确认故障。其原七节点、mean/reading、并发 8、版本化死信、同版本停止续接、GC/保留与原预算不变，既有 PostgreSQL/worker/部署恢复成果继续保留。S-04 的真实模型质量和 S-05 的共享输入不能只靠结构改造通过，有缺口仍在原 owner 修复。

最终结构证据是入口/参与者覆盖、历史兼容、重复协调路径退出、负向授权、实际提交/恢复和三类变更的责任域/人工同步点比较；不是字段数、接口数或“新增资产只改一文件”的绝对承诺。产品交付还须两行业环境、完整任务、部署恢复与独立 FDE；负责人体验和生产容量分别记录。初始评审只做静态核验；当前代码交付范围归下方 As built。

检查方法归 [Testing](../Testing.md)，当前代码事实和能力摘要归 [Platform](../Platform.md)，可执行用法归 Apps/部署说明。旧 ADR 的已实施语义与历史格式继续在原位置维护，状态行注明本文接续范围；不新建第二队列、评审日志或报告体系。

## 7. As built

`platform.Runtime.ProbeDecision` 已是必需的正式契约，删除匿名检测与缺能力时直接执行的兜底。普通 runtime 从现有 stagedDecision 创建私有视图，已暂存的父决策从 privateFork 派生；预检状态只属于该视图。Tenant 的全局 probing 字段及审批/导入切换路径已删除。协议与 Agent 原消费者经同一契约运行；审批预检看到父决策的未提交记录，预检不会再创建审批请求。`boundaries.sh` 在原检查入口禁止恢复 Tenant 共享开关。

`Runtime` 的 `DecisionRuntime` 明确要求 Decide、Attempt 和 ProbeDecision；有宿主的调用不再匿名探测后兜底直调 App.Submit。`StagedRuntime` 是具名的完整私有 Runtime 与 DraftChanges 契约，替代 marker；账本拒绝空日志或 live 日志，不能降回权威账本。无宿主单应用、普通内存/未迁移入口及旧输入 replay 的明确直接语义仍保留，不能把正式方法的存在当成全入口原子接受保证。Work 的嵌套 Attempt 与普通协议调用经正式 Runtime 路由；原审批行为、调用主体与提交锁边界保持。

保存点/预检的 privateFork 现隔离预备 Compute 输入队列、输入诊断及其路径、OperationResult 的可变输出/引用。拒绝或异常恢复父决策，预检丢弃子视图；成功只消费本次输入，不改不可变制品或已接受历史的归属。`TestAcceptedNestedAttemptOwnsPreparedComputeAndPrivateState` 沿真实 RequestOperation、私有 Console 状态、记录及通知验证四种结果；对重构前 privateFork 的同一测试复现子拒绝/异常/预检消耗父输入。新契约与历史 owner 定向检查经独立子智能体审查通过。

规则检查仍可检查尚未迁到接受结果的旧动作：私有账本验证后不运行应用 callback，也不能将该预检当作可提交的决定。已有 AcceptedStateApp 的私有状态沿原 fork 保留；未声明状态参与者的应用私有副作用仍须在后续迁移中治理，不宣称所有任意规则都已隔离。普通规则异常继续抛出；不支持的宿主效果明确拒绝。原 journal/结果格式、动作语义与预算未改。

`TestPrivateProbeDoesNotChangeLiveOrParentState` 沿原 testkit 检查成功、拒绝、不支持效果和规则异常下的 live/父记录、通知及模式保全；原审批、协议、嵌套接受结果用例继续守业务行为。全部新写入口的共同接受边界、七类选择接口退出、资产生命周期注册及宿主角色迁移尚未完成。

`make check`、宿主全包 `make test-go PKG=./...`、`scripts/verify.sh composition` 与预检/审批/协议/嵌套的定向 race 检查通过。持续 Flow 的 64 批既有用例修正派发时钟：固定事件时间不能早于上一轮真实完成时间和接受记录的 Due；原预算、历史、重放断言保留。检查不代表全部提交统一、SRS 完整场景、负责人体验或生产验收。

已覆盖的顶级 Submit 由 stagedDecision.sealResult 封存，先按动作声明检查目标，不能利用编码回退接受错误目标。单记录格式的 writer 明确拒绝无法携带的私有状态、观察、计算取消、通知及其他意图，转由完整批次 writer 表达；删除宿主中按 schema 后缀/选择接口加九个草稿条件的编码分流。保留 App.Submit 的现有返回类型、旧单记录/批次解码与预算，尚未迁移入口的准入范围不随此编码整理扩大。`TestAcceptedGeneratedRecordKeepsPrivateOwnerState` 检查一个生成记录动作同时修改私有状态，在追加失败、成功、重试及禁止再调用决策的重放中保持同一接受保证；在重构前源码上，该用例复现提交成功但私有状态丢失。

封存及正式嵌套契约/保存点改动通过 `make check`、宿主全包 `make test-go PKG=./...`、应用/协议组合检查、相关 owner 定向 race 与 `make rehearse`。隔离排演包含两行业 PostgreSQL、接受结果/输入崩溃恢复、真实 worker 与来源、重启、备份/全混合日志重建及前后浏览器路线；原单记录/批次历史保持可读。新私有状态与保存点用例是内存接受存储的行为证据，不能据此提升为所有入口或生产容量保证。
