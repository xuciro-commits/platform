# ADR-0097：提交契约、资产生命周期与宿主角色收敛

**意图：** 当前平台已经有契约内核、自治应用、受控定义和不可变候选，但提交覆盖、资产安装和宿主角色仍靠多处特例连接。本次把这些连接收敛到明确的提交契约、原资产模型的生命周期契约和按消费者需要提供的角色边界；业务语义、执行 owner 与产品入口保持原归属。

共同标准是**权威唯一、行为一致、变化局部**：相同保证覆盖全部适用入口；不同领域保留自己的语义和执行过程；重构以实际调用、故障行为及变更影响验收。统一 Go 返回类型、字段数量或一个巨大注册表不能替代这些结果。

**状态：** 已决定重构方向（2026-10-11）；W1 提交与恢复、W2 资产生命周期与集成闭包、W3 宿主角色收敛已实施并按 §7 边界验证。具体接口签名、结果格式和兼容迁移随所属整块落实，不能以本文替代产品验收。实施直接按已确认问题推进，必要核查随代码迁移，不设全平台盘点前置。

**基线：** `40fc87bce03ec65a81f1cc4d7e16b21b01c0f42d`，本地 `main` 静态代码阅读。原评审及另一 AI 的“100% 吻合”审查分别作为待核对材料；没有把对方声称的运行失败、代码行号或工期当作本次证据。

**取代关系：** 接续 ADR-0038 的选择加入式分批迁移，明确统一新写入的最终契约及旧路径退出；取代 ADR-0047 §10.2 的历史实施排序。保留两者的接受结果不变量、现有成果与持续 Flow 接受条件。扩展 ADR-0039 的资产生命周期覆盖，保留规范字节、版本、原子激活与环境绑定语义。ADR-0080 的零行为结构整理已经关闭；本文接续处理它有意未改变的契约耦合，不重开其搬文件任务。Shell/门户/投影及编辑器仍分别归 ADR-0052、0053。

## 3. 唯一新写入提交契约

1. **入口显式。** 所有改变租户权威状态的 Submit、connector Input、审批、订阅/作业、模型/Agent 结果、外部效果应答和运行管理动作，都进入同一暂存 → 校验 → 持久接受 → 应用管线。统一的是接受、拒绝、幂等、恢复及外部效果保证，不强制所有 App 改为同一个 Decision 返回类型。现有类型化收据可保留，完整记录/状态/意图由本次暂存区收集并校验封存；编码由格式能完整表达的内容决定，不能因动作名字或返回类型丢失状态。应用不能绕过宿主校验或提交任意 journal 字节。
2. **能力显式。** 当前匿名暂存能力迁到命名契约，受权读取/查询迁到相应读取契约；具名角色接口检测可以保留。缺必需能力时组合预检或调用明确拒绝，不以调用 live runtime 兜底。撤掉租户全局 probing，审批预检使用只读声明及私有 fork/savepoint，不写共享状态。
3. **状态完整。** 账本、owner 私有事实/状态、发布定义、投影通知、序列、工作/效果意图和幂等收据都有具类型的参与者与原子边界。原七类能力不再选择是否接受；账本成为 App 必需契约，动作/工作准入标记退出，必需的输入解码、事实、发布及 Validate/Apply/Fork 等纯状态能力以具名参与者保留，不能为了“Accepted 字符串归零”删除恢复职责。
4. **拒绝与重试。** 拒绝不留下可见变更或效果；同键同内容返回持久的原答案，异内容冲突。嵌套决定并入父级结果，允许显式可回滚 attempt；异步应答是新的顶级结果，不建立跨远程系统事务。
5. **持久与恢复。** 有序 journal、版本化结果族、前驱校验、1 MiB 接受结果限制及原制品预算保留。内存开发也走同语义的接受存储；不能因为没有持久回调就使用另一套直接修改器。历史 submission/input 解码、旧 record/batch 格式及其必要版本仍保留读取/恢复义务，直至有可验证迁移依据；停止产生旧业务输入条目不等于删除 journal 存储。
6. **外部效果。** 恢复只应用已保存结果，不重新裁决、调用模型或发送请求；恢复完成后的 dispatcher 可继续交付已持久的未完成意图。外部系统通常是至少一次交付，必须用稳定身份、接收方幂等或对账处理结果不明；不宣称仅靠统一提交实现远程 exactly-once。

迁移按实际依赖和状态 owner 分组，不机械照抄评审的应用名单。每组须证明正常接受、拒绝无写、追加失败无暴露、追加后崩溃、快照/日志尾及全日志恢复、重复/冲突、权限/撤权和旧版本读取；随后关闭该组旧写入口。全部状态写入口迁完后退出选择式分流；中间版本继续公开实际覆盖范围。

## 4. 复用现有资产模型，统一生命周期协调

**注册的是可信 owner 能力。** `AssetKind` 保持现有身份类型；新增生命周期参与者注册，由可信应用/宿主能力实现，租户只提交受控描述符。注册表不得执行租户钩子、脚本或从 Body 加载任意代码；名称、重复归属、版本和支持操作在组合期检查。

生命周期契约覆盖：完整类型化描述符的校验与规范化、显式依赖/环境绑定要求、私有试装及兼容/迁移计划、已接受安装映像的纯应用、定义状态的快照/恢复。各 kind 声明支持/拒绝哪些操作；序列、接口、原生回调、Agent 和只读行为声明不因 Manifest 有切片就自动成为可发布租户资产。Manifest 可保留有业务语义的类型化声明；用于交付的共同描述符统一投影为已有 ReleaseAsset，不强制把清单压成一个无类型 Assets 切片。

候选封存、依赖闭包、安装审阅、激活和晋级复用 `Candidate` 与原发布存储，在通用协调层按注册能力工作。类型特定的校验/解码保留在 owner；删除重复的逐类编排，不把“全仓无 kind switch”当成果。计划必须验证整个集合及相互依赖，再一次提交；不得逐 kind 安装到 live 状态后才发现后续失败。

Connection/Source/Dataset/Pipeline 的**定义描述符**及选定任务必需的 Writeback/Matching 等依赖按原 owner 接入共同闭包。凭据值、来源游标、数据集实际内容、Pipeline 运行记录和外部回执分别属于环境或运行/数据 owner，不放进可移植定义，不在晋级中偷偷复制。定义固定版本和支持的兼容关系；目标环境重新验证绑定及权限，不支持的连接/数据迁移显式拒绝。

发布回退与数据迁移分别审阅：切回定义版本不保证数据或外部效果可逆。测试覆盖草稿→候选→激活→目标环境晋级→受支持升级/失败保留或回退、缺依赖/缺绑定拒绝、历史读取与运行版本保持。不支持的迁移必须有可见拒绝，不能通过注册一个 Migrate 方法就声称通用升级完成。

运行 frame/checkpoint 的引用与清理由 Flow、原制品 owner 及持久清理意图治理；定义快照接口不能替代在途引用、历史保留和 GC 安全检查。引用查询失败、截断或提交结果不明时保留制品，不推断未引用并删除。

## 5. 宿主角色与并发边界

宿主内部公共面按真实消费者分出权威/声明、身份/受权读取、定义生命周期、提交/协议路由及运行/任务角色。名称与数量按调用关系确定，不为满足五个接口或单接口方法数上限造分层。平台应用只接收必要角色；Console/Agents 的状态迁回应用 owner，身份读取、审批暂留、Agent 声明/运行与 Flow 预备能力通过具名契约接入。

消除根包生产实现对具体平台应用包、类型与私有状态的依赖；组合入口和测试可导入实现，但不应嵌入提交/恢复管线。先盘点所有反向边，再迁消费者与原状态/历史；组合的 Attach→全部声明就绪→Ready 时序须明确并可验证，替代 Console 的 defer 初始化，不改变权限装载时机。

`boundaries.sh` 在原 Makefile/check 路径调用 AST 守门，扫描全部生产 Go 源码（包括当前系统不编译的 build tag 文件），阻断根包具体应用导入、Console/Agents 具体状态断言、owner 间依赖、公共 API 匿名 runtime 探测和平台 owner 接收组合 Host。消费者已迁完，不保留迁移例外、数量抵扣或宽 Attach 入口。当前仅标签 CI 运行，规则必须首先进入本地 `make check`，不把常规推送当 CI 验证。

**保留每租户单写者。** 逐调用核对并记录哪些状态受 mu、opsMu、streamMu 和组件锁保护，哪些组合禁止同持、哪些短时嵌套合法，以及谁能调用已持锁的方法。不得直接照搬评审锁层级。锁外 I/O 是共同的 prepare→revalidate→accept 规则：只捕获固定定义、主体、来源和 generation/ticket；锁外读写有界不可变字节；回锁复核当前权限、版本、实例和前驱后接受；过期结果拒绝/回收，提交不明保留。来源读取、Compute、外部投递及制品清理按各自语义遵守规则，不强制经过唯一串行 I/O 执行器。沿现有 owner 测试加入必要的 race 检查、锁边界/撤权时序断言；race 无报告不等于已证明不存在死锁。

## 6. 迁移、验收与文档归属

实施顺序、当前状态和停止条件只归 [WorkQueue](../WorkQueue.md)。本 ADR 说明结构决定与兼容义务，产品要求仍归 [SRS/SOW v1.1](../Platform-Refactoring-SOW.md) 的 AR-01–17、S-01–05、D-01–10；产品域是覆盖维度，结构根因是工程组织依据。已有能力与 77 项目录继续逐项有 owner、支持边界和证据，不能只盘点本 ADR 涉及的接口。

持续 Flow 完整交付依赖它实际使用的状态、提交、资产与 I/O 契约收敛，不要求先迁完全平台所有无关应用才修复一个已确认故障。其原七节点、mean/reading、并发 8、版本化死信、同版本停止续接、GC/保留与原预算不变，既有 PostgreSQL/worker/部署恢复成果继续保留。S-04 的真实模型质量和 S-05 的共享输入不能只靠结构改造通过，有缺口仍在原 owner 修复。

最终结构证据是入口/参与者覆盖、历史兼容、重复协调路径退出、负向授权、实际提交/恢复和三类变更的责任域/人工同步点比较；不是字段数、接口数或“新增资产只改一文件”的绝对承诺。产品交付还须两行业环境、完整任务、部署恢复与独立 FDE；负责人体验和生产容量分别记录。初始评审只做静态核验；当前代码交付范围归下方 As built。

检查方法归 [Testing](../Testing.md)，当前代码事实和能力摘要归 [Platform](../Platform.md)，可执行用法归 Apps/部署说明。旧 ADR 的已实施语义与历史格式继续在原位置维护，状态行注明本文接续范围；不新建第二队列、评审日志或报告体系。

## 7. As built

**唯一新写管线。** Submit、记录型 Input、审批/协议、订阅/作业、外部应答、Agent 步骤及模型计量都先暂存，再经 `Tenant.acceptResult` 接受，最后纯应用。Compute、连续来源、候选保存/激活、组合编辑及宿主管理使用同一接受边界。内存、Record、AcceptResult 只决定存储方式；内存没有进程崩溃持久性，Record 保留追加失败停服的义务。删除 `acceptsGenerated`、动作/工作名单、直接提交后记录输入及第二协议应答协调器；普通 live Runtime 拒绝新决定和管理写入，仅保留历史重放与读取。

**正式契约和私有上下文。** App 必须提供非空账本，组合期检查；ResultApp、AcceptedActionApp、AcceptedWorker 已退出。Runtime 按决策、读取、操作、函数、审批、通知、诊断和管理提供必需的具名角色，Caller 不再匿名探测能力。状态、事实、输入和发布的纯验证/恢复职责保留；DecisionForkApp 隔离只读声明与单次执行上下文。AI/Enterprise 新增完整私有状态，原 Console/MES/PMS/Relations 状态参与者继续复用；Build/Work/Flow/Agent/Files/Knowledge 的私有 Host 读取同一父视图。

**保存点。** ProbeDecision、Attempt 与 HoldChanges 共用私有决策。HoldChanges 在账本持锁之前拒绝重复进入；保存点保留仍在执行的父 receiver 和捕获日志，其余状态/日志/输入队列/诊断/计算结果/控制组件另行 fork。子拒绝、异常或预检不能消耗父输入、污染父状态，也不能丢失父决定后续写入。连续 Flow 的 opaque prepared 包装器在 fork 后仍保留原计划；商业拒绝由保存点交回原重试/补偿逻辑。Tenant 的全局 probing 已删除。

**完整结果。** 单记录 writer 只在能表达全部修改时使用，否则封存完整批次。`record-batch` 格式 1 保留完整历史，2 保留增量历史，3 增加按组件的控制映像，4 同批承载实际外部应答的直接观测行；后者只允许已有效果来源及其 owner 的合法回调，不接受普通动作遗漏的未发布决定。旧格式/字节不重写，前驱和原收据严格校验，1 MiB 接受结果预算保留。Console 的连接器、设置、绑定、工作板、通知、端点、效果与翻译在私有组件上决策；取消外部 Compute 在接受后执行。

**各类入口。** MES states、PMS channel-bookings 在三种存储中均保存 `input-result`，成功/拒绝重试返回原答复；拒绝不泄漏新事实或成功游标，LastError 由保存拒绝恢复，已接受事实不删除。旧订单首次转入新路径只允许与 live 完全相同的私有账本重用旧收据。Work/Effect 保留原 K9 世代、回调、预算、配额、公平调度及 Trace 关系；Agent 工具、步骤和计量由 `agent-result` 一起接受，直接 Chat/评估/Embedding 用 `usage-result` 接受计量。恢复不再调用模型、工具或当前业务规则。

**组合与宿主管理。** 新 composite-result 格式 2 保存封存批次或无变更拒绝及原答复，恢复不重新编辑；格式 1 仅保留历史规则回放。Host lifecycle、support open/use 和迁移清单由 host-result 保存自身状态、请求收据与审计；不借全 Tenant Restore 覆盖业务记录。原宿主接口没有客户端键，接受时间参与身份，同一次请求/时间可复用收据，新时间是新操作；support 的健康/审计读取仍是当前投影，不冻结为业务答复。发布、来源和管理不因缺 AcceptResult 降到另一套修改语义。

**可信资产生命周期。** `platform.AssetRegistry` 在组合期注册可信 `AssetLifecycleOwner`，复用原 `AssetRef/ReleaseAsset/Candidate` 身份、规范字节及闭包。代码声明固定当前 owner 契约；受控定义由原 owner 产生 typed descriptor、声明依赖及环境要求、解析保留版本、计划草稿与安装、验证及纯应用。页面内容摘要独立于来源版本，精确保留内容也由同一 owner 解析。发现与资源选择沿当前成员可读的 owner 元数据投影，不暴露构建者描述符。租户不能注册执行钩子；根发布协调不再维护逐 kind 的解码/安装分支，原类型化执行、字段校验与历史解码留在各 owner。

**私有首次装配和一次接受。** `AssetDraft.Ref` 对应候选内原资产；owner 按真实依赖安排草稿及安装计划。`BeginAssetBootstrap` 仅在私有 owner 暂存完整候选对象形状，原 create 权限与输入校验可识别自引用/互引用。缺失元数据通过真实 create 决定写入共享私有记录视图；前置 typed 安装使后续校验看见依赖，不修改 live 或提前裁决未完成闭包。完整集合另从原运行视图试装并校验；新 `release-result` 格式 4 将 create 的封存批次、owner 安装映像、升级/幂等收据及活跃指针一次接受。晚期拒绝或追加失败均不暴露草稿、定义、指针或外部请求。恢复校验原前驱并应用已保存映像；格式 1–3 保留原字节与解码义务。原 live `materialiseDrafts` 循环及根类型安装编排已退出。

**集成定义与环境。** Connection、Source、Dataset、Pipeline、Writeback、Matching 使用 Build 的 typed descriptor 进入原候选闭包；来源/管道的对象、数据集、连接及匹配规则的实际 producer 依赖保持原身份。候选携带逻辑名称、配置与版本；地址、密钥名称/值及本地绑定 ID、执行主体、游标、数据/schema/运行历史和外部回执均不移植。目标 Connection 必须是唯一同名、同 kind、已就绪的本地配置，需要凭据时还要有可解析的本地密钥；不自动生成空端点。依赖名称映射为目标记录 ID，Puller/Runner/Publisher 绑定目标成员，保留目标运行状态。准备检查原调用者 token scope，最终私有试装检查目标当前角色及实际数据写/答复编辑权限；发布不授予权限。

**固定执行与支持边界。** 接受后六类集成执行配置取原固定 descriptor，只叠加本地环境和运行观测，后续草稿编辑不暗换执行语义。已有数据/游标的来源变更输入身份、目标或映射，管道变更输入/输出身份仍需迁移并明确拒绝；标题、受支持变换/期待规则及原可选标量升级沿显式候选/计划处理，目标已接受数据与历史不回滚。PropertyType/LinkType/Query/Function 首次部署支持第 1 版；高 ordinal 而目标没有所需保留 family 时拒绝，不捏造前驱。Compute 保持已有匹配的已编译目标 owner/制品要求，只有 module 描述符不足以首次创建源代码或编译证据。企业模型落地管道、含裸地址/内嵌 header 的旧来源等未纳入便携 profile：旧开发/重放行为保留，明确选择交付则拒绝，不阻断无关候选。production profile 同时拒绝四个集成直接 publish；development 保留原入口及历史。

**在途集成结果。** Writeback 请求保存原目标与答复映射，升级后旧回复按原请求处理；缺固定映射的旧请求跨入新版本时明确拒绝。Source/Pipeline 的结果携带实际定义版本；保留版本的 typed 执行内容（仅忽略标题）及 Ref/依赖均相同时允许旧请求完成。映射、目标、变换或期待规则不同则旧结果拒绝，保留已接受行及新定义的重跑请求。空版本只兼容当前仍无 Published 的旧定义；Flow/审批/函数/Compute 的原启动绑定与迁移门禁继续保留。
