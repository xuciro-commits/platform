# ADR-0047 — 应用设计台：围绕一个应用构建

<a id="adr-0047"></a>

状态：已接受；工程已实现（2026-10-14），体验待验收。合并 ADR-0047 的语义构建归属与 ADR-0047 的编辑器交互，修订 ADR-0019、ADR-0018 的构建侧组织。事务、关系、页面与隔离试跑分别归 ADR-0039、ADR-0043、ADR-0048、ADR-0050；其余运行保证不变。

## 0. 意图

设计台按应用组织原编辑器，共享资产身份、草稿与返回位置；构建者也能从本体、集成、界面、逻辑、函数和发布菜单直接进入已有编辑器。应用组织方式不能隐藏实体、动作等常用入口。

ADR-0038 第一阶段六步流程（理解业务 → 设计应用 → 配置规则 → 构建界面 → 验证发布）**不是设计要求**，是设计起点。本 ADR 只定一件事：**装配骨架按应用组织，而不是按资产类型**；六步是否唯一路径要真实用户验证，所以**不把六步做成强制向导**。

**判据**：构建者围绕一个应用连续工作，不需要知道平台有哪些编辑器、更不需要知道它们之间怎么连接；切换资产时上下文与未保存状态不丢（这是 ADR-0015、ADR-0036 已有的行为，必须在新骨架下保留）。

## 1. 决定

### D1 一个设计台，五个工作区，共享一个应用上下文

```text
Application Studio（当前应用 = ADR-0046 的工件）
├─ Model    业务模型   对象、字段、关系、共享类型、主数据（ADR-0042 的版本）、约束（ADR-0041）
├─ Behavior 业务行为   状态、事务（ADR-0039）、规则（ADR-0040）、决策表、审批、异常与返工
├─ Interface 业务界面  页面、模块、应用外壳、专业组件（ADR-0048、ADR-0049）
├─ Assemble 装配       数据来源与集成、自动化与流程、AI 函数与智能体（ADR-0051）
└─ Verify   验证与发布  样本试跑、角色检查、候选、迁移计划、交付（ADR-0045、ADR-0046、ADR-0050）
```

- 每个工作区**复用现有编辑器**，不重写：`ModelWorkbench`（对象/属性/链接）、对象编辑器（状态/动作）、页面编辑器（`EditorWorkbench` 三栏）、流程画布（`FlowCanvas`/`BlockCanvas`）、函数与智能体编辑器、集成编辑器、Releases 工作台。
- **变化的是骨架与导航**：左栏是上述五个工作区 + 应用的资产树（按**业务概念**分组，不按资产类型平铺），右栏是当前资产的 Inspector，中间是编辑器。沿用 ADR-0019 的 Shell 页签模型（Dock）。
- **应用上下文**贯穿五个工作区：当前应用、当前资产、未保存草稿、历史。切换工作区不丢上下文（复用 `DraftSession`/AutoSave 的既有机制，ADR-0036 §9）。
- **导航范围明确分开**：应用工作区与业务资产树服务当前应用；全部应用、本体、集成、界面、逻辑、函数、发布与探索菜单服务跨应用查找，直接使用原列表和编辑器。进入具体应用时显示当前工作区资产树和“全部应用”返回入口，跨应用工具在返回后展示，不再把两套菜单连续铺开；构建者不必先创建或进入应用，才能编辑实体、动作等资源。跨应用入口不暗带当前应用筛选；应用内返回和资产选择共用同一原引用及路由识别。Home、门户、命令菜单可以提供快捷入口，但不增加资产目录、授权或第二份归属信息。

### D2 按业务概念分组，不按资产类型平铺

原资产树按"对象 / 关系 / 属性 / 页面 / 查询 / 流程 / 函数 / 代码"排列（ADR-0018 §1 的诊断表原话："菜单是能力清单，不是任务路径"），现已由下面的应用业务概念分组取代。

新的资产树按**应用自己的领域词汇**分组，分组由构建者命名；侧栏先按当前工作区筛选，再保留业务概念分组，未分组资产使用“业务模型”“规则与决策”“连接与数据”等可读分类，不显示原始命名空间标题：

```text
<应用>
├─ 主数据        物料、设备、工作中心、工序、工艺路线
├─ 单据与记录    工单、批次、派工单、报工
├─ 异常与质量    不合格品、返工、检验
├─ 规则          完工判定、返工限制、可加工设备
├─ 界面          工作站、工艺路线图、工单详情、看板
├─ 自动化        到期提醒、质量升级
└─ AI            工艺问答、异常分类
```

**分组不是授权、不是发布单位、不是依赖边界**——它只是导航。资产的真实归属（应用、版本、依赖）仍在定义里。构建者可以重命名、移动分组而不影响任何语义。

### D3 跨编辑器跳转保留上下文（沿 ADR-0018 §3.4 的 "Open in"，扩展到构建侧）

从任意位置一键到相关位置，且**带着当前选中的资产与草稿状态**：

- 对象 → 它的动作/状态/约束/引用它的页面/使用它的规则/它的记录样本；
- 规则 → 它引用的字段与关系、被哪些动作/页面使用；
- 页面 → 它绑定的对象与动作、它使用的查询；
- 运行物 → 产生它的定义版本与决策（ADR-0046 的诊断面）。

**"使用处/被使用处"必须由声明依赖推导**（`Definition.requires`），不靠扫描。

### D4 应用存在感：一个应用从创建到交付的完整轨迹

设计台要能回答"这个应用现在处于什么状态"，而不只是提供编辑入口：

- **新建**：从空白、从模板（ADR-0048 的模块模板）、从已有资产引用（ADR-0020 §2 的"添加已有"）；
- **进度**：模型是否完整、规则是否有未决错误、页面是否绑定有效、是否有未发布的变更（**由定义与候选状态推导，不维护第二份进度**）；
- **交付**：当前活跃版本、待发布候选、上一版本、迁移计划（ADR-0045）；
- **运行**：该应用的运行概览（ADR-0046 D3 的投影）。

### D5 六步流程是可选引导，不是强制路径

- 提供"从业务意图开始"的可选引导（描述业务 → 建议模型骨架 → 建议规则 → 建议页面），走**同一套定义与候选**（沿 ADR-0008 的 Builder Assist 边界：生成草稿，人类审查，同一发布门禁）；
- 引导**可跳过**、可退出、可从中途进入；
- 引导产生的草稿与手工产生的草稿没有区别（**这是硬要求**：否则会形成两套构建路径，ADR-0038 的自举约束会立刻失败）。

### D6 构建者工作台与业务操作台的分工

构建者在设计台编辑，业务成员在正式应用操作；两者使用同一份定义与原权限。Operations / Build / Admin 是门户类别筛选，沿 ADR-0018 与本文 As built，不再作为三套工作区投影。

### D7 统一语义资产，各归原运行归属

应用 API 定义公共资产契约与类型化代码扩展；宿主检查、授权、执行；Build 管租户草稿；relations 管记录关联；`@platform/app` 管绑定，`@platform/ui` 管组件与共享画布。代码、可视化和 AI 编写使用同一资产标识、候选与权限，不增加构建器专属执行器或任意租户脚本。跨应用写入走原动作/协议，一个构建器动作不能修改另一权威的私有状态。

代码应用与 Build 应用从同一 Applications 列表进入，以完整 `AssetRef` 识别应用，草稿记录 ID 单独保留。原生结构读取已授权的 `Definition`，不为查看操作创建 `build.app`。AppUI 只提供已加载的视图、菜单和记录入口元数据；任意 React 组件与 Go 函数不支持无损反向转换。声明式 Page 可在能够完整表达其绑定时生成原 `build.page` 草稿，对象和动作仍引用原 owner。

应用可用 `extends` 引用已安装原生 Application，`entry` 指定现有 AppUI 入口，`replacements` 把原 view 指向自己的页面。扩展保存和发布沿原 Build 路径；发布后通用 Shell 合并导航，不另列启动入口。页面运行仍使用扩展自身的 Application 身份，Shell 显示原入口。来源依赖、候选和入口冲突检查归原发布机制；声明入口不授予原应用权限。平台执行能力不因此转为客户可编辑的实现。

共享节点目录声明类型化端口、连接数量与资产引用。各语义归属把编辑写回原对象、动作、流程或函数定义，原校验器决定合法性；位置、选择和缩放只用于展示。生命周期可以循环，结构图可以成环，数据流采用自己的规则，通用画布不能给所有图强加一种执行语义。依赖与影响读取原声明，不扫描页面拼第二份业务模型。

对象条件、赋值与引用路径按声明类型检查，审批放行按申请人的当前权限与来源重新检查；缺失值与零/假区分。单记录转换仍有效，多记录变更沿 ADR-0039 的同权威事务；关系保证沿 ADR-0043 的实际写入检查，不能把引用、通用链接或图上连线当作基数/删除约束。固定候选、迁移、已接受结果分别归 ADR-0011、ADR-0045、ADR-0010，旧定义和在途版本不因界面重组而重新解释。

### D8 一个 Workbench，原记录与草稿各自保留

`@platform/ui` 的 `Workbench` 是共同编辑器容器：标题与状态、按需结构区、主区、Inspector、Problems/Variables/Runs 底栏；没有独立作用的结构列表直接省略。页签使用 `ContentTabs`，已访问内容隐藏后保留输入，隐藏的 Dialog/Sheet 撤下全局浮层。面板宽度按可用空间切换，保留拖动、键盘和复位操作，布局不进入业务文档。

每种资产只有一个正式编辑器；动作编辑器修改所属对象的原 `actions[]` 与同一草稿会话，独立视图不新增动作存储。对象和动作由明确 Save 提交新增及修改，拒绝保留输入且不自动重试；其他编辑器使用各自既有自动保存。发布前先保存，归档草稿保留历史，已发布版本不会因草稿归档退出运行。取消修改恢复保存内容，不提交业务决定。

页面、页头、导航和浮层在原模块/页面编辑器配置；组件库与 Inspector 来自组件契约。预览复用正式渲染器，业务写入被阻止；动作验证使用 ADR-0050 的隔离执行器。事件的顺序效果沿原 `PageEventBinding.effects`，拒绝或取消即停止，动作使用共享表单和原提交。自动化是原 `build.process` 的线性形态，复杂逻辑打开原流程图，不新建 automation 资产或执行器。页面事件的手动流程启动与任意运算赋值没有承诺为已实现能力。

Changes 读取 Build 的已保存定义比较，按字段展示与选择，进入同一候选审阅；不以生命周期状态猜测变化。复杂 document/sections/events 目前按原属性展示，不能称为逐组件语义比较。Shell 按文档身份归并页签；跨资源、跨应用切换保留输入与应用范围，迟到保存不能抢回已切换的文档。原路由别名只解析历史书签；类型菜单和应用工作区使用同一套现行路由、资源列表与编辑器。

## 2. 不做

- **不做新的一套页面/表单/流程编辑器**：全部复用（ADR-0038 §3 的硬要求之一）。
- **不做"零代码"的强制**：需要代码的地方（ADR-0013 的受控代码）在设计台里有同一入口，不隐藏在别处。
- **不做资产树的分组权限**：分组只导航。
- **不做六步强制向导**（见 D5）。
- **不把设计台做成一个新的平台应用**：它是 Build 投影下应用的组织方式，仍由 `@pkg/build` 贡献（ADR-0018 §3.2 的分类不变）。

## 3. 后果

- `@pkg/build` 在原类型菜单之外提供应用上下文，保留本体实体、动作等直接编辑入口（ADR-0019 D2 的一个 Builder 不变）；应用工作区用于组织业务任务，不能取代常用构建菜单。
- 需要一次真实用户验证：构建者围绕业务意图连续工作是否成立、五工作区划分是否与真实任务匹配、六步引导是否必要。**未验证前不得宣称体验重构完成**（这是 ADR-0038 第三阶段的判据）。
- 资产树的分组由构建者命名，因此需要持久化（属于应用的元数据，随工件版本走）。
- 反向工作：现有 e2e 路线（`web/e2e`）需要随导航变化更新；按 ADR-0030 只保留有证据价值的路线。

## 4. 验收

1. 构建者在一个应用里完成"加一个对象 + 一个状态动作 + 一个页面 + 发布"，全程不离开应用上下文，未保存草稿在切换工作区时不丢。
2. 从对象一键跳到引用它的页面、使用它的规则、产生它的记录样本；从规则跳到它引用的字段与关系。
3. 资产树按业务概念分组，分组可重命名与移动且不影响任何语义（用测试证明：移动分组后定义字节不变）。
4. 应用状态可见：模型完整性、未决错误、当前版本与候选、迁移计划。
5. 可选引导产生的草稿与手工草稿在定义层**完全一致**（同一份字节），走同一候选与发布。
6. 真实用户验证：至少一次由非平台开发者完成的走查，记录任务、断点与结论；未完成前本 ADR 标记为"体验待验收"。

测试：`make check-web` + 一条 e2e 路线（`make e2e SPEC=...`）；视觉与手感由负责人走查，不写像素断言（沿 ADR-0030）。

## 5. As built

Applications 合并原 `/v1/apps` 安装项、获权 Application 定义与 `build.app` 草稿，完整 `AssetRef` 和草稿记录 ID 分别保留。查看原生应用不创建记录；五工作区共用原资产引用、依赖读取及编辑器。已加载 AppUI 的入口、菜单和路由作为只读结构显示，纯 React 页面只提供运行入口；缺少结构读取权限时保留安装元数据并说明限制。声明式页面可无损转换为原 `build.page` 草稿，不能完整表示的页面不转换。扩展通过原应用设置保存 `extends`、`entry` 和替换映射，发布后加入原入口，页面保留扩展运行身份；延迟到达的发布定义会刷新当前旧链接，保留原标签输入。

原 New 菜单展示当前应用有权创建的资源，当前工作区只影响排列优先级，同一种类只出现一次；创建不同种类不再要求先切工作区。侧栏只列当前工作区资产，切换工作区后仍沿原完整引用打开编辑器；业务概念编辑保留完整应用成员，不改变资源归属。

资源发现按真实记录类型只建立一次库存观察与分页订阅；流程/自动化、测试计划/评测集不再各自注册同一类型的刷新回调。分类记录和完整资产引用只计算一次，资产树、成员匹配与“添加已有”共用索引，不再为每个成员反复扫描库存。原分类优先级、共享资产归属、完整读取限制、权限和不可用/缺失状态保留；不同页面的可见读取仍各自管理，不宣称 HTTP 或 SSE 连接数量按比例下降。

页面切换使用短的元数据版本作为查询范围标识，完整成员、权限与定义内容变化仍生成新范围；查询键不再重复携带整份定义。实时读取把宿主元数据和动态记录分批订阅，记录读取变化只替换有变化的批次，保留未变连接；原授权、刷新、断线重连与停止清理行为保留。单资产依赖读取仍由原授权图计算关系，只返回焦点及相关资产的描述，全图读取不变。窄屏侧栏选择资产或切换应用后关闭抽屉。

工程实现落在 `@pkg/build`，应用仍是原 `build.app` / `platform.Application` 工件。真实非平台开发者走查尚未完成，**体验待验收**；下面只声明实现与自动证据的边界。无可见业务页面的已发布应用归入交付与运维类别，主页说明用途，再由明确按钮进入原运行诊断；有业务页面的应用仍直接进入业务页；没有共享变量的单一应用页面不显示实例管理控件，原页面上下文和深链接保留。对象字段引用、动作引用参数、关系和页面模板共用可读的已保存对象描述，草稿优先于旧发布字段；事务当前对象仍使用未保存的编辑内容。模板可绑定草稿动作，引导直接进入应用内模板，页面与模型一起经原候选发布，不要求先单独发布对象。构建期描述不替换运行目录或执行授权；字段别名、公式和固定版本的只读属性保留，状态转换复用原事务投影。关系同批交付使用原联合对象描述和私有安装检查，单独交付仍须有原对象。对象详情打开动作正式编辑器前先保存当前草稿，拒绝时不离开原输入。告警和决策表新建完成时，只在原文档仍是当前文档时跳到已保存资源；用户已选择另一文档则不抢回焦点，原新建标签按原确认规则关闭。页面能保存绑定新增草稿字段，但预览仍读取原发布数据；未发布字段明确提示模型与页面一起发布，不把设计可选性当成运行可用性。

应用角色矩阵通过原 `build.object.edit` 仅提交变更的 access 与当前修订，不再把整条对象记录及只读/派生字段作为编辑输入。对象权限与应用矩阵因此沿用同一部分修改语义，原草稿和其他对象设置保留。

应用内页面预览通过原应用 AssetRef 选择已发布会话，不再把构建 `build.app` 记录 ID 当成运行应用名称。预览的应用/实例参数与构建参数分开，页头和页面调用继续进入同一预览实例，返回原编辑器时保留构建上下文；新实例和关闭实例仍归原 ApplicationSession，不改变仍打开的正式页面共享值。原 ComposedPage 统一阻止预览中的业务写入，展示值、导航和返回仍可交互；已保存但未发布的应用不会因此获得运行定义。`application-context` 已检查这些操作、原定义与业务记录不变，并观察桌面/390px 页头；跨应用切换销毁最后页面时仍清理临时会话，不增加持久状态。

流程与自动化的对象选择同样读取保存中的模型；动作块的参数来自原对象归属方的 `EntityActions`，不再要求先发布动作。已保存草稿替换该对象旧发布动作的编辑选项，其他查询、AI 与计算块保留原来源与固定版本。独立的构建期读取只向 Builder 提供描述，不进入正式能力目录或授予执行资格。来源触发、手动和定时流程的 Validate 使用可读保存对象调用原检查器，发布和候选仍以已安装或本次选定的对象为准。来源记录 ID 按原记录读取授权解析，不误当普通业务字段拒绝；其他路径保留字段检查。页面变量的字段选择与 create/edit 的属性和路径规则也按保存模型检查；单独发布不能借用未选中的模型修改。

项目总览的已保存变更数量与 Changes 共用原 Build 的变更读取，包含应用自身及其成员，不再用 `state=published` 推断草稿一致。清单显示字段、修改人和时间，选定后才读取原值/草稿值，普通记录元数据与版本序号不算定义改动；可移交接入、告警、测试、样本和迁移计划沿原归属方的描述比较，无效声明保留诊断。环境绑定和运行数据不当作可移交定义变更。数据读取不发布、不改变保留声明；批量选择仍进入原 ReleaseReview。Publisher 从 Release history 审阅已封存候选，不再给它一个没有读取权限的草稿变更入口。迁移计划按已有封存资产单独审阅，不因此执行迁移。原 `table` 编辑器在发布请求中映射回同一 `compute` 身份；选择解码、依赖追加与封存共用该身份去重，不把同一决策表同时选为两份草稿。Automation 继续是原 `flow`。

- **应用骨架**：Builder 从应用列表进入一个应用，由同一侧栏切换 Model / Behavior / Interface / Assemble / Verify，并在当前工作区按业务概念或可读分类选择资产；完整业务概念仍在概念编辑面统一组织。动作依据原声明的目标对象折叠到对象下，不从名称猜归属；无法关联的动作仍可访问。搜索限当前工作区并展开命中项，当前资产所在组自动展开，手动折叠仍可用。已删除应用导航、ProjectHome 和编辑器上下文条中重复的五区入口；ProjectHome 不再复制主资产树，业务概念编辑面保留自己的选择控件。未选应用时仅主区域列应用。同一应用的导航只更新一个总览页签，资产编辑器各保留自己的页签与输入；旧布局中的重复总览由原布局读取合并。Shell 保留当前应用标题，Model 的对象总览按应用成员收窄。
- **业务概念**：`Application.concepts` 是随应用定义和封存候选保存的导航元数据，每组稳定 ID、标题和原 `AssetRef`，最多 100 组、1000 个分组引用。可命名、重命名、排序、移动资产；未分组资产在侧栏按工作区内的业务类别归组，概念编辑面保留完整成员。分组不进入 `Application.Dependencies`，不增加权限，不改资源定义。移除成员后可保留历史分组引用，当前树只显示实际成员；删除分组返回默认归组。
- **上下文与跳转**：应用中的业务测试计划、决策表发布审阅与共享观测查看按原完整资产引用定位并返回；资源打开统一走 `assetRoute`，新建资源的迟到关联不抢走已切换文档。原编辑器页签切换保留局部草稿；共享定义与页面预览也由原 Build 上下文包裹。资产树与编辑器返回栏共用 `studioContext` 识别原资产、引用与工作区，已删除两份独立识别；记录 ID 同时按原编辑器类型判断，页面预览及动作引用保持一致。应用内工作区跳转携带应用与选中资产，跨应用的类型菜单明确不带应用筛选，原 Verify 内的应用筛选不变。对象可到动作/状态/约束/集合/样本；跨资产的“使用 / 使用处”只读取已发布 `Definition.requires`。未发布草稿的依赖与规则/页面诊断继续由原发布 owner 在候选审阅时计算，浏览器不扫描定义拼第二份依赖图。字段与关系的选择仍由原模型/行为 Inspector 提供。
- **应用轨迹**：空白应用、新建资产、添加已有/共享资产和页面模板继续使用原创建/成员编辑动作。已有资源同时提供可读草稿与已发布的非导航资源，不再限于外部对象；完整 `AssetRef` 的成员不会因没有本地编辑器而消失。无草稿的动作、函数、流程等进入同一只读详情，显示原名称、归属、版本、声明能力与依赖，返回和依赖跳转保留应用上下文；不可读或失效的引用明确提示，不提供无法创建该种类的伪编辑入口。Overview 的成员、缺失与未发布数量来自原记录/定义；Verify 嵌入原 ReleaseReview、迁移工作台与 ADR-0046 的版本/运行/恢复投影，只有共享资源的应用也按应用根创建联合候选。引用不复制定义、不转移归属、不增加权限。候选按应用根从封存字节筛选，筛选在分页前执行；`activeId` 保留原租户激活指针语义。引导、模板与发布面首次打开后保持挂载，隐藏时停止其可见读取。资产种类较多时，原实时读取客户端按服务器登记的条数与字节限制分组订阅，避免发布面增加一种资产便令整个工作区读取失败。
- **可选引导**：业务意图写入原应用 description；模型建议用原 `useNewRecord` / GeneratedForm 的初始值打开原表单，行为建议和页面建议跳到原编辑器/模板。所有步骤可自由进入或跳过。没有新生成定义格式、独立引导进度或发布路径；空项目首先呈现该业务任务入口，可直接跳过；可选择已有业务对象继续状态/操作设计，并进入原数据装配、页面和验证。当前是确定性的构建引导，不宣称已实现开放式 AI 模型/规则生成。
- **唯一入口与菜单**：顶栏切换大应用，左侧显示当前应用菜单，中央保留原工作区，Inspector 按需打开，不增加永久的左侧应用栏。主功能直接可见，每层按语义组织约 4±1（3–5）项，已有功能少的应用不补造页面；详情、记录动作与应用资源树保留上下文入口。顶栏与门户展示 Business applications、Knowledge and data、Build and intelligence、Run and manage 四类，保留原 `category` 与后端身份；运行与管理包括 My work、Runs、Control Panel、Host Console。My work 统一待办、申请、通知、发件箱，通知 Rail 是同一原页面的快捷方式；Home、门户与搜索仍由 Shell 共享。
- **功能归属与棕地**：Builder 的直接菜单只管 Applications、Ontology、Logic、Verify 与 Releases；Functions 在 Logic 下组合原 AI 函数、代码函数与决策表。连接、来源、处理、观测和 Lineage 只归 Data Connection；Agent 定义从 Agents 的 Design 进入，与原运行、记忆、评测及获权 Assistant 同属 Agents。AI 管体验、模型配置与用量，Enterprise 独立，Master data 管共享 core 资料与 Object Explorer，无 core 角色但有可读实体的成员只以 Explorer 为主页，不开放受限 core 记录；Knowledge 归知识与数据；Control Panel、Runs、Host Console 分别保留治理设置、运行与宿主管理，Asset Library 是唯一开发参考入口。多包贡献合并到同一大应用，不增加第二个同名入口；完整菜单与原路由见 [Apps](../Apps.md)。应用五工作区与业务概念树继续组织当前应用资源，跨应用功能按唯一归属进入同一原列表和编辑器。旧 `resourceGroups` 不恢复，不新增资源目录；Integrator 使用 Data Connection，Publisher 使用 Builder 原发布入口。编辑器 URL、完整资产身份、原权限、历史缺省 concepts、旧发布字节与日志保留，两宿主更新保留原数据卷。
- **入口与打开方式**：从所属大应用可直接查找原对象类型、动作类型、关系、共享属性、查询、集成、模块页面、流程、函数和发布；这些入口不要求先有应用成员关系，连接与 Agent 编辑器不再在 Builder 重复列出。Automation 创建/添加到应用时仍是同一 `flow` 引用，按原记录的 `kind` 打开对应编辑器，不新建 AssetKind。Decision table 作为原 `compute` 资产，Alert 作为 `alert` 资产进入应用成员与同一发布候选；保存草稿不会替换运行版本，复制、升级和回退携带完整规则。普通 `useOpenRecord` 使用原 Sheet 与获权 RecordPage 只读查看；审批、工作任务、流程及智能体运行进入原处理页签，显式快速查看仍可使用；收件箱处理与“打开记录”进入原正式页签，`beside` 保留为显式比较。侧栏不增加 Dock 页签、不改变原任务 URL；关闭后原输入保留。异步菜单首次就绪可见，手动折叠在同应用刷新后保留，手机沿原抽屉操作。
- **对象编辑**：删除重复的字段/状态/动作/角色结构树，主区域列表与流程图负责选择，原 Inspector 负责编辑；概览中的四项数量可直接进入对应任务。配置页签统一复用原 ContentTabs，保留已访问面板，支持方向键/Home/End，窄屏换行。对象属性表、权限表与应用角色矩阵统一使用公共 DataTable，选择/行内控件仍写原对象草稿，删除三处手写表格及两项文件豁免。字段创建、状态定义、动作与权限等原入口保留，生命周期面补明确的新增状态按钮；原 URL、草稿 owner、保存和发布方式不变。
- **门户**：普通成员的控制面板保留账户入口，开发者资产库工作区入口仅向构建者与管理员显示；公开参考内容不改变。租户构建应用的 description 进入原应用卡片与搜索。Operations / Build / Admin 现在实际筛选门户类别；仅重排类别的 Rail `Workspaces` 控件、公共参数和示例已删除，旧门户 URL 继续解析。此处取代 ADR-0018 §3.1 的三种工作区投影，不产生三套 Shell 或新的权限模式。
- **验证方法**：Go 定义检查沿 `make check`、`make test-go PKG='./platform ./apps/build'` 及根包 `TestApplicationStudio|TestLanguages|TestAPIContract|TestJointDraft`。公共交互修正通过 `make check-web`、`Workspace.test.tsx` 的文档切换、输入保留与迟到保存导航检查，以及 `workspaces` / `application-studio` 两条浏览器路线：引导创建与手工定义等价、对象状态动作、五区切换保留草稿且只有一个应用总览页签、业务分组与联合候选激活、普通成员只读查看→正式记录。`application-authoring` 另从空白应用完成两对象、引用字段、动作参数、草稿模板和一次联合发布，保存后续新字段、页面绑定与属性变量并核对原发布字节不变；`business-transaction` 保留原事务、审批与外部请求行为。关系首次联合交付、错误引用与约束由 `TestJointDraftsDeliverNewObjectsAndRelationship` 检查。草稿动作描述、普通成员拒绝、手动/定时/状态触发流程、未选择草稿拒绝及页面规则联合发布由 `build_authoring_test.go` 与 `TestPageDraftRulesUseSavedModelsWithoutPublishingThem` 检查；原流程版本恢复、查询固定版本和应用试跑测试继续通过。桌面与窄屏已观察；不外推为真实构建者体验或楼宇供暖客户交付通过。
