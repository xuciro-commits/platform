# ADR-0044 — 一个授权引擎：四层判定合成一个决定

<a id="adr-0044"></a>

状态：已接受（2026-10-12，负责人指令，ADR-0038 B 块第三份）· 修订 ADR-0027 的分层判定口径、扩展 ADR-0009 的派生闭包 · 合并 ADR-0044 的对象动作/访问控制及 ADR-0044 的角色与组织范围决定 · 不实现 ReBAC `related` 谓词（维持 ADR-0027 §0 的既有边界）

## 0. 意图

动作、行范围、字段、派生来源和标记共同构成一次授权决定。新读取、事务步骤、集合或导出复用相同顺序，避免某一入口只检查角色而漏掉记录与来源权限。授权声明属于原对象，管理员授予角色；应用分组与发布不授予访问权。

**判据**：任意一次平台操作（读一条、读一个集合、执行一个事务、导出、跨应用请求）的授权结果是**一个决定**，有唯一定义、唯一定序、可复现、可审计。

## 1. 决定

### D0 对象动作与权限声明

对象声明状态、动作的可用状态、类型化输入及执行角色；有动作的对象必须声明状态。状态提供初始值和只读 `state`，动作编译到原 `platform.Lifecycle.Transition`；规则与赋值归 ADR-0040，实际业务写入归 ADR-0039 的唯一事务实现。记录详情、页面、工作区和 Agent 使用同一动作目录，不增加租户动作运行时，也不重新执行接受后的规则。

`Access` 按 `build` 应用的角色声明读取范围及创建/编辑/归档资格；`Action.Roles` 限定业务动作，字段 `Read` / `Write` 编译成原字段权限。未配置 Access 的旧对象保留原默认声明，显式配置的对象不让未命名角色取得权限。`builder` 是原有构建资格，不绕过显式 deny、来源和标记。角色由管理员授予，成员的直接、团队和项目授予共同参与判定，不再按每应用一个角色解释权限。

`own` 默认使用 `Scope.Owner = "created"`，范围外记录的读取和动作都返回 NOT_FOUND，避免暴露记录存在。`none` 隐藏类型和记录；不能给无读取资格的角色配置对象写入，也不能授予字段写入却不授予该字段读取。

动作审批只声明等待/拒绝状态及有序角色层级，允许要求该层全部审批人同意；work 仍是审批、任务和通知的唯一归属。发布检查等待动作起始状态、独立等待状态、有效拒绝状态与能读完整对象的审批角色；发起时没有实际审批人则拒绝。等待期间不执行业务写入，放行后按申请人当前权限执行同一事务；业务审批人不需要构建或 work 管理角色。基于组织单元的审批人选择不是此动作声明的当前支持项。

### D0.1 角色设计与组织范围

`Access.read` 使用 `all | below | unit | own | none`，编译到记录 owner 的既有 Scope。`Object.scope = {owner, unit, structure}` 指定所有者、组织单元字段及下级遍历结构；owner 为空沿用创建人，owner/unit 接受文本或引用字段，unit 保存组织单元身份。声明 unit/below 却缺少合法范围字段时发布拒绝，不新增记录过滤器。

应用设计台的 Roles 矩阵展示对象声明的角色及每对象的读取、创建、编辑和归档权限，修改只提交原 `build.object.edit` 草稿；对象权限面继续负责字段权限与范围字段，动作执行角色仍在动作编辑器配置。矩阵不提供第二套授予记录或授权规则。委派、标记与审计采用各自现行 owner，不把原早期延期条目恢复成新待办。

### D1 一个决定类型

```go
// 一次授权判定的完整输入与输出。
type AuthzRequest struct {
    Principal   string        // 主体（含 agent / service 主体，沿 ADR-0027）
    Tenant      string
    Kind        string        // read | write | create | archive | action | derive | export | protocol
    Type        string        // 对象类型
    Record      string        // 记录 ID（集合判定时逐元素）
    Fields      []string      // 涉及的字段（读/写）
    Action      string        // 动作名（Kind=action）
    From        string        // 派生/协议：来源链（见 D4）
}

type AuthzDecision struct {
    Allowed   bool
    Reason    string          // 可读原因（英文 + zh-CN）
    Layers    []AuthzLayer    // 每一层的判定与依据，供审计与前端解释
    Withheld  []string        // 被遮蔽的字段
}
```

`Layers` 是**必须**的：用户问"我为什么看不到这条"，答案在决定里，不靠事后猜。

### D2 唯一定序

判定顺序**固定**，且每一层只能**收窄**，不能放宽前一层：

```
1. 租户隔离      跨租户一律拒绝
2. 主体有效性    主体存在、未撤权、未被停用（ADR-0027 的撤销语义）
3. 显式 deny     策略拒绝优先于一切允许
4. 动作/动词     该主体是否有权执行 Kind（RBAC）
5. 行范围        Scope.Levels/Unit/Structure/Owner
6. 字段          read/write 标签（ADR-0038）
7. 派生闭包      全部来源可读才可读
8. 标记          Markings 与分级随血缘传播（ADR-0025）
9. allow 策略    最后才是允许
```

`authz.Decide` 按同一定序合成这九层；允许策略只能补足动词资格，不能放宽其他层。

### D3 集合与事务：一次判定，逐元素结果

- 一个集合的读取产生**一个决定外壳** + 每个元素的判定结果。元素不可见不产生 `Allowed=false` 的失败，而是被过滤掉；`count` 只计可见元素，并提供"部分不可见"标记（ADR-0043 D5）。
- 一个事务（ADR-0039）的每一步都要过判定：**任一步不允许则整个事务拒绝**（与约束失败同一条路径），Layers 里指出是哪一步哪一层。事务的判定在**私有上下文**中做（沿 ADR-0037 §3.2 的"审批预检使用只读声明及私有 fork/savepoint，不写共享状态"）。

### D4 派生闭包是授权的一部分，不是事后修补

派生字段写入时必须声明来源，读取时按第 7 层重新判定，因为角色和行可见性会变化。来源字段须叠加其所属记录的行范围，记录不可见时字段同样不可读。

自由文本（AI 生成、评论、备注）须声明来源类型；在派生上下文中，未声明来源的文本一律遮蔽，并在构建时提示。生成文本还须有具体记录出处。原始记录读取保留其权威数据，派生投影不能用复制文本保留已经撤销的权限。

### D5 递归与反向引用的边界

ADR-0043 D4 决定反向引用必须**声明**。本 ADR 明确：**不实现 ReBAC `related` 谓词**（ADR-0027 §0 的既有决定维持），因为任意深度关系遍历会让"派生授权完全闭包"（Platform §10.6）无法证明。声明的反向引用 + 有界深度（16 段）覆盖实际业务需要。

### D6 判定的记录与不可重放

- 接受结果保存**判定依据**（主体、角色、当时的定义版本、命中的层），因此审计不需要重新推导（沿 ADR-0037 §3：恢复不重新授权）。
- **恢复不重跑授权**：历史记录按当时已经确立的事实恢复。
- 撤权后新操作被拒；历史事实保留，读取历史仍按当前权限收窄，不重新授权或改变原接受结果。

## 2. 不做

- **不做第二套权限引擎**，不引入 OPA/Cedar 之类的策略语言（ADR-0027 已拒绝策略表达式）。
- **不做 ReBAC**（见 D5）。
- **不做"管理员绕过"**：运维动作（记录迁移、修复）走 ADR-0044 之外的显式管理路径并留痕，不通过放宽判定实现。
- **不做前端权限判断**：前端只显示后端决定的结果（今天已有此原则，ADR-0057）；判定结果里的 `Layers` 是给用户解释用的，不是给前端自己算的。

## 3. 后果

- 读取与写入入口使用同一个决定点；九类入口的覆盖范围与新增绕过检查见 As built。
- `narrow.go`、`records.go` 的可见性函数、`transfer.go` 的标记检查从"分散实现"变为"引擎的层"，实现可以留在原地，但**入口与顺序统一**。
- 前端"为什么我看不到"从 Cannot-see 的猜测变为可显示的解释（`Layers`）。
- 性能：集合判定逐元素过一次引擎，需要缓存（每次请求内的判定缓存，键为主体+类型+层+定义版本）。**缓存不得跨主体复用**。

## 4. 验收

1. 九类入口（Submit、Input、审批/协议、订阅/作业、外部应答、Agent 步骤、模型计量、Compute/来源、发布/组合/宿主管理）各有一个越权用例，全部在同一个决定点被拒，错误码与原因一致。
2. 定序：构造"第 5 层不允许但第 9 层允许"的场景，结果必须是拒绝；调换层级即测试失败（用一条断言锁住顺序）。
3. 集合：含不可见元素的集合，`count` 不泄漏、`all` 不默认通过、`Layers` 可解释。
4. 派生：记录不可见时其字段不可读；未声明来源的自由文本字段在派生读取里被遮蔽（含既有 AI/评论字段的行为变化用例）。
5. 撤权：撤权后新操作被拒、历史仍可读、恢复不重跑授权。
6. 反例：跨租户、未知 Kind、`related` 谓词被请求 → 明确拒绝。

测试归宿主 platform 包与 authz 包；`docs/Testing.md` 增"授权判定"手测行。

## As built

`platform.AuthzRequest`、`AuthzDecision`、`AuthzLayer` 已由应用 API 公开。决定直接复用 `authz.Verdict` 的 `allow` 字段，避免与既有解释 API 同时维护 `allowed`/`allow` 两种结果。`authz.Decide` 固定执行九层；允许策略只能补足动词授权，不能恢复被行范围、字段、出处或标记收窄的权限。旧日志解码保留原恢复分支，新接受结果恢复不调用授权引擎。

宿主事实解析归 `authorization_decision.go`：原 `Scope` 谓词仍由记录 owner 提供，记录可见性、来源字段与 CSV 标记检查经过同一决定点。`Catalog.DecideSubmission` 将普通 create/edit 的输入字段和事务逐步字段带入决定；不可变字段的结构错误仍归输入校验，原生类型化动作保留显式接收盲写输入的资格。命名读取、连接器入口、作业/订阅入口、效果回调和模型调用接入引擎。连接器的声明提供受控输入资格，实际数据类别/游标仍由 K8 校验；宿主服务以声明 owner 的范围执行，经过显式 deny，保留其与人的单位范围不同的既有语义。当前目录与过期角色快照取交集；有目录的租户拒绝不存在的主体，应用服务与内置 agent 由注册 owner 声明，维护索引使用单独的宿主维护主体。无身份目录的编译期 owner 测试不提供认证 HTTP 入口。

Compute 的输入准备、接受前计划、执行前检查、锁外输入读取后复核和结果读取共用 `authorizeCapability`；函数调用与会话历史也使用同一来源判定和全部有效角色。定义指纹与来源授权随私有接受结果保存。发布/预览/仿真路由不再维护第二套角色条件；宿主路由把部署显式授予的 `host-admin` 作为独立管理资格送入同一引擎，HTTP 管理结果保存真实 host 主体与层级。宿主管理资格不转成客户数据角色，支援与迁移仍沿原受控成员/会话路径。

声明记录集返回 `authorization`：外层决定、可见元素决定与一份匿名的过滤原因。过滤结果不返回隐藏记录的 ID 或数量；原可见 count、部分不可见与 `all` 的严格语义保留。来源遍历有 16 段边界、循环拒绝和请求内缓存；公式/集合保存的自身记录见证只复用已经判定的所属行，不能使外部来源取得权限。

`FieldInfo.SourceType` 与原生 `source` 标签、Build 字段配置提供 `record` / `user-input` / `external-input` / `generated`。命名/派生读取遮蔽未声明的自由文本；生成文本还须有记录出处。普通原始记录读取保留其权威数据。任务 title/body 声明来自任务 ref，并提供 `withheld`；审批引用/动作等固有元数据与用户拒绝备注显式声明类型。旧发布与已保存记录不重写。

同一投影覆盖非实体结构、指针、接口、命名切片、数组、map、字节和 `json.RawMessage`。非实体字段复用 `source`，`from` 指向保存出处的 Go 字段，可附 `#字段`；实际来源仍交给同一授权引擎检查行与字段。任意 map 的未声明键/值、未声明文本与不透明序列化结果关闭；JSON 解码复用有界、拒绝重复键且保留精确整数的 `DecodeValue`。指针循环与过深容器停止投影，不改原值。数组不再沿旧路径原样返回。

`Manifest.ReadSources` 只声明 owner 自己的配置、身份、定义与运行元数据等原始非实体结果，组合期拒绝未知来源类型及未注册的读取名；它不能扩大嵌入实体的行/字段权限，也不能盖过字段的显式派生来源。酒店/生产协议投影、输入选项和账簿/库存合计携带具体来源，后续 Agent 读取沿 `refsIn` 保留可见字段出处。成员协议读取复用 `Tenant.Read`，删除旧单角色短路。控制台任务/效果/通知的未声明正文与诊断被遮蔽，并提供 `withheld`。缺少出处的实体整字段、列表元素及合并来源只在派生上下文中收窄；原始 Flow 状态保留，声明原始输入的字段保留，有来源时仍逐源检查。引用元素由自己的来源逐个过滤，不因另一个不可见引用而清掉可见引用。

record / batch / input / work / effect / usage / host 接受结果保存可选 `authorizations`，包含原请求、有效角色、定义指纹与命中层。指纹包含字段、派生声明、遮蔽字段和生效策略，修改出处或策略不会继续使用同一依据标识。解码只检验身份、层级顺序和结果一致性；旧结果没有该字段仍可恢复。私有 savepoint 克隆依据；被拒的子尝试随其私有状态丢弃。原 ledger 的拒绝原因不再重新求值一次。治理页支持对象/记录/字段解释并展示后端层级，英中翻译随现有 API 生成。

具名读取中的实体记录逐行判定后投影；直接返回一批 owner 记录不能跳过行范围。Agent run 和 memory 的原受益人声明为参与者，保留其既有读取资格；记录详情的评论列表属于派生投影，未声明自由文本被遮蔽，原始评论记录及历史字节保留。隔离仿真的配置主体在沙箱身份 owner 里显式登记，不靠虚构成员取得管理资格。`check-boundaries` 的 AST 检查经 `scripts/escapes.sh` 拦截新增的成员存储投影；namespace 内部存储、私有写入和授权事实解析仍是各自 owner。

`TestAuthorizationNineEntryFamilies` 覆盖 Submit、Input、协议、作业、效果回调、Agent 步骤、模型计量、Compute 和发布路由的显式拒绝；`TestHostHTTPRetainsItsExplicitAuthorityAndRecoversWithoutAuthorization` 覆盖宿主角色隔离、HTTP 管理接受依据和纯恢复。成员/来源与集合的反例另归 `authorization_decision_test.go` 和记录集测试。

能力目录、当前/保留版本详情与 AI 调用结果读取共用原 `authorizeCapability`，不再各自按主角色字符串决定权限。发现投影与保留版本的来源字段都收窄到当前目录仍保留的角色与原 owner 策略；计算详情直接使用原定义投影，不再重复解析一份当前定义。AI 结果保留原调用人/构建者的读取范围，并由同一决定检查函数角色、显式拒绝及来源。`TestCapabilityDiscoveryAndResultsUseCurrentOwnerAuthorization` 检查非主角色授予、当前与保留函数、原调用结果、deny、函数角色撤销，以及保留函数角色但撤销来源字段角色时旧成员快照均被拒绝；历史版本字节与接受结果不改。

非实体/JSON、缺少出处、撤权、原始声明不能扩大嵌入权限以及原值不变的反例归 `authorization_projection_test.go`；定义依据变化归 `TestAuthorizationDefinitionChangesWithItsSourceContractAndPolicies`。实现边界仍是声明的来源与有界遍历，不实现 `related`、第二套授权语言或跨主体缓存。原生 owner 须如实声明自己复制的字段；AST 守门与反例不构成对任意新 Go 业务算法的数学证明。
