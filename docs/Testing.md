# 测试

怎么通过应用测试平台，以及每个场景怎么走。环境（启动、地址、账号、接入外部系统要填什么）在 [deploy/local/README.md](../deploy/local/README.md)；账号按"一个人一份职责"分好了，测权限差别时换人登录，要同时看两个人就用一个普通窗口加一个无痕窗口。

## 测的是什么

**应用是探针，不是产品**（Intent.md，AGENTS.md 规则 12）。现阶段我们用应用来打磨平台，不是用平台来打磨应用；等平台稳定了，再反过来用平台把应用做深。所以测试的对象是下面"平台能力表"里的每一项能力和它给出的保证；制造、财务、酒店、请假这些业务只是载体，让能力在接近真实的情况下被用到。

发现问题时按顺序问两句：

1. **换一个应用，这个问题还会不会出现？** 会，就是平台的问题：记进 [WorkQueue.md](WorkQueue.md)，马上在平台里修（修的是表里"失败时修哪里"那一栏的主人），不在出问题的应用里打补丁。
2. **不会的话：要证明或推翻某个平台保证，是否必须有这层业务深度？** 不是，就记进工作队列"应用深度"那一项，这一轮不做（比如 SFC 数量怎么拆、生产成本怎么结转、赢单后怎么退房）。

另一类问题是**能力逃逸**（AGENTS.md 规则 11）：应用自己做了一份平台已经有、或者本该由平台拥有的能力（自己画表格和面板、自己管签名和审批、自己做时间线）。它往往不会让测试失败，却会让同一件事有两种行为。`scripts/escapes.sh` 列出已知的逃逸并阻止新增；测试中看到"这个应用的这块和别的应用长得不一样、做法不一样"，就是线索，记下来。

## 规则

1. **按能力测，由场景承载，一项能力只测一次。** 平台能力表是主表：每项能力写明平台保证、在哪个场景的哪一步测、失败时修哪里。场景是一段业务，路上自然经过多项能力；场景里每一步开头的 `[C…]` 标出它测的能力。
2. **优先级**：P0 每轮都要走完，阻断发布；P1 能力做完或改动过时走；P2 暂缓，条件具备（外部系统、向量模型、采集器）再走。
3. **每个场景都在界面上走通过，才写进本文。** 演练脚本（`deploy/local/rehearse.sh`）和自动测试直接调接口，界面上走不通的地方它们发现不了。
4. **每个应用先能自己干**（ADR-0025 D3）：涉及外部系统的步骤，都有一步说明不接外部系统时怎么走。
5. **失败也是场景的一部分**：被拒绝时写明看到的原因；超时、没人处理时，谁在哪里看到了什么。
6. 标【自动】的步骤已写成浏览器测试（`web/e2e`，Playwright），`scripts/verify.sh web` 和 CI 每次都会跑；其余靠人走。
7. 业务细节只写到能力需要的程度：步骤里出现的数量、工序、科目只是数据，不是被测对象。

## P0 场景（每轮必测）

### S1 制造：生产订单跨两个应用走到确认，失败时交给人和智能体（制造业主机）

载体：ERP 下达生产订单，MES 执行后向 ERP 报工。测的是状态启动的流程、跨应用答复和原因、失败后的任务、智能体治理和调用链。账号：`sup@plant.test`（主管，同时是 ERP 主管会计）、`op1@plant.test`（操作员）。先在 设置 → AI 添加模型并在 应用设置 → 智能体 选"智能体使用的模型"（没有模型也能走，智能体那一步会停下交给人）。

1. [C1] **ERP 下达生产订单**：ERP → 生产订单 → 新建 P-100、数量 2，打开点"下达"，得到 `MO/2026/00001`。
2. [C2 C3] **MES 按计划订单下达车间订单**：MES → 车间订单 → 下达：P-100、数量 2，计划订单选刚才那张。故意超过计划数量或选草稿订单：被拒，提示写明原因。
3. **车间执行**：`op1` 打开 SFC，逐道工序开工、完工直到做完（这一步只是把订单推到"已完成"，工序细节不是被测对象）。
4. [C7 C8] **状态启动流程、跨应用确认**：订单变"已完成"时，"向 ERP 报工"流程自动启动（MES 没有发任何事件）；ERP 答复后车间订单显示凭证号 `MJ/…`。
5. [C3 C6 C10] **被拒后交给人和智能体**：再下达一张计划订单选"无"的车间订单并做完。ERP 拒绝（没有计划订单），原因传回 MES，主管收到通知。纠正智能体去找对得上的计划订单：
   - 找到时，车间订单页上方的"等你处理"和收件箱里有"Resend … against MO-…?"，点 resend 就按它找的重发，点 correct myself 自己改；
   - 找不到时，"等你处理"里是"Correct and resend"：在车间订单页点"Resend confirmation to the ERP"，表单里直接从 ERP 的计划订单下拉中选一张（选项来自 MES 的读取，平台的通用表单，MES 不再自己做对话框）。
6. [C12] **看清楚发生了什么**：车间订单记录页的"流程"列出这条确认流程；打开流程实例，流程图标出走过和停着的步骤，下面的"调用链"画出 车间订单 → 流程 → 智能体运行；打开智能体运行，看每一步用了什么工具、理由和 token。
7. [C10] **助手只起草**：在车间订单上"问助手"，让它纠正并重发：它只起草，你确认后才提交，提交算你的决定。以助手自己的身份直接提交（`mes-agent` 命令行，演练里自动做）会被 ERP 拒绝，因为它在 ERP 没有角色。
8. [C22] **不接 ERP 也能干**【自动】：MES 不接 ERP 时照样能下达和执行车间订单（ADR-0025 D3）。

### S2 ERP：凭证和采购（制造业主机）

载体：会计凭证和采购订单。测的是拒绝原因、连续编号、按状态的动作、按数据分支的审批和角色。账号：`accountant@plant.test`（会计）、`buyer@plant.test`（采购员）、`sup@plant.test`（主管会计，审批大额采购）。

1. [C3] **拒绝和原因**：`accountant` 新建凭证，借贷不平时过账：被拒，写明"借方合计 … 与贷方合计 … 不相等"，也不占编号。（凭证还有别的校验，道理相同，测一种即可。）
2. [C2 C13] **过账、编号、冲销**：改对后过账，得到 `GJ/2026/00001`；过账后不能再改，点"冲销"生成冲销凭证，编号接着排；记录页"历史"里明细行的改动逐行显示。关掉本月期间再过账：被拒，写明日期不在开启的期间内。
3. [C5 C4] **按数据分支的审批和角色**：`buyer` 新建采购订单点"下单"：合计不到审批限额时直接下单；达到 10 000 时待审批，`sup` 在收件箱批准后才下单，订单页"审批"一栏画出审批链（限额在 应用设置 → ERP 里改）。换一个没有采购员角色的人下单：被拒，提示写明是哪个角色不能下单。

### S3 请假：审批、委托和个人数据（酒店业主机）

载体：请假。测的是审批的全部形态、实时刷新、工作日历和个人数据。账号：`sales@hotel.test`（员工）、`manager@hotel.test`（经理，两级审批人）、`deputy@hotel.test`（被委托人）、`hr@hotel.test`（人事）。

1. [C5] **提交**【自动】：`sales` 新建 3 天年假，点"提交审批"：变"待审批"，"我的申请"里有，请假页"审批"一栏画出 提交人 → 经理 → 结果。
2. [C5 C17] **驳回和再提交**【自动】：`manager` 在收件箱驳回并写理由：`sales` 收到带理由的通知，页面写着谁驳回、为什么。`sales` 再提交，`manager` 批准，`sales` 开着的页面自己刷新。
3. [C5] **待审批的约束**：待审批期间不能取消、不能重复提交；在"我的申请"里撤回后回到草稿。
4. [C5 C23] **两级审批和工作日**：7 天的请假要两级；第二级驳回时，第一级已批准的人也收到通知。审批期限按提交人所在单位的日历算 2 个工作日（办公室跳过周末和国庆，前台每天都算），收件箱里能看到到期时间。
5. [C5] **委托代批**：`manager` 用"委托审批"（`work.delegation.add`）把某几天交给 `deputy-1`；这几天里提交的请假进 `deputy` 的收件箱，批准后"代批"一栏写着 `deputy-1 代 manager-1`。
6. [C4] **个人数据**：`sales` 起草病假并填"医疗原因"。`hr` 能看到；`manager` 和 `sales` 自己都看不到，搜索、筛选、分组也够不着。管理员在 设置 → 审计 的"个人数据的读取"里看到 `hr-1` 什么时候看了哪条的哪个字段。（填写人本人能否看，待决定，见工作队列 #128。）

### S4 客户、商机和住宿（酒店业主机）

载体：CRM 商机向酒店订团队房。测的是声明即得、字段权限、评论、导入导出、实时刷新，以及协议的部分成功、补偿、换提供方和无提供方。账号：`sales@hotel.test`（销售）、`manager@hotel.test`（销售经理、管理员）。

1. [C1] **一个列表、一种记录页**【自动】：CRM → 客户，一个列表，右上角"新建客户"；打开客户是平台的记录页：字段、文件、评论、历史，下面列出它的商机（CRM 不再有自己的客户页）。
2. [C1 C4] **选择器只列能看的**【自动】：新建商机时客户从下拉里选，只列你能看到的。
3. [C15] **评论、提及、关注**【自动】：在商机评论里写 `@manager-1 帮我看一下`，`manager` 收到通知；评论后你自动关注，旁边写着"你已关注"和"取消关注"按钮。
4. [C4 C16] **字段权限跟到导出**【自动】：`manager` 在商机上填"预期毛利"，`sales` 看不到也改不了；`sales` 导出 CSV，文件里没有这一列。
5. [C1 C8] **保留 → 确认**【自动】：商机上"规划团队住宿"：1 间 suite。房块"已保留"；商机页下方"预订（1，链接）"列出酒店那边的这间房（别的应用的记录，平台按链接列出），点开是酒店的预订页。点"赢单"：酒店确认，房块"已确认"。日期填错（离店早于到达、保留期不早于到达）时被拒，写明哪里不对。
6. [C3 C8] **部分成功和补偿**：另一个商机规划同样日期的 suite：直接被拒，提示写明没有空的 suite（酒店的原因原样传回 CRM）；改成 2 间：第一间保留、第二间被拒，房块"失败"，已保留的那间自动释放，住宿表里写着酒店给的原因。
7. [C8] **释放**：输单时已保留的房间被释放；截止日过了没赢单，酒店自己释放，房块变"已释放"。
8. [C8] **换提供方**：管理员在 设置 → 协议 把住宿协议从 pms 换到 memstay：之前保留的，确认和释放仍发给原来的酒店；新订的发给 memstay；商机页下方两家的住宿各列一组。酒店自己取消一间时，商机页的"动态"里出现"Booking canceled"。
9. [C22 C8] **没有提供方**：规划后房间停在"已请求"，由人点"记录提供方的答复"逐间记下。
10. [C16] **导入**【自动】：客户列表"导入 CSV"：先预览每行新建还是修改、哪行有错，确认后导入；同一个文件再导一次不会重复。
11. [C17] **别的窗口改了会自己刷新**【自动】：另一个身份改同一个商机，原来的页面自己更新。

## P1 场景

### S5 客服、智能体和 AI 运营（酒店业主机）

载体：客服工单和分诊智能体。测的是智能体治理的全部、对外效果被扣住、应用向模型提问、文件权限和调用链。账号：`desk@hotel.test`（客服）、`manager@hotel.test`（客服 lead、管理员）。准备：设置 → AI 添加提供方、启用一个支持工具调用的模型；应用设置 → 智能体 选"智能体使用的模型"，应用设置 → AI 选"应用使用的模型"；设置 → 集成 添加接收地址并勾选 `csm/reply`（本地用 `http://webhook-sink:8080/hook`，允许内部地址）。

1. [C11 C13] **开工单和摘要**：`desk` 开一张"Wifi keeps dropping"（客户账号 `ACME`，先在 CRM 建好）：编号 `CS-2026-0001`，几秒后自动有一句"摘要"。
2. [C9 C10] **被扣住的回复**：分诊智能体查客户、查知识、分类并回复；它写的邮件被扣住，`manager` 的通知里有"批准…回复"，到 集成 批准后才发出（`http://127.0.0.1:8497/received` 能看到）。丢弃的话，工单回到"已分诊"，写着谁丢弃的，客服收到"回复未发出"。
3. [C10] **规则拦住智能体**：开一张"I want a refund"：回复里承诺退款会被规则拒绝，工单留给人；模型不可用时工单直接进 `desk` 的收件箱。
4. [C14] **文件跟着记录权限**：在工单上添加一张截图：能看这张工单的人能下载，看不到的人下载不到；在 知识 → 文档 新建"House rules"并挂上 Markdown 文件，分诊时会引用它；⌘K 输入文件名能找到。
5. [C12] **调用链**：打开分诊运行，看每一步和理由，"调用链"画出 工单 → 服务级别流程 → 分诊运行 → 回复邮件。
6. [C10] **总览和开关**【自动】：设置 → 智能体 → 总览列出每个智能体的运行、动作、被采纳/修改/拒绝次数和费用；"暂停"后它不再处理新工单（转给客服），"恢复"后恢复。
7. [C10] **用例评估**【自动】：设置 → 评估，选 `csm.triage` 和候选模型，勾"声明的测试用例"：每个用例空跑三次，报告写着几次通过和原因。不勾时拿人评判过的运行比；没有时报告直接说明。
8. [C10] **限额和流式**：设置 → AI → 用量 → 限额给 `agent:csm.triage` 设每天 1 个 token：下一张工单它停下并写明额度用完，转给客服。Playground 里回答一个字一个字地出来。
9. [C10] **记忆**：在商机上"问助手"让它标记赢单：它起草，你修改后确认或写原因驳回；之后它提议一条记忆，可以保留或忘掉。

## 这一轮测试的问题和说明（2026-09-27）

- **"执行时被拒绝 CONFLICT"**：驳回再提交、全部批准后反而被拒，是平台缺陷（审批把请假移到"待审批"会改变它的版本，最后执行时拿的是提交时的旧版本），已修复。
- **对话框在浮动窗口后面**：平台缺陷，已修复，所有应用生效；之前"点了没反应"很可能就是对话框被挡住了。
- **采购订单页白屏（levels）**：平台缺陷，空列表被存成了 null，已在存记录的地方统一修复。下单被拒是因为当时没有采购员账号，现在有 `buyer@plant.test`，拒绝也会写明是哪个角色不够。
- **跨应用只传错误码**：平台缺陷，已修复：提供方的拒绝原因会跟着答复传回来（比如 CRM 看到"… 没有空的 suite"）。
- **审批图闪一下就不见**：流程图在节点还没量好尺寸时就去适配窗口，缩成了看不见，已修复。
- **两个"客户"**：同一个对象有两个入口，已合并成一个列表；之后（#129）CRM 自己的客户页也去掉了，客户和商机都用平台的记录页；客户分公司和个人，和 Salesforce 的 Account（含 Person Account）一样，联系人（Contact）以后需要时再加。
- **赢单后没有"确认中"**：本地酒店当场答复，所以直接变"已确认"；接外部酒店时才会看到"确认中"。赢单后客户又不来了怎么退房（赢单后取消），现在没有，已记进工作队列。
- **找不到"住宿方无法确认"**：本地酒店不会拒绝确认，这一步在自动测试里测；人工测试已从场景里拿掉。
- **取消关注**：按钮一直在评论区标题旁边，但写成"关注"像个标题，已改成写明状态加按钮。
- **⌘K 搜不到 README**：⌘K 原来只搜命令和页面，已改成同时搜记录（包括文件名）。挂在工单上的文件不会进知识库，要挂在知识文档上。
- **文件"允许谁下载"在哪配**：没有单独配置，文件跟着它所在记录的权限走。
- **评估秒结束、token 为 0**：因为还没有人评判过的运行，没有可比的；现在报告会直接说明。模型改成从下拉里选。
- **自动化页"没有排队、熔断"**：以前只在有问题时才显示，现在全部列出，没有就是 0。
- **采集器地址**：本地没有装采集器，不影响功能，见 README。
- **HR 账号、多账号**：已加 `hr`、`desk`、`deputy`（酒店）和 `buyer`、`accountant`（工厂），见 README。
