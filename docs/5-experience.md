# 5 用户体验

## 目标

让每类用户以最少的步骤完成首要任务，并且在任何一步都知道自己在哪、能做什么、为什么不能做。本层给出用户与任务、任务路径、可发现性与效率标准、文案规范与评估方法。任务路径同时是验收用例的来源（见 [7-system/verification](7-system/verification.md)）。

## 5.1 用户与任务

| 角色 | 心智 | 首要任务（当……时，我想……，以便……） | 入口 |
|---|---|---|---|
| 构建者 | “我在把业务建模成软件” | 当业务需要一个新应用时，我想从数据或空白开始建出对象、动作和页面，以便业务用户当天就能用 | Home、Files、工具应用 |
| 集成者 | “我在接通系统” | 当外部系统有新数据时，我想把它稳定地同步成数据集，以便构建者放心地建模 | Data Connection、Monitoring |
| 业务用户 | “我在处理我的工作” | 当一件事需要我处理时，我想找到相关对象并执行正确的动作，以便工作继续流转 | Notifications、Applications、Search |
| 管理员 | “我在守住边界” | 当有人加入或离开时，我想一次给对角色和标记，以便他只看到该看的 | Control Panel、Marketplace |
| 发布者 | “我在交付版本” | 当一组变更完成时，我想验证并发布为产品版本，以便安装到客户租户 | DevOps、Marketplace |

构建者优先：平台的默认视角是构建者；业务用户的体验由构建者建出的模块决定，平台只保证对象视图、动作表单与收件箱的质量。

## 5.2 任务路径

每条路径给出起点、步骤（入口 → 资源或动作）与成功标准。编号即验收用例编号。

### F1 构建者：从空租户到可用应用（黄金路径）

1. Home → “New project”，命名项目。
2. 项目 Overview → 下一步“Connect data”（可选）→ 新建源与同步 → 得到数据集。
3. 数据集 Overview → “Create object type” → 映射列到属性，选标题与主键。
4. 对象类型 Actions → “New action type”（模板：创建、修改、删除、改状态）。
5. 项目 Overview → “Open Workshop” → 从模板生成模块（对象表 + 详情 + 动作按钮）。
6. 分支控件 → “Review and save” → 保存到 main。
7. Applications 中出现该模块；业务用户角色可打开并执行动作。

成功标准：不写代码、不离开平台、每一步都从上一步的页面就地进入；一位熟悉业务的构建者 30 分钟内完成。

### F2 构建者：在分支上修改并提案

1. 分支控件 → “New branch”。
2. 修改对象类型属性与动作；工作状态自动保存到分支。
3. “Review and save” → 字段级差异 → “Propose”。
4. 审阅者在 Home 或 Notifications 打开提案 → 检查结果 → “Merge”。

成功标准：main 在合并前不受影响；审阅者不打开任何编辑器即可判断变更。

### F3 集成者：接入外部系统并保持同步

1. Data Connection → “New source” → 选连接器 → 填参数与凭据引用 → “Test connection”。
2. 源 Explorer → 选表 → “Create sync” → 目标数据集 → 计划。
3. 首次运行后数据集出现版本；失败在 Monitoring 可见并可重试。

成功标准：凭据从不明文显示；同步失败时原因指向可操作的修正。

### F4 业务用户：查找对象并执行动作

1. ⌘K 输入对象标题 → 打开对象视图。
2. 动作栏 → 动作表单 → 以动作名命名的按钮执行。
3. 对象视图的 Activity 立即显示这次编辑。

成功标准：三次交互内到达对象；不能执行的动作说明原因。

### F5 业务用户：处理工作项与审批

1. Notifications 徽标 → Inbox → 打开工作项。
2. 工作项显示关联对象与可执行动作 → 执行（批准、驳回、完成）。
3. 工作项关闭，发起人收到通知。

成功标准：从通知到完成不超过三次点击；关闭的工作项从收件箱消失。

### F6 管理员：接纳成员

1. Control Panel → Members → 邀请（邮箱）。
2. 成员页 → 业务角色、团队、标记许可。
3. Files 项目 Access → 给项目角色。

成功标准：成员首次登录即看到且只看到被授权的应用与数据。

### F7 管理员：安装与升级产品

1. Marketplace → Catalog → 产品详情 → “Install” → 目标项目、角色映射、标记映射 → 安装审阅 → 确认。
2. 有新版本时 Updates → 升级审阅（列出受影响的客户扩展）→ 确认。

成功标准：安装前看到将创建的全部资源与所需权限；升级不使客户扩展失效，或在审阅中提前指出。

### F8 发布者：发布产品版本

1. DevOps → Products → 产品 Contents（确认依赖闭包）。
2. Releases → “New candidate” → 发布审阅（差异、检查、测试计划）→ “Release”。

成功标准：版本不可变；检查与测试计划全部通过才能发布。

### F9 构建者：诊断失败

1. Home 统计块“运行失败”或 Monitoring → Runs → 失败行。
2. 运行详情：错误、输入版本、关联资源 → 打开资源修正 → “Retry”。

成功标准：从失败入口到出错资源不超过两次点击；重试保留原输入。

### F10 任何人：借助 AIP Assist

1. 在任意页面打开 AIP Assist → 用自然语言描述目的。
2. 助手读取当前上下文（受同样的权限与标记约束）→ 回答，或提议一个动作（M20 表单）。
3. 用户确认后执行；助手从不绕过动作直接写入。

成功标准：回答只含调用者可读的内容；任何写入都经用户确认的动作表单。

## 5.3 可发现性

- 任何资源都能被 Search 与 Files 找到；任何对象都能经 Search 与关系导航到达。
- 每个空状态告诉用户第一步做什么（M12）；每个资源 Overview 给出下一步（M13）。
- 能力不藏在悬停与右键里：右键菜单与 ⋯ 菜单内容一致；快捷键都在菜单和 `?` 中可见。
- 新租户首次进入：构建者看到 F1 的第一步；业务用户看到“你还没有被分配应用，联系管理员”与管理员名单。

## 5.4 效率标准

| 指标 | 目标 |
|---|---|
| 到达任何资源 | ⌘K ≤ 3 次按键 + Enter |
| 新建一个资源 | 从列表或下一步 1 次点击打开 Sheet，必填字段 ≤ 4 |
| 常用编辑 | 不打开新页面（Inspector、行内、Sheet） |
| 页面首屏 | 2 秒内可交互；列表 1 万行可滚动不卡顿 |
| 保存反馈 | 停止输入后 1 秒内显示保存状态 |

## 5.5 文案

- 语气：简洁、陈述、主动；不客套、不感叹、不用“请”。
- 按钮：动词 + 宾语（“Create object type”“创建对象类型”）；确认按钮重复标题动词。
- 错误：说发生了什么 + 怎么修（“The dataset has no primary key column. Choose one in Schema.”）。
- 术语：只用 [glossary](glossary.md) 中的词；工具应用名不翻译。
- 中文：全角标点；中英文之间不加空格的地方由排版统一处理，文案里不手工加；数字、单位、代码保持半角。
- 时间：列表用相对时间，悬停显示按成员时区与格式的绝对时间；导出用 ISO 8601。
- 键：英文原文就是翻译键；每个新字符串同时提供 `zh-CN`；动态键（`t(variable)`）必须能在字典中找到全部取值。

## 5.6 启发式检查清单

每次改动界面，对照以下十项自查；任何一项不满足即为缺陷：

1. 我在哪：页头、面包屑、侧栏高亮一致。
2. 我能做什么：主操作唯一且醒目。
3. 为什么不能：禁用与拒绝都有原因。
4. 我做了什么：保存状态与 Toast 反馈及时。
5. 能撤回吗：可撤销的不确认，不可撤销的确认写明后果。
6. 一致：同一操作在所有工具同名同位。
7. 错误预防：校验就地、即时。
8. 认出而非回忆：引用用选取，不要求输入 ID。
9. 高效：键盘可完成，批量可完成。
10. 简洁：没有原始 JSON、没有重复信息、没有装饰。

## 5.7 评估

- 黄金路径验收：F1–F10 每条一个端到端用例，随代码运行（见 7-system/verification）。
- 负责人走查：每批结束负责人在浏览器走查改动的界面，判断观感；问题进入路线图。
- 不做埋点分析，直到终局第三段有客户租户。

## 现存差距
