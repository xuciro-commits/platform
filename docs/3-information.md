# 3 信息架构

## 目标

任何资源、对象、应用和命令都能在三步内被找到，并且每样东西只有一个规范位置。用户靠“它属于哪个项目”和“它是什么类型”定位，不靠记忆菜单。

## 3.1 规则

- R1 全局导航只有左侧导航轨；导航轨之外不出现全局入口（无顶部菜单栏、无文档页签）。
- R2 层级至多四级：外壳 → 应用 → 资源 → 资源分区。视图内不再增加导航层（无重复侧栏的胶囊行，无在列表页之间切换的分段控件）。
- R3 每个资源有不可变的 RID、唯一所属项目和文件夹路径；规范 URL 由 RID 决定，与位置无关（移动资源不改 URL）。
- R4 资源在全局可被搜索；列表显示全部可见资源并带“项目”列，不按项目复制列表。
- R5 应用侧栏至多 8 个导航项，按带标题的段落分组；打开资源后侧栏切换为该资源的分区导航。
- R6 同一样东西在所有地方用同一个名字；名字取自 [glossary](glossary.md)，新名字先进术语表。
- R7 系统文案双语；资源名、对象数据等租户数据不翻译。

## 3.2 导航轨

| 位置 | 项 | 内容 |
|---|---|---|
| 上 | Home | 个人工作台：我的工作项、最近、我的项目、待我审阅的提案 |
| 上 | Search ⌘K | 统一搜索与命令（§3.8） |
| 上 | Files | 项目与文件夹 |
| 上 | Applications | 应用门户 |
| 上 | Recent | 最近打开的资源与对象 |
| 上 | Favorites | 固定的应用、资源、对象 |
| 下 | Notifications | 通知、工作项、审批请求，带未读数 |
| 下 | AIP Assist | 作用于当前页面的助手面板 |
| 下 | Help | 当前页面的帮助与快捷键 |
| 下 | Account | 外观、语言、通知摘要、租户切换、退出 |

导航轨宽 48px，深色；只显示图标，悬停显示名称。

## 3.3 应用门户

门户按用途分四组，组内按名称排序：

| 组 | 应用 |
|---|---|
| 构建 | Data Connection、Pipeline Builder、Dataset Preview、Ontology Manager、Logic、Automate、Workshop、Agent Studio |
| 分析 | Object Explorer |
| 治理 | Control Panel、DevOps、Marketplace、Data Lineage、Monitoring |
| 业务 | 已安装产品与本租户已保存到 main 的 Workshop 模块，按产品或项目分组 |

门户只列当前成员有权打开的应用；无权的应用不显示，而不是显示为禁用。

## 3.4 资源分类

| 类别 | 资源类型 | 拥有者 | 可见范围 |
|---|---|---|---|
| 容器 | 项目、文件夹 | Files | 按项目访问 |
| 数据 | 连接、数据源、监听器、回写、观测源 | Data Connection | 按项目访问 |
| 数据 | 数据集、媒体集 | Dataset Preview | 按项目访问 + 标记 |
| 数据 | 管道、调度、匹配规则 | Pipeline Builder | 按项目访问 |
| 本体 | 对象类型、共享属性、关系类型、接口、值类型、动作类型、对象类型组 | Ontology Manager | 定义全租户可发现；编辑按项目 |
| 逻辑 | 函数 | Logic | 按项目访问 |
| 逻辑 | 自动化 | Automate | 按项目访问 |
| 应用 | 模块、对象视图、模板 | Workshop | 按项目访问；保存到 main 后按使用者的业务角色 |
| 应用 | 探索、对象列表 | Object Explorer | 个人私有；可发布对象集由项目内 `build.query` 拥有 |
| AI | 智能体、检索源、评估集 | Agent Studio | 按项目访问 |
| 交付 | 产品、产品版本、测试计划 | DevOps | 按项目访问 |
| 交付 | 安装 | Marketplace | 管理员与构建者 |
| 治理 | 组织单元、成员、团队、业务角色、标记、模型、凭据 | Control Panel | 管理员 |

对象（实例）不是资源：对象没有项目，可见性由对象类型、标记与行策略决定；每个对象只有一个落点——它的对象视图。

## 3.5 标识与命名

| 标识 | 格式 | 说明 |
|---|---|---|
| RID | `ri.<service>.<tenant>.<kind>.<id>` | 不可变；用于 URL、引用、审计 |
| API 名 | 对象类型、属性、动作、函数用 `camelCase`；类型名首字母大写 | 不可变（改名即新资源）；等宽字体显示 |
| 显示名 | 自由文本 | 租户数据，不翻译 |
| 路径 | `/项目/文件夹/资源名` | 随移动变化，只用于浏览 |

界面上 RID 与 API 名用等宽 `text-2xs` 弱化色显示，从不作标题。

## 3.6 页面层级与 URL

| 层级 | URL | 页面 |
|---|---|---|
| 外壳 | `#/` | Home |
| 外壳 | `#/files`、`#/files/<项目 RID>` | Files 根、项目页 |
| 应用 | `#/<app>` | 应用首页（默认列表） |
| 应用 | `#/<app>/<列表>` | 应用内的其他列表 |
| 资源 | `#/<app>/<RID>` | 资源页 Overview |
| 分区 | `#/<app>/<RID>/<分区>` | 资源页的某个分区 |
| 对象 | `#/objects/<对象类型>/<主键>` | 对象视图 |

- 一个 URL 对应一个主视图；浏览器前进后退可用。
- 打开任何 RID 时，由拥有该类型的应用打开（Files、Search、引用链接都一样）。
- 侧窗（Inspector、`beside`）与弹窗状态不进 URL；“作为页面打开”转为规范 URL。

## 3.7 Files

- 结构：项目 → 文件夹 → 资源；不设 Space。
- Files 是外壳入口，不是工具应用；所有成员都能进入 Files，看到自己的可见项目，不需要加载构建工具包。
- Files 根与项目页是同一个入口：`#/files` 列项目，`#/files/<项目 RID>` 列该项目资源；项目工作台 `#/project/<项目 RID>` 是唯一的资源编辑入口。
- 资源只属于一个项目，可被其他项目引用；引用不改变所有者、定义与权限。
- 项目页的分区见 [4-interaction §4.4](4-interaction/README.md)。
- 已安装产品的受管项目在 Files 中带“受管”标记，内容只读。

## 3.8 Search

- ⌘K 与 Search 页共用一个输入合同与结果合同；结果分组依次为：命令、当前应用、应用、资源、对象、成员、知识；输入为空时显示最近。
- 同一查询在两个入口返回同一分组集合；各组独立截断，资源结果再多也不挤掉对象或其他分组。
- 前缀限定范围：`>` 命令，`@` 成员，`#` 项目，`:` 对象类型。
- 资源结果显示类型图标、显示名、项目路径；对象结果显示对象类型与标题属性。
- 资源结果先校验 `canOpen`，不可打开时停在结果中说明原因；对象结果统一打开规范对象 URL。两个入口对同一结果使用同一规范打开目标。
- 只返回调用者可见的结果；被标记挡住的数据不出现在结果里。

## 3.9 入口矩阵

| 任务 | 首要入口 | 次要入口 |
|---|---|---|
| 新建资源 | 拥有者应用列表页的“新建…” | 项目页 Overview 的下一步；Files 的“新建”菜单 |
| 打开资源 | Search、Files、Recent | 引用链接、血缘图 |
| 查找对象 | Search、Object Explorer | 模块中的对象表、关系链接 |
| 执行动作 | 对象视图的动作栏 | 模块中的按钮、工作项 |
| 处理任务 | Notifications 收件箱 | Home 的我的工作项 |
| 审阅变更 | 分支控件“审阅并保存” | Home 的提案、Notifications |
| 发布与安装 | DevOps、Marketplace | 项目页“验证与交付” |
| 定义产品与版本 | DevOps Products | 项目页“Release in DevOps…”、Marketplace |
| 退役与重装产品 | Marketplace → Installed / Retired | 无；退役包不从目录消失 |
| 管理权限 | 项目页 Access（项目角色） | Control Panel（成员、标记、业务角色） |

资源 URL 使用 RID；编辑器在入口将 RID 解析为所属服务的记录身份。Files 的文件夹树、Search 的资源结果与血缘图的编辑入口读取同一份资源目录，移动只改变目录位置。Search 展示项目与文件夹路径，业务门户及扩展模块的运行页面使用已发布定义的 RID。
