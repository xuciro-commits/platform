# 3 信息架构

## 目标

任何资源、对象、应用和命令都能在三步内被找到，并且每样东西只有一个规范位置。用户靠“它属于哪个项目”和“它是什么类型”定位，不靠记忆菜单。

## 3.1 规则

- R1 全局导航只有外壳：应用轨与当前应用的侧栏；此外不出现全局入口（无顶部菜单栏、无文档页签、无应用门户页）。
- R2 层级至多四级：应用 → 入口 → 记录 → 页签。记录页内不再增加第二套导航。
- R3 每个项目资源有不可变的 RID、唯一所属项目和文件夹路径；规范 URL 由 RID 决定，与位置无关（移动资源不改 URL）。
- R4 资源在全局可被搜索；列表显示全部可见资源并带“项目”列，不按项目复制列表。
- R5 一个应用的一级菜单项至多 12 个，按带标题的分节分组；一个入口只属于一个应用；打开记录不改变侧栏。
- R6 同一样东西在所有地方用同一个名字；名字取自 [glossary](glossary.md)，新名字先进术语表。
- R7 系统文案和资源声明文案（名称、说明、字段、状态、动作、页面）可双语；对象记录的业务数据不翻译。

## 3.2 应用轨

| 位置 | 项 | 内容 |
|---|---|---|
| 上 | 搜索 ⌘K | 统一搜索与命令（§3.8） |
| 上 | 通知 | 通知、工作项、审批请求，带未读数 |
| 中 | 平台应用 | 主页、数据、本体、逻辑、应用、AI、交付、运行、管理、宿主，顺序固定 |
| 中 | 业务应用 | 已安装的产品，按安装顺序排在平台应用之后 |
| 下 | 助手 | 作用于当前页面的助手面板 |
| 下 | 成员菜单 | 租户切换、语言、外观、帮助与快捷键、账户、退出 |

应用轨只显示图标，悬停显示名称；成员无权打开的应用不显示，而不是显示为禁用；应用多到放不下时中段滚动。最近打开的记录在主页的“最近”，固定的入口是侧栏里的置顶视图。

## 3.3 应用与菜单

应用侧栏顶部是应用切换器，下面是该应用的菜单。每个入口是一个列表；标“仪表盘”的入口是仪表盘（[4-interaction §4.3](4-interaction/README.md)）。

| 应用 | 分节 | 入口 |
|---|---|---|
| 主页 | 工作区 | 概览（仪表盘）、我的工作、提案、最近、项目 |
| 数据 | 接入 | 连接、数据源、监听器、回写、观测源 |
| 数据 | 加工 | 数据集、管道、调度、匹配规则、媒体集 |
| 数据 | 追溯 | 血缘 |
| 本体 | 定义 | 对象类型、关系类型、动作类型、接口、共享属性、值类型、对象类型组 |
| 本体 | 浏览 | 对象 |
| 逻辑 | 搭建 | 函数、自动化 |
| 应用 | 搭建 | 模块、对象视图、模板 |
| AI | 搭建 | 智能体、检索源、评估集 |
| 交付 | 发布 | 产品、版本、测试计划、样本集 |
| 交付 | 安装 | 市场、安装 |
| 运行 | 观测 | 运行记录、日志、追踪、指标、告警、健康（仪表盘）、审计 |
| 管理 | 人员 | 组织、成员、团队 |
| 管理 | 访问 | 业务角色、标记、支持授权 |
| 管理 | 工作区 | 模型、语言与词汇、凭据、设置 |
| 宿主 | 运维 | 租户、升级 |

- 属性不单列入口，在对象类型的记录页内编辑；发布候选与发布审阅在版本的记录页内。
- 探索与保存的对象列表是“对象”入口的视图（4-interaction R3），不另列入口。
- 函数的四种引擎（代码函数、决策表、AIP Logic、逻辑流）是“函数”入口的快速筛选，不各占一个入口。
- 业务应用的菜单由产品包声明：每个入口是它的模块里的一个页面。

## 3.4 资源分类

| 类别 | 资源类型 | 拥有它的应用 | 可见范围 |
|---|---|---|---|
| 容器 | 项目、文件夹 | 主页 | 按项目访问 |
| 数据 | 连接、数据源、监听器、回写、观测源 | 数据 | 按项目访问 |
| 数据 | 数据集、媒体集 | 数据 | 按项目访问 + 标记 |
| 数据 | 管道、调度、匹配规则 | 数据 | 按项目访问 |
| 本体 | 对象类型、共享属性、关系类型、接口、值类型、动作类型、对象类型组 | 本体 | 定义全租户可发现；编辑按项目 |
| 逻辑 | 函数 | 逻辑 | 按项目访问 |
| 逻辑 | 自动化 | 逻辑 | 按项目访问 |
| 应用 | 模块、对象视图、模板 | 应用 | 按项目访问；保存到 main 后按使用者的业务角色 |
| 应用 | 探索、对象列表 | 本体 | 个人私有；可发布对象集由项目内 `build.query` 拥有 |
| AI | 智能体、检索源、评估集 | AI | 按项目访问 |
| 交付 | 产品、产品版本、测试计划 | 交付 | 按项目访问 |
| 交付 | 安装 | 交付 | 管理员与构建者 |
| 治理 | 组织单元、成员、团队、业务角色、标记、模型、凭据 | 管理 | 管理员；审计员按能力只读 |

对象（实例）不是资源：对象没有项目，可见性由对象类型、标记与行策略决定；每个对象只有一个落点——它的对象视图。

## 3.5 标识与命名

| 标识 | 格式 | 说明 |
|---|---|---|
| RID | `ri.<service>.<tenant>.<kind>.<id>` | 不可变；用于 URL、引用、审计 |
| API 名 | 对象类型、属性、动作、函数用 `camelCase`；类型名首字母大写 | 不可变（改名即新资源）；等宽字体显示 |
| 显示名 | 自由文本 | 租户数据，不翻译 |
| 路径 | `/项目/文件夹/资源名` | 随移动变化，只用于浏览 |

界面上 RID 与 API 名用等宽 `text-2xs` 弱化色显示，从不作标题。

## 3.6 页面层级与 URL

| 层级 | URL | 页面 |
|---|---|---|
| 应用 | `/<应用>` | 该应用的第一个入口 |
| 入口 | `/<应用>/<入口>` | 列表或仪表盘；视图的筛选、排序、列、分组与呈现方式在查询串 |
| 记录 | `/<应用>/<入口>/<RID>` | 资源的记录页，第一个页签 |
| 页签 | `/<应用>/<入口>/<RID>/<页签>` | 记录页的某个页签 |
| 对象 | `/ontology/objects/<对象类型>/<主键>` | 对象的记录页 |
| 项目 | `/home/projects/<项目 RID>` | 项目的记录页：该项目的资源 |

- 一个 URL 对应一个主视图；浏览器前进后退可用；分享链接看到同一个界面（4-interaction R12）。
- 资源类型决定拥有它的应用与入口，所以规范 URL 仍只由 RID 决定：打开任何 RID（搜索、项目、引用链接都一样）都落到同一个地址。
- 成员等原生身份保留其主键地址；文件夹是项目记录页的位置参数，不伪造 RID 或对象类型。
- 选中项、覆盖层与未提交的输入不进 URL。

## 3.7 项目与文件夹

- 结构：项目 → 文件夹 → 资源；不设 Space。
- “项目”是主页应用的入口；所有成员都能进入，看到自己可见的项目，不需要构建权限。
- 项目的记录页列出该项目的全部资源，是从位置找资源的唯一入口；资源本身仍由拥有它的应用打开。
- 资源只属于一个项目，可被其他项目引用；引用不改变所有者、定义与权限。
- 项目页的分区见 [4-interaction §4.4](4-interaction/README.md)。
- 已安装产品的受管项目带“受管”标记，内容只读。

## 3.8 搜索

- ⌘K 与搜索页共用一个输入合同与结果合同；结果分组依次为：命令、当前应用、应用、资源、对象、成员、知识；输入为空时显示最近。
- 同一查询在两个入口返回同一分组集合；各组独立截断，资源结果再多也不挤掉对象或其他分组。
- 前缀限定范围：`>` 命令，`@` 成员，`#` 项目，`:` 对象类型。
- 资源结果显示类型图标、显示名、项目路径；对象结果显示对象类型与标题属性。
- 资源结果先校验 `canOpen`，不可打开时停在结果中说明原因；对象结果统一打开规范对象 URL。两个入口对同一结果使用同一规范打开目标。
- 只返回调用者可见的结果；被标记挡住的数据不出现在结果里。

## 3.9 入口矩阵

| 任务 | 首要入口 | 次要入口 |
|---|---|---|
| 新建资源 | 拥有它的入口的“新建…” | 项目记录页的“新建”菜单 |
| 打开资源 | 搜索、主页的项目与最近 | 引用链接、血缘图 |
| 追溯数据来源与影响 | 数据资源记录页 Usage 的“在血缘中打开” | 数据应用的血缘入口、命令面板 |
| 查找对象 | 搜索、本体应用的对象入口 | 模块中的对象表、关系链接 |
| 执行动作 | 对象记录页的主动作与 ⋯ | 模块中的按钮、工作项 |
| 处理任务 | 通知 | 主页的我的工作 |
| 审阅变更 | 分支控件“审阅并保存” | 主页的提案、通知 |
| 发布与安装 | 交付应用的版本与市场 | 项目记录页“验证与交付” |
| 定义产品与版本 | 交付应用的产品 | 项目记录页“在交付中发布…” |
| 退役与重装产品 | 交付应用的安装（已安装与已退役视图） | 无；退役包不从目录消失 |
| 管理权限 | 项目记录页 Access（项目角色） | 管理应用（成员、标记、业务角色） |

资源 URL 使用 RID；编辑器在入口将 RID 解析为所属服务的记录身份。项目的文件夹树、搜索的资源结果与血缘图的编辑入口读取同一份资源目录，移动只改变目录位置。搜索展示项目与文件夹路径，业务门户及扩展模块的运行页面使用已发布定义的 RID。

## 现存差距

- 信息架构（第 7 层）：本文描述的应用轨、菜单与地址只在 `frontend/` 的外壳里成立（`frontend/src/apps.ts`），各入口尚未接数据；宿主的应用注册与 `web/` 仍是上一套（导航轨、应用门户、`#/` 哈希地址、产品名，对照见 [2-product 现存差距](2-product.md#现存差距)）。§3.8 之后的正文与 §3.9 的次要入口里个别旧称随对应应用重建时改写。
