# 6 领域架构

## 目标

用一套小而完整的领域模型表达一切：资源（定义）、对象（实例）、事实（变更）。每个概念只有一种表示、一条写入路径、一个读取代数。本目录五份文件：

- 本文：领域地图、资源内核、本体、对象、数据、动作、函数、自动化、工作项、组织、规则语言。
- [security.md](security.md)：权限三层、角色、标记、对象策略。
- [change.md](change.md)：工作状态、分支、提案、产品、版本、安装、升级。
- [packages.md](packages.md)：产品包生命周期、卸载与重装、数据保留、ERP/MES 拆包边界。
- [lineage.md](lineage.md)：血缘推导、Preview 与 Guard 两条基线、影响分析、列级血缘、读取合同。

## 6.1 规则

- R1 一切权威写入只经接受结果：动作的执行、数据源拉取与管道的事务、资源的保存。没有第四条路径。
- R2 对象只经动作写入。应用、自动化、函数、AIP 都调用动作；同步与管道写数据集，不写对象。
- R3 对象读取只经 ObjectSet；谓词只用 Expr。
- R4 函数只计算，不写入；需要写入时返回编辑提议，由调用它的动作接受。
- R5 一个动作的全部编辑原子生效，且只在一个权威内；跨权威一致性经版本化协议与补偿，不做跨权威事务。
- R6 定义带版本；引用在产品版本中固定到版本。
- R7 规则求值、约束检查、授权、依赖解析各一个实现。

## 6.2 领域地图

| 领域 | 拥有的概念 | 对外提供 |
|---|---|---|
| 资源 | RID、项目、文件夹、资源生命周期、工作状态、分支、提案 | 资源的创建、保存、移动、归档、引用解析 |
| 本体 | 对象类型、属性、关系类型、接口、共享属性、值类型、动作类型、对象类型组 | 本体元数据、类型检查 |
| 对象 | 对象、编辑事实、对象索引 | ObjectSet 查询、对象读取 |
| 数据 | 连接、数据源、观测源、数据集与事务、管道、调度、回写、匹配规则、媒体集、监听器、血缘 | 数据集读取、血缘、生效标记 |
| 逻辑 | 函数与其制品 | 函数调用 |
| 动作 | 动作执行 | 校验、执行、副作用调度 |
| 自动化 | 自动化、运行 | 条件监听与效果执行 |
| 工作 | 工作项、通知 | 收件箱、通知投递 |
| 组织 | 成员、团队、组织单元、业务角色、标记 | 主体解析、范围解析 |
| 交付 | 产品、产品版本、安装 | 打包、安装、升级 |
| AI | 模型、智能体、检索源 | 模型调用、智能体运行 |

依赖方向：组织 ← 资源 ← 本体 ← 对象 ← 动作；数据 → 对象（数据源）；逻辑、自动化、AI 只经动作与 ObjectSet 使用对象。

## 6.3 资源内核

每个资源都有：

| 字段 | 说明 |
|---|---|
| RID | `ri.<service>.<tenant>.<kind>.<id>`，不可变 |
| kind | 资源类型，决定拥有它的应用 |
| project / folder | 唯一位置 |
| apiName | 可被引用的稳定名（本体与函数类资源必有） |
| displayName、description | 租户数据 |
| version | 每次保存到 main 递增 |
| state | `new`（从未保存到 main）、`active`、`archived` |
| spec | 资源类型自己的定义体 |

生命周期：新建（`new`）→ 编辑累积在工作状态 → 保存（main 上成为新版本；分支上写分支）→ 归档（可恢复；被引用时归档需确认影响）。删除只对 `new` 状态的资源开放。

资源目录记录唯一项目与文件夹；应用的资源引用表达组成，不决定权限归属。保存使用该资源原生记录的预期版本，保存与后续动作共享同一版本序列。

引用：资源之间按 RID 引用；保存时检查引用存在且调用者可见；被引用资源归档时引用方出现问题提示，不级联。

## 6.4 本体

- 对象类型：apiName、显示名、主键属性、标题属性、属性列表、数据源、状态（实验、活跃、弃用）。
- 属性类型：字符串、整数、长整数、小数、布尔、日期、时间戳、地理点、附件（媒体引用）、数组、结构；可约束为值类型。
- 关系类型：两端对象类型、基数（一对一、一对多、多对多）；一对多经外键属性，多对多经关系数据集或动作编辑。
- 接口：一组共享属性的形状，是独立的 `build.interface` 资源，拥有项目、RID、草稿、发布版本、安装与历史；对象类型声明实现接口，ObjectSet 可按接口查询。应用 Manifest 声明的接口与其发布资产进入同一注册，作为兼容来源；对象实现校验、接口查询绑定和安装都读这一注册，不维护第二套形状。已发布接口保留字段名与类型，新增字段的版本在发布和升级时校验现有实现。
- 共享属性：跨类型复用的属性定义；改动传播到使用它的类型。
- 值类型：基础类型 + 约束（正则、范围、枚举）+ 显示格式。
- 动作类型：见 6.7。
- 对象类型组：仅用于组织与浏览，无语义。
- 生命周期状态：对象类型可声明一个状态属性与允许的转换；转换只由动作执行（这是流程的唯一表达，见 2-product R7）。
- 兼容性：删除属性或改变属性类型时，保存审阅列出依赖该资源的已发布下游，复用资源依赖图；审阅行为见 [M18](../4-interaction/patterns.md#m18-差异审阅review)。
- 默认对象视图属于对象类型的展示选择，引用 Workshop 模块及其对象入口页；入口必须接收该类型的当前对象，不得要求其他必填输入。展示引用进入交付闭包与影响分析，但不作为对象执行的前置依赖。完整候选校验模块归属和输入契约；页面编辑保存后即生效，版本与回滚沿用候选快照，不另设页面版本绑定。

## 6.5 对象

- 身份：对象类型 + 主键。
- 构成：数据源投影（数据集版本、外部源快照或管道输出按声明映射得到的行）+ 编辑事实（动作产生的按属性的修改，只追加）。
- 合并：同一属性上编辑事实优先于数据源值；无编辑时采用仍提供该对象的来源中最新的属性值。最后一个来源删除行时归档对象，除非该对象由动作创建；来源重新提供该行时恢复由来源归档的对象。数据集、外部源全量快照与管道共用同一删除路径；增量拉取不推断缺失行。存在映射错误、写入拒绝或管道隔离行时不按该批结果删除对象。
- 只由动作创建的对象类型（无数据源）是合法的。
- 索引：对象写入后进入索引以支持 ObjectSet 筛选、排序、聚合与搜索；索引是派生的，可重建。
- 状态版本：`work.view.state` 是 JSON；缺少 `version` 或 `version: 0` 表示历史版本，读取时接受；新保存统一写入 `version: 1`，未知版本拒绝。探索中的 `set` 是完整 ObjectSet，列表状态保留列表视图字段。
- 保存边界：成员探索保存为私有 `work.view`，只属于保存者，不占项目、没有资源 RID，也不进入发布闭包；实体以 `owner` 为记录作用域，`/v1/views` 的通用记录窄化只能读回保存者自己的视图。可被 Workshop、函数和动作复用的对象集是项目 `build.query` 资源，拥有 RID、版本、项目权限和发布生命周期。`build.query` 的发布字节是 v1 共享 ObjectSet 查询合同：对象或接口、Expr 筛选、domain、排序和容量随版本固定，执行始终经共享 ObjectSet 求值器，不降级为筛选字符串。二者都保留，但不得互相冒充。

## 6.6 数据

- 数据集：带模式的表；每次写入是一个事务（快照、追加、更新、删除），形成新版本；旧版本可读。可配置一个主键列；有主键时键值必须非空且唯一。更新按键合并列值，不存在的键插入；删除只需提供键。未配置主键时不得更新或删除。
- 数据源拉取：按数据源声明的连接、读取方式与周期，把行写入对象或数据集；记录读取位置以增量。
- 流式数据源：数据源以持续模式读取增量记录，写入其指定的流式数据集；批次与读取位置经接受结果保存，重试与恢复不得重复追加。未指定目标数据集时仍可供函数观测使用。
- 调度：管道构建的独立时间计划资源，引用管道并配置周期与启停；只由一个调度执行路径触发构建。自动化的时间条件不是调度。
- 管道：确定性的变换图，输入为数据集版本，输出为数据集或对象类型数据源；每次构建记录所读的输入版本；输入有新版本时管道为过期。专项标记与分级沿输出传播；数据集输出可在最后一步按明确许可解除选定标记（security §6.15）。
- 回写：把数据集或对象集写回外部系统。
- 媒体集：非结构化文件集合（文档、图片），带版本；附件属性以媒体集与内容哈希引用其中的项。移除当前项不改变旧版本或既有附件；历史读取仍受媒体集权限控制。媒体版本与所引用字节随产品版本交付。
- 血缘：由上述声明推导；标记沿血缘取最严格者向下游传播。视图读取当前保存的定义（Preview），授权读取执行使用的已接受定义与写出证据（Guard），两者共用一个推导算法（见 [lineage](lineage.md) L3、security §6.15）。

## 6.7 动作

动作类型是独立的 `build.actiontype` 资源，有自己的记录、RID、项目、编辑页和保存版本。对象类型的当前定义只保存动作类型引用；动作参数、规则和条件保存在动作资源中。对象字段、状态和引用保存不写入动作定义，也不生成动作版本；普通对象保存携带已变更的内嵌 `actions` 会被拒绝。个人工作状态不产生共享版本，显式保存后才保留不可变的动作版本。

对象页的生命周期画布只可视化和编辑动作的引用关系；连接状态与动作、删除动作都保存为动作资源的版本，不写回对象草稿。

发布候选可以单独选择动作类型；发布时校验目标对象的发布权限，并将选定动作版本编入目标对象的执行映像。映像包含完整规则和所用版本，因此历史执行与恢复不读取最新动作草稿。动作版本的增加只由动作资源的保存决定；发布闭包和动作目录从动作资源读取，并按对象执行映像固定的版本冻结。产品安装使用原有发布机制创建动作资源，并保留交付版本的冻结定义。旧对象草稿中的内嵌动作只经显式、幂等的一次接受结果迁出；历史发布字节保持原样。

动作类型的五个部分：

| 部分 | 内容 |
|---|---|
| Parameters | 类型化参数；默认值可为常量、当前用户、当前时间、对象属性；可见性与必填可依赖其他参数 |
| Rules | 有序规则：创建对象、修改对象、删除对象、增加关系、删除关系、函数支撑（函数返回编辑） |
| Submission criteria | Expr 条件列表，每条带失败文案；对参数、目标对象、当前用户求值 |
| Form | 参数的呈现顺序与分组 |
| Side effects | 通知、回写；在动作接受后执行 |

执行：校验参数 → 授权（动作的业务角色 + 目标对象的读写权限）→ 求值提交条件 → 求值规则得到编辑集 → 一次接受结果原子写入 → 调度副作用（至少一次，带幂等键）。每次执行有请求键；重复提交同一请求键返回同一结果。

## 6.8 函数

- 引擎：代码函数（受控编译、隔离执行）、决策表、AIP Logic（模型调用块）、逻辑流（节点图）。
- 签名：类型化输入与输出；输入可为对象、对象集、基本类型；输出可为值、对象集或编辑提议。
- 编辑提议使用 `edit-proposal/v1`：包含动作模式、目标、输入与预期修订；函数只返回提议。用户审阅后，宿主重新读取原始调用结果并通过同一动作引擎执行，权限、规则与修订冲突照常生效。
- 纯粹：函数无副作用；读取经 ObjectSet，受调用者权限约束。
- 制品：每次保存生成不可变的制品版本；动作与模块引用制品版本。
- 测试与评估：业务测试计划和函数评估集共用历史 `build.testplan` 记录类型，但必须写入显式 `variant`（`test-plan` / `evaluation-set`）并发布为不同资产种类。旧记录缺少 `variant` 时只在读取时按 `evaluation` 是否存在推断；Agent Studio 路由评估集，DevOps 路由业务测试计划，二者不靠界面状态猜测。

## 6.9 自动化

- 条件：对象集变化（进入、离开、属性变化）、时间计划、阈值（Expr 对聚合求值）。
- 效果：执行动作、发送通知、执行回写、运行函数；按顺序执行，单个效果失败按其重试策略处理。
- 执行身份：自动化以其所有者（发布它的成员）的授权运行；对象集变化、时间计划与持续源触发都以该发布者身份执行动作、查询与函数。所有者失去权限时自动化暂停。
- 暂停状态和原因属于运行状态，不进入发布版本；权限恢复后显式继续，不改变已发布版本或既有运行。手动运行也使用发布者身份；对象自动化须选择目标对象，每次运行有独立幂等键。
- 告警是对象条件加通知效果的自动化。旧告警描述经接受结果迁移，保留历史描述和通知去重键；历史资产仍可读取，新建与编辑统一使用自动化。
- 每次触发一条运行记录；失败可重试。
- 流程中的条件（分支、循环、等待）是 Expr：引用写作 `input.…`、`subject.…`、`step.<节点>.…`、`item`、`index`、`answer`，均为 JSON 类型；引用不到的字段按 null 求值；条件只比较流程中的值，不读时钟、调用者或集合。存储格式 v1 的 Predicate（left / right / terms）只在读取时转为 Expr，不改写历史字节；发布资产比较前两侧都先转换。

## 6.10 工作项与通知

- 工作项是平台内置对象类型：主题对象、类型（任务、审批）、指派（成员或团队）、期限、状态。
- 工作项由动作创建、由动作关闭；审批是带“批准 / 驳回”动作的工作项。
- 评论是内置“评论”动作产生的编辑事实，显示在对象视图的 Activity 分区。
- 通知由动作副作用与自动化效果产生；投递渠道为站内与邮件；摘要频率由成员在 Account 中设置。

## 6.11 组织

- 成员：已验证主体在租户中的身份；状态：受邀、活跃、暂停、离开。
- 团队：成员集合；授权可授予团队。
- 组织单元：树形结构；业务角色授予可限定在单元内（范围）。
- 业务角色：由产品包或租户定义，授权动作与字段；与项目角色、标记相互独立（见 security）。

## 6.12 规则语言与读取代数

- Expr：类型化表达式语言，用于提交条件、行策略、筛选、自动化条件、可见性、派生属性；一个解析器、一个类型检查器、一个求值器，前后端共用（前端经 WASM）。
- ObjectSet：起点（对象类型或接口）→ 筛选（Expr）→ 沿关系转到 → 集合运算 → 排序、聚合、分页；授权在每一步生效。
- Workshop 查询的筛选与派生页面变量保存为 Expr，查询的页面变量引用经 ObjectSet 的有类型根参数绑定。新页面格式 4 只接受 Expr；旧格式的条件与运算在读取时按版本投影，需对象字段类型才能转换的查询在构建者保存时升级，已发布字节与摘要不改写。
