# 6 领域架构 · 产品包生命周期

## 目标

产品包是行业应用的可安装交付单位，但不是业务事务边界。包拥有定义，租户拥有记录；安装、升级、卸载只改变定义和执行入口，不复制或级联删除租户数据。

## 规则

- P1 版本不可变、内容寻址；同一 `id@version` 不能被替换。产品版本只能从已保存候选冻结，Marketplace 只消费产品版本。
- P2 包拥有定义、页面、应用、连接声明和受管项目；租户拥有业务记录、数据集、媒体、凭据引用、业务授权、运行和审计历史。
- P3 安装和升级各产品分别经接受结果完成。跨产品安装是可见的步骤序列，不是跨产品数据库事务；失败停在当前产品，已完成产品保持可用，重试必须幂等。
- P4 升级只替换受管定义，不覆盖客户扩展、客户项目、连接地址、凭据引用或业务记录。破坏性变更必须在审阅中列出并在接受前阻止。
- P5 卸载（retire）是归档：归档受管定义和项目，保留客户数据、引用、扩展、凭据引用、历史与包制品。永久删除是独立动作，不得与卸载合并。
- P6 重装恢复同一精确版本的受管定义和项目，不复制业务记录、不重跑 `blueprint.setup`、不自动授予角色。恢复只作用于本包拥有的引用。
- P7 依赖包必须先安装，卸载按反向依赖顺序。包资源所有权必须唯一；存量包的拆分或迁移只能经显式所有权转移接受结果，不得用卸载重装伪装迁移。
- P8 包来源（source）只决定目录中可安装的产品版本；删除来源不等于卸载，不等于删除安装制品或业务数据。
- P9 包资源引用未声明的内部资源是发布错误。行业产品之间只经对象接口、动作或版本化协议协作。

## 6.24 生命周期

### 构建与发布

1. DevOps 产品选择项目 Contents，声明产品依赖。
2. 保存候选冻结完整资产闭包，运行审阅、测试计划和依赖检查。
3. 发布精确版本，记录内容摘要、依赖范围、平台兼容性、所需角色和要求连接。
4. 版本只能发布新版本；发布者停止提供新安装用 `withdraw/yank`，已安装实例不受影响。

### 安装

1. Marketplace 选择精确 `id@version`，展示来源、摘要、依赖闭包、安装顺序、将创建的资源、角色/连接/初始化前提。
2. 审阅按依赖拓扑列出每个产品的精确版本和动作。
3. 每个产品单独接受；UI 显示 `installed / pending / failed` 和可重试步骤。
4. 安装不自动授予业务角色，不自动执行 `blueprint.setup`，不写业务记录。
5. 安装完成后才允许配置连接、凭据引用、业务角色和初始化数据。

### 升级与降级

1. 显示 `from -> to`、新增/变更/移除资源、存储迁移、客户扩展、客户引用、在飞工作、连接和凭据前提。
2. 删除非代码动作、改变有记录对象的存储形状、删除必填字段或类型变更必须阻止。
3. `upgrade`、`downgrade`、`rollback` 是三个词。低版本切换只经 `downgrade` 并重新执行存储兼容检查；`rollback` 只在失败后恢复可逆的上一接受状态。
4. 旧制品保留，但只有在目录仍可取得且旧定义能读取当前数据时才提供切换。

### 排空与卸载

1. 真正的 `drain` 停止新页面运行、新动作、新 Flow、新 Agent 触发和新外发，并列出在飞工作。
2. 未实现运行时门禁时，状态只能叫 `marked for uninstall`，界面不得声称“新使用已停止”。
3. `retire` 归档受管定义和项目，保留业务记录、数据集、媒体、客户扩展、凭据引用、运行和审计。
4. 审阅列出失效的客户引用，但不级联删除客户资源；引用 owner 负责修复或迁移。
5. 永久删除（purge）另设管理员危险路径，只删除包拥有的归档物和安装记录，不删除租户数据。

### 重装

1. 退役包保留在独立的 Retired 页签，显示最后安装版本、时间、保留制品和依赖状态。
2. 选择精确版本重装，预检本包归档定义、客户扩展、保留制品和依赖。
3. 恢复本包受管定义和项目；不恢复其他包的归档定义，不接管平台工作区资源。
4. 同版本重装保持同一项目 ID、资源 RID、应用身份、业务记录和媒体历史。
5. 失败保持 retired，不产生半 active 状态。

### 永久删除与来源

- `remove source` 只删除未安装来源的目录映射；已安装实例、封存制品和业务历史保留。
- `purge` 只能在 retired 后由管理员执行，展示不可逆清单并留下 tombstone。
- 不提供“一键删除租户数据”的包动作；数据删除属于租户数据治理。

## 6.25 数据保留矩阵

| 类别 | 卸载 | 重装 | 永久删除 |
|---|---|---|---|
| 应用、页面、对象类型、动作、连接定义、受管项目 | 归档 | 恢复本包定义 | 只删除包拥有物 |
| 对象实例、业务记录 | 保留 | 继续使用 | 不级联删除 |
| 数据集、数据集版本、媒体、文件字节 | 保留 | 继续使用 | 不级联删除 |
| 运行、Flow 历史、接受结果、审计 | 保留 | 保留 | 默认不删除 |
| 客户扩展、客户项目、客户引用 | 保留 | 保留 | 不删除 |
| 连接地址、凭据引用、业务授权 | 保留 | 需确认配置和授权 | 不随包删除 |
| `blueprint.setup` 创建的初始化数据 | 作为租户数据保留 | 不自动重跑 | 按数据治理策略处理 |
| 包制品、`Retained`、安装记录 | 保留 | 可复用 | purge 单独删除 |

## 6.26 ERP/MES 拆包

当前 `application.manufacturing` 是一个包、两个应用根，不能独立升级或卸载。拆分的目标边界是所有权的拆分，不是文件拆分：

| 包 | 责任 |
|---|---|
| `manufacturing.core` | 共享本体、公共值类型、版本化协议和共享查询；不承载采购、会计或车间执行页面 |
| `manufacturing.erp` | 物料、采购、库存、会计、生产订单、库存和会计过账 |
| `manufacturing.mes` | 工艺路线、工单执行、质量、设备、停机、现场动作和执行记录 |

依赖是 `erp -> core`、`mes -> core`。ERP 与 MES 不通过对方内部资源协作；MES 通过对象接口、动作或版本化查询绑定上游生产事实。

当前包模型要求每个包有 app root；不能表达纯契约包。若需要 `manufacturing.core`，使用一个最小的 Foundation app，或单独扩展包格式，不另建包注册表。

`productionorder.confirm` 当前在一个动作事务中创建 ERP 收货、生产批次、库存过账、生产过账和日记账。拆包前必须选择：

- 生产完成与会计过账允许最终一致：生产事实归一个 owner，ERP 通过事件/outbox 幂等过账。
- 两者必须同步：不能在两个产品包之间拆分开，保留合并包或以 ERP 为 base、MES 依赖 ERP。

存量租户不能直接安装拆分包。先增加 ownership rehome 接受结果，只改变资源 `Project / ManagedBy`，保留 RID、类型名、应用身份、记录、媒体和历史；完成后再归档旧包。未完成迁移前，旧单体包保留为兼容伞，新租户使用拆分包。

## 6.27 现存差距

- `draining` 只设置状态，静态代码没有阻止新使用；界面明确标为“标记卸载”，不宣称运行排空已完成。
- `Uninstall` 实际是 archive；永久删除、输出 detach、制品 GC 未实现。
- `Retained` 只是制品记录，不等于可选回滚版本。
- `productionorder.confirm` 仍跨 ERP 库存、生产批次和会计过账，拆包边界未决定。
- 没有 ownership rehome，存量单体包不能安全拆分。
- 没有 closure receipt、依赖锁、真正的 drain 和永久删除。
