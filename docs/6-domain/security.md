# 6 领域架构 · 安全

## 目标

任何主体对任何数据的任何操作，都由同一条决定路径按三层权限给出允许或带原因的拒绝。三层互不替代：项目角色管资源，标记管数据，对象策略管行与列；业务角色另管动作。

## 规则

- R1 只有一条决定路径；所有读、写、导出、派生、AI 上下文都经它（授权只有一个实现）。
- R2 默认拒绝；每个拒绝带可翻译的原因。
- R3 各层同时满足才允许；任何一层拒绝即拒绝。
- R4 标记是强制的：任何角色（含管理员）都不能绕过，只能被授予许可。
- R5 导出、派生内容（摘要、检索）、AI 上下文与直接读取适用同样的规则，不另设宽松通道。
- R6 写入类决定与所有拒绝都进入审计。

## 6.13 决定模型

请求：主体、租户、请求类型（read、derive、export、create、write、action、manage）、资源或对象、字段。

| 关口 | 判断 | 来源 |
|---|---|---|
| Tenant | 主体与资源属于同一租户 | 宿主 |
| Principal | 主体有效且活跃 | 组织 |
| Verb | 动作的业务角色，或类型级读写角色 | 业务角色 |
| Project | 主体在资源所属项目中的角色足够 | 项目角色 |
| Markings | 主体获准数据生效标记中的每一项 | 标记 |
| Row | 对象满足行策略 | 对象策略 |
| Fields | 涉及的字段可读或可写；不可读字段在读取中被隐去 | 字段权限 |
| Derived | 派生内容的来源全部可读 | 血缘 |

## 6.14 项目角色（自主权限）

| 能力 | Discoverer | Viewer | Editor | Owner |
|---|---|---|---|---|
| 在 Search 与 Files 看到资源名称与类型 | ✓ | ✓ | ✓ | ✓ |
| 打开资源、查看定义与数据 | | ✓ | ✓ | ✓ |
| 编辑资源（工作状态、分支） | | | ✓ | ✓ |
| 归档资源、移动到其他项目 | | | ✓ | ✓ |
| 管理项目访问 | | | | ✓ |

- 资源继承所属项目的角色；不在单个资源上另设角色。
- 项目至少保留一位 Owner；首次设置访问需管理员或独立构建者。
- 保存到 main 需要 Editor 及以上并持有构建者角色；安装到其他租户只经 DevOps 与 Marketplace。
- 角色可授予成员或团队。

## 6.15 标记（强制权限）

- 两类标记：
  - 分级：一个有序类别 `internal < confidential < restricted`；获准高级别即获准其下各级。
  - 专项：互相独立的命名标记（如 PII、薪酬、财务）；每项单独获准。
- 标记是 Control Panel 中的资源；许可授予成员或团队。
- 生效标记：数据集、管道输出、对象类型取其上游的并集（专项）与最高级（分级），沿血缘自动传播；连接与源的标记作为起点。
- 解除：只能在管道中显式“解除标记”步骤完成，执行者必须获准该标记并持有“解除标记”权限；解除写入审计。
- 可见性：被标记挡住的数据集版本按行过滤；对象类型整体把关；资源定义与血缘图仍可发现（不暴露数据）。
- 受限（restricted）数据不导出为 CSV。
- 所属应用的服务自动化（如管道构建）在其应用边界内读取标记数据；输出继承标记。

## 6.16 对象级策略

- 行策略：Expr，针对对象属性与当前主体属性（成员、团队、单元、业务角色）；在 ObjectSet 的每一步生效。
- 字段权限：属性声明读者与写者（业务角色）；读取中隐去，界面显示“受限”。
- 带分级标记 confidential 及以上的数据只能进入声明了读者的字段。
- 策略随对象类型版本化，进入产品包。

## 6.17 业务角色

- 业务角色由产品包或租户定义，授权动作、类型级读写与字段。
- 授予可限定组织单元范围；可设起止日期。
- 业务角色与项目角色独立：业务用户执行动作不需要项目角色；构建者编辑资源不需要业务角色。

## 6.18 特殊主体与通道

| 主体或通道 | 规则 |
|---|---|
| 自动化 | 见 6-domain §6.9 |
| 服务自动化 | 只在所属应用的边界内免除行策略；标记仍随输出传播 |
| 智能体与 AIP Assist | 以调用者的授权读取；不可用于 AI 的字段被隐去；写入只经动作并需调用者确认 |
| 导出 | 与读取同规则，另加 R5 与受限不导出 |
| 支持访问 | 成员可开启限时支持授权；到期自动撤销；全程审计 |
| 宿主运维者 | 默认不能读取租户数据；只管理租户生命周期 |

## 现存差距

- Discoverer 与项目级读取未实现（路线图 P3.7）。
- 标记只有分级，以平台应用的 `confidential`、`restricted` 角色表示许可；专项标记、标记资源、解除标记步骤未实现（P3.8）。

- 授权上下文构造在宿主根包，未在 `services/security`（P2.6）。
