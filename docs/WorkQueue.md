# 执行队列

唯一的活动执行队列。目标与门禁见 [Intent.md](Intent.md)、[Platform.md §10](Platform.md#10-未来方向)；已实现证据归各 ADR 的“实际构建”，测试方法归 [Testing.md](Testing.md)。

## 执行规则

- **下一项：#123，FDE 应用工坊与工作流编辑体验。** 每次交付一段跨界面的构建者→发布→操作员路径，先修共享 UI、`@platform/app` 和 `build` 的归属能力。代码、适用检查、文档和提交一起收尾；负责人视觉验收单独记录，不作为每批工程提交的前置条件。
- 正确性保证覆盖当前交付实际使用的权限、版本与提交/恢复边界；无关的极端故障分支和行业深度留在各自工作项。自动脚本通过只证明其覆盖的功能，不等于产品视觉验收或真实客户交付。
- 完成的批次从队列移除，剩余承诺留在原工作号。W1–W4 是年度阶段，不是并行开工清单。

## 当前事实与下一批

共享工作区已提供应用启动器、可停靠标签、命令搜索；`@platform/ui` 已有设计令牌、`StatusTag`、虚拟化且可排序/行内编辑/冻结列的 `DataTable`、记录视图、表单、抽屉与节点画布。`build` 已能编辑对象、页面、原生工作流、AI 函数并测试/审查候选；这些入口仍以分离的导航页组织。浏览器路线覆盖两行业的功能与桌面/窄屏截图，但未建立视觉差异、任务耗时或统一跨界面上下文门禁。#138 21a 编辑器局部体验已获负责人认可；不外推为整个工作区验收。现有能力范围见 ADR-0034–0043 与 Platform §2.4。
