# 执行队列

只放当前要交付的工作。整个项目的收敛范围与文档分工归 [ADR-0124](ADR/0124-platform-consolidation.md)；产品宗旨归 [Intent](Intent.md)，应用构建方向与边界归 [ADR-0098](ADR/0098-build-the-capability-to-build.md)，第一次真实交付归 [ADR-0122](ADR/0122-first-real-delivery.md)，能力现状归 [Platform](Platform.md)。本队列不复制各 ADR 的实现记录，不保存完成记录。

## 当前：平台整体收敛——连续应用构建与资产演进

沿 [ADR-0124](ADR/0124-platform-consolidation.md) 的整个项目范围，围绕实际应用继续检查建模、装配、规则、验证、发布后修改与运行的一致性，不限于 ADR-0098 的后续功能。按实际阻断选择下一整块；现行职责、已移除的重复实现与检查范围归该 ADR 和相关能力的 As built，不另列完成清单。

- 先修正发布后的变更发现：当前 Changes 未列应用自身，并把 `state=published` 当作草稿与运行定义一致，导致成员或定义修改没有进入正常变更列表。沿原草稿/候选比较修复，不增加发布状态权威。再从空白应用连续完成对象/关系、事务与规则、页面、流程/集成/AI、试跑、发布和后续修改；复杂操作沿原类型化编辑器，不以手写底层定义或预改生产状态绕过。
- 检查主要功能的自然入口、引用与错误定位，以及查看/选择/编辑/执行/管理的打开方式；切换应用和资源时保留草稿、返回位置与权限范围。
- 对发现的重复职责、不同入口授权或结果显示不一致，在原归属方合并或修复；保留历史版本和运行语义，不为了界面统一降低已有表达能力。

每次完成一个实际任务涉及的整块修改，再统一检查。完成条件是构建者与业务成员能够沿正常入口完成这项任务，保存/拒绝/发布/运行结果可理解，原数据与权限保证保留。其余收敛范围仍按 ADR-0124 和真实依赖选择下一块，不在此复制完整工程目标。

## 之后：第一次真实交付（楼宇供暖）

当前仍是开发阶段。范围包括门禁，数据分发包括推送、看板报表与导出/API。平台工程先完成，真实使用不作为继续开发的前置条件。

楼宇供暖、暖通、门禁、数据分发、健康诊断和 AI 的现行范围归 [ADR-0122](ADR/0122-first-real-delivery.md)。系统上线、行业资产和缺口清单仍是同一次交付的三件产出。具体楼栋、现场设备、物业角色和保留目标在接入时补齐；资料中的旧范围不撤销负责人已确认的门禁要求。

`industry.heating`、两份模拟配置和 Modbus 点表接入用于开发验证；客户实际上线、客户变更与第二城市记录保持未验证。负责人使用与独立构建者体验各按原 ADR 记录，不用模拟或自动测试冒充。规模优化先按确定的目标密度测量，原生应用按 ADR-0114 在等价替代和历史责任明确后退出。

两宿主酒店 `8495`、制造 `8490` 的版本、健康、页面资源和原数据卷随 main 更新维护，不另作为交付块。

已交付能力的实现与证据边界归各自 As built，主题入口见 [ADR-0124 §1.2](ADR/0124-platform-consolidation.md#12-现行主题入口)，不另占队列位。真实上线、行业包与客户判据保持 ADR-0122 的停止条件；既有 SRS/SOW 承诺与 ADR-0097 的实现边界继续保留。

每次只推进一块；块内按实际依赖迁移。已经通过且未受影响的证据直接复用。检查按 [Testing](Testing.md) 选择，代码合入 main 后沿既有同步协议更新两宿主，保留原数据卷。

## 队列规则

- 旧 W0/W5 与 XXL/L 编号不恢复为另一套队列；本次负责人明确授权的整个项目收敛以 ADR-0124 为范围，核查与实际修改一起完成。
- 已完成、被替代、仅待一般体验走查的旧条目不再作为工程欠账；确有阻断时修复当前任务，不另起专项。
- XMI/UAF/EPC 深度、画布新形态、跨设备排布、本轮协议包之外的更多连接器、行业交易/排产、插件市场、第二数据库及更多形式化证明不在当前施工范围。现有支持边界留在原 ADR，新需求到来再决定是否排队。
- 外部分支持续 Flow 候选不自动成为集成任务；当前七节点实现与边界修复已在 main，剩余验收以 ADR-0047 / SRS 为准。
- SRS 已承诺的任务与历史/权限/恢复保证保留；登记未来可能性不增加实施范围。只有当前交付阻断、已确认回归或负责人明确的新目标才能入队。
