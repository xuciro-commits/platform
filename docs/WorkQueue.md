# 执行队列

平台活跃工作的唯一清单。重排于 **2026-09-28**。方向与年度门禁见 [Intent.md](Intent.md) 和 [Platform.md §10](Platform.md#10-未来方向)；实现细节与历史证据归对应 ADR，操作路线归 [Testing.md](Testing.md)。这里只保留执行顺序、剩余工作、依赖和交付条件。

## 如何执行

- **下一项：用 #136 的最小不可变发布完成首条构建者 → 操作员任务链。** 复用已有对象、引用、动作、审批、页面和受管 AI，不先扩张任何一个单独子系统；随后补足具名关系与主从语义，再让流程与 AI Logic 进入同一条交付链。不要重新开发已整合的前端代码。
- 一次推进一个**跨能力的可用增量**，而不是把一个支柱纵向做完：选定酒店与制造的极简任务，明确构建者的改动、操作员的结果以及版本/权限/失败边界。代码、适用检查、文档、提交与合并一起收尾；实施者负责清理队列，不把内部拆分交给负责人。长期工作号可以逐次交付，当前增量完成不等于整个 ADR 已实现。
- 开工时核对分支与主线；发现安全泄露、数据损坏或当前交付的阻断缺陷，优先修复。无关增强归回下面对应工作号，不在当前任务中无限扩展。
- #135 当前批次已经收尾。**正确性底线不后移到客户现场**：已确认结果不得丢失或被重新裁决，权限不得泄漏；但只在当前交付实际使用的路径上补齐提交/恢复保证，不以“所有宿主入口尚未迁移”为由重开整项。旧历史、未接入入口及正式客户升级仍有明确门禁，不把受限证明扩大宣称。
- 下表是**串行执行顺序，不是同时开工清单**。W1–W4 沿用年度阶段，分别为 2026 年 10–12 月、2027 年 1–3 月、4–6 月、7–9 月；不是第几周。近期按交付完成顺延，不编造尚无工时依据的完工日期。每次收尾由实施者更新下一项，提前具备条件可提前推进。

四个观察维度——语义/数据、动作/协作（含 AI）、界面/工作区、治理/发布——用于发现短板，**不按“各到 60–70 分”分配工作，也不是四套运行时**。集成与数据对齐贯穿整条任务链。每次收尾核对：构建者能否在不改宿主和共享 UI 基础的前提下完成该增量，操作员能否在确切版本上完成任务，失败/无权/旧任务如何处理；缺一项就如实标为部分能力，不用单元测试或代码量替代完整旅程。无关的多对多、复杂流程、性能极限和全入口恢复留在它们自身的触发条件下。

## 当前基线

主线已包含 #135 本批次提交 `8b1be05`；其结果保存、应用接入及租户原地恢复的范围与验证见 [ADR-0038](ADR/0038-accepted-results-and-tenant-recovery.md)。#138 21a 编辑体验已由负责人走查通过，不重复索要该项验收。对象、页面、交付应用与生命周期/权限/审批基础已构建（ADR-0034–0037）；它们不等于不可变发布或隔离沙箱。#136 的只读候选闭包已接入真实代码与构建器归属方；构建者现能审查一份已保存草稿的差异、受影响闭包及拒绝诊断（路线 37），包括已安装页面因移除绑定字段而失效的诊断；对象开发期发布也不会绕过同一依赖校验。20b 首批已在主线：审查过的候选以精确字节存为已接受结果，构建者可把租户唯一活跃指针移到与运行定义一致的候选（重放/快照保留，路线 37 覆盖保存与激活）。剩余第 1 项：新工作与操作员读取记录活跃发布、在途审批固定其启动版本或拒绝不兼容激活，以及酒店/制造双行业操作员探针和崩溃点/`rehearse.sh` 验证；第一项未完成，不转去第二项。

首条任务链先用已有酒店与制造应用做小范围基线：记录从外部输入/现有数据到对象与动作、页面、发布、操作员结果所经过的真实路径；同时核对现有智能体能提供的受权辅助及其缺口。此处不新建连接器或 AI 引擎，不把现有智能体调用等同于 #133 的可复用 AI 函数，也不把仅有的代码页面/样例预览算作客户已能独立构建。
