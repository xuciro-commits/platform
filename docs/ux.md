# 界面与交互

这份文档回答：用户看到什么结构，怎样操作，文字怎么写。
长什么样在 [design](design.md)，怎样实现在 [frontend](frontend.md)。

整个产品只有一套交互：一个外壳、四种页面、一个保存模型。用户学会一个列表和一条记录，就会用全部工具与全部业务应用。
基准：外壳取 ERPNext 的应用轨加应用菜单；列表、记录与录入取 Frappe CRM；要胜出的对照物是 Frappe 的通用工作台。

## 用户

| 角色 | 心里想的 | 首要任务 |
|---|---|---|
| 业务用户 | 我在处理我的工作 | 找到相关的单据，做对的动作，让事情继续流转 |
| 构建者 | 我在把业务建成软件 | 从空白建出对象、动作与流程，业务用户当天能用 |
| 管理员 | 我在守住边界 | 人来人走时一次给对角色与标记 |
| 发布者 | 我在交付版本 | 把一组变更验证后发布成产品版本 |
| 集成者 | 我在接通系统 | 把外部系统的数据稳定地同步进来 |

## 十三条不变式

任何界面不得违反。要改其中一条，先改本文。

1. 一个外壳，两级导航。最外侧是应用轨，其右是当前应用的侧栏。没有顶部菜单栏，没有第三级导航；打开记录不改变侧栏。
2. 四种页面。每个页面是列表、记录、画布或仪表盘之一。不属于这四种的界面不建。
3. 列表即视图。筛选、排序、列、分组与布局立即生效。命名、置顶、公开与设为个人默认都是显式操作。
4. 记录一个形状。资源与对象用同一种记录页，不为某类记录另造详情布局。
5. 输入即保存。没有编辑模式，没有“保存”按钮：字段在失焦或回车时提交。成功不打断；失败显示在出错的字段上并保留输入。
6. 新建只经快速录入。新建是一个只含必填与关键字段的对话框，创建后进入记录页继续完善。不做向导，不做整页表单。
7. 一个区域一个主动作。主动作是这个区域最可能的下一步；其余操作次级或进入“⋯”菜单。
8. ⌘K／Ctrl+K 到达一切。命令面板只列可进入的应用、视图、记录与当前能执行的动作；每个操作都能只用键盘完成。
9. 选择出现批量条。只列宿主判定对全部选中项可用的动作；结果按记录返回，允许只对尚未成功的记录重试。
10. 四种状态齐全。每个读数据的区域都有空、加载、错误、拒绝：空状态说明怎样产生第一条数据，拒绝显示服务端给的原因。
11. 普通动作直接执行。宿主声明回程时提供撤销；删除、发布、安装、发送等不可撤销的高影响动作先确认并写明后果。
12. 地址还原应用、视图、可分享筛选、记录与页签；后退恢复列表位置与焦点。选中项、未提交的输入与敏感筛选值不进地址。
13. 只用 Astryx，从官方模板起步。不从空白写页面，不写裸 HTML 控件，不硬编码颜色与尺寸。

不显示原始 JSON：常规流程用结构化的编辑；JSON 只在“高级”折叠里出现。

## 导航与信息架构

- 层级至多四级：应用 → 入口 → 记录 → 页签。
- 每样东西只有一个规范位置与一个规范地址；移动资源不改地址。
- 同一样东西在所有地方用同一个名字，名字取自 [glossary](glossary.md)。
- 一个应用的一级菜单至多 12 项，按带标题的分节分组；一个入口只属于一个应用。
- 成员无权打开的应用与入口不显示，而不是显示成禁用。
- 界面文字与资源声明（名称、字段、状态、动作）可双语；业务数据不翻译。

应用轨自上而下：搜索（⌘K）、通知、平台应用、已安装的业务应用、助手、成员菜单（租户、语言、外观、账户、退出）。
通知铃铛带未读数，点开是渠道菜单：第一项是收件箱（/home/inbox），邮件、即时通讯、助手等渠道由产品包贡献。
收件箱按要做的事分页签，来源只是一列标签；对话类消息另用频道式的页面，不进收件箱。
“提及与评论”列出评论中的点名和关注记录的新评论，“通知”仍列出全部通知。阅读区可回到相关记录。
应用侧栏自上而下：应用切换器、该应用的菜单、置顶的视图。

平台有十个应用。一个应用是一个功能块：完成一类工作要的全部入口都在它的菜单里。

| 应用 | 分节与入口 |
|---|---|
| 主页 | 概览、我的工作、提案、最近、项目 |
| 数据 | 接入：连接、数据源、监听器、回写、观测源。加工：数据集、管道、调度、匹配规则、媒体集。追溯：血缘 |
| 本体 | 定义：对象类型、关系类型、动作类型、接口、共享属性、值类型、对象类型组。浏览：对象 |
| 逻辑 | 函数、自动化 |
| 应用 | 模块、对象视图、模板 |
| AI | 智能体、检索源、评估集 |
| 交付 | 发布：产品、版本、测试计划、样本集。安装：市场、安装 |
| 运行 | 运行记录、日志、追踪、指标、告警、健康、审计 |
| 管理 | 人员：组织、成员、团队。访问：业务角色、标记、支持授权。工作区：模型、语言与词汇、凭据、设置 |
| 宿主 | 租户、升级 |

已安装产品包声明的应用进入应用轨，应用侧栏放它声明的入口。只提供能力的包可在原工作台的相关位置出现，如记录页动作菜单。

“交付”里能分别查看市场与本租户安装，安装前审阅版本、依赖与配置，安装后能从同一处继续配置和管理启用状态。
获授权的管理员能看见待配置原因和停用影响。成员在原工作台操作，来源与参数可查。成员权限决定可见入口与可执行动作。

| 层级 | 地址 | 页面 |
|---|---|---|
| 入口 | `/<应用>/<入口>` | 列表或仪表盘；筛选、排序、分组与布局在查询串里 |
| 记录 | `/<应用>/<入口>/<标识>` | 记录页的第一个页签 |
| 页签 | `/<应用>/<入口>/<标识>/<页签>` | 记录页的某个页签 |
| 对象 | `/ontology/objects/<类型>/<主键>` | 对象的记录页 |

搜索：应用轨的搜索按钮与 ⌘K／Ctrl+K 打开命令面板。结果依次分组为命令、当前应用入口、其他应用入口、资源、对象、成员；输入为空时显示最近打开的记录和入口（至多八条）。
命令经当前页面的动作运行器执行。搜索时，回车打开高亮结果，未高亮时打开第一条结果。
前缀限定范围：`>` 命令，`@` 成员，`#` 项目，`:` 对象类型。只返回调用者看得见的结果。

## 四种页面

每个页面先声明自己是哪一种，再从对应的官方模板改造（[frontend](frontend.md)）。

### 列表

- 形状改造自官方模板 `table-filter`，所有列表共用。页头放标题与主动作“新建”。次级工具栏放刷新、筛选，以及同组的布局切换、视图选项与保存视图。
- 搜索回车生效。筛选芯片按字段类型生成，放不下折成 +N；高级查询与芯片读写同一份条件。无筛选显示总数，筛选后显示命中数与总数。
  已保存的视图经修改后显示未保存状态，可以保存或恢复保存时的配置。导入导出放“⋯”。
- 布局：表格是默认；分组把一个字段折叠成段。看板优先沿生命周期分列，没有生命周期时可沿首个可编辑且至多八个选项的字段分列。
  拖卡走对应动作与授权，需要参数或发布审阅时先打开对话框。泳道显示卡片数和可用的数值合计。
  层级数据用树，通知、待办与审批用左列表右详情的收件箱。
- 首列是显示字段，点它进记录页。点行的其余位置在右侧打开可拖宽的详情：状态、名称、主动作、“打开”与其余字段；窄屏是底部抽屉。
  行内不放编辑控件。末列是相对时间的更新时间。
- 有批量动作的类型显示复选框。选择后底部显示批量动作、已选数和取消选择。
- 空列表说明这类记录是什么，并给出“新建”。筛选无匹配时可以清空条件。

### 记录

- 页头：回到来源列表（保留它的筛选与位置）、显示名、状态、唯一的主动作、“⋯”。
  主动作是这条记录最可能的下一步，通常是当前状态下的首要动作。
- 主区是页签。第一个页签是字段，按类型描述分节，明细是表；之后是活动、关联、文件。
  活动是一条时间线，合并评论、字段变更与状态流转。
- 右栏：属性、指派与关注、记录信息（创建、更新、修订）；状态在页头。窄屏时右栏并入页签“属性”。
- 字段就地编辑（不变式 5）。只显示调用者能执行的动作；看得见但不能执行的动作禁用并说明原因。

### 画布

只给确实是图的东西：页面搭建、管道、逻辑流、血缘。左面板（结构与组件）、中画布、右检查器、底部停靠栏。
画布内容用专用的库，它的工具条、面板与表单仍只用 Astryx。画布是记录页的一个全幅页签。

### 仪表盘

全局筛选 → 一行统计块（点进去是对应的列表）→ 图表与紧凑的行列表，带“查看全部”。仪表盘不放编辑，只放导航与下一步。

设置不是页面：用对话框，左侧分节，右侧表单，输入即保存。
登录页是产品里唯一的营销式页面：宽屏左栏是产品说明，右栏是登录卡；窄屏登录卡在最前。

## 类型开箱清单

声明一个对象类型就该得到的能力。这是对 Frappe 工作台追平的清单；每一项只做在界面运行时里，不为某个类型另写。

| 能力 | Frappe 里叫 | 我们怎样给 |
|---|---|---|
| 列表：筛选、排序、分组、保存的视图 | List View、Report View | 列表页 |
| 看板、树、收件箱、日历 | Kanban、Tree、Calendar | 列表页的布局 |
| 记录页与就地编辑 | Form View | 记录页加编辑动作 |
| 新建 | Quick Entry | 创建动作的对话框 |
| 明细 | Child Table | 引用父记录的子对象（带 `inverse`，父类型声明集合），在父记录页上是可编辑的表 |
| 引用 | Link | 字段类型 `reference`，输入即搜 |
| 状态与流程 | Workflow、可提交单据 | 类型的状态加动作 |
| 评论、指派、关注、时间线 | Comments、Assign、Follow、Timeline | 记录页的活动 |
| 附件 | Attach | 字段类型 `attachment` 与记录页的文件 |
| 权限 | Role Permission、User Permission | 授权引擎；界面只显示能做的 |
| 搜索 | Awesomebar | ⌘K |
| 通知 | Notification、Email | 通知与收件箱 |
| 统计与图表 | Dashboard、Number Card | 仪表盘 |
| 应用首页与菜单 | Workspace | 应用菜单，由产品包声明 |
| 编号、默认值、取自引用的值 | Naming、Default、Fetch From | 类型描述 |
| 导入导出、打印 | Data Import、Print Format | 列表的“⋯”；打印的归属到阶段 2 再定 |
| 定制 | Custom Field、Customize Form、Script | 客户项目里的扩展：追加字段、动作、页面与受控函数 |
| 接口 | `/api/resource` | 记录读取、对象集与动作 |

## 编辑与保存

- 对象：字段就地提交，立即生效；每次提交一个字段，走该类型的编辑动作。
- 定义（对象类型这类资源）：同样就地提交，保存的是草稿；“发布”之后才对业务用户生效。
- 两人改同一条记录时，后提交的人看到“别人先保存了”，按字段对比原值、我的值和已保存值；选择之前保留输入。
- 提交等待时留在原位置并显示状态，相关数据更新后保持焦点；响应丢失时在原处重试同一次提交。
- 离开页面前，等待提交的输入先提交；被拒绝而没能保存的输入要提示，不悄悄丢掉。

## 覆盖层

| 需要 | 用 | 不用 |
|---|---|---|
| 新建记录、设置、选取 | 对话框 | 整页表单 |
| 确认不可撤销的操作 | 警示对话框，写明后果，危险按钮写出动词 | 没有说明的“确定” |
| 单字段修改、分组、列 | 行内编辑或气泡 | 对话框 |
| 少于 8 项的操作 | 下拉菜单、“⋯”、右键菜单 | 对话框 |
| 操作结果 | 轻提示，能撤销时带“撤销” | 对话框 |
| 持续的警告、错误、下一步 | 就地的横幅 | 轻提示 |

覆盖层不叠覆盖层。记录只在主视图打开，没有侧窗。看一眼被引用的记录用悬停卡片。

## 键盘

| 快捷键 | 作用 |
|---|---|
| ⌘K／Ctrl+K | 命令面板与搜索 |
| ⌘\／Ctrl+\ | 收起或展开侧栏 |
| ⌘,／Ctrl+, | 设置 |
| ↑↓、Enter、空格 | 在列表里移动、打开、勾选 |
| Esc | 关闭最上层的覆盖层；没有覆盖层时取消选择 |
| ? | 当前页面的快捷键一览 |

打开覆盖层时焦点进入第一个可编辑字段，关闭后回到触发它的元素；创建成功后焦点进入新记录的第一个空字段。
输入法组字期间的回车及文本输入里的 `?` 交给输入框；拖动可用同一动作的键盘入口完成。窄屏保留同一组操作与可见焦点。

## 文字

- 语气：简洁、陈述、主动。不客套，不感叹，不用“请”。
- 按钮：动词加宾语；确认按钮重复标题里的动词。
- 错误：说发生了什么，再说怎么修。
- 术语只用 [glossary](glossary.md) 里的词。
- 中文用全角标点；数字、单位、代码保持半角。
- 时间：列表用相对时间，悬停显示绝对时间；导出用 ISO 8601。
- 英文原文就是翻译键；每个新字符串同时给出简体中文。

## 自查十问

每次改界面对照一遍，任何一项不满足就是缺陷。

1. 我在哪：页头、返回链接、侧栏高亮一致。
2. 我能做什么：主动作唯一且醒目。
3. 为什么不能：禁用与拒绝都有原因。
4. 我做了什么：提交之后有及时的反馈。
5. 能撤回吗：能撤销的不确认，不能撤销的确认并写明后果。
6. 一致：同一个操作在所有地方同名、同位。
7. 防错：校验就地、即时。
8. 认出而不是回忆：引用靠选，不要求输入标识。
9. 高效：键盘能完成，批量能完成。
10. 简洁：没有原始 JSON，没有重复的信息，没有装饰。

效率的底线：⌘K 三次按键内到达任何东西；新建的必填字段不超过四个；常用编辑不打开新页面；
首屏两秒内可交互，一万行的列表滚动不卡。
