# 2 产品体系

## 目标

给出平台的产品矩阵与能力归属：每类资源由哪个工具应用拥有，每项能力由哪个产品唯一提供，平台与行业应用的边界在哪里。新能力写代码前必须先在本文找到唯一归属。

## 2.1 规则

- R1 一类资源只由一个工具应用打开和编辑；一个应用可拥有多类资源。别的应用只引用、不编辑（引用时跳转到拥有者）。
- R2 一项能力只有一个提供者。通知、文件、审批、评论、审计、搜索、调度、出站调用、模型调用等通用能力由下表的唯一产品提供，其他产品只调用（否则就是“能力逃逸”）。
- R3 工具应用使用 Palantir 产品名作专有名词，中英文界面都不翻译；资源类型名按行业通用词翻译，见 [glossary](glossary.md)。
- R4 平台不含行业代码。行业概念（总账、工单、房态、BOM）只能以产品包中的本体与应用表达。
- R5 平台的每项能力都必须能进入产品包、被安装与升级（否则不算完成）。
- R6 不建第二套构建路径：平台方构建行业应用与客户构建者扩展应用，用的是同一批工具。
- R7 业务流程用本体表达：对象类型的生命周期状态 + 动作 + 自动化 + 工作项。不建独立的流程引擎（Foundry 也没有；独立引擎会形成第二套写入路径）。

## 2.2 产品矩阵

### 外壳

| 产品 | 拥有的资源 | 用户 |
|---|---|---|
| Home | 无；个人工作台：待办、最近、项目、提案 | 所有人 |
| Search | 无；资源、对象、应用、命令统一搜索 | 所有人 |
| Files | 项目、文件夹；所有资源的位置与项目访问 | 所有人 |
| Applications | 无；应用门户 | 所有人 |
| Notifications | 无；通知、工作项收件箱、审批请求 | 所有人 |

### 数据集成

| 产品 | 拥有的资源 | 用户 |
|---|---|---|
| Data Connection | 源、同步、流、导出、监听器（入站 webhook）、出站 webhook | 集成者 |
| Pipeline Builder | 管道、调度 | 构建者 |
| Dataset Preview | 数据集、媒体集（非结构化文件集） | 构建者 |

### 本体

| 产品 | 拥有的资源 | 用户 |
|---|---|---|
| Ontology Manager | 对象类型、属性、共享属性、关系类型、接口、值类型、动作类型、对象类型组 | 构建者 |

### 逻辑与自动化

| 产品 | 拥有的资源 | 用户 |
|---|---|---|
| Logic | 函数：代码函数、决策表、AIP Logic、逻辑流 | 构建者 |
| Automate | 自动化（条件 → 效果；告警是带通知效果的自动化） | 构建者 |

### 应用

| 产品 | 拥有的资源 | 用户 |
|---|---|---|
| Workshop | 模块（多页面应用）、对象视图（绑定到对象类型的模块）、模板 | 构建者 |
| Object Explorer | 探索、保存的对象列表 | 业务用户、构建者 |

### AI

| 产品 | 拥有的资源 | 用户 |
|---|---|---|
| Agent Studio | 智能体、检索源、评估集 | 构建者 |
| AIP Assist | 无；全局助手，作用于当前页面上下文 | 所有人 |

### 治理

| 产品 | 拥有的资源 | 用户 |
|---|---|---|
| Control Panel | 组织、成员、团队、业务角色、标记、支持授权、模型供应商与模型、语言与词汇、凭据、租户与应用设置、审计查询 | 管理员 |
| DevOps | 产品（打包定义）、产品版本、发布审阅、业务测试计划 | 构建者、发布者 |
| Marketplace | 安装、升级 | 管理员、构建者 |
| Data Lineage | 无；血缘图与标记传播 | 构建者 |
| Monitoring | 监控视图；运行记录（同步、构建、自动化、函数、投递） | 构建者、管理员 |

分支与提案属于治理面：每个工具应用侧栏顶部的分支控件进入，提案在 Home 与 Notifications 汇总，不属于任何工具。

### 宿主

| 产品 | 拥有的资源 | 用户 |
|---|---|---|
| Host Console | 租户、宿主升级、迁移 | 宿主运维者 |

## 2.3 通用能力归属

| 能力 | 唯一提供者 | 其他产品如何使用 |
|---|---|---|
| 写入对象 | 动作（Ontology Manager 定义） | 应用、自动化、AIP 都只调用动作 |
| 计算 | 函数（Logic） | 动作规则、Workshop 变量、自动化条件调用函数 |
| 谓词与条件 | Expr（领域内核） | 提交条件、行策略、过滤、自动化条件共用一个构建器 |
| 对象读取 | ObjectSet（领域内核） | Workshop、Object Explorer、函数、AIP 共用 |
| 通知 | Notifications | 动作副作用与自动化效果产生通知 |
| 工作项与审批 | 平台内置对象类型“工作项” + Notifications 收件箱 | 动作创建与关闭工作项；审批是带决定动作的工作项 |
| 文件与附件 | 媒体集 + 附件属性类型 | 对象以属性引用文件，不各自存文件 |
| 评论与时间线 | 内置“评论”动作 + 对象视图的 Activity 分区 | 不在模块里自建时间线 |
| 调度 | Pipeline Builder 的调度（构建的时间计划）；自动化的时间条件属于自动化本身 | 不在其他产品里放定时器 |
| 出站调用 | Data Connection 的出站 webhook 与导出 | 动作副作用引用它们，不直接发 HTTP |
| 模型调用 | AI 网关（模型在 Control Panel 配置） | AIP Logic、Agent Studio、AIP Assist 调用网关 |
| 搜索 | Search 索引 | 各产品提供可索引的元数据，不自建搜索 |
| 审计 | 接受结果日志 | Control Panel 查询；资源页 History 分区展示 |
| 权限 | 授权引擎（唯一实现） | 所有读写都过同一决定路径 |
| 打包与安装 | DevOps 与 Marketplace | 资源声明可打包性，不自建导入导出 |

## 2.4 平台内置与产品包

| 放在平台 | 放进产品包 |
|---|---|
| 资源内核、本体元模型、动作与函数引擎、授权 | 行业对象类型、动作、函数、模块 |
| 组织、成员、团队、标记 | 行业角色（作为业务角色定义在包里） |
| 工作项、通知、文件、评论 | 行业流程（状态、动作、自动化） |
| 模型网关、Agent 运行时 | 行业智能体与提示 |
| 跨行业共用的参考数据类型（货币、计量单位、国家） | 行业主数据（物料、客户、房型） |

判断方法：同一需求在两个以上行业出现，且无法用现有资源表达，才进入平台；否则进包。

## 2.5 行业应用

- 一个行业应用是一个产品：一个项目中的资源集合，经 DevOps 打包为不可变的产品版本。
- 命名用行业标准系统名：MES、ERP、PMS、HCM、WMS、CRM，不用临时词。
- 每个行业应用先能独立运转（例如 MES 自己创建生产订单），再接受外部系统推送同类事实（ERP 下达订单）；两条路径进入同一组动作。
- 行业应用之间只经产品依赖与版本化接口（对象类型接口、动作）协作，不共享内部资源。
- 安装到客户租户后，产品的资源位于受管项目中，客户不能直接编辑；客户扩展放在自己的项目中，引用受管资源（继承接口、追加属性、新增动作与模块）。升级只替换受管项目，客户扩展保持有效；不兼容的升级由发布审阅提前列出。

## 2.6 产品边界

| 不做 | 去处 |
|---|---|
| 报表设计器、BI 看板 | Workshop 的图表与指标组件；专业分析待 Contour/Quiver 类工具进入矩阵 |
| 低代码表单引擎 | 动作类型的 Form 分区 |
| 独立流程引擎、BPMN | R7 |
| 通用脚本执行 | 代码函数的受控编译与隔离执行 |
| 每个应用自带的权限页 | Files 项目访问 + Control Panel |
| 每个应用自带的导入导出 | Data Connection 与 DevOps |

## 2.7 交付形态

- 平台：宿主二进制与 Web 资源，按部署形态交付（见 [1-enterprise §1.6](1-enterprise.md)）。
- 行业应用：产品版本（声明式，内容寻址），可发布到 Marketplace 目录，安装到任意租户。
- 客户资源：留在客户租户，可用 DevOps 打包为客户自己的产品。
