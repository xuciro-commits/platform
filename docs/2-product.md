# 2 产品体系

## 目标

给出平台的产品矩阵与能力归属：每类资源由哪个应用拥有，每项能力由哪个产品唯一提供，平台与行业应用的边界在哪里。新能力写代码前必须先在本文找到唯一归属。

## 2.1 规则

- R1 一类资源只由一个应用打开和编辑；一个应用可拥有多类资源。别的应用只引用、不编辑（引用时跳转到拥有者）。
- R2 一项能力只有一个提供者。通知、文件、审批、评论、审计、搜索、调度、出站调用、模型调用等通用能力由下表的唯一产品提供，其他产品只调用（否则就是“能力逃逸”）。
- R3 应用按它承担的工作命名，用行业通用词，中英文各一个名字，随界面语言显示；不用厂商产品名（用户按要做的事找入口，不按产品名找）。菜单项用它列出的资源类型名；名字都在 [glossary](glossary.md)。
- R4 平台不含行业代码。行业概念（总账、工单、房态、BOM）只能以产品包中的本体与应用表达。
- R5 平台的每项能力都必须能进入产品包、被安装与升级（否则不算完成）。
- R6 不建第二套构建路径：平台方构建行业应用与客户构建者扩展应用，用的是同一批工具。
- R7 业务流程用本体表达：对象类型的生命周期状态 + 动作 + 自动化 + 工作项。不建独立的流程引擎（Foundry 也没有；独立引擎会形成第二套写入路径）。
- R8 内置应用自举：能用本体、动作、自动化与 Workshop 表达的内置能力，以系统产品包交付并随宿主预装，不写成 Go（平台工具做不出平台自己的应用，就做不出客户的应用）。首批是工作项、审批、通知收件箱与监控视图；投递、索引、授权、观测存储等引擎留在平台。

## 2.2 产品矩阵

平台有十个应用。一个应用是一个功能块：完成一类工作所需的全部入口都在它的菜单里，一个入口只属于一个应用。菜单见 [3-information §3.3](3-information.md)。

### 外壳

| 能力 | 内容 | 用户 |
|---|---|---|
| 搜索 | 资源、对象、应用、命令的统一搜索（⌘K） | 所有人 |
| 通知 | 通知、工作项收件箱、审批请求 | 所有人 |
| 助手 | 全局助手，作用于当前页面上下文 | 所有人 |

### 应用

| 应用 | 承担的工作 | 拥有的资源 | 用户 |
|---|---|---|---|
| 主页 Home | 个人工作台与资源的位置 | 项目、文件夹；待办、提案与最近是汇总，不是资源 | 所有人 |
| 数据 Data | 接入外部系统，加工成数据集，追溯来源 | 连接、数据源、监听器、回写、观测源；数据集、媒体集；管道、调度、匹配规则。血缘是只读视图（数据血缘、影响分析与标记传播；定义依赖与能力发现不属于它） | 集成者、构建者（项目委派者按项目范围） |
| 本体 Ontology | 定义业务对象并浏览它们 | 对象类型、属性、共享属性、关系类型、接口、值类型、动作类型、对象类型组；探索、保存的对象列表 | 构建者、业务用户 |
| 逻辑 Logic | 写计算与自动反应 | 函数（代码函数、决策表、AIP Logic、逻辑流）；自动化（条件 → 效果；告警是带通知效果的自动化） | 构建者 |
| 应用 Apps | 搭建业务界面 | 模块（多页面应用）、对象视图（绑定到对象类型的模块）、模板 | 构建者 |
| AI | 构建与评估智能体 | 智能体、检索源、评估集 | 构建者 |
| 交付 Delivery | 打包、发布、安装与升级 | 产品（项目中的 Contents 与依赖）、发布候选、不可变产品版本、发布审阅、业务测试计划、样本集；安装、升级、退役、重装 | 构建者、发布者、管理员 |
| 运行 Operations | 看系统在做什么 | 监控视图；运行、日志、追踪、指标、告警、健康与审计查询是只读视图 | 构建者、管理员、审计员（按能力） |
| 管理 Admin | 管人、权限与工作区设置 | 组织、成员、团队、业务角色、标记、支持授权、模型供应商与模型、语言与词汇、凭据、租户与应用设置 | 管理员；审计员按能力只读 |
| 宿主 Host | 运维宿主 | 租户、宿主升级、迁移 | 宿主运维者 |

已安装的产品包各自成为一个业务应用，排在平台应用之后；它的菜单由产品包里的模块声明。

分支与提案属于治理面：从每个应用侧栏的分支控件进入，提案在主页与通知汇总，不属于任何应用。

## 2.3 通用能力归属

| 能力 | 唯一提供者 | 其他产品如何使用 |
|---|---|---|
| 写入对象 | 动作（Ontology Manager 定义） | 应用、自动化、AIP 都只调用动作 |
| 计算 | 函数（Logic） | 动作规则、Workshop 变量、自动化条件调用函数 |
| 谓词与条件 | Expr（领域内核） | 提交条件、行策略、过滤、自动化条件共用一个构建器 |
| 对象读取 | ObjectSet（领域内核） | Workshop、Object Explorer、函数、AIP 共用 |
| 通知 | Notifications | 动作副作用与自动化效果产生通知 |
| 工作项与审批 | 系统产品包的对象类型“工作项” + Notifications 收件箱 | 动作创建与关闭工作项；审批是带决定动作的工作项 |
| 文件与附件 | 媒体集 + 附件属性类型 | 对象以属性引用文件，不各自存文件 |
| 评论与时间线 | 内置“评论”动作 + 对象视图的 Activity 分区 | 不在模块里自建时间线 |
| 调度 | Pipeline Builder 的调度（构建的时间计划）；自动化的时间条件属于自动化本身 | 不在其他产品里放定时器 |
| 出站调用 | Data Connection 的回写 | 动作副作用引用它们，不直接发 HTTP |
| 模型调用 | AI 网关（模型在 Control Panel 配置） | AIP Logic、Agent Studio、AIP Assist 调用网关 |
| 搜索 | Search 索引 | 各产品提供可索引的元数据，不自建搜索 |
| 审计 | 接受结果与拒绝、安全事件账本 | Control Panel 查询；资源页 History 分区展示 |
| 运营日志 | Monitoring 的独立观测存储 | 只用于诊断，不进入 journal；按租户、运行、资源与请求关联 |
| 追踪与指标 | OpenTelemetry 与受限 rollup | Monitoring 查询；告警复用 Automate |
| 权限 | 授权引擎（唯一实现） | 所有读写都过同一决定路径 |
| 打包与安装 | DevOps 与 Marketplace | 资源声明可打包性，不自建导入导出 |
| 外部应用定义的转换 | 仓库的构建工具（[6-domain/packages §6.28](6-domain/packages.md)） | 产出作者态包源，之后与其他产品包同路；租户里没有这项能力 |

日志不是审计，审计也不是日志。运行状态仍由原 owner 拥有，Monitoring 只投影与关联；任何产品不得建立第二套运行扫描或日志网关。

## 2.4 平台内置与产品包

| 放在平台 | 放进产品包 |
|---|---|
| 资源内核、本体元模型、动作与函数引擎、授权 | 行业对象类型、动作、函数、模块 |
| 组织、成员、团队、标记 | 行业角色（作为业务角色定义在包里） |
| 通知投递、文件与媒体存储、评论动作 | 行业流程（状态、动作、自动化） |
| 系统产品包（R8）：工作项、审批、通知收件箱、监控视图 | 行业自己的任务类型与审批流 |
| 模型网关、Agent 运行时 | 行业智能体与提示 |
| 跨行业共用的参考数据类型（货币、计量单位、国家） | 行业主数据（物料、客户、房型） |

判断方法：同一需求在两个以上行业出现，且无法用现有资源表达，才进入平台；否则进包。系统产品包与行业产品包同格式、同安装路径，区别只是随宿主预装。

## 2.5 行业应用

- 一个行业应用是一个产品：一个项目中的资源集合，经 DevOps 打包为不可变的产品版本。
- 命名用行业标准系统名：MES、ERP、PMS、HCM、WMS、CRM，不用临时词。
- 每个行业应用先能独立运转（例如 MES 自己创建生产订单），再接受外部系统推送同类事实（ERP 下达订单）；两条路径进入同一组动作。
- 行业应用之间只经产品依赖与版本化接口（对象类型接口、动作）协作，不共享内部资源。
- 安装到客户租户后，产品的资源位于受管项目中，客户不能直接编辑；客户扩展放在自己的项目中，引用受管资源（继承接口、追加属性、新增动作与模块）。升级只替换受管项目，客户扩展保持有效；不兼容的升级由发布审阅提前列出。

## 2.6 产品边界

| 不做 | 去处 |
|---|---|
| 报表设计器、BI 看板 | Workshop 的图表与指标组件；专业分析待 Contour/Quiver 类工具进入矩阵 |
| 低代码表单引擎 | 动作类型的 Form 分区 |
| 独立流程引擎、BPMN | R7 |
| 通用脚本执行 | 代码函数的受控编译与隔离执行 |
| 每个应用自带的权限页 | Files 项目访问 + Control Panel |
| 每个应用自带的导入导出 | Data Connection 与 DevOps |

## 2.7 交付形态

- 平台：宿主二进制与 Web 资源，按部署形态交付（见 [1-enterprise §1.6](1-enterprise.md)）。
- 行业应用：产品版本（声明式，内容寻址），可发布到 Marketplace 目录，安装到任意租户。
- 客户资源：留在客户租户，可用 DevOps 打包为客户自己的产品。

## 2.8 类型开箱能力

声明一个对象类型就应得到的能力；这是对 Frappe 追平的清单（[1-enterprise §1.11](1-enterprise.md)）。每项由一个提供者给出，界面由界面运行时按类型生成（[7-system/web](7-system/web.md)），不为某个类型另写。“新前端”一列只记 `frontend/` 是否已经给出。

| 能力 | Frappe 里的名字 | 提供者 | 新前端 |
|---|---|---|---|
| 列表：筛选、排序、分组、保存的视图 | List View、Report View | 列表原型 | 文本筛选与分组 |
| 记录页与就地编辑 | Form View | 记录原型 + 动作 | 只读页，编辑经对话框 |
| 新建 | Quick Entry | 创建动作的表单 | 按动作参数生成的对话框 |
| 看板、收件箱、树、日历 | Kanban、Tree、Calendar、Gantt | 列表原型的表现方式 | 无 |
| 明细行 | Child Table | 字段类型“明细行” | 无 |
| 状态与流程 | Workflow、可提交单据 | 生命周期状态 + 动作（R7） | 无 |
| 评论、指派、关注、时间线 | Comments、Assign、Follow、Timeline | 评论动作、工作项、记录页 Activity | 无 |
| 附件 | Attach | 媒体集 + 附件属性 | 无 |
| 接口 | `/api/resource` | 记录读取、ObjectSet 与动作 | 读取 |
| 权限 | Role Permission、User Permission | 授权引擎：项目角色、标记、行列策略 | 拒绝态 |
| 搜索 | Awesomebar | 搜索（⌘K） | 无 |
| 通知 | Notification、Email | 通知 | 无 |
| 统计与图表 | Dashboard、Number Card | 仪表盘原型、Workshop 图表 | 无 |
| 应用首页与菜单 | Workspace | 应用菜单（产品包的模块声明） | 手写清单 |
| 导入导出 | Data Import、Export | 数据应用与交付（2.6） | 无 |
| 外发与定时 | Webhook、Scheduler | 回写、监听器、自动化、调度 | 无 |
| 翻译 | Translation | 管理的语言与词汇 | 界面文案 |
| 定制 | Custom Field、Customize Form、Client 与 Server Script | 客户项目里的扩展：追加属性、动作、模块与受控函数（2.5） | 无 |
| 打印 | Print Format | 未定归属 | 无 |
| 对外页面 | Website、Portal、Web Form | 未定归属 | 无 |

## 现存差距

- 类型开箱能力（2.8，第 6、7 层）：宿主一侧每项能力的现状尚未逐项核对；打印与对外页面没有归属。排期见[路线图](roadmap.md)“五、前端重建”。
- 产品矩阵（2.2、R3；第 7 层与其余规范）：宿主的应用注册（`capabilities/server/platform/app_registry.json`）、`web/` 以及本文 2.3 起和其余规范仍用上一套产品名。对照：Home、Files → 主页；Data Connection、Pipeline Builder、Dataset Preview、Data Lineage → 数据；Ontology Manager、Object Explorer → 本体；Logic、Automate → 逻辑；Workshop → 应用；Agent Studio → AI；DevOps、Marketplace → 交付；Monitoring 与 Control Panel 的审计查询 → 运行；Control Panel → 管理；Host Console → 宿主；Search、Notifications、AIP Assist → 外壳的搜索、通知、助手；Applications 门户由应用轨取代。各处随所在小节改写时换名；注册表在新前端接入宿主时换名（路线图“五、前端重建”W1）。
- 验证范围与尚未覆盖的运行模式统一见 [7-system/verification §7.13](7-system/verification.md#713-sql-模式)。
- 内置应用（R8，第 7 层）：工作项、审批、通知收件箱与监控视图是 Go 与手写前端（`capabilities/server/services/work`、`web/packages/*`），没有系统产品包。
- 能力归属（2.3，第 7 层）：资源编辑集中在 `services/resources/authoring`，位置见 [7-system 现存差距](7-system/README.md#现存差距)。
