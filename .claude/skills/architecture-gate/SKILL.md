# 架构门禁 (Architecture gate)

先确认已有 ADR 是否已决定该选择。负责人已有授权持续有效；一个缺失的实现或测试分支本身不要求新 ADR。

1. 按 AGENTS 的入口读取相关设计，对照受影响代码确认现状。只有外部产品做法影响这次选择时才查当前一手资料，不默认调研所有标杆。
2. 对未决选择写 ADR：状态、具体问题、现状证据、可行选项、推荐及代价、能力归属和必要的权限/版本/恢复边界。篇幅与选择复杂度匹配，不为格式补充无关章节或比较表。
3. 在 WorkQueue 标记 `gate, owner decision`，只就仍未授权且会改变设计的选择请负责人决定；已经授权的部分继续推进。设计授权不代表所有年度能力立即开工。
4. 决定接受后记录日期与范围，按 WorkQueue 交付小批次，用 `close-out` 收尾。ADR 描述实现顺序与依赖，活动批次状态只放 WorkQueue。

阶段出口仍按 Platform §10.6 验收。两行业复用、完整构建者/操作员旅程、视觉认可与恢复演练在对应集成或阶段检查点验证；每个小批次只承担其实际改变的边界，不能把全部门禁抄成每批停止条件。
