# 完成工作批次 (Close out a batch)

对照 WorkQueue 中本批的可见结果与停止条件审查 diff。测试选择与重复条件以 [Testing](../../../docs/Testing.md#检查选择与停止) 为准；同一事实只在其归属处维护。

## 验证

运行本批适用检查。检查通过后进入交付；有新变更、失败或尚未验证的必要边界时才重跑相关检查。纯文档批次只查链接、引用、语义一致性与 `git diff --check`；修改技能时运行可用的技能校验工具。说明实际观察和测试的范围，不把工程通过写成负责人或年度验收。

## 只更新事实改变的文档

| 变化 | 归宿 |
|---|---|
| 架构决策、实现范围与限制 | 对应 ADR；改变决策才改设计，能力增量合并更新当前 As built，不追加逐批日志 |
| 能力增加或保证改变 | Platform §2.4 摘要，链接 ADR；新日志语义另更新 §2.7 并覆盖 `CheckReplay` |
| 产品方向、阶段目标 | Intent / Platform §10；日常修复无需更新 |
| 批次完成、下一步、待办缺口 | WorkQueue；完成批次移除，剩余范围留在原工作号 |
| 新的操作路径或检查方法 | Apps / Testing；记录实际可用路径，环境配置归部署 README |
| 数据归属、术语、入口变化 | Platform §2.3 / §2.5 或 AGENTS 对应入口；只改受影响项 |

若已有文字明确冲突，针对该事实修正或链接到其权威说明；无需每批全文扫描所有历史文档。保留 ADR 历史及取代关系，不复制测试日志、逐提交流水账或完整能力状态表。

## 交付

按已有授权提交、推送或保留可审查 diff；只包含本批改动。汇报可用结果、检查结论、必要限制与下一项。仅在集中产品验收或负责人要求时交接人工走查，不为每次小修复安排一轮负责人测试。
